::: quiz 01-confusion
Какая ошибка — «ложная тревога» в задаче об уходе гостей?

- [x] FP: модель сказала «уйдёт», а гость остался
  > Бонус отправлен зря.
- [ ] FN: модель сказала «останется», а гость ушёл
  > Это пропуск, а не ложная тревога.
- [ ] TP
  > TP — верно найденный уходящий.
- [ ] TN
  > TN — верно найденный остающийся.
:::

::: quiz 02-precision-recall
Модель отметила 50 гостей, 20 из них действительно ушли. Всего ушло 80. Чему равны точность и полнота?

- [x] Точность 0.4 (20 / 50), полнота 0.25 (20 / 80)
  > Точность — среди отмеченных, полнота — среди всех уходящих.
- [ ] Точность 0.25, полнота 0.4
  > Перепутаны знаменатели.
- [ ] Обе 0.4
  > Полнота считается от всех 80 ушедших.
- [ ] Точность 0.2, полнота 0.8
  > Здесь использованы не те числа.
:::

::: quiz 03-threshold
Что происходит с точностью и полнотой при снижении порога?

- [x] Полнота обычно растёт, точность обычно падает
  > Отмечаем больше гостей: ловим больше уходящих, но и ложных тревог больше.
- [ ] Обе растут
  > Полнота растёт, а точность обычно падает: в отмеченные попадает всё больше остающихся. Это компромисс.
- [ ] Обе падают
  > При снижении порога полнота не может упасть: отмеченных становится только больше.
- [ ] Ничего не меняется
  > Порог прямо меняет, кого модель отмечает.
:::

::: quiz 03b-money-threshold
Бонус стоит 300 ₽, а бонус уходящему гостю приносит 1 200 ₽. С какой вероятности ухода бонус в среднем окупается (если вероятностям модели можно верить)?

- [x] С p > 0.25: ожидаемая выгода p × 1200 больше стоимости 300 ₽
  > Порог безубыточности — стоимость, делённая на выгоду: 300 / 1200 = 0.25.
- [ ] С p > 0.5: бонус даём, только если гость скорее уйдёт, чем останется
  > 0.5 — порог по умолчанию, деньги он не учитывает. Бонус окупается уже при p × 1200 > 300.
- [ ] С p > 0.8: бонус дорогой, нужна большая уверенность
  > Бонус в четыре раза дешевле выгоды, поэтому он окупается уже при четверти шансов.
- [ ] С любой p: бонус дешевле выгоды
  > Выгода есть только от гостя, который иначе ушёл бы; при p = 0.1 ожидаемая выгода 120 ₽ меньше 300 ₽.
:::

::: quiz 04-imbalance
Аналитик сначала размножил уходящих во всей таблице, а потом разделил её на train и test. F1 на тесте — 0.94. Чему верить?

- [x] Не верить: копии одних и тех же уходящих попали и в train, и в test, модель их просто узнаёт
  > Балансировку делают только на обучающей части (или внутри обучающих фолдов). Честная оценка будет заметно ниже.
- [ ] Верить: балансировка сделала модель лучше
  > Балансировка сдвигает компромисс точности и полноты, но не поднимает F1 до 0.94 — это утечка.
- [ ] Верить, если тест стратифицирован
  > Стратификация не мешает копиям одного гостя оказаться по обе стороны разбиения.
- [ ] Верить, если F1 на train ещё выше
  > Высокий F1 на train ничего не доказывает про новых гостей.
:::

::: quiz 04-imbalance
Что делает `class_weight="balanced"`?

- [x] Увеличивает вес ошибок на редком классе, чтобы модель не игнорировала его
  > Модель перестаёт тянуться к большинству; часто это похоже на сдвиг порога.
- [ ] Удаляет часть частого класса
  > Это downsampling, другой приём.
- [ ] Делает классы одинаковыми по размеру в данных
  > Данные не меняются — меняются веса в обучении.
- [ ] Повышает accuracy
  > Accuracy часто даже падает — растёт полнота редкого класса.
:::

::: quiz 05-scaling
Каким моделям масштабирование признаков важно, а каким почти нет?

- [x] Важно kNN и моделям с регуляризацией вроде логистической регрессии; деревьям и лесу почти нет
  > Деревья режут по порогам, и масштаб признака на это не влияет.
- [ ] Важно всем одинаково
  > Деревьям всё равно.
- [ ] Важно только деревьям
  > Наоборот.
- [ ] Не важно никому
  > kNN без масштаба меряет расстояния в «рублях против дней».
:::

::: quiz 05b-regularization
Что делает L1-регуляризация, чего не делает L2?

- [x] Может обнулить веса части признаков — то есть отбирает признаки
  > L2 уменьшает веса, но обычно не до нуля.
- [ ] Увеличивает веса
  > Регуляризация штрафует большие веса.
- [ ] Ничем не отличается
  > Отличие — в том, обнуляет ли она веса.
- [ ] Работает только для деревьев
  > Это приём для линейных моделей.
:::

::: quiz 06-features
Как проверить, полезен ли новый признак?

- [x] Сравнить качество на кросс-валидации с признаком и без него
  > Польза — это прирост качества на данных, которые модель не видела.
- [ ] Посмотреть, коррелирует ли он с ответом
  > Корреляция подсказывает, но не доказывает пользу для модели.
- [ ] Посмотреть на качество на обучении
  > На обучении почти любой признак «помогает».
- [ ] Если признак логичный — он полезен
  > Логика — повод проверить, а не доказательство.
:::

::: quiz 06b-feature-check
В таблицу добавили столбец случайного шума, и по `feature_importances_` леса он обогнал несколько настоящих признаков. Что это значит?

- [x] Встроенная важность меряет, как часто признак пригодился при обучении, и завышает признаки с множеством разных значений; проверять пользу лучше перестановкой на отложенных данных
  > У шума почти все значения разные, и дерево находит в них много случайных порогов. Перестановка покажет, что модель на шум не опирается.
- [ ] Шум действительно полезен — оставить его
  > Случайный столбец по определению ничего не знает об уходе гостей.
- [ ] Настоящие признаки, которых обогнал шум, бесполезны — удалить их
  > Важность по `feature_importances_` здесь искажена; без проверки перестановкой удалять признаки рано.
- [ ] Лес сломан — нужна другая модель
  > Лес работает нормально; так ведёт себя именно встроенная мера важности.
:::

::: quiz 07-pipeline
Главная польза Pipeline?

- [x] Подготовка и модель — один объект: одинаково применяются к новым данным и учатся только на train внутри кросс-валидации
  > Это и воспроизводимость, и защита от утечек.
- [ ] Модель становится точнее
  > Сам по себе Pipeline качество не меняет.
- [ ] Работает быстрее
  > Скорость примерно та же.
- [ ] Можно не делить на train и test
  > Делить по-прежнему нужно.
:::

::: quiz 08-tuning
Чем случайный поиск может быть лучше перебора по сетке?

- [x] При том же числе запусков он пробует больше разных значений важных параметров
  > Сетка тратит запуски на сочетания с неважными параметрами.
- [ ] Он всегда находит лучшее значение
  > Не гарантирует — как и сетка.
- [ ] Он не требует кросс-валидации
  > Требует так же, как сетка.
- [ ] Он не зависит от случайности
  > Зависит — поэтому фиксируют `random_state`.
:::

::: quiz 09-project
Почему для заявок метрика «доля договоров в верхних 30 % списка» лучше ROC-AUC?

- [x] Она описывает реальный процесс: менеджеры успевают 30 % заявок, и важно, сколько договоров среди них
  > ROC-AUC смотрит на весь порядок, включая хвост, который всё равно не обзванивают.
- [ ] ROC-AUC нельзя посчитать на этих данных
  > Можно, просто он отвечает на другой вопрос.
- [ ] Она всегда выше AUC
  > Это разные шкалы — сравнивать числа бессмысленно.
- [ ] Директор не любит английские сокращения
  > Дело в смысле метрики, а не в названии.
:::
