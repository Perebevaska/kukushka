**До выбора вариантов.** Две модели ищут проблемные заявки, а сотрудники могут проверить только 30 заявок в день. Как организовать сравнение моделей при таком ограничении?

::: quiz 01-confusion
Какая ошибка — «ложная тревога» в задаче об уходе гостей?

- [x] FP: предсказан уход, но гость остался
  > Бонус отправлен зря.
- [ ] FN: предсказано сохранение, но гость ушёл
  > Это пропуск, а не ложная тревога.
- [ ] TP: предсказан уход, и гость ушёл
  > TP — верно найденный уходящий.
- [ ] TN: предсказано сохранение, и гость остался
  > TN — верно найденный остающийся.
:::

::: quiz 02-precision-recall
Модель отметила 50 гостей, 20 из них действительно ушли. Всего ушло 80. Чему равны точность и полнота?

- [x] Точность 0.4, полнота 0.25
  > Точность — среди отмеченных, полнота — среди всех уходящих.
- [ ] Точность 0.25, полнота 0.4
  > Перепутаны знаменатели.
- [ ] Точность 0.4, полнота 0.4
  > Полнота считается от всех 80 ушедших.
- [ ] Точность 0.2, полнота 0.8
  > Здесь использованы не те числа.
:::

::: quiz 03-threshold
Что происходит с точностью и полнотой при снижении порога?

- [x] Полнота обычно растёт, а точность обычно падает
  > Отмечаем больше гостей: ловим больше уходящих, но и ложных тревог больше.
- [ ] Точность и полнота обычно растут вместе
  > Полнота растёт, а точность обычно падает: в отмеченные попадает всё больше остающихся. Это компромисс.
- [ ] Точность и полнота обычно падают вместе
  > При снижении порога полнота не может упасть: отмеченных становится только больше.
- [ ] Точность и полнота сохраняются при любом пороге
  > Порог прямо меняет, кого модель отмечает.
:::

::: quiz 03b-money-threshold
Бонус стоит 300 ₽ для каждого получателя. По условиям сценария бонус гостю, который без акции ушёл бы, приносит в среднем 1 200 ₽ дополнительной маржи до стоимости бонуса; остальным — ноль. Какова точная граница, выше которой ожидаемая чистая маржа строго положительна? Считайте вероятности модели надёжными.

- [x] При p > 0.25
  > Маржа равна p × 1 200 − 300. При p = 0.25 она нулевая, положительной становится при p > 0.25.
- [ ] При p > 0.5
  > 0.5 — порог по умолчанию, деньги он не учитывает. Бонус окупается уже при p × 1200 > 300.
- [ ] При p > 0.8
  > При p = 0.3 ожидаемая маржа уже положительна: 360 − 300 = 60 ₽.
- [ ] При любом p > 0
  > Выгода есть только от гостя, который иначе ушёл бы; при p = 0.1 ожидаемая выгода 120 ₽ меньше 300 ₽.
:::

::: quiz 04-imbalance
Аналитик сначала размножил уходящих во всей таблице, а потом разделил её на train и test. F1 на тесте — 0.94. Чему верить?

- [x] Не верить: копии утекли из обучения в тест
  > Балансировку делают только на обучающей части (или внутри обучающих фолдов). Насколько изменится F1 на новых гостях, покажет только честная оценка.
- [ ] Верить: балансировка повысила качество
  > Балансировка может изменить качество, но здесь оценка скомпрометирована копиями между train и test. Само число 0.94 не доказывает утечку.
- [ ] Верить: стратификация убирает утечку
  > Стратификация не мешает копиям одного гостя оказаться по обе стороны разбиения.
- [ ] Верить: достаточно ещё большего F1 на train
  > Высокий F1 на train ничего не доказывает про новых гостей.
:::

::: quiz 04-imbalance
Что делает `class_weight="balanced"`?

- [x] Увеличивает вес ошибок редкого класса
  > Модель перестаёт тянуться к большинству; часто это похоже на сдвиг порога.
- [ ] Удаляет часть наблюдений частого класса
  > Это downsampling, другой приём.
- [ ] Уравнивает число наблюдений двух классов
  > Данные не меняются — меняются веса в обучении.
- [ ] Гарантирует повышение общей accuracy
  > Accuracy часто даже падает — растёт полнота редкого класса.
:::

::: quiz 05-scaling
Каким моделям масштабирование признаков важно, а каким почти нет?

- [x] Важно kNN и регрессии со штрафом, не деревьям
  > Деревья режут по порогам, и масштаб признака на это не влияет.
- [ ] Одинаково важно всем моделям, включая деревья
  > Деревьям всё равно.
- [ ] Важно только деревьям, регрессиям не требуется
  > Наоборот.
- [ ] Не важно никому при числовых входных данных
  > kNN без масштаба меряет расстояния в «рублях против дней».
:::

::: quiz 05b-regularization
Что делает L1-регуляризация, чего не делает L2?

- [x] Может обнулить веса и тем самым отобрать признаки
  > L2 уменьшает веса, но обычно не до нуля.
- [ ] Увеличивает модуль всех весов признаков
  > Регуляризация штрафует большие веса.
- [ ] Даёт ровно тот же результат, что и L2
  > Отличие — в том, обнуляет ли она веса.
- [ ] Применяется исключительно к деревьям решений
  > Это приём для линейных моделей.
:::

::: quiz 06-features
Как проверить, полезен ли новый признак?

- [x] Сравнить качество кросс-валидации с ним и без него
  > Польза — это прирост качества на данных, которые модель не видела.
- [ ] Сравнить только корреляцию признака с ответом
  > Корреляция подсказывает, но не доказывает пользу для модели.
- [ ] Проверить рост метрики на обучающих данных
  > На обучении почти любой признак «помогает».
- [ ] Оценить правдоподобие его делового объяснения
  > Логика — повод проверить, а не доказательство.
:::

::: quiz 06b-feature-check
В таблицу добавили столбец случайного шума, и по `feature_importances_` леса он обогнал несколько настоящих признаков. Что это значит?

- [x] Важность на train не гарантирует пользу на новых данных
  > Встроенная важность может отражать случайные зависимости на train. Проверьте важность перестановкой на отложенных данных: результат и его разброс нужно измерить, а не выводить из места в рейтинге.
- [ ] Шум полезен: высокая важность достаточна для отбора
  > Случайный столбец по определению ничего не знает об уходе гостей.
- [ ] Признаки ниже шума бесполезны и подлежат удалению
  > Важность по `feature_importances_` здесь искажена; без проверки перестановкой удалять признаки рано.
- [ ] Алгоритм леса сломан: надо заменить семейство моделей
  > Лес работает нормально; так ведёт себя именно встроенная мера важности.
:::

::: quiz 07-pipeline
Главная польза Pipeline?

- [x] Подготовка и модель обучаются на train фолда
  > При кросс-валидации Pipeline обучает подготовку только на обучающей части фолда, затем применяет её к проверочной. Это защищает от утечки через предобработку.
- [ ] Гарантированное повышение точности любой модели
  > Сам по себе Pipeline качество не меняет.
- [ ] Сокращение времени обучения каждого алгоритма
  > Скорость примерно та же.
- [ ] Объединение train и test без риска утечки
  > Делить по-прежнему нужно.
:::

::: quiz 08-tuning
Чем случайный поиск может быть лучше перебора по сетке?

- [x] Пробует больше разных значений при том же бюджете
  > Сетка тратит запуски на сочетания с неважными параметрами.
- [ ] Гарантирует нахождение глобально лучшего набора
  > Не гарантирует — как и сетка.
- [ ] Позволяет оценивать параметры без кросс-валидации
  > Требует так же, как сетка.
- [ ] Даёт один результат независимо от зерна случайности
  > Зависит — поэтому фиксируют `random_state`.
:::

::: quiz 09-project
В сервисе ремонта за день 200 заявок. Диспетчер может перепроверить 20. Для ретроспективной оценки исходы всех 200 заявок уже известны. Как честно сравнить две модели поиска повторных поломок?

- [x] За тот же день проверить повторы в топ-20 каждой модели
  > Общие кандидаты, период и бюджет позволяют сравнить, сколько нужных событий найдено при одной мощности отдела.
- [ ] Проверить топ-20 первой модели и топ-60 второй
  > Разная нагрузка может объяснить разницу числа найденных поломок.
- [ ] Сравнить accuracy обеих моделей на всех 200 заявках
  > Она не показывает результат конкретной очереди из 20 заявок.
- [ ] Выбрать модель с наибольшими численными вероятностями
  > Масштаб вероятностей сам по себе не определяет порядок и число событий в верхних 20.
:::
