В уроке «Эмбеддинги: векторы слов и отзывов» вектор отзыва получался усреднением векторов слов, а у каждого слова был один вектор на все случаи. Здесь — как устроены модели, которые учитывают контекст.

## Внутри трансформера: токены, паддинг, маска, пулинг

У word2vec одно слово — один вектор, где бы оно ни стояло: «холодный» в «холодный кофе» (жалоба) и в «холодный раф со льдом» (заказ) — одна точка. Модели семейства **BERT** (трансформеры-энкодеры, 2018) дают вектор каждому слову **в его контексте**: механизм внимания смешивает вектор слова с векторами соседей по всему тексту. **Внимание** (attention) — это взвешенное среднее: для каждого токена модель считает веса всех токенов текста (неотрицательные, в сумме 1), и новый вектор токена — сумма векторов всех токенов с этими весами. Веса модель вычисляет сама по векторам токенов, а маска внимания (о ней ниже) ставит вес заполнителей в 0. Именно такая модель — `rubert-tiny2` — стояла в разделе «Предобученные эмбеддинги» урока «Эмбеддинги: векторы слов и отзывов». Для неё же есть библиотека-обёртка `sentence-transformers`: она делает токенизацию и пулинг за вас одной строкой `encode(texts)`, но внутри идёт тот же путь, который мы разберём руками.

Саму сеть мы не обучаем — её берут готовой. Но путь «текст → вектор» аналитик проходит руками, и на каждом шаге есть своя ловушка:

```text
текст → токенизатор → id токенов → дополнение до общей длины + маска → модель → вектор на каждый токен → пулинг → вектор текста
```

::: tip Аналогия
Пакет текстов для модели — как поднос с чашками разного размера в кофемашине-автомате: машина работает только с одинаковыми ячейками, поэтому короткие тексты дополняют «пустыми чашками» (паддинг), а маска — наклейка «пусто, не наливать». Если при подсчёте среднего забыть про наклейки, пустые чашки попадут в итог.
:::

**Токенизатор: слова → кусочки.** Словарь BERT — десятки тысяч **подслов** (subword): частые слова целиком, редкие — из кусочков. Кусочек из середины слова помечен `##`. Алгоритм WordPiece жадный: с начала слова берёт самый длинный кусок, который есть в словаре, затем продолжает с места, где остановился. Если на каком-то шаге подходящего куска нет, всё слово становится `[UNK]` (неизвестный).

Игрушечный словарь из 23 кусочков:

| слово | разбор | почему |
|---|---|---|
| курьером | курьер, ##ом | «курьером» целиком нет, самый длинный кусок с начала — «курьер» |
| привезли | при, ##вез, ##ли | слово собрано из трёх кусочков |
| невкусно | не, ##вкус, ##но | приставка, корень, суффикс |
| латте | [UNK] | ни «латте», ни «л…» в словаре нет |

```python
VOCAB = ["[PAD]", "[UNK]", "[CLS]", "[SEP]", "кофе", "курьер", "##ом", "##а", "при", "##вез", "##ли",
         "холод", "##ный", "##ным", "кап", "##учино", "бар", "##иста", "не", "##вкус", "вкус", "##но", "раф"]
ID = {t: i for i, t in enumerate(VOCAB)}         # кусочек → номер (id)

def wordpiece(word):
    pieces, start = [], 0
    while start < len(word):
        end = len(word)
        while end > start:                         # ищем самый длинный кусок с позиции start
            piece = word[start:end] if start == 0 else "##" + word[start:end]
            if piece in ID:
                break
            end -= 1
        if end == start:                           # ни один кусок не подошёл
            return ["[UNK]"]
        pieces.append(piece)
        start = end
    return pieces

def encode(text):
    tokens = ["[CLS]"] + [p for w in text.lower().split() for p in wordpiece(w)] + ["[SEP]"]
    return tokens, [ID[t] for t in tokens]

for text in ["курьер привезли холодный капучино", "раф невкусно", "латте"]:
    print(encode(text))
```

**Что здесь происходит:**

- Внутренний `while` укорачивает кусок с конца, пока он не найдётся в словаре; кусок не с начала слова ищется с префиксом `##`.
- `encode` добавляет служебные токены: `[CLS]` в начале (его вектор иногда берут как вектор всего текста) и `[SEP]` в конце (граница текста).
- Модель видит не слова, а id — номера строк в её таблице векторов.

**Паддинг и маска.** В пакете тексты разной длины, а модель принимает прямоугольную матрицу. Короткие дополняют id `[PAD]` (здесь 0) до длины самого длинного, а рядом передают **маску внимания** (`attention_mask`): 1 — настоящий токен, 0 — заполнитель. Модель по маске не смотрит на заполнители, когда считает векторы настоящих токенов.

```python
import numpy as np

batch = [[2, 5, 8, 9, 10, 11, 12, 14, 15, 3],     # «курьер привезли холодный капучино»
         [2, 22, 18, 19, 21, 3]]                   # «раф невкусно»
L = max(len(ids) for ids in batch)
input_ids = np.array([ids + [0] * (L - len(ids)) for ids in batch])
attention_mask = (input_ids != 0).astype(int)
print(input_ids)
print(attention_mask)
```

**Как маска работает внутри модели.** Посмотрим на внимание в игрушечном виде. Три настоящих токена с векторами из двух чисел и один заполнитель с «мусорным» вектором (5, 5). Вес токена j для токена i — экспонента скалярного произведения их векторов, делённая на сумму таких экспонент по строке: так веса становятся положительными и в сумме дают 1 (это softmax — обобщение сигмоиды на много вариантов). Маска ставит заполнителю оценку −∞, его экспонента равна 0 — и вес тоже.

```python
import numpy as np

X = np.array([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0], [5.0, 5.0]])   # 3 токена + заполнитель
mask = np.array([1, 1, 1, 0])

scores = X @ X.T                          # сходство каждого токена с каждым
scores[:, mask == 0] = -np.inf            # на заполнители не смотрим
W = np.exp(scores) / np.exp(scores).sum(axis=1, keepdims=True)
print(W.round(2))                         # веса: строка — токен, который «смотрит»
print((W @ X).round(2))                   # новые векторы — взвешенные средние
```

**Что получилось:** у первого токена веса 0.42, 0.16, 0.42 и 0 — его новый вектор (0.84, 0.58) — смесь его самого и соседей, заполнитель не участвует. Без строки с маской заполнитель с большим вектором забрал бы у первых двух токенов по 0.96 веса, и все векторы стали бы почти (5, 5) — мусором. В настоящей модели векторы перед этим умножаются на обученные матрицы, а слоёв внимания несколько, но роль маски та же. Строка заполнителя тоже что-то считает, но её результат дальше никто не использует — если не забыть маску в пулинге.

**Пулинг с маской.** На выходе модель даёт тензор формы (тексты × токены × признаки) — вектор на каждую позицию, **включая заполнители**: их векторы не нулевые, это просто мусор. Вектор текста — среднее по настоящим токенам. Игрушечный пример: в тексте два токена с векторами (1, 3) и (3, 1) и два заполнителя с векторами (0.5, −2).

- Среднее с маской: ((1 + 3) / 2, (3 + 1) / 2) = **(2, 2)**.
- Среднее «в лоб» по всем четырём позициям: ((1 + 3 + 0.5 + 0.5) / 4, (3 + 1 − 2 − 2) / 4) = **(1.25, 0)** — другой вектор, и он зависит от того, сколько заполнителей добавили.

::: figure masked-pool
Игрушечный пример: два настоящих токена и два заполнителя. С маской — (2, 2), «в лоб» — (1.25, 0): заполнители тянут вектор текста к мусору.
:::

$$\bar h = \frac{\sum_t m_t \, h_t}{\sum_t m_t}$$

Здесь $h_t$ — вектор токена на позиции $t$, $m_t$ — значение маски (1 или 0), $\bar h$ — вектор текста. В числителе заполнители умножаются на 0, в знаменателе — число настоящих токенов.

```python
import numpy as np

H = np.array([[[1.0, 3.0], [3.0, 1.0], [0.5, -2.0], [0.5, -2.0]]])   # 1 текст × 4 позиции × 2 признака
mask = np.array([[1, 1, 0, 0]])

pooled = (H * mask[:, :, None]).sum(axis=1) / mask.sum(axis=1, keepdims=True)
naive = H.mean(axis=1)
print("с маской:", pooled, "| в лоб:", naive)
```

**Что здесь происходит:**

- `mask[:, :, None]` — маска формы (1, 4) становится (1, 4, 1). numpy сам растянет её до формы `H` (1, 4, 2): каждая координата токена умножится на его 0 или 1.
- `.sum(axis=1)` — сумма по позициям; `mask.sum(axis=1, keepdims=True)` — число настоящих токенов, форма (1, 1), чтобы делить построчно.
- `naive` — ошибочный вариант для сравнения.

**Что получилось:** с маской — (2, 2), в лоб — (1.25, 0). В настоящем пакете короткий отзыв, оказавшийся рядом с длинным, получил бы десятки заполнителей, и его вектор «в лоб» почти целиком состоял бы из мусора. Хуже того, вектор одного и того же отзыва зависел бы от соседей по пакету.

На своём компьютере весь путь — несколько строк с библиотекой `transformers` (нужен PyTorch, в браузере не работает). Модель `cointegrated/rubert-tiny2` — маленький русский BERT, около 120 МБ:

```python static
# uv add transformers torch
import numpy as np
import torch
from transformers import AutoTokenizer, AutoModel

name = "cointegrated/rubert-tiny2"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModel.from_pretrained(name).eval()          # eval(): режим применения, без dropout

texts = ["Курьер опоздал, кофе остыл.", "Очень вкусный раф!"]
batch = tok(texts, padding=True, truncation=True, max_length=128, return_tensors="pt")
print(tok.convert_ids_to_tokens(batch["input_ids"][0]))  # кусочки первого текста
print(batch["attention_mask"])

with torch.no_grad():                                    # без градиентов: быстрее и меньше памяти
    H = model(**batch).last_hidden_state                 # тексты × токены × 312
m = batch["attention_mask"].unsqueeze(-1)
E = ((H * m).sum(1) / m.sum(1)).numpy()                  # пулинг с маской
E = E / np.linalg.norm(E, axis=1, keepdims=True)
print(E.shape, E[0] @ E[1])
```

- `tok(texts, padding=True, truncation=True, max_length=128, return_tensors="pt")` — токенизация, дополнение и маска одной строкой; длинные тексты обрезаются до 128 токенов.
- `model(**batch).last_hidden_state` — те самые векторы токенов; `.unsqueeze(-1)` — то же, что `[:, :, None]` в numpy.

Кодирование тысяч текстов на процессоре занимает минуты. Заполнители модель тоже обрабатывает, поэтому длинный отзыв в пакете с короткими заставляет считать много пустых позиций; тексты перед разбивкой на пакеты часто сортируют по длине — заполнителей становится меньше. И векторы **кэшируют**: считают один раз, сохраняют в файл и при повторном запуске читают с диска. Полный пример — пакетная обработка, кэш с проверкой, что тексты не поменялись, и классификатор поверх векторов — в локальном блокноте [ch13-transformers.ipynb](../notebooks/extra/ch13-transformers.ipynb).

::: warn Типичные ошибки
- **Пулинг без маски** — см. вопрос выше. Симптом: качество классификатора на векторах «плавает» от размера пакета.
- **Токенизатор от другой модели.** Номера кусочков у каждой модели свои; чужой токенизатор даёт бессмысленные id без всякой ошибки. Токенизатор и модель грузят по одному имени.
- **Обрезка длинных текстов.** У классического BERT предел — 512 токенов, у каждой модели он свой (`tok.model_max_length`). Всё, что дальше `max_length`, модель не видит — длинные отзывы режут на куски или берут начало и конец. При `truncation=True` токенизатор обрезает середину списка так, чтобы `[CLS]` остался в начале, `[SEP]` — в конце, а вся длина вместе с ними не превысила `max_length`.
- **Забыть `torch.no_grad()` и `eval()`.** Без `no_grad()` для каждого пакета хранится граф вычислений для градиентов — память растёт; без `eval()` работает dropout и векторы получаются случайными.
:::

         "холод", "##ный", "##ным", "кап", "##учино", "бар", "##иста", "не", "##вкус", "вкус", "##но", "раф"]
ID = {t: i for i, t in enumerate(VOCAB)}
words = ["курьером", "привезли", "холодным", "невкусно", "бариста", "латте", "кофейня"]

def wordpiece(word):
    pieces, start = [], 0
    while start < len(word):
        end = len(word)
        while end > start:
            piece = word[start:end] if start == 0 else "##" + word[start:end]
            if piece in ID:
                break
            end -= 1
        if end == start:
            return ["[UNK]"]
        pieces.append(piece)
        start = end
    return pieces

### hint
Пакеты — срезы `lens[i:i + size]` для `i` в `range(0, len(lens), size)`. Последний пакет может быть короче — берите его реальную длину `len(chunk)`.

### hint
Заполнителей в пакете: `max(chunk) * len(chunk) - sum(chunk)`. Отсортированный вариант — `pad_count(sorted(lens))`.

### solution
```python
def pad_count(lens, size=8):
    total = 0
    for i in range(0, len(lens), size):
        chunk = lens[i:i + size]
        total += max(chunk) * len(chunk) - sum(chunk)
    return total

pad_plain = pad_count(lens)
pad_sorted = pad_count(sorted(lens))
saved = round(1 - pad_sorted / pad_plain, 3)
print(pad_plain, pad_sorted, saved)
```

### explain
В исходном порядке добавляется 9722 заполнителя при 24 470 настоящих токенах — больше четверти позиций (28 %), которые обработает модель, пустые. После сортировки заполнителей 66: соседи по пакету почти одной длины, экономия 99.3 %. С маской векторы от этого не меняются, только время. Порядок результатов потом надо вернуть исходный — запомните индексы до сортировки (`np.argsort(lens)`), иначе векторы окажутся у чужих отзывов.
