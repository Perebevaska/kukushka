::: quiz 01-gradient
Что показывает знак производной функции потерь по весу?

- [x] В какую сторону потеря растёт; шаг делают в обратную
  > Спуск: w ← w − lr · производная.
- [ ] Насколько хороша модель
  > Качество показывает сама потеря.
- [ ] Сколько шагов осталось
  > Производная этого не знает.
- [ ] Нужен ли свободный член
  > Это вопрос устройства модели.
:::

::: quiz 01-gradient
Шаг обучения слишком маленький. Что будет?

- [x] Спуск сойдётся, но очень медленно — понадобится много шагов
  > Слишком большой шаг опаснее: спуск расходится.
- [ ] Спуск разойдётся
  > Расходится при слишком большом шаге.
- [ ] Модель переобучится
  > Шаг влияет на скорость, а не прямо на переобучение.
- [ ] Ничего не изменится
  > Число шагов до цели сильно вырастет.
:::

::: quiz 02-gd-many
Чем стохастический спуск по мини-батчам отличается от обычного?

- [x] Градиент считается по небольшой порции строк, поэтому шагов за проход по данным гораздо больше
  > Каждый шаг шумнее, но в сумме спуск быстрее и подходит для больших данных.
- [ ] Он точнее на каждом шаге
  > Наоборот, шумнее.
- [ ] Он не использует градиент
  > Использует, только по части данных.
- [ ] Он не требует шага обучения
  > Требует.
:::

::: quiz 03-boosting
Чему учится каждое следующее дерево в градиентном бустинге (для MSE)?

- [x] Остаткам: разнице между ответом и текущим прогнозом ансамбля
  > Каждое дерево исправляет то, что ещё не объяснено.
- [ ] Тем же ответам, что и первое
  > Это был бы лес без бутстрэпа.
- [ ] Случайным подвыборкам независимо от других
  > Так устроен случайный лес.
- [ ] Ошибкам на тесте
  > Тест в обучении не участвует.
:::

::: quiz 03-boosting
Зачем в бустинге маленький шаг (learning rate), а не прибавлять поправку целиком?

- [x] Маленькие шаги делают ансамбль устойчивее и меньше подгоняют шум, ценой большего числа деревьев
  > Шаг и число деревьев настраивают вместе.
- [ ] Чтобы обучение шло быстрее
  > Наоборот, нужно больше деревьев.
- [ ] Иначе деревья станут глубже
  > Глубина задаётся отдельно.
- [ ] Без шага бустинг не работает
  > Работает, но обычно хуже обобщает.
:::

::: quiz 02-gd-many
Спуск идёт со штрафом L2: к градиенту прибавляется 2λw. Что это значит для весов на каждом шаге?

- [x] Перед обычным шагом каждый вес (кроме свободного члена) умножается на число чуть меньше 1 — веса «затухают», если градиент их не поддерживает
  > w − η(g + 2λw) = (1 − 2ηλ)w − ηg. Поэтому L2-штраф называют ещё затуханием весов, а в итоге спуск приходит к решению Ridge.
- [ ] Все веса обнуляются, как только λ > 0
  > Вес уменьшается на долю 2ηλ, а градиент тянет его обратно. Вес остаётся ненулевым, если признак полезен.
- [ ] Шаг обучения увеличивается в (1 + 2λ) раз
  > Шаг η не меняется. Меняется сама цель: к ошибке добавлен штраф за размер весов.
- [ ] Штраф действует только на свободный член
  > Наоборот: свободный член не штрафуют, он отвечает за средний уровень прогноза.
:::

::: quiz 04-tuning
Что такое ранняя остановка бустинга?

- [x] Прекратить добавлять деревья, когда качество на валидации перестаёт улучшаться
  > Так выбирают число деревьев без перебора.
- [ ] Остановить обучение через фиксированное время
  > Время тут ни при чём.
- [ ] Ограничить глубину деревьев
  > Глубина — другой параметр.
- [ ] Взять первые 10 деревьев
  > Число определяется по валидации.
:::

:::

::: quiz 05-project
Признак «тренд» (номер дня) помогает бустингу на обучении, но вредит на будущих данных. Почему?

- [x] Деревья не экстраполируют: для дней после конца обучения они повторят последние значения
  > Бустинг на деревьях хорошо описывает прошлое, но не продолжает рост за его пределы.
- [ ] Номер дня — утечка
  > Номер дня известен заранее — это не утечка.
- [ ] Признак слишком большой по величине
  > Деревьям масштаб не важен.
- [ ] Бустинг не работает с целыми числами
  > Работает.
:::

::: quiz 01-gradient
Модель тональности отзывов: 200 000 текстов и 30 000 слов-признаков. Почему её учат спуском, а не нормальным уравнением?

- [x] Формуле нужна таблица XᵀX размером 30 000 × 30 000 и решение системы порядка d³ операций, а шаг спуска стоит всего около 2·n·d
  > Цена формулы растёт как n·d² + d³, спуска — как k·n·d. При десятках тысяч признаков формула проигрывает и по времени, и по памяти.
- [ ] Для текстов нормальное уравнение даёт неверные веса
  > Если бы его удалось посчитать, веса были бы точными. Проблема в цене вычислений, а не в правильности.
- [ ] Спуск всегда быстрее формулы
  > На таблице с десятком признаков формула дешевле спуска в сотни раз.
- [ ] 200 000 строк слишком много для формулы
  > Число строк входит в обе оценки линейно. Решает число признаков.
:::
