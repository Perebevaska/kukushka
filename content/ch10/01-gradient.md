## Ошибка как функция веса

Возьмём простую модель: $\text{время доставки} = w \times \text{расстояние}$. Какой выбрать $w$? Для каждого значения $w$ можно посчитать среднеквадратичную ошибку (MSE) на данных — это **функция потерь** $L(w)$. Нарисуем её:

```python
import numpy as np
import matplotlib.pyplot as plt

km = np.array([1.0, 2.0, 3.0, 4.5, 6.0])
minutes = np.array([18.0, 25.0, 34.0, 44.0, 55.0])

def loss(w):
    return np.mean((w * km - minutes) ** 2)

ws = np.linspace(0, 20, 81)
fig, ax = plt.subplots(figsize=(6, 3.5))
ax.plot(ws, [loss(w) for w in ws])
ax.set_xlabel("w, минут на км")
ax.set_ylabel("MSE")
plt.show()
```

Посчитаем одну точку руками: $w = 5$. Прогнозы 5, 10, 15, 22.5, 30 минут, ошибки −13, −15, −19, −21.5, −25. Квадраты: 169, 225, 361, 462.25, 625; среднее — **368.45**. А при $w = 10$: прогнозы 10, 20, 30, 45, 60, ошибки −8, −5, −4, 1, 5, MSE = (64 + 25 + 16 + 1 + 25) / 5 = **26.2** — гораздо лучше.

**Что здесь происходит в коде:**

- `loss(w)` — MSE модели «$\text{минуты} = w \times \text{км}$» на пяти доставках.
- `np.linspace(0, 20, 81)` — 81 значение $w$ от 0 до 20; для каждого считаем потерю и рисуем кривую.

Получилась «яма»: при маленьком и большом $w$ ошибка большая, где-то посередине — минимальная. Обучение модели — это поиск дна ямы.

Здесь параметр один, и дно видно глазами. Но у модели могут быть тысячи весов — перебрать все сочетания невозможно. Нужен способ двигаться к дну, зная только, куда наклонена поверхность в текущей точке.

## Наклон: производная

**Производная** $L'(w)$ — наклон кривой в точке $w$. Если она положительна, ошибка растёт с ростом $w$ — значит, $w$ надо уменьшать. Если отрицательна — увеличивать. Чем круче наклон, тем дальше мы от дна.

Для MSE производная по $w$ считается вручную: $L(w) = \operatorname{mean}\big((w \cdot x - y)^2\big)$, $L'(w) = \operatorname{mean}\big(2 \cdot (w \cdot x - y) \cdot x\big)$. Откуда множители. Производная квадрата $u^2$ равна $2u$ — отсюда $2 \cdot (\text{ошибка})$. Но ошибка $w \cdot x - y$ сама зависит от $w$: при сдвиге $w$ на единицу она меняется на $x$. Поэтому результат умножают ещё на $x$ (это правило цепочки: производная внешней функции × производная внутренней). Среднее по строкам просто переносится на производные каждой строки.

Формулу легко проверить численно — посмотреть, как меняется ошибка при крошечном сдвиге $w$:

```python
import numpy as np
km = np.array([1.0, 2.0, 3.0, 4.5, 6.0])
minutes = np.array([18.0, 25.0, 34.0, 44.0, 55.0])

def loss(w):
    return np.mean((w * km - minutes) ** 2)

def grad(w):
    return np.mean(2 * (w * km - minutes) * km)

w, eps = 5.0, 1e-5
numeric = (loss(w + eps) - loss(w - eps)) / (2 * eps)
print(round(float(grad(w)), 4), round(float(numeric), 4))
```

**Что здесь происходит:**

- `grad(w)` — производная по формуле: среднее от 2 · ошибка · признак.
- `numeric` — та же производная «на глаз»: сдвигаем $w$ чуть вправо и чуть влево и смотрим, насколько изменилась потеря; делим на расстояние между точками ($2\varepsilon$).
- $\varepsilon = 0.00001$ — достаточно маленький сдвиг, чтобы кривая на этом отрезке была почти прямой.

Формула и численная оценка совпадают. При $w = 5$ производная отрицательная: ошибка падает, если $w$ увеличить.

::: figure loss-slope
Та же кривая потерь на пяти доставках. Красные отрезки — касательные: при w = 5 наклон −138.7 (ошибка падает вправо, w надо увеличивать), при w = 15 — +142.3 (надо уменьшать). На дне наклон равен нулю.
:::

::: quiz
В текущей точке производная потери по весу положительная и большая. Что делает следующий шаг градиентного спуска?

- [x] Уменьшает вес, и заметно: ошибка растёт с ростом веса, а склон крутой
  > Шаг идёт против наклона: из веса вычитается шаг обучения, умноженный на производную. Положительная производная — вес уменьшается, большая — шаг длинный.
- [ ] Увеличивает вес: раз производная положительная, двигаемся в плюс
  > Знак производной показывает, куда ошибка **растёт**. Спуск идёт в обратную сторону — поэтому в правиле стоит минус.
- [ ] Ничего не меняет: большая производная означает, что мы у минимума
  > У минимума производная близка к нулю. Большая по модулю производная — признак, что до дна далеко.
- [ ] Сначала нужно узнать саму потерю: по наклону направление не определить
  > Как раз по наклону направление и определяется — значение потери для шага не нужно.
:::

## Шаг вниз

**Градиентный спуск** повторяет одно правило:

$$
w \leftarrow w - \eta \cdot L'(w)
$$

Число $\eta$ (эта) — **шаг обучения** (learning rate): насколько далеко шагаем против наклона.

::: tip Аналогия
Представьте спуск с холма в густом тумане: дна не видно, но под ногами чувствуется, куда склон идёт вниз и насколько он крут. Вы делаете шаг под уклон и снова ощупываете склон — это и есть градиентный спуск, а шаг обучения задаёт, насколько широко шагать. Хромает аналогия в одном: в спуске длина шага ещё и пропорциональна крутизне ($\eta \cdot L'(w)$), поэтому на крутом склоне слишком большой $\eta$ перебрасывает не на соседнюю кочку, а на противоположный склон.
:::

```python
import numpy as np
km = np.array([1.0, 2.0, 3.0, 4.5, 6.0])
minutes = np.array([18.0, 25.0, 34.0, 44.0, 55.0])

def loss(w):
    return np.mean((w * km - minutes) ** 2)

def grad(w):
    return np.mean(2 * (w * km - minutes) * km)

w, lr = 0.0, 0.01
for step in range(30):
    w = w - lr * grad(w)
    if step % 5 == 4:
        print(f"шаг {step + 1}: w = {w:.3f}, MSE = {loss(w):.2f}")
```

Первые шаги руками (lr = 0.01, старт $w = 0$):

| шаг | $w$ до шага | производная | $w$ после $= w - 0.01 \cdot \text{производная}$ | MSE после |
|---|---|---|---|---|
| 1 | 0.000 | −279.20 | 2.792 | 743.2 |
| 2 | 2.792 | −200.74 | 4.799 | 396.8 |
| 3 | 4.799 | −144.34 | 6.243 | 217.8 |

Производная отрицательная — $w$ растёт; ближе ко дну она меньше по модулю — шаги укорачиваются сами, хотя lr не меняется.

**Что здесь происходит в коде:**

- `w = w - lr * grad(w)` — одна строка и есть весь алгоритм.
- `if step % 5 == 4` — печатаем каждый пятый шаг, чтобы не засорять вывод.

За 30 шагов $w$ подбирается к значению около 9.9 минуты на км, а ошибка перестаёт падать. Для этой модели точный минимум можно найти и формулой: приравнять производную к нулю, $\operatorname{mean}\big(2 \cdot (w x - y) \cdot x\big) = 0$, откуда $w = \frac{\sum xy}{\sum x^2} \approx 9.936$. Это нормальное уравнение из главы 9 для одного признака без свободного члена. Спуск пришёл туда же, ни разу не решив уравнение.

Почему: производная отрицательная — ошибка падает при росте w, поэтому шаг увеличивает w: 2 − 0.1 · (−5) = 2.5.
:::

## Длина шага решает

Шаг обучения — главный «рычаг» градиентного спуска:

- **маленький** (0.001) — спуск верный, но медленный: за 30 шагов далеко не дойдём;
- **подходящий** (0.01) — быстро и устойчиво;
- **слишком большой** (0.1) — перепрыгиваем дно, оказываемся на другом склоне ещё выше, и ошибка растёт с каждым шагом.

Почему так: у крутых ям даже небольшой шаг по $w$ сильно меняет ошибку. В задачах ниже вы увидите все три режима.

Покрутите шаг сами — те же пять доставок, старт с $w = 0$, 12 шагов спуска:

::: widget gd-lr
Стрелки — шаги спуска по кривой ошибки. При шаге до ≈ 0,07 спуск сходится (при больших шагах — с качанием через дно), выше — расходится.
:::

::: tip
На практике шаг подбирают как гиперпараметр (глава 7) и часто уменьшают по ходу обучения. А чтобы «яма» была одинаково крутой по всем весам, признаки масштабируют — об этом урок «Спуск для многих признаков».
:::

::: quiz
При шаге обучения 0.1 потеря с каждым шагом растёт и уходит в бесконечность. Что происходит?

- [x] Шаг слишком большой: спуск перепрыгивает дно ямы и с каждым разом оказывается всё дальше от него
  > Сдвиг пропорционален наклону: на крутом склоне большой шаг уносит на противоположный, ещё более крутой склон.
- [ ] Модель нашла минимум и ушла дальше
  > Если бы шаг был умеренным, у дна шаги сами бы сократились.
- [ ] Ошибка в формуле производной
  > Формула верна: при маленьком шаге тот же код сходится.
- [ ] Нужно больше итераций
  > Больше итераций при расходимости только ухудшат результат.

## Несколько весов: градиент

Добавим свободный член: $\text{время} = w \times \text{км} + b$. Теперь у потери два параметра, и производных тоже две — по $w$ и по $b$. Вместе они образуют вектор — **градиент**. Шаг делается по обоим весам сразу:

```python
import numpy as np
km = np.array([1.0, 2.0, 3.0, 4.5, 6.0])
minutes = np.array([18.0, 25.0, 34.0, 44.0, 55.0])

w, b, lr = 0.0, 0.0, 0.02
for step in range(3000):
    err = w * km + b - minutes
    dw = np.mean(2 * err * km)          # производная по w
    db = np.mean(2 * err)               # производная по b
    w, b = w - lr * dw, b - lr * db
print(round(float(w), 2), round(float(b), 2))
print(np.polyfit(km, minutes, 1).round(2))    # точное решение для сравнения
```

**Что здесь происходит:**

- `err = w * km + b - minutes` — ошибки при текущих $w$ и $b$.
- Две производные: по $w$ (ошибка умножается на признак) и по $b$ (признак у свободного члена — константа 1, поэтому просто `2 * err`).
- `w, b = w - lr * dw, b - lr * db` — **одновременное** обновление: обе производные посчитаны по старым $w$ и $b$. Если сначала обновить $w$, а потом считать db по новому $w$, получится другой (хотя тоже рабочий) алгоритм.

`np.polyfit(x, y, 1)` подбирает прямую методом наименьших квадратов — то же решение, что нормальное уравнение. Спуск сходится к нему: около 7.4 минуты на км и 10.7 минуты базово. Шагов понадобилось больше: свободный член «тянется» медленнее, чем вес у расстояния.

## Разберём вместе: когда остановиться

В примерах мы делали фиксированное число шагов. В работе спуск останавливают, когда он «перестал двигаться» — например, когда изменение потери за шаг меньше заданного порога. Напишем такой спуск и посмотрим, сколько шагов он сделает.

```python
import numpy as np
km = np.array([1.0, 2.0, 3.0, 4.5, 6.0])
minutes = np.array([18.0, 25.0, 34.0, 44.0, 55.0])

def loss(w):
    return np.mean((w * km - minutes) ** 2)

def grad(w):
    return np.mean(2 * (w * km - minutes) * km)

def descend(lr, tol=1e-6, max_steps=10_000):
    w, prev = 0.0, loss(0.0)
    for step in range(1, max_steps + 1):
        w = w - lr * grad(w)
        cur = loss(w)
        if abs(prev - cur) < tol:          # потеря почти не меняется — стоп
            return w, step
        prev = cur
    return w, max_steps

for lr in [0.001, 0.01, 0.03]:
    w, steps = descend(lr)
    print(f"lr = {lr}: w = {w:.4f}, шагов {steps}")
print("точный минимум:", round(float((km * minutes).sum() / (km ** 2).sum()), 4))
```

**Что здесь происходит:**

- `descend` останавливается, когда потеря за шаг изменилась меньше чем на `tol`, или после `max_steps` шагов — страховка от бесконечного цикла.
- `10_000` — подчёркивание в числе просто для читаемости.

**Что получилось:** все три шага приходят к одному и тому же $w \approx 9.936$, но за очень разное число шагов: маленький шаг — в десятки раз дольше. Порог остановки тоже гиперпараметр: слишком грубый — остановимся, не дойдя до дна; слишком мелкий — потратим лишние шаги.

Численная производная — насколько изменилась функция между точками `w − eps` и `w + eps`, делённое на расстояние между ними.

### hint
`return (f(w + eps) - f(w - eps)) / (2 * eps)`.

### solution
```python
import numpy as np
km = np.array([1.0, 2.0, 3.0, 4.5, 6.0])
minutes = np.array([18.0, 25.0, 34.0, 44.0, 55.0])

def loss(w):
    return np.mean((w * km - minutes) ** 2)

def grad(w):
    return np.mean(2 * (w * km - minutes) * km)

def num_grad(f, w, eps=1e-5):
    return (f(w + eps) - f(w - eps)) / (2 * eps)

g3 = num_grad(lambda w: w ** 2, 3)
g5_formula = grad(5)
g5_numeric = num_grad(loss, 5)
print(g3, g5_formula, g5_numeric)
```

### explain
Формула и численная оценка совпали до четвёртого знака: −138.7. Значит, множители 2 и $x$ в формуле на месте. Почему сдвигаются в обе стороны: односторонняя разность (f(w + eps) − f(w)) / eps смотрит на наклон чуть правее точки и ошибается примерно на eps · f″ / 2. Симметричная берёт наклон с обеих сторон, и эти ошибки взаимно гасятся. На гладкой функции разница крошечная: для `loss` в точке 5 односторонняя разность даёт −138.69986 вместо −138.7. А на изломе, как у |w| в нуле, односторонняя даёт 1, хотя наклон слева −1, а справа +1. Симметричная честно показывает 0 — середину между ними.

## task: stop-rule | Правило остановки | base

Напишите `descend(lr, tol=1e-6, max_steps=10000)` как в разборе урока: спуск из `w = 0`, остановка, когда потеря за шаг изменилась меньше чем на `tol`; вернуть `(w, число шагов)`. ### hint
Цикл по номерам шагов от 1: обновить `w`, посчитать новую потерю, сравнить с предыдущей; если разница меньше `tol` — `return w, step`. В конце цикла — `prev = cur`.

### hint
После цикла (если так и не остановились) — `return w, max_steps`.

### hint
При `lr = 0.1` потеря растёт с каждым шагом, разница никогда не становится маленькой — спуск отработает все `max_steps` шагов, а вес станет огромным (или `inf`/`nan`).

### solution
```python
def descend(lr, tol=1e-6, max_steps=10000):
    w, prev = 0.0, loss(0.0)
    for step in range(1, max_steps + 1):
        w = w - lr * grad(w)
        cur = loss(w)
        if abs(prev - cur) < tol:
            return w, step
        prev = cur
    return w, max_steps

steps, w_found = {}, {}
for lr in [0.001, 0.01, 0.03]:
    w, n = descend(lr)
    steps[lr], w_found[lr] = n, round(float(w), 4)
w_01, steps_01 = descend(0.1)
print(steps, w_found, steps_01, w_01)
```

### explain
Правило остановки «потеря почти не меняется» срабатывает и тогда, когда спуск просто очень медленный, — поэтому его дополняют страховкой `max_steps` и проверкой результата. При `lr = 0.1` правило не сработало ни разу: потеря росла всё быстрее, и за 10 000 шагов вес улетел в бесконечность (numpy при этом может напечатать предупреждение о переполнении). В рабочем коде расхождение ловят явно: если потеря стала больше стартовой или `nan` — останавливаются и уменьшают шаг.

```python
import numpy as np
x = np.array([0.5, 1.5, 2.0, 3.5, 5.0, 7.0])
y = np.array([14.0, 19.0, 22.0, 31.0, 38.0, 52.0])

w = b = 0.0
for _ in range(3000):
    err = w * x + b - y
    dw = np.mean(2 * err * x)
    db = np.mean(2 * err)
    w, b = w - 0.02 * dw, b - 0.02 * db
exact = np.polyfit(x, y, 1).round(2)

```

### explain
