## Офлайн и онлайн: что обещала модель и что вышло

Все прибыли прошлого урока мы посчитали **офлайн** — на исторических данных, по допущению «бонус удерживает 25 % уходящих». Ни один гость при этом бонуса не получил. Такие числа — обещание, а не факт.

- **Офлайн-метрики** считают до запуска, на отложенных данных: ROC-AUC, точность, полнота, ожидаемая прибыль на тесте. Они отвечают на вопрос «хорошо ли модель ранжирует гостей».
- **Онлайн-метрики** меряют на живых гостях после запуска: удержание, выручка на гостя, прибыль кампании. Они отвечают на вопрос «заработали ли мы». Честно их меряют в A/B-тесте (глава 5): одна случайная половина получает бонус, другая — нет.

| | офлайн | онлайн |
|---|---|---|
| когда | до запуска | после запуска |
| на чём | история, тестовая выборка | живые гости, A/B |
| модельные | ROC-AUC, полнота, калибровка | доля «высокого риска» среди новых гостей |
| бизнесовые | ожидаемая прибыль по допущениям | удержание и прибыль: бонус против контроля |

::: tip Аналогия
Офлайн — это экзамен по билетам прошлых лет: показывает, что вы знаете материал. Онлайн — первая неделя на новой работе: выясняется, что задачи немного другие. Хороший результат на экзамене — повод выйти на работу, а не гарантия успеха.
:::

«Зерно» провело пилот: из гостей с прогнозом ухода выше 1/3 случайно выбрали две группы по 1000 человек. Первая получила бонус, вторая (контроль) — нет. Через полгода посмотрели, кто ушёл (`bonus_pilot.csv`):

```python
import pandas as pd

b = pd.read_csv("bonus_pilot.csv")
res = b.groupby("group").agg(guests=("churned", "size"), churn=("churned", "mean"),
                             p_model=("p_model", "mean"))
print(res.round(3))

delta = res.loc["контроль", "churn"] - res.loc["бонус", "churn"]   # на сколько бонус снизил отток
offline = res.loc["бонус", "p_model"] * 0.25 * 2400 - 200          # обещание: p × 600 − 200
online = delta * 2400 - 200                                        # факт: удержано × маржа − бонус
print(f"снижение оттока {delta:.3f}; на один бонус: офлайн {offline:.0f} ₽, онлайн {online:.0f} ₽")
```

**Что здесь происходит:**

- `res` — по строке на группу: сколько гостей, доля ушедших и средний прогноз модели.
- `delta` — разница оттока «контроль минус бонус». Контроль показывает, сколько ушло бы **без** бонуса, поэтому разница и есть эффект бонуса.
- `offline` — что обещал расчёт прошлого урока: каждый получатель уходит с вероятностью p, бонус удерживает четверть, удержанный приносит 2400 ₽.
- `online` — что вышло: на каждые 100 бонусов удержали `delta × 100` гостей.

**Что получилось.** В контроле ушли 67.3 %, с бонусом — 53.6 %: бонус снизил отток на 13.7 п. п. Из 67.3 % уходивших это 0.137 / 0.673 ≈ 20 % удержанных, а не 25 %, и модель немного завысила риск (в контроле обещала 0.73, ушли 0.67). В итоге бонус приносит **129 ₽**, а офлайн-расчёт обещал **230 ₽**. Кампания выгодна, но почти вдвое скромнее обещания. Именно поэтому офлайн-прибыль никогда не пишут в план продаж без пилота.

С чем сравнивать 13.7 п. п.? Не с нулём, а с границей окупаемости: бонус за 200 ₽ окупается, если на каждый бонус удержано хотя бы 200 / 2400 ≈ 0.083 гостя, то есть отток снизился на **8.3 п. п.** Пилот дал 13.7 — запас есть. Насколько он надёжен с учётом погрешности, посчитаем в задаче «Какой эффект окупает бонус».

### P&L-памятка

**P&L** (profit and loss, отчёт о прибылях и убытках) — привычный финансистам формат: сверху доходы, ниже расходы, внизу итог. Перед тем как нести результат модели или пилота руководителю, переведите его в такую таблицу. Памятка из шести пунктов:

1. **Решение.** Какое действие предлагаем и для скольких гостей: «бонус 5 000 гостям с риском выше 1/3».
2. **Доход — только дополнительный.** Маржа удержанных **сверх контроля**: тех, кто остался бы и без бонуса, не считаем.
3. **Расходы — по всем получателям.** Бонус получают и те, кто остался бы, и те, кто всё равно уйдёт.
4. **Допущения — отдельной строкой, с источником.** «Удержанный приносит 2400 ₽ за полгода — оценка финслужбы по маржинальности».
5. **Диапазон, а не точка.** Эффект пилота измерен с погрешностью — покажите итог для нижней и верхней границы интервала.
6. **Срок и что не учтено.** За какой период маржа; что осталось за скобками (разработка, работа маркетинга).

```python
import numpy as np
import pandas as pd

b = pd.read_csv("bonus_pilot.csv")
churn = b.groupby("group")["churned"].mean()
n_grp = b.groupby("group")["churned"].size()
delta = churn["контроль"] - churn["бонус"]
se = np.sqrt((churn * (1 - churn) / n_grp).sum())     # стандартная ошибка разности долей (глава 5)

n = 5000                                              # сколько бонусов предлагаем выдать
memo = pd.DataFrame({
    "оценка": [n * delta * 2400, -n * 200, n * (delta * 2400 - 200)],
    "пессимистично": [n * (delta - 1.96 * se) * 2400, -n * 200, n * ((delta - 1.96 * se) * 2400 - 200)],
    "оптимистично": [n * (delta + 1.96 * se) * 2400, -n * 200, n * ((delta + 1.96 * se) * 2400 - 200)],
}, index=["доп. маржа удержанных", "бонусы", "итог за полгода"])
(memo / 1000).round()                                  # тыс. ₽
```

**Что здесь происходит:**

- `se` — стандартная ошибка разности двух долей: корень из суммы p(1 − p)/n по группам. Почему так: разброс одной доли — p(1 − p)/n (урок «Выборки и центральная предельная теорема» главы 5), а у разности двух независимых долей разбросы складываются — как дисперсии, под корнем. `1.96 * se` — половина 95-процентного интервала.
- Три столбца — один и тот же расчёт при разных `delta`: оценка пилота и две границы интервала.
- Строка «бонусы» во всех столбцах одинаковая: расход не зависит от эффекта.

**Как читать.** 5 000 бонусов стоят 1 млн ₽ и приносят 1.64 млн ₽ дополнительной маржи — итог около +644 тыс. ₽ за полгода. При пессимистичном эффекте — около +135 тыс., при оптимистичном — около +1.15 млн. Во всех трёх случаях кампания в плюсе: это и есть тот аргумент, который финансист примет.

::: quiz
Офлайн-расчёт обещал 230 ₽ на бонус, пилот показал 129 ₽. Что из этого следует?

- [x] Главная причина разрыва — слишком оптимистичное допущение об эффекте бонуса; в расчётах дальше используем эффект из пилота
  > Офлайн-прибыль держится на допущении «удержание 25 %». Пилот с контрольной группой измерил настоящий эффект — около 20 %. Вклад модели меньше: она завысила риск (0.73 против 0.67 в контроле), но основную часть разрыва даёт эффект бонуса. Его и подставляют в следующие расчёты.
- [ ] Модель плохая, её нужно переобучить
  > Качество ранжирования проверяют офлайн-метриками (AUC, полнота), а пилот их не опровергает. Разрыв в деньгах здесь в основном из-за эффекта бонуса, а его модель оттока не предсказывает.
- [ ] Пилот неудачный: надо было сравнивать отток «до» и «после» кампании
  > «До и после» смешивает эффект бонуса с сезоном и всем остальным. Контрольная группа, выбранная случайно, — единственный честный способ.
- [ ] Кампания убыточна, её надо остановить
  > 129 ₽ на бонус — это прибыль. Даже нижняя граница 95-процентного интервала из P&L-памятки (около 27 ₽ на бонус, +135 тыс. на 5 000 бонусов) положительна.
:::

::: warn Типичные ошибки
- **Офлайн-прибыль в плане продаж.** Она держится на допущениях. До пилота пишут «ожидаем от … до …» и называют допущение, которое сильнее всего двигает итог.
- **«До и после» вместо контроля.** Отток в сентябре ниже, чем в августе, — может быть и бонус, и сезон. Без случайной контрольной группы эффект не отделить.
- **Доход по всем удержанным.** «Остались 464 гостя из 1000 с бонусом» — но 327 из них остались бы и без бонуса. Дополнительных — 137.
- **Одна цифра без интервала.** Пилот на 2 000 гостей измеряет эффект с погрешностью ±4 п. п.; в деньгах это разница в разы.
:::

## task: pilot-pnl | Пилот и P&L | base

Разность долей `delta` вы уже считали в разминке. Теперь сравните её с обещанием и соберите P&L. По `bonus_pilot.csv` посчитайте `offline` — что обещал офлайн-расчёт на один бонус (средний `p_model` в группе «бонус» × 0.25 × 2400 − 200, целые рубли). Затем соберите P&L для 8 000 бонусов: словарь `pnl` с ключами `"маржа"`, `"бонусы"` (расход со знаком минус) и `"итог"`, в рублях, целыми. Для `pnl` используйте неокруглённую разность долей «контроль минус бонус».

### starter

```

import pandas as _pd
_b = _pd.read_csv('bonus_pilot.csv')
c = _b.groupby('group')['churned'].mean()
d = c['контроль'] - c['бонус']
off = _b[_b['group'] == 'бонус']['p_model'].mean() * 600 - 200
assert close(need('offline'), round(off), 1), f'offline = {need("offline")}. Средний p_model в группе «бонус» × 0.25 × 2400 − 200.'

### hint

d = churn["контроль"] - churn["бонус"]
offline = round(... * 0.25 * 2400 - 200)

```

### solution
```python
import pandas as pd

b = pd.read_csv("bonus_pilot.csv")
churn = b.groupby("group")["churned"].mean()
d = churn["контроль"] - churn["бонус"]
offline = round(b[b["group"] == "бонус"]["p_model"].mean() * 0.25 * 2400 - 200)

```

## task: pnl-range | P&L с диапазоном | plus

### solution
```python
import numpy as np
import pandas as pd

b = pd.read_csv("bonus_pilot.csv")
n, z = 3000, 1.645
churn = b.groupby("group")["churned"].mean()
n_grp = b.groupby("group")["churned"].size()
delta = churn["контроль"] - churn["бонус"]
se = np.sqrt((churn * (1 - churn) / n_grp).sum())
total = lambda d: n * (d * 2400 - 200) / 1000
total_est = round(total(delta))
total_low = round(total(delta - z * se))
total_high = round(total(delta + z * se))
safe = bool(total_low > 0)
```

### explain
3 000 бонусов дают около +386 тыс. ₽ за полгода, с 90-процентной уверенностью — от +130 до +643 тыс. Нижняя граница выше нуля, и финансист может закладывать кампанию в план хотя бы на пессимистичном уровне. 90-процентный интервал ýже 95-процентного (там нижняя граница была бы около +81 тыс.): чем меньше уверенность, тем уже диапазон — уровень уверенности тоже пишут в P&L. Частая ошибка — сдвигать на `z * se` итог в рублях, а не эффект: интервал считают для доли, а потом переводят в деньги.

## task: min-effect | Какой эффект окупает бонус | star

Каким должно быть снижение оттока, чтобы бонус хотя бы окупился? Найдите `delta_min` — эффект, при котором прибыль на один бонус равна нулю (`delta × 2400 − 200 = 0`, 4 знака). ### solution
```python
import numpy as np
import pandas as pd

b = pd.read_csv("bonus_pilot.csv")
churn = b.groupby("group")["churned"].mean()
n_grp = b.groupby("group")["churned"].size()
delta = churn["контроль"] - churn["бонус"]
se = np.sqrt((churn * (1 - churn) / n_grp).sum())
delta_min = round(200 / 2400, 4)
z_gap = round((delta - 200 / 2400) / se, 2)
```

### explain
Бонус окупается, если снижает отток хотя бы на 8.3 п. п. (на каждые 12 бонусов — один удержанный). Пилот показал 13.7 п. п. — на 2.48 стандартной ошибки выше границы. Это больше 1.96, поэтому с 95-процентной уверенностью эффект выше порога окупаемости. Если бы вы сравнивали эффект с нулём, получили бы 6.3 стандартной ошибки и слишком оптимистичный вывод: «эффект есть» ещё не значит «эффект окупается». В отчёте сравнивают с той границей, где решение меняется.
