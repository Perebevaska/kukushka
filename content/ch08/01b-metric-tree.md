## Дерево метрик: откуда берётся выручка

Финансовый директор приносит отчёт: «В сентябре гостей в кофейнях стало больше на 9 %, а выручка **упала**. Кто виноват — меньше покупок у тех, кто зашёл, чек или конкретные кофейни?» Одно число «выручка» на этот вопрос не отвечает. Нужно разложить его на части, каждую из которых двигают свои люди и свои решения. Такую схему называют **деревом метрик**.

Для кофейни главная формула — три множителя:

```text
выручка
├── гости на входе (счётчик у двери)
│   ├── новые гости
│   └── вернувшиеся = база гостей × (1 − отток)   ← сюда работает модель оттока и бонус
├── конверсия = чеки / гости на входе           ← очереди, скорость кассы, витрина
└── средний чек = выручка / чеки                ← цены, акции, допродажи
```

::: tip Аналогия
Это как счёт за такси: сумма = число поездок × доля поездок, которые не отменились × средняя цена поездки. Если счёт вырос, по одной сумме не понять, ездили ли вы чаще или подорожал тариф. Разложение по множителям сразу показывает, какая ручка повернулась. Где аналогия хромает: в кофейне множители влияют друг на друга (длинная очередь отпугивает гостей и снижает конверсию), а формула этого не видит — она только честно делит изменение на части.
:::

::: sql
В SQL это одна строка `GROUP BY month` с тремя отношениями: `SUM(checks) * 1.0 / SUM(visitors) AS conv`, `SUM(revenue) * 1.0 / SUM(checks) AS avg_check`. Перемножьте их на `SUM(visitors)` — получится ровно `SUM(revenue)`.
:::

### Разберём вместе: одна кофейня руками

В августе в кофейню зашли **1000** гостей, из них **700** что-то купили (конверсия 0.70), средний чек — **350 ₽**. Выручка: 1000 × 0.70 × 350 = **245 000 ₽**.

В сентябре зашли **1100** гостей, конверсия упала до **0.63**, чек — **335 ₽**. Выручка: 1100 × 0.63 × 335 = **232 155 ₽**. Минус 12 845 ₽. Кто виноват?

Меняем множители **по одному**, в порядке «гости → конверсия → чек», и смотрим, на сколько сдвигается выручка на каждом шаге:

1. **Гости.** Сентябрьские гости, остальное августовское: 1100 × 0.70 × 350 = 269 500. Разница с августом: **+24 500 ₽**.
2. **Конверсия.** Добавляем сентябрьскую конверсию: 1100 × 0.63 × 350 = 242 550. Разница с шагом 1: **−26 950 ₽**.
3. **Чек.** Добавляем сентябрьский чек: 1100 × 0.63 × 335 = 232 155 — это и есть сентябрь. Разница с шагом 2: **−10 395 ₽**.

Проверка: 24 500 − 26 950 − 10 395 = −12 845 — ровно общее изменение. Вывод для директора: гостей стало больше (+24.5 тыс.), но конверсия съела этот прирост и ещё 2.5 тыс. сверху, а снижение чека добавило минус 10 тыс.

::: figure chain-subst
Каскад цепных подстановок: на каждом шаге меняется один множитель (выделен), высота ступеньки — его вклад. Три ступеньки в сумме дают всё изменение выручки.
:::

Этот приём экономисты называют **методом цепных подстановок**. Формулой:

$$R = G \times CR \times AC$$

где $R$ — выручка, $G$ — гости на входе, $CR$ — конверсия (доля вошедших, кто купил), $AC$ — средний чек. Вклад множителя — разница выручки до и после замены **только его** на новое значение, при уже заменённых предыдущих.

::: predict
```python static
print(round(1100 * 0.63 * 350 - 1100 * 0.70 * 350))
```

- `26950`
- [x] `-26950`
- `-12845`

Почему: это шаг 2 — гости уже сентябрьские, чек ещё августовский, меняется только конверсия: 1100 × 350 × (0.63 − 0.70) = −26 950.
:::

### На данных сети

Файл `shop_funnel.csv` — шесть кофеен за июль–сентябрь 2026: сколько гостей зашло (`visitors`), сколько пробито чеков (`checks`) и выручка в рублях (`revenue`). Соберём дерево для всей сети:

```python
import pandas as pd

f = pd.read_csv("shop_funnel.csv")
net = f.groupby("month")[["visitors", "checks", "revenue"]].sum()
net["conv"] = net["checks"] / net["visitors"]        # конверсия сети
net["avg_check"] = net["revenue"] / net["checks"]    # средний чек сети
a, s = net.loc["2026-08"], net.loc["2026-09"]        # август и сентябрь

r0 = a["visitors"] * a["conv"] * a["avg_check"]      # август как есть
r1 = s["visitors"] * a["conv"] * a["avg_check"]      # заменили гостей
r2 = s["visitors"] * s["conv"] * a["avg_check"]      # + конверсию
r3 = s["visitors"] * s["conv"] * s["avg_check"]      # + чек = сентябрь
parts = pd.Series({"гости": r1 - r0, "конверсия": r2 - r1, "чек": r3 - r2}).round()
print(net.round(3))
print(parts)
print("итого:", round(r3 - r0), "₽")
```

**Что здесь происходит:**

- `groupby("month")[...].sum()` — сначала **складываем** гостей, чеки и выручку по кофейням, а уже потом делим. Так конверсия и чек получаются «сетевыми», с весом каждой кофейни.
- `net.loc["2026-08"]` — строка августа (Series): к её полям обращаемся по имени, `a["conv"]`.
- `r0` … `r3` — четыре состояния цепочки: на каждом шаге ещё один множитель переходит с августовского значения на сентябрьское.
- `parts` — три разницы, их сумма равна `r3 - r0`.

**Что получилось.** Гостей в сентябре на 9.3 % больше — это +1.39 млн ₽. Но конверсия упала с 0.694 до 0.649 (−1.06 млн ₽), а средний чек — с 347 до 331 ₽ (−0.70 млн ₽). Итого −362 тыс. ₽, или −2.4 %. Рост гостей был, его «съели» две другие ветки.

Какая кофейня тянет конверсию вниз? Посмотрим на изменение по каждой:

```python
import pandas as pd

f = pd.read_csv("shop_funnel.csv")
f["conv"] = f["checks"] / f["visitors"]
conv = f.pivot(index="shop_id", columns="month", values="conv")   # строки — кофейни, столбцы — месяцы
(conv["2026-09"] - conv["2026-08"]).round(3).sort_values()
```

У пяти кофеен конверсия почти не изменилась (±0.015), а у KZN-1 упала на 0.157 — с 0.727 до 0.570. Это уже вопрос не к аналитику, а к управляющему: что случилось в Казани на Баумана в сентябре? (В нашей истории — новая касса и очереди.) Средний чек снизился во всех кофейнях — на 3–6 %: это след сетевой акции «кофе дня».

**Где здесь модель оттока.** Бонус удерживает гостей — он работает только на ветку «вернувшиеся гости». Даже идеальная кампания не спасёт выручку, если в это же время ломается конверсия. Поэтому, отчитываясь о кампании, показывают её ветку дерева, а не «выручка сети выросла/упала».

::: warn Типичные ошибки
- **Среднее средних.** Конверсия сети — это `сумма чеков / сумма гостей`, а не среднее конверсий кофеен. В сентябре среднее шести конверсий 0.656, а настоящая сетевая — 0.649: большие кофейни весят больше.
- **Разный знаменатель.** «Конверсия» у маркетинга — доля гостей с картой, сделавших заказ за месяц, у управляющего — доля вошедших, кто купил. Прежде чем сравнивать, договоритесь о формуле и запишите её рядом с числом.
- **Порядок подстановок забыли указать.** Если менять сначала чек, потом гостей, вклады немного сдвинутся (сумма та же). Порядок фиксируют один раз и пишут в отчёте.
- **Вклад = причина.** «Конверсия отняла 1.06 млн» — это арифметика. Почему она упала, показывают данные кофейни и разговор с управляющим.
:::

::: quiz
В сентябре конверсии шести кофеен — от 0.570 (KZN-1) до 0.698 (TMN-1), их среднее — 0.656. Отношение суммы чеков к сумме гостей по сети — 0.649. Какое число ставить в дерево метрик сети?

- [x] 0.649 — отношение сумм: с ним гости × конверсия × чек дают ровно выручку сети
  > Конверсия сети взвешена числом гостей каждой кофейни. Только с ней произведение множителей сходится с настоящей выручкой, а вклады — с её изменением.
- [ ] 0.656 — среднее конверсий кофеен, так честнее к маленьким кофейням
  > Это «среднее средних»: маленькая кофейня весит столько же, сколько большая, и произведение множителей уже не равно выручке сети.
- [ ] Любое: разница меньше процента
  > Разница 0.007 при 68 тысячах гостей в месяц — почти 500 чеков. И вклады перестанут складываться в изменение выручки.
- [ ] Медиану конверсий кофеен — она устойчива к выбросам
  > Медиана тоже не взвешивает кофейни по числу гостей; выброс KZN-1 здесь как раз и есть главная новость месяца.
:::

### check
```python
r0, r3 = 1200 * 0.65 * 340, 1260 * 0.60 * 345
assert close(need('rev_aug'), r0, 1) and close(need('rev_sep'), r3, 1), f'rev_aug, rev_sep = {need("rev_aug")}, {need("rev_sep")}. Выручка = гости × конверсия × чек.'
assert close(need('d_guests'), 1260 * 0.65 * 340 - r0, 1), f'd_guests = {need("d_guests")}. Меняем только гостей: g1 × cr0 × ac0 − август.'
```

### hint
Посчитайте четыре выручки: август; август с сентябрьскими гостями; плюс сентябрьская конверсия; сентябрь целиком. Вклады — разницы соседних.

### hint
`r1 = g1 * cr0 * ac0`, `r2 = g1 * cr1 * ac0`; `d_guests = round(r1 - rev_aug)` и так далее.

### hint
```python
rev_aug = round(g0 * cr0 * ac0)
r1 = g1 * cr0 * ac0
r2 = g1 * cr1 * ac0
rev_sep = round(g1 * cr1 * ac1)
d_guests = round(r1 - ...)
d_conv = round(... - r1)
d_check = round(rev_sep - ...)
```

### solution
```python
g0, cr0, ac0 = 1200, 0.65, 340    # август
g1, cr1, ac1 = 1260, 0.60, 345    # сентябрь

rev_aug = round(g0 * cr0 * ac0)
r1 = g1 * cr0 * ac0
r2 = g1 * cr1 * ac0
rev_sep = round(g1 * cr1 * ac1)
d_guests = round(r1 - rev_aug)
d_conv = round(r2 - r1)
d_check = round(rev_sep - r2)
```

### explain
Гостей стало больше (+13 260 ₽), чек подрос (+3 780 ₽), но конверсия упала на 5 п. п. и отняла 21 420 ₽. Итог −4 380 ₽ — сумма трёх вкладов. Если бы вы смотрели только на гостей и чек, сентябрь выглядел бы удачным.

### hint
Те же четыре выручки, что в разборе, только множители меняются в другом порядке: сначала чек, потом конверсия, потом гости.

### hint
`r1 = g0 * cr0 * ac1` (новый чек), `r2 = g0 * cr1 * ac1` (+ новая конверсия), `r3 = g1 * cr1 * ac1` (сентябрь целиком). Вклады — разницы соседних.

### hint
```python
r0 = g0 * cr0 * ac0
r1 = g0 * cr0 * ac1
r2 = g0 * cr1 * ...
r3 = g1 * cr1 * ac1
d_check = round(r1 - r0)
d_conv = round(...)
d_guests = round(...)
total = d_check + d_conv + d_guests
```

### solution
```python
g0, cr0, ac0 = 1000, 0.70, 350    # август
g1, cr1, ac1 = 1100, 0.63, 335    # сентябрь

r0 = g0 * cr0 * ac0
r1 = g0 * cr0 * ac1
r2 = g0 * cr1 * ac1
r3 = g1 * cr1 * ac1
d_check = round(r1 - r0)
d_conv = round(r2 - r1)
d_guests = round(r3 - r2)
total = d_check + d_conv + d_guests
```

### explain
Итог тот же — −12 845 ₽, но вклады сдвинулись: чек −10 500 (было −10 395), конверсия −23 450 (было −26 950), гости +21 105 (было +24 500). Множитель, который меняется позже, «видит» уже изменённые остальные, поэтому его вклад считается по другой базе. Вывод для отчёта не меняется — гости в плюсе, конверсия съела больше всех, — но цифры другие. Поэтому порядок подстановок фиксируют один раз и пишут рядом с таблицей, а сравнивают между месяцами только разложения с одинаковым порядком.

## task: tree-shift | Дерево сети: август против сентября | base

По `shop_funnel.csv` разложите изменение выручки **сети** с августа на сентябрь. Сохраните Series `parts` с индексом `["гости", "конверсия", "чек"]` и вкладами в рублях (округлите до целых). Затем найдите кофейню с самым большим **падением** конверсии и сохраните её `shop_id` в `worst_shop`, а само падение (сентябрь минус август, 3 знака, отрицательное число) — в `worst_drop`.

### starter
```python
import pandas as pd

f = pd.read_csv("shop_funnel.csv")

```

### check
```python
import pandas as _pd
_f = _pd.read_csv('shop_funnel.csv')
n = _f.groupby('month')[['visitors', 'checks', 'revenue']].sum()
a, s = n.loc['2026-08'], n.loc['2026-09']
ca, cs = a.checks / a.visitors, s.checks / s.visitors
ka, ks = a.revenue / a.checks, s.revenue / s.checks

p = need('parts', _pd.Series)
assert list(p.index) == ['гости', 'конверсия', 'чек'], f'Индекс parts: {list(p.index)}, нужен ["гости", "конверсия", "чек"].'
for k, v in zip(p.index, [r1 - r0, r2 - r1, r3 - r2]):
    assert close(p[k], v, 2), f'Вклад «{k}» = {p[k]}, ожидалось около {round(v)}. Конверсию и чек сети считайте из сумм: sum(checks) / sum(visitors).'
_f['c'] = _f.checks / _f.visitors
d = _f.pivot(index='shop_id', columns='month', values='c')
```

### solution
```python
import pandas as pd

f = pd.read_csv("shop_funnel.csv")
net = f.groupby("month")[["visitors", "checks", "revenue"]].sum()
net["conv"] = net["checks"] / net["visitors"]
net["avg_check"] = net["revenue"] / net["checks"]
a, s = net.loc["2026-08"], net.loc["2026-09"]
r0 = a["visitors"] * a["conv"] * a["avg_check"]
r1 = s["visitors"] * a["conv"] * a["avg_check"]
r2 = s["visitors"] * s["conv"] * a["avg_check"]
r3 = s["visitors"] * s["conv"] * s["avg_check"]
parts = pd.Series({"гости": r1 - r0, "конверсия": r2 - r1, "чек": r3 - r2}).round()

f["conv"] = f["checks"] / f["visitors"]
conv = f.pivot(index="shop_id", columns="month", values="conv")
drop = conv["2026-09"] - conv["2026-08"]
worst_shop = drop.idxmin()
worst_drop = round(drop.min(), 3)
```

### explain
Гости дали +1.39 млн ₽, конверсия −1.06 млн, чек −0.70 млн. Почти вся потеря конверсии — одна кофейня, KZN-1 (−0.157). Если пересчитать дерево без неё, конверсия сети почти не изменилась бы. Типичная ошибка — взять `mean()` конверсий кофеен вместо отношения сумм: тогда маленькая UFA-1 весит столько же, сколько большая KZN-1, и вклады не сходятся с изменением выручки.
