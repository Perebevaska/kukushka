## Истина и ложь

Сравнение двух значений даёт ответ «да» или «нет». В Python это значения `True` и `False`, тип `bool`:

```python
revenue = 52300
plan = 50000
print(revenue > plan)
print(revenue == plan)
print(type(revenue > plan))
```

Операторы сравнения:

| Запись | Значение |
|---|---|
| `a == b` | равно |
| `a != b` | не равно |
| `a < b`, `a > b` | меньше, больше |
| `a <= b`, `a >= b` | меньше или равно, больше или равно |

Строки тоже можно сравнивать: `city == "Пермь"`.

::: warn
`=` и `==` — разные вещи. `=` кладёт значение в переменную, `==` спрашивает «равны ли?». Если перепутать в условии, Python сообщит `SyntaxError`. Обратная путаница опаснее: `x == 5` отдельной строкой ничего не присвоит и не упадёт — Python просто посчитает `True` или `False` и выбросит, а в `x` останется старое значение.
:::

::: sql
В SQL равенство — одиночное `=`, неравенство — `<>`. В Python — `==` и `!=`.
:::

## if: выполнить, только если…

`if` выполняет блок, только если условие истинно. Синтаксис такой же, как у `for`: двоеточие и отступ.

```python
revenue = 52300
plan = 50000
if revenue >= plan:
    print("План выполнен")
print("Отчёт готов")
```

`else` — что делать в противном случае:

```python
revenue = 47800
plan = 50000
if revenue >= plan:
    print("План выполнен")
else:
    print("Не хватило", plan - revenue)
```

### Несколько вариантов: elif

Когда вариантов больше двух, добавляют `elif` (сокращение от *else if*). Python проверяет условия сверху вниз и выполняет **первую** подходящую ветку — остальные пропускает:

```python
avg_check = 420
if avg_check < 300:
    segment = "низкий"
elif avg_check < 600:
    segment = "средний"
else:
    segment = "высокий"
print(segment)
```

Во второй ветке не нужно писать `300 <= avg_check`: до неё дойдёт, только если первое условие ложно.

::: figure elif-flow
Проверки идут слева направо; для 420 первая ложна, вторая истинна — выполняется ветка «средний», третья даже не проверяется.
:::

::: sql
Это `CASE WHEN avg_check < 300 THEN 'низкий' WHEN avg_check < 600 THEN 'средний' ELSE 'высокий' END`. Логика та же: первая подходящая ветка.
:::

::: predict
```python static
x = 300
if x < 300:
    print("низкий")
elif x < 600:
    print("средний")
else:
    print("высокий")
```

- `низкий`
- [x] `средний`
- `средний высокий`

Почему: 300 < 300 — ложь, 300 < 600 — истина. Выполняется первая подходящая ветка, остальные пропускаются.
:::

### Разберём вместе: порядок веток elif

Сегмент по чеку: меньше 300 — «низкий», меньше 600 — «средний», иначе «высокий». Посмотрим, что будет при неправильном порядке веток.

```python static
if avg_check < 600:
    segment = "средний"
elif avg_check < 300:
    segment = "низкий"
else:
    segment = "высокий"
```

| `avg_check` | первая проверка `< 600` | вторая `< 300` | итог | правильно |
|---|---|---|---|---|
| 250 | **True** → «средний» | не проверяется | средний | низкий |
| 450 | True → «средний» | не проверяется | средний | средний |
| 700 | False | False | высокий | высокий |

1. Python проверяет ветки сверху вниз и выполняет **первую** подходящую — остальные пропускает.
2. 250 меньше и 300, и 600, но до второй проверки дело не доходит: первая уже сработала.
3. Поэтому узкие условия ставят выше широких: сначала `< 300`, потом `< 600`.

Что получилось: ошибок нет, программа работает — и тихо выдаёт неверный сегмент дешёвым гостям. Проверяйте `if/elif` на значениях-границах и по одному значению из каждой ветки.

## Составные условия: and, or, not

- `and` — истинно, если истинны **оба** условия;
- `or` — если истинно **хотя бы одно**;
- `not` — переворачивает: `not True` — это `False`.

```python
city = "Пермь"
amount = 850
print(city == "Пермь" and amount > 500)
print(city == "Казань" or amount > 500)
print(not amount > 500)
```

Проверку диапазона можно записать цепочкой, как в математике:

```python
amount = 450
print(300 <= amount < 600)
```

::: figure range-check
Сверху: цепочка `300 <= amount < 600` — отрезок, где 300 входит, а 600 уже нет. Снизу: с `or` условие истинно для любого числа.
:::

::: sql
`300 <= amount < 600` — почти `amount BETWEEN 300 AND 599`. Только `BETWEEN` включает обе границы, а здесь правая не включается.
:::

::: predict
```python static
print(5 > 3 and 2 > 4)
```

- `True`
- [x] `False`
- `Ошибка SyntaxError`

Почему: `and` требует, чтобы были истинны оба условия, а `2 > 4` ложно.
:::

::: quiz
Заказ считается «средним», если сумма от 300 до 600 рублей: 300 включительно, 600 — нет. Какое условие верное?

- [x] `300 <= amount < 600`
  > Python понимает цепочку сравнений, как в математике: обе границы проверяются сразу.
- [ ] `amount >= 300 or amount < 600`
  > С `or` условие истинно почти всегда: любое число либо не меньше 300, либо меньше 600.
- [ ] `300 < amount <= 600`
  > Границы перепутаны: 300 не попадёт, а 600 попадёт.
- [ ] `amount >= 300 and < 600`
  > Синтаксическая ошибка: у второго сравнения нет левой части. Нужно `amount >= 300 and amount < 600`.
:::

## Цикл + условие = фильтр

Теперь самое полезное: соединяем `for` и `if`. Отобрать дни с выручкой больше 50 000:

```python
revenue = [41200, 38900, 45100, 39800, 52300, 61700, 58400]
good_days = []
for r in revenue:
    if r > 50000:
        good_days.append(r)
print(good_days)
```

Обратите внимание на отступы: `if` сдвинут на 4 пробела (он внутри цикла), а `append` — на 8 (внутри `if`).

Посчитать, сколько таких дней:

```python
revenue = [41200, 38900, 45100, 39800, 52300, 61700, 58400]
count = 0
for r in revenue:
    if r > 50000:
        count += 1
print("Дней выше 50 000:", count)
```

::: sql
Первое — `SELECT revenue FROM daily WHERE revenue > 50000`. Второе — `SELECT COUNT(*) … WHERE revenue > 50000` или `SUM(CASE WHEN revenue > 50000 THEN 1 ELSE 0 END)`.
:::

### Поиск лучшего

Как найти максимум и **на каком он месте**? Запоминаем «лучшее на данный момент» и обновляем, если встретили что-то больше:

```python
revenue = [41200, 38900, 45100, 39800, 52300, 61700, 58400]
best = revenue[0]
best_day = 0
for i in range(len(revenue)):
    if revenue[i] > best:
        best = revenue[i]
        best_day = i
print("Лучший день — индекс", best_day, "выручка", best)
```

Начальное значение — первый элемент, а не 0. Для минимума 0 сломал бы поиск: ни одна выручка не меньше нуля, и «худший день» никогда не нашёлся бы. Первый элемент списка подходит всегда.

## Цикл while: пока условие верно

`for` идёт по готовому списку. А если заранее неизвестно, сколько будет шагов? Например: на складе 26 кг зерна, в день уходит 3,5 кг — через сколько дней останется меньше 5 кг? Для этого есть `while`: он повторяет блок, **пока** условие истинно.

```python
stock = 26
days = 0
while stock >= 5:
    stock -= 3.5
    days += 1
print("Дней:", days, "остаток:", stock)
```

::: figure while-steps
Остаток зерна по дням. Условие проверяется перед каждым шагом: при 5 кг оно ещё истинно, при 1.5 кг — ложно, и цикл заканчивается.
:::

::: warn Бесконечный цикл
Если внутри `while` ничего не меняет условие, цикл никогда не закончится. Например, забыть `stock -= 3.5`:

```python static
stock = 26
while stock >= 5:
    print("остаток", stock)   # stock не меняется — условие верно всегда
```

Не запускайте такой код нарочно; если запустили по ошибке — через несколько секунд появится кнопка «Остановить», она прервёт выполнение.
:::

### break: выйти досрочно

`break` немедленно прерывает цикл — и `for`, и `while`. Удобно, когда нужно найти **первое** подходящее значение:

```python
revenue = [41200, 38900, 45100, 29800, 52300, 27700]
for i in range(len(revenue)):
    if revenue[i] < 30000:
        print("Первый провальный день — индекс", i)
        break
```

::: warn Типичные ошибки
- **`=` вместо `==`.** Внутри `if` нужно сравнение; одно `=` — `SyntaxError`.
- **Широкое условие первым.** `elif` после сработавшей ветки не проверяется.
- **Граница не та.** «От 300 до 600, не включая 600» — `300 <= a < 600`; проверьте сами 300 и 600.
- **`while` без изменения условия.** Если внутри цикла ничего не приближает выход, цикл бесконечный.
:::

## task: worst-day | Худший день | plus

Найдите без `min` и `sort` минимальную выручку `worst` и **номер дня** `worst_day`, когда она была (дни нумеруются с 1, а не с 0).

### starter
```python
revenue = [41200, 38900, 45100, 36800, 52300, 61700, 58400]

```

### check
```python
assert need('worst') == 36800, f'worst = {need("worst")}.'
assert need('worst_day') == 4, f'worst_day = {need("worst_day")}. Минимум — четвёртый день (индекс 3).'
assert calls('min') == 0 and calls('sorted') == 0 and calls('sort') == 0, 'Решите циклом, без min и сортировки.'
```

### hint
Как в теории про поиск лучшего, только сравнение в другую сторону: `if revenue[i] < worst:`.

### hint
Индекс → номер дня: `i + 1`.

### solution
```python
revenue = [41200, 38900, 45100, 36800, 52300, 61700, 58400]
worst = revenue[0]
worst_day = 1
for i in range(len(revenue)):
    if revenue[i] < worst:
        worst = revenue[i]
        worst_day = i + 1
```

### explain
Худший день — 36 800 ₽, четвёртый. Запоминать нужно сразу два значения: само минимальное и где оно было; поэтому в теле `if` — две строки.

## task: while | На сколько дней хватит зерна | plus

На складе 40 кг зерна, в день уходит 3,5 кг. Закупку делают, когда остаётся меньше 8 кг: цикл продолжается, пока остаток не меньше 8. Посчитайте циклом `while`, через сколько дней (`days`) нужна закупка.

### starter
```python
stock = 40
per_day = 3.5

```

### check
```python
assert need('days') == 10, f'days = {need("days")}. Цикл должен идти, пока остаток не меньше 8 кг.'
assert 'while' in _code, 'Используйте while.'
```

### hint
Условие продолжения — «остаток ещё не меньше 8»: `while stock >= 8:`. Внутри уменьшайте `stock` и увеличивайте `days`.

### hint
Проверьте руками первые шаги: 40 → 36.5 → 33 → … — цикл остановится, когда остаток станет меньше 8.

### solution
```python
stock = 40
per_day = 3.5
days = 0
while stock >= 8:
    stock -= per_day
    days += 1
```

### explain
Можно посчитать и формулой, но `while` хорош, когда правило сложнее: например, по выходным расход больше. Тогда формула неудобна, а цикл легко дополнить условием.

## task: combo | Кофе и булочка | star

Акция по номерам заказов от 1 до 15. Для каждого номера выведите строку:

- `комбо`, если номер делится и на 3, и на 5;
- `кофе`, если делится только на 3;
- `булочка`, если только на 5;
- сам номер — в остальных случаях.

### starter
```python

```

### check
```python
want = []
for n in range(1, 16):
    want.append('комбо' if n % 15 == 0 else 'кофе' if n % 3 == 0 else 'булочка' if n % 5 == 0 else str(n))
assert _lines == want, f'Сейчас вывод: {_lines}. Ожидалось 15 строк: 1, 2, кофе, 4, булочка, …, комбо.'
```

### hint
«Делится на 3» — остаток от деления равен нулю: `n % 3 == 0`.

### hint
Порядок веток важен: если первой проверить «делится на 3», то 15 туда и попадёт. Самое узкое условие ставьте первым.

### solution
```python
for n in range(1, 16):
    if n % 3 == 0 and n % 5 == 0:
        print("комбо")
    elif n % 3 == 0:
        print("кофе")
    elif n % 5 == 0:
        print("булочка")
    else:
        print(n)
```

### explain
Это вариант классической задачи FizzBuzz, которую часто дают на собеседованиях. Она проверяет ровно одно: понимаете ли вы, что `elif` выполняет первую подходящую ветку.
