## Повторить для каждого элемента

Допустим, нужно вывести каждый город сети на отдельной строке. Можно написать `print` три раза, но если городов сорок — уже нет. Для повторения есть **цикл** `for`:

```python
cities = ["Пермь", "Казань", "Тюмень"]
for city in cities:
    print("Кофейня в городе", city)
```

Читается почти по-русски: «для каждого `city` в `cities` выполни…». Python берёт первый элемент, кладёт его в переменную `city`, выполняет тело цикла, затем берёт второй элемент — и так до конца списка.

Устройство цикла:

- в конце строки с `for` — **двоеточие**;
- **тело цикла** — строки с отступом в 4 пробела. Они повторяются;
- первая строка без отступа — уже после цикла, она выполнится один раз.

::: figure for-loop
Цикл берёт элементы по одному, для каждого выполняет тело с отступом, а когда элементы кончаются, переходит к первой строке без отступа.
:::

```python
cities = ["Пермь", "Казань", "Тюмень"]
for city in cities:
    print("Открываем:", city)
    print("  проверяем кассу")
print("Все кофейни открыты")
```

::: warn
Отступ — часть синтаксиса Python, а не украшение. Забытый отступ даст `IndentationError`, а лишний или пропущенный в теле цикла — тихую логическую ошибку: строка выполнится не столько раз, сколько вы думали. В редакторе курса <kbd>Tab</kbd> ставит 4 пробела, <kbd>Shift</kbd>+<kbd>Tab</kbd> убирает.
:::

::: sql
В SQL вы не пишете циклы: `SELECT` сам обрабатывает каждую строку. В чистом Python цикл приходится писать руками. Во второй главе pandas снова «спрячет» циклы, но понимать, что происходит внутри, полезно.
:::

## Накопитель: сумма своими руками

Как посчитать сумму без `sum`? Завести переменную-**накопитель**, равную нулю, и в цикле прибавлять к ней каждый элемент:

```python
revenue = [41200, 38900, 45100]
total = 0
for r in revenue:
    total += r
    print("Прибавили", r, "→ итого", total)
print("Сумма:", total)
```

Три правила накопителя:

1. Начальное значение задаётся **до** цикла. Если написать `total = 0` внутри цикла, он будет обнуляться на каждом шаге.
2. В теле цикла накопитель обновляется.
3. Результат читается **после** цикла.

::: figure accum-steps
Накопитель на трёх ценах: 0 → 210 → 400 → 660. Внизу — что будет, если обнуление `total = 0` попало внутрь цикла.
:::

Так же можно считать количество, произведение, склеивать строки.

::: predict
```python static
total = 0
for x in [1, 2, 3]:
    total = 0
    total += x
print(total)
```

- `6`
- [x] `3`
- `0`

Почему: `total = 0` внутри цикла обнуляет накопитель на каждом шаге, поэтому остаётся только последнее значение.
:::

### Разберём вместе: цикл по шагам

Программа складывает три цены:

```python
prices = [210, 190, 260]
total = 0
for p in prices:
    total += p
print(total)
```

Пройдём её как Python — по шагам, записывая значения:

| шаг | `p` | `total` до | `total` после |
|---|---|---|---|
| перед циклом | — | — | 0 |
| 1-й проход | 210 | 0 | 210 |
| 2-й проход | 190 | 210 | 400 |
| 3-й проход | 260 | 400 | 660 |
| после цикла | — | — | **660** → `print` |

1. `total = 0` выполняется **один раз**, до цикла. Если поставить его внутрь цикла, накопитель обнулялся бы на каждом проходе и в конце было бы 260.
2. Тело цикла (строки с отступом) выполняется столько раз, сколько элементов в списке; `p` каждый раз — следующий элемент.
3. `print` без отступа — после цикла, один раз. С отступом он напечатал бы 210, 400, 660 — промежуточные суммы.

Что получилось: в цикле важно, что стоит **до**, **внутри** и **после**. Отступ — это не оформление, а часть смысла программы.

::: quiz
Сумму цен считают циклом, но строку `total = 0` по ошибке поставили **внутрь** цикла, перед `total += price`. Что окажется в `total` после цикла?

- [x] Только последняя цена
  > На каждом шаге накопитель обнуляется и получает одну текущую цену. После последнего шага в нём последняя цена.
- [ ] Сумма всех цен
  > Сумма копится, только если накопитель создан один раз — до цикла.
- [ ] Ошибка `NameError`
  > Переменная существует: её заново создают на каждом шаге.
- [ ] Ноль
  > Обнуление стоит до прибавления, поэтому к концу шага в `total` уже лежит цена.
:::

## Новый список из старого

Часто нужно получить из одного списка другой: цены с наценкой, суммы в тысячах, очищенные названия. Шаблон — пустой список до цикла и `append` в цикле:

```python
prices = [210, 190, 260]
new_prices = []
for p in prices:
    new_prices.append(round(p * 1.1))
print(new_prices)
```

::: sql
Это вычисляемый столбец: `SELECT ROUND(price * 1.1) AS new_price FROM menu`.
:::

## Цикл по числам: range

`range(n)` выдаёт числа от 0 до n−1 — удобно, когда нужно повторить что-то n раз или пройти по номерам:

```python
for i in range(3):
    print("Попытка", i)
```

`range(a, b)` — числа от `a` до `b−1`. Правая граница не включается, как в срезах:

```python
for day in range(1, 8):
    print("День", day)
```

::: predict
```python static
total = 0
for i in range(1, 4):
    total += i
print(total)
```

- `10`
- [x] `6`
- `3`

Почему: `range(1, 4)` — это 1, 2, 3 (правая граница не включается). 1 + 2 + 3 = 6.
:::

### Два списка с общими позициями

Если в двух списках данные идут «параллельно» (выручка и число заказов за одни и те же дни), по ним удобно идти по индексу: `range(len(список))` даёт все номера позиций.

```python
revenue = [41200, 38900, 45100]
orders = [130, 121, 140]
for i in range(len(revenue)):
    print("День", i + 1, "средний чек", round(revenue[i] / orders[i], 2))
```

Номер позиции нужен и сам по себе — например, чтобы взять соседний день: `revenue[i - 1]` (так решается задача про прирост ко вчерашнему дню). Для простого прохода по двум спискам позже появится способ удобнее.

## Номер и элемент: enumerate

Для нумерованных списков есть `enumerate`: он выдаёт пары «номер, элемент». Второй аргумент задаёт, с какого числа начинать:

```python
menu = ["Латте", "Капучино", "Раф"]
for n, drink in enumerate(menu, 1):
    print(f"{n}. {drink}")
```

`enumerate` отдаёт на каждом шаге два значения сразу, и их можно принять в две переменные через запятую — так же, как работает обычное присваивание `a, b = 1, 2`:

```python
n, drink = 1, "Латте"
print(n, drink)
```

## По строке тоже можно идти циклом

Строка — последовательность символов, поэтому `for` проходит по ним по одному:

```python
for ch in "Зерно":
    print(ch)
```

::: warn Типичные ошибки
- **Накопитель внутри цикла.** `total = 0` в теле цикла обнуляет сумму на каждом проходе.
- **`print` с отступом.** Напечатает промежуточные значения на каждом шаге.
- **`range(5)` вместо `range(1, 6)`.** `range` не включает правую границу и по умолчанию начинается с 0.
- **Изменение списка во время цикла по нему.** Если внутри `for x in lst` вызывать `lst.remove(...)`, цикл пропустит соседний элемент. Не меняйте список, по которому идёте, — собирайте новый.
:::

## task: cumsum | Накопительный итог | plus

Постройте список `running` — выручку нарастающим итогом: первый элемент — выручка первого дня, второй — сумма первых двух дней и так далее.

### starter
```python
revenue = [41200, 38900, 45100, 39800, 52300]

```

### check
```python
r = need('running', list)
assert r == [41200, 80100, 125200, 165000, 217300], f'running = {r}.'
```

### hint
Нужны сразу и накопитель (`total`), и новый список. На каждом шаге: прибавить день к `total`, затем добавить `total` в список.

### hint
Проверьте себя на первых двух днях: 41 200, затем 41 200 + 38 900 = 80 100.

### solution
```python
revenue = [41200, 38900, 45100, 39800, 52300]
running = []
total = 0
for r in revenue:
    total += r
    running.append(total)
```

### explain
В SQL это оконная функция `SUM(revenue) OVER (ORDER BY day)`. В pandas — метод `cumsum()`.

## task: dod | Изменение к предыдущему дню | star

Постройте список `changes` — изменение выручки к предыдущему дню в процентах, округлённое до одного знака. Для первого дня сравнивать не с чем, поэтому в списке на один элемент меньше, чем дней.
