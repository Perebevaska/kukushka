## Кортеж: запись, которую нельзя изменить

Кортеж (тип `tuple`) похож на список, только записывается в круглых скобках и **не меняется** после создания:

```python
point = ("Пермь", 412, 205)
print(point[0])
print(len(point))
city, cups, price = point     # распаковка — как у строк таблицы
print(city, cups * price)
```

Кортежи вы уже встречали, не зная этого: пары «номер, элемент» из `enumerate` и «ключ, значение» из `items()` — это кортежи, и в цикле `for n, drink in ...` они распаковывались по двум именам. В этом уроке кортеж понадобится ещё дважды: функция вернёт им несколько результатов, а словарь использует его как ключ по двум полям.

Изменить элемент кортежа нельзя:

```python error
point = ("Пермь", 412, 205)
point[1] = 500
```

Это не недоработка, а следствие роли кортежа: он хранит одну **запись** с фиксированным составом полей (город, чашки, цена). Список — набор значений, куда что-то добавляют; в запись новых полей не добавляют.

Скобки при создании кортежа можно опускать — запятые важнее скобок:

```python
pair = "Латте", 210
print(pair, type(pair))
```

### Обмен значениями и несколько результатов функции

Благодаря кортежам две переменные меняются местами в одну строку:

```python
a = 10
b = 20
a, b = b, a
print(a, b)
```

А функция может вернуть сразу несколько значений — на самом деле она возвращает кортеж, который удобно распаковать:

```python
def min_max(values):
    return min(values), max(values)

lo, hi = min_max([41200, 38900, 61700])
print("от", lo, "до", hi)
```

::: predict
```python static
t = (1, 2, 3)
t[0] = 5
print(t)
```

- `(5, 2, 3)`
- `(1, 2, 3)`
- [x] `Ошибка TypeError`

Почему: кортеж нельзя изменить после создания. Python сообщит `'tuple' object does not support item assignment`.
:::

### Кортеж как ключ словаря

Ключом словаря может быть кортеж. Это даёт группировку сразу по двум полям:

```python
orders = [("Пермь", "сентябрь", 450), ("Пермь", "октябрь", 610),
          ("Казань", "сентябрь", 320), ("Пермь", "сентябрь", 390)]
sales = {}
for city, month, amount in orders:
    key = (city, month)
    sales[key] = sales.get(key, 0) + amount
print(sales)
print(sales[("Пермь", "сентябрь")])
```

::: figure tuple-key
Каждая пара (город, месяц) — один ключ словаря. Две сентябрьские строки Перми попали в один ключ и сложились.
:::

::: sql
Это `SELECT city, month, SUM(amount) FROM orders GROUP BY city, month`. Список ключом быть не может — он изменяемый, а ключи словаря обязаны быть неизменными. Словарь находит значение по ключу, как гардероб — пальто по номерку: если номерок может измениться после того, как пальто сдали, пальто уже не найти.
:::

## Множество: только уникальные значения

Множество (тип `set`) хранит значения **без повторов** и **без порядка**. Самый частый способ получить множество — передать список в `set`:

```python
order_cities = ["Пермь", "Казань", "Пермь", "Уфа", "Казань", "Пермь"]
cities = set(order_cities)
print(cities)
print(len(cities))
```

Порядок элементов при выводе может отличаться от порядка в списке — у множества его просто нет. Если нужен порядок, отсортируйте: `sorted(cities)` вернёт обычный список.

::: sql
`set(список)` — это `SELECT DISTINCT`, а `len(set(список))` — `COUNT(DISTINCT …)`.
:::

Проверка `in` для множества работает мгновенно даже на миллионах элементов — быстрее, чем для списка. Добавить элемент — `add`:

```python
seen = set()
seen.add("Z-1001")
seen.add("Z-1002")
seen.add("Z-1001")       # повтор — ничего не изменится
print(len(seen), "Z-1002" in seen)
```

::: predict
```python static
print(len({"Латте", "Раф", "Латте", "Мокко", "Раф"}))
```

- `5`
- [x] `3`
- `2`

Почему: в множестве повторы не хранятся. Остаются Латте, Раф и Мокко.
:::

## Операции над множествами

Множества можно пересекать, объединять и вычитать — как таблицы в SQL:

```python
september = {"Анна", "Борис", "Вера", "Глеб"}     # гости в сентябре
october = {"Борис", "Глеб", "Дина"}            # гости в октябре
print("были в оба месяца:", sorted(september & october))
print("все гости:", sorted(september | october))
print("ушли после сентября:", sorted(september - october))
print("новые в октябре:", sorted(october - september))
```

| Запись | Смысл | В SQL |
|---|---|---|
| `a & b` | есть и в `a`, и в `b` | `INTERSECT` |
| `a \| b` | есть хотя бы в одном | `UNION` |
| `a - b` | есть в `a`, но нет в `b` | `EXCEPT` |

### Разберём вместе: гости двух месяцев

Сентябрь: Анна, Борис, Вера, Глеб, Анна. Октябрь: Борис, Глеб, Дина, Ева, Глеб.

1. Множества убирают повторы: `S = {Анна, Борис, Вера, Глеб}` — 4 гостя, `O = {Борис, Глеб, Дина, Ева}` — 4 гостя.
2. **Пересечение** `S & O` — кто был в оба месяца: {Борис, Глеб}.
3. **Разность** `O - S` — кто пришёл впервые в октябре: {Дина, Ева}.
4. **Разность** `S - O` — кто был в сентябре, но не вернулся: {Анна, Вера}.
5. **Объединение** `S | O` — все гости двух месяцев: 6 человек.

::: figure set-venn
Гости двух месяцев на круговой схеме: в пересечении — вернувшиеся, по краям — ушедшие и новые. Каждая область — одна операция над множествами.
:::

Удержание сентябрьских гостей: вернулись 2 из 4 — **50 %**. Если бы считали по спискам с повторами, вышло бы 2 из 5 — повторный визит Анны исказил бы знаменатель.

```python
september = ["Анна", "Борис", "Вера", "Глеб", "Анна"]
october = ["Борис", "Глеб", "Дина", "Ева", "Глеб"]
S, O = set(september), set(october)
print(sorted(S & O), sorted(O - S), sorted(S - O), len(S | O))
print(round(len(S & O) / len(S) * 100, 1))
```

Что получилось: четыре операции над множествами отвечают на четыре вопроса маркетинга — «кто остался», «кто новый», «кто ушёл», «сколько всего». В SQL это `INTERSECT`, `EXCEPT` и `UNION`.

::: warn
Пустое множество создаётся как `set()`, а не `{}`: пустые фигурные скобки — это пустой **словарь**.
:::

::: warn Типичные ошибки
- **Порядок в множестве.** Множество не хранит порядок; для отчёта — `sorted(...)`.
- **`{}` — это словарь.** Пустое множество — `set()`.
- **Изменение кортежа.** `t[0] = ...` — `TypeError`; кортеж создают заново.
- **Распаковка не на то число имён.** `a, b = (1, 2, 3)` — `ValueError`.
:::

::: quiz
`sep` — множество гостей сентября, `oct` — октября. Как получить гостей, которые были в сентябре, но **не вернулись** в октябре?

- [x] `sep - oct`
  > Разность множеств: элементы первого, которых нет во втором. Это «ушедшие» гости.
- [ ] `sep & oct`
  > Пересечение — гости, которые были в оба месяца, то есть вернувшиеся.
- [ ] `sep | oct`
  > Объединение — все гости за два месяца.
- [ ] `oct - sep`
  > Это новые октябрьские гости, которых не было в сентябре.
:::

### starter

```python
def day_range(values):
```

### check


## task: dupes | Повторённые заказы | plus

В выгрузке некоторые номера заказов повторяются — это дубли. Соберите отсортированный список `dupes` номеров, которые встречаются больше одного раза (каждый номер — один раз). Используйте множество «уже видели».

### starter
```python
ids = ["Z-1001", "Z-1002", "Z-1003", "Z-1002", "Z-1004", "Z-1001", "Z-1002"]

```

### check
```python
assert need('dupes') == ['Z-1001', 'Z-1002'], f'dupes = {need("dupes")}. Каждый повторённый номер — один раз.'
```

### hint
Два множества: `seen` — встречали, `repeated` — встречали повторно. В цикле: если номер уже в `seen`, добавить его в `repeated`; иначе — в `seen`.

### hint
Почему два множества, а не одно: в `seen` попадает каждый номер, а нужны только повторы. «Z-1002» встречается трижды, но в `repeated` он окажется один раз — множество само убирает дубли. В конце `sorted(repeated)` превращает множество в отсортированный список.

### solution
```python
ids = ["Z-1001", "Z-1002", "Z-1003", "Z-1002", "Z-1004", "Z-1001", "Z-1002"]
seen = set()
repeated = set()
for i in ids:
    if i in seen:
        repeated.add(i)
    else:
        seen.add(i)
dupes = sorted(repeated)
```

### explain
Так ищут дубли в выгрузках перед расчётами. В SQL это `SELECT id FROM t GROUP BY id HAVING COUNT(*) > 1`, в pandas — `duplicated()`.

## task: retained-share | Удержание гостей | star


### hint
Вернулись в оба месяца — пересечение трёх множеств: `s & o & n`.

### hint
Процент считается от числа **уникальных** сентябрьских гостей: `len(set(september))`.

### solution
```python
september = ["Анна", "Борис", "Вера", "Глеб", "Анна", "Дина"]
october = ["Борис", "Глеб", "Дина", "Ева"]
november = ["Глеб", "Дина", "Ева", "Анна"]
s, o, n = set(september), set(october), set(november)
retention = round(len(s & o & n) / len(s) * 100, 1)
```

### explain
В сентябре 5 уникальных гостей; во все три месяца ходили Глеб и Дина — 40 %. Если бы знаменателем взяли список с повтором Анны (6 визитов), вышло бы 33.3 % — удержание считается по людям, а не по визитам.
