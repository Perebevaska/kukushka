## Новый список одной строкой

В уроке про циклы новый список строился так:

```python
prices = [210, 190, 260]
new_prices = []
for p in prices:
    new_prices.append(round(p * 1.1))
print(new_prices)
```

Для такого шаблона в Python есть короткая запись — **генератор списка** (*list comprehension*):

```python
prices = [210, 190, 260]
new_prices = [round(p * 1.1) for p in prices]
print(new_prices)
```

Читается справа налево: «для каждого `p` из `prices` — посчитай `round(p * 1.1)` — и собери в список». Результат тот же, но в одну строку и без пустого списка и `append`.

### С условием

В конец можно дописать фильтр `if`:

```python
revenue = [41200, 38900, 45100, 39800, 52300, 61700, 58400]
good_days = [r for r in revenue if r > 50000]
print(good_days)
```

::: sql
`[r for r in revenue if r > 50000]` — это `SELECT revenue FROM daily WHERE revenue > 50000`, а `[round(p * 1.1) for p in prices]` — `SELECT ROUND(price * 1.1) FROM menu`. Порядок частей похож: что выбрать — откуда — с каким условием.
:::

::: predict
```python static
print([x * 2 for x in [1, 2, 3] if x > 1])
```

- `[2, 4, 6]`
- [x] `[4, 6]`
- `[1, 4, 6]`

Почему: фильтр `if x > 1` отбрасывает 1, остаются 2 и 3, каждое умножается на 2.
:::

Бывает нужно не отбросить элементы, а подписать каждый по условию. Для этого есть выражение `A if условие else B` — «если… иначе» в одну строку. Оно ставится на место «что положить», в начало:

```python
profit = [1200, -300, 450]
labels = ["плюс" if x > 0 else "минус" for x in profit]
print(labels)
```

Это `CASE WHEN profit > 0 THEN 'плюс' ELSE 'минус' END`: ни один элемент не отбрасывается, в результате столько же значений, сколько в `profit`. Фильтр `if` без `else` стоит в конце, выбор значения `if … else` — в начале.

::: tip
Генератор списка хорош, когда помещается в одну понятную строку. Если внутри появляются вложенные условия и длинные выражения, обычный цикл читается легче — это не хуже.
:::

### Генератор словаря

Так же собирается словарь — в фигурных скобках, с двоеточием между ключом и значением:

```python
prices = {"Латте": 210, "Капучино": 190, "Раф": 260}
with_markup = {name: round(p * 1.1) for name, p in prices.items()}
print(with_markup)
```

### Разберём вместе: цикл → одна строка

Цикл, собирающий цены дешевле 250 ₽ с наценкой 10 %:

```python static
result = []
for p in prices:
    if p < 250:
        result.append(round(p * 1.1))
```

Генератор списка — те же три части, переставленные:

| часть | в цикле | в генераторе |
|---|---|---|
| что положить | `round(p * 1.1)` в `append` | **первым**: `round(p * 1.1)` |
| откуда брать | `for p in prices` | `for p in prices` |
| условие | `if p < 250:` | **последним**: `if p < 250` |

Итог: `[round(p * 1.1) for p in prices if p < 250]`.

::: figure comp-parts
Одинаковые цвета — одинаковые части. В генераторе «что положить» переезжает в начало, условие — в конец.
:::

Для `prices = [210, 190, 260, 150]`: 210 → 231, 190 → 209, 260 — пропущен условием, 150 → 165. Результат `[231, 209, 165]`.

```python
prices = [210, 190, 260, 150]
print([round(p * 1.1) for p in prices if p < 250])
```

Что получилось: генератор читается как фраза «округлённую цену с наценкой — для каждой цены — если она меньше 250». Если фраза не помещается в голове, лучше оставить обычный цикл: короткий код ценен, только пока он понятен.

## zip: два списка параллельно

В уроке про циклы, чтобы идти по двум «параллельным» спискам, мы использовали `range(len(...))` и индексы. `zip` делает это проще — склеивает списки попарно:

```python
cities = ["Пермь", "Казань", "Тюмень"]
cups = [412, 538, 297]
for city, c in zip(cities, cups):
    print(city, c)
```

::: figure zip-pairs
Слева: `zip` берёт по элементу с каждой позиции и складывает в пару. Справа: если один список короче, лишние элементы длинного молча пропадают.
:::

`zip` отлично сочетается с генераторами:

```python
revenue = [41200, 38900, 45100]
orders = [130, 121, 140]
checks = [round(r / o) for r, o in zip(revenue, orders)]
print(checks)

names = ["Латте", "Раф"]
prices = [210, 260]
menu = dict(zip(names, prices))     # пары сразу в словарь
print(menu)
```

`dict(пары)` собирает словарь из пар «ключ, значение» — так же, как `set(список)` собирает множество.

::: warn
Если списки разной длины, `zip` молча остановится на самом коротком. Перед этим стоит убедиться, что длины совпадают.
:::

## Сортировка по признаку: key

До сих пор функции только вызывали — со скобками: `len("Раф")`. Но функцию можно и **передать** как значение — по имени, без скобок. Тогда её вызовет тот, кому её передали:

```python
f = len            # без скобок: f теперь — та же функция len
print(f("Раф"))    # вызываем через новое имя: 3
```

На этом построен параметр `key`. `sorted` умеет сортировать не только по самим значениям, но и по **признаку**: вы передаёте в `key` функцию (именем, без скобок), а `sorted` сама вызывает её для каждого элемента и сортирует по результатам:

```python
drinks = ["Раф", "Флэт уайт", "Латте", "Американо"]
print(sorted(drinks))            # по алфавиту
print(sorted(drinks, key=len))   # по длине названия
```

::: figure sort-key
`key=len` считает для каждого напитка признак — длину названия, — и сортируются элементы по этому признаку, а не по алфавиту.
:::

Для строк таблицы признак обычно — один из столбцов. Можно написать для него обычную функцию и передать её имя:

```python
def second(row):
    return row[1]

sales = [["Пермь", 84460], ["Казань", 106524], ["Тюмень", 63558]]
print(sorted(sales, key=second, reverse=True))
```

Заводить отдельную функцию ради одной сортировки неудобно, поэтому то же самое пишут прямо на месте, в одну строку — через `lambda`:

```python
sales = [["Пермь", 84460], ["Казань", 106524], ["Тюмень", 63558]]
by_revenue = sorted(sales, key=lambda row: row[1], reverse=True)
print(by_revenue)
```

`lambda row: row[1]` читается так: «функция, которая берёт `row` и возвращает `row[1]`». Это та же `second`, только без имени (поэтому `lambda` называют безымянной функцией) и без `return`: результат — выражение после двоеточия.

::: predict
```python static
print(sorted(["Раф", "Латте", "Мокко"], key=len))
```

- `['Латте', 'Мокко', 'Раф']`
- [x] `['Раф', 'Латте', 'Мокко']`
- `['Мокко', 'Латте', 'Раф']`

Почему: сортировка по длине: «Раф» — 3 буквы, «Латте» и «Мокко» — по 5. При равном признаке порядок сохраняется исходный.
:::

### Максимум по значению словаря

Частая задача — найти ключ с наибольшим значением. `max` тоже принимает `key`:

```python
counts = {"Латте": 41, "Раф": 23, "Флэт уайт": 44}
print(max(counts, key=counts.get))
```

`counts.get` — функция, которая по ключу возвращает значение. Значит, `max` сравнивает ключи по их значениям.

А отсортировать словарь по значениям — так:

```python
counts = {"Латте": 41, "Раф": 23, "Флэт уайт": 44, "Мокко": 12}
top = sorted(counts.items(), key=lambda kv: kv[1], reverse=True)
print(top[:3])
```

::: sql
`sorted(..., key=lambda row: row[1], reverse=True)[:3]` — это `ORDER BY revenue DESC LIMIT 3`.
:::

Ключом может быть и кортеж — так записывают сортировку по нескольким полям. Кортежи сравниваются по первому элементу, а при равенстве — по второму. Минус перед числом разворачивает порядок только для этого поля:

```python
counts = {"Латте": 41, "Раф": 8, "Флэт уайт": 8, "Мокко": 12}
print(sorted(counts.items(), key=lambda kv: (-kv[1], kv[0])))
```

Это `ORDER BY count DESC, name ASC`: Раф и Флэт уайт продали поровну, и между ними решает алфавит.

::: quiz
`counts = {"Латте": 345, "Раф": 120, "Капучино": 365}`. Что вернёт `max(counts)` без `key`?

- [x] `"Раф"`
  > Цикл по словарю идёт по ключам, и `max` сравнивает названия как строки — по алфавиту. «Р» стоит дальше всех.
- [ ] `"Капучино"`
  > Чтобы сравнить по количеству, нужно `max(counts, key=counts.get)`.
- [ ] `365`
  > `max` от словаря работает с ключами, а не со значениями. Максимум значений — `max(counts.values())`.
- [ ] Ошибку: словари сравнивать нельзя
  > Сравниваются не словари, а их ключи-строки, и это допустимо.
:::

Коварство в том, что `max(counts)` без `key` иногда случайно даёт верный ответ: в `{"Латте": 41, "Флэт уайт": 44}` лидер и по продажам, и по алфавиту — «Флэт уайт». На других данных ответ окажется неверным, и такую ошибку трудно заметить.

## sum, any, all по выражению

Сумму можно посчитать прямо по выражению — без промежуточного списка:

```python
sales = [["Пермь", 412, 205], ["Казань", 538, 198], ["Казань", 301, 210]]
kazan = sum(c * p for city, c, p in sales if city == "Казань")
print(kazan)
```

Это тот же генератор, только без квадратных скобок: внутри скобок вызова функции их можно опустить — Python считает значения на лету, не собирая список целиком.

`any` отвечает «есть ли хоть один», `all` — «все ли»:

```python
profit = [12000, 8300, -1500, 9100]
print(any(x < 0 for x in profit))     # был ли убыточный день
print(all(x > 0 for x in profit))     # все ли дни в плюсе
```

::: sql
`any(...)` — как `EXISTS (SELECT … WHERE …)`.
:::

::: warn Типичные ошибки
- **Условие не на месте.** Фильтр `if` — в конце генератора: `[x for x in profit if x > 0]`. Запись `if ... else` перед `for` — это не фильтр, а выбор значения для каждого элемента, как в примере с подписями «плюс» и «минус».
- **`zip` списков разной длины.** Лишние элементы длинного списка молча отбрасываются.
- **`sort(key=...)` без функции.** `key` принимает функцию: `key=len`, `key=lambda r: r[1]` — без скобок вызова.
- **`max(counts)` у словаря.** Без `key` вернёт максимальный **ключ** по алфавиту, а не самый частый.
:::

## task: ranking | Рейтинг городов | base

Отсортируйте строки по выручке от большей к меньшей и сохраните в `ranking` только названия городов в этом порядке.


### explain
Рейтинг: Казань, Пермь, Уфа, Тюмень. `lambda row: row[1]` — маленькая функция «взять выручку из строки»; `sorted` вызывает её для каждой строки, чтобы понять, что с чем сравнивать.

### explain
Убыточный день был (−1 500), и не во все дни прибыль ≥ 5 000 (4 800 в последний). `any`/`all` останавливаются, как только ответ ясен, — на длинных списках это экономит время.

## task: top3 | Тройка лидеров | plus

Получите `top3` — список из трёх пар `(напиток, количество)` с наибольшими продажами, по убыванию.

### starter
```python
counts = {"Латте": 41, "Раф": 23, "Капучино": 37, "Флэт уайт": 44, "Мокко": 12}

```

### check
```python
t = need('top3')
assert [tuple(x) for x in t] == [('Флэт уайт', 44), ('Латте', 41), ('Капучино', 37)], f'top3 = {t}.'
```

### hint
`counts.items()` даёт пары. Отсортируйте их по второму элементу пары по убыванию и возьмите первые три.

### hint
`sorted(counts.items(), key=lambda kv: kv[1], reverse=True)[:3]`.

### solution
```python
counts = {"Латте": 41, "Раф": 23, "Капучино": 37, "Флэт уайт": 44, "Мокко": 12}
top3 = sorted(counts.items(), key=lambda kv: kv[1], reverse=True)[:3]
```

### explain
Тройка: флэт уайт (44), латте (41), капучино (37). Пары «ключ, значение» сортируются целиком, поэтому название не теряется — в отличие от сортировки одних чисел.

## task: moving | Скользящее среднее | star

Скользящее среднее за 3 дня сглаживает колебания: для каждого дня, начиная с третьего, это среднее его выручки и двух предыдущих дней. Постройте `ma3` одним генератором списка, округлив до целого.

### starter
```python
revenue = [41200, 38900, 45100, 39800, 52300, 61700, 58400]

```

### check
```python
assert need('ma3') == [41733, 41267, 45733, 51267, 57467], f'ma3 = {need("ma3")}.'
assert 'append' not in _code, 'Попробуйте одним генератором списка.'
```

### hint
Окно из трёх дней, заканчивающееся на дне `i`, — это срез `revenue[i - 2:i + 1]`.

### hint
`[round(sum(revenue[i - 2:i + 1]) / 3) for i in range(2, len(revenue))]`

### solution
```python
revenue = [41200, 38900, 45100, 39800, 52300, 61700, 58400]
ma3 = [round(sum(revenue[i - 2:i + 1]) / 3) for i in range(2, len(revenue))]
```

### explain
В SQL это `AVG(revenue) OVER (ORDER BY day ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)`, в pandas — `rolling(3).mean()`. Скользящее среднее ещё встретится в главе про временные ряды.
