**До выбора вариантов.** В двух выгрузках один и тот же код записан как «ab12» и « AB12 ». Как подготовить ключи перед соединением и проверить, не появились ли после подготовки дубликаты?

::: quiz 01-inspect
С чего начинать работу с новой выгрузкой?

- [x] С осмотра структуры, пропусков, значений и дублей
  > Сначала понять, что не так, — потом чистить и считать.
- [ ] Построить график выручки по всем строкам
  > График может помочь осмотру, но один график выручки не обнаружит пропуски ключей, неверные типы и дубли. Сначала проверьте структуру выгрузки.
- [ ] Удалить строки с любыми пустыми полями
  > Так можно потерять большую часть данных без причины.
- [ ] Перевести названия всех столбцов на русский
  > Это оформление, к качеству данных оно не относится.
:::

::: quiz 02-missing
У первого мастера за неделю ноль завершённых ремонтов, у второго есть ремонты, но потеряны суммы счетов. Кому можно восстановить среднюю стоимость ремонта из копий счетов?

- [x] Второму: можно восстановить суммы его счетов
  > После восстановления сумм их делят на число ремонтов. У первого за неделю нет наблюдений для среднего.
- [ ] Первому: его средний ремонт стоит ровно ноль
  > Ноль ремонтов означает неопределённое среднее, а не бесплатный ремонт.
- [ ] Обоим: достаточно среднего по всем мастерам
  > Заполнение не создаёт ремонты и не восстанавливает реальные счета второго мастера.
- [ ] Никому: пустое среднее нельзя восстановить
  > У второго существовали счета; их копии дают недостающие суммы.
:::

::: quiz 02-missing
В столбце `birth_date` встречается текст «не указано». Как его считать?

- [x] Как скрытый пропуск через `na_values`
  > Иначе `isna()` его не увидит, а при переводе в даты «не указано» придётся отлавливать отдельно.
- [ ] Как отдельное значение даты рождения
  > Это не дата, а отсутствие ответа.
- [ ] Как причину удалить всю анкету гостя
  > Остальные поля анкеты могут быть в порядке.
- [ ] Как наиболее частую дату рождения
  > Это выдумывание данных.
:::

::: quiz 02-missing
Бонусный баланс чаще не указывают гости, у которых он большой. Какой это механизм пропуска и чем он опасен для среднего баланса по заполненным анкетам?

- [x] MNAR: пропуски зависят от баланса, среднее занижено
  > Пропали именно большие значения. Заполнение средним или медианой группы этого не исправит.
- [ ] MCAR; среднее по заполненным остаётся несмещённым
  > MCAR — когда пропуск ни от чего не зависит. Здесь он зависит от величины баланса.
- [ ] MAR; заполнение средним по городу убирает смещение
  > MAR — когда пропуск зависит от другого известного столбца. Здесь причина — сам пропавший баланс.
- [ ] Механизм несущественен; `mean()` исключает пропуски
  > Именно поэтому важен: `mean()` считает по оставшимся, а у оставшихся балансы меньше.
:::

::: quiz 03-types
Почему кассовый CSV читают с `sep=";"` и `decimal=","`?

- [x] Это разделитель полей и знак дробной части в файле
  > Без этих параметров pandas прочитает всё одним столбцом или примет «125,5» за текст.
- [ ] Это настройки для ускоренного чтения любого CSV
  > Дело в формате файла, а не в скорости.
- [ ] Это обязательные настройки для всех русских таблиц
  > По умолчанию pandas ждёт запятую-разделитель и точку в дробях.
- [ ] Это настройки удаления повторяющихся строк файла
  > Параметры чтения не убирают дубли.
:::

::: quiz 03b-excel
Перед строкой с названиями столбцов Excel стоят три служебные строки, после данных — строка «Итого». Как прочитать лист для расчётов?

- [x] Пропустить шапку, убрать итог и сверить суммы
  > Шапку пропускают параметром чтения, итог — фильтром по значению. Сверка суммы с «Итого» помогает обнаружить потери или двойной учёт, но сама по себе не доказывает правильность всех строк.
- [ ] Прочитать лист без параметров: шапка определится сама
  > Не найдёт: заголовком станет первая строка листа, а «Итого» — обычной строкой данных.
- [ ] Прочитать фиксированные семь строк через `nrows=7`
  > Когда в книге появится восьмая строка данных, она молча пропадёт. Фильтр по значению надёжнее.
- [ ] Прочитать книгу через `read_csv` с разделителем `;`
  > `.xlsx` — не текстовый файл, `read_csv` его не прочитает.
:::

::: quiz 04-duplicates
В CRM номер карты уникален для гостя; регистр букв и внешние пробелы незначимы. Анкеты «C1023» и «c1023 » — один гость или два?

- [x] Один: нормализованные номера карт совпадут
  > После удаления внешних пробелов и выравнивания регистра ключи совпадают. Для выбора одной анкеты проверьте остальные поля и правило приоритета, например дату обновления.
- [ ] Два: регистр и пробел различают номера карт
  > Разница только в регистре и пробеле — это одна карта.
- [ ] Неизвестно: сравнение требует номера телефона
  > Номер карты — ключ: после нормализации его достаточно.
- [ ] Один: но нормализация запрещает удаление дубля
  > Нормализация обнаруживает совпадение ключей. Затем нужно разрешить конфликт полей по правилу CRM и оставить одну анкету, иначе гость посчитается дважды.
:::

::: quiz 05-strings
Как получить «Пермь» из всех трёх написаний: «г. Пермь», « пермь» и «Пермь»?

- [x] Убрать префикс, выровнять пробелы и регистр
  > Например: strip → lower → удалить начальное «г.» → strip → capitalize. Для «г. Тула», « тула» и «Тула» проверьте, что все три результата равны «Тула». Это правило для данных примеров; сложные названия требуют словаря.
- [ ] Только заменить точное «г. Пермь» на «Пермь»
  > Так исправится одно написание, а остальные останутся.
- [ ] Только перевести все значения в верхний регистр
  > Регистр выровняется, но «г.» и пробелы останутся.
- [ ] Удалить строки со всеми редкими написаниями
  > Это потеря данных: те же гости из Перми.
:::

::: quiz 06-categories
Что делает `pd.cut(age, bins=[14, 25, 35], right=False)` со значением 25?

- [x] Относит его к интервалу [25, 35)
  > `right=False` — левая граница включена, правая нет.
- [ ] Относит его к интервалу [14, 25)
  > Правая граница 25 при `right=False` не включена.
- [ ] Заменяет значение 25 пропуском NaN
  > 25 попадает во второй интервал.
- [ ] Выдаёт ошибку совпадения с границей
  > Совпадение границы со значением — обычная ситуация.
:::

::: quiz 07-anomalies
Расчёт дал возраст гостя 126 лет. Источник даты и формулу ещё не проверяли. Как поступить с этой записью?

- [x] Проверить дату и способ расчёта возраста
  > Сначала сверьте дату, дату расчёта и формулу. Например, 1900-01-01 может быть заглушкой, но по одному возрасту причину не установить. После проверки примените согласованное правило очистки.
- [ ] Принять возраст за достоверный без сверки
  > Редкость значения — повод для проверки. Пока дата и расчёт не сверены, достоверность не установлена.
- [ ] Исправить формулу для всех гостей сразу
  > Одна подозрительная запись не доказывает общую ошибку формулы. Сначала проверьте её и исходную дату именно этой записи.
- [ ] Заменить возраст нулём без проверки даты
  > Ноль означает конкретный возраст и исказит анализ. Если после проверки дату признали недостоверной, пометьте её пропуском, сохранив исходник и причину.
:::

Зачем оформлять очистку функцией `clean_clients(raw)`, а не держать в двадцати ячейках?

- [x] Чтобы повторять очистку на следующих выгрузках
  > Функция — это повторяемость и одно место для исправлений.
- [ ] Чтобы pandas быстрее выполнял те же операции
  > Скорость та же.
- [ ] Чтобы pandas разрешил сохранить новую таблицу
  > Сохранить можно и без функции.

  > Наоборот: функцию проще прочитать и проверить.

::: quiz 08-pipeline
В pandas 3 написали `df[df["bonus"] < 0]["bonus"] = 0`. Что произойдёт с отрицательными бонусами в `df`?

- [x] Исходный `df` останется прежним: это копия
  > Цепочка скобок сначала отбирает строки — это новая таблица, — и правка уходит в неё. Менять часть таблицы нужно одним `.loc`: `df.loc[df["bonus"] < 0, "bonus"] = 0`.
- [ ] Отрицательные значения в `df` станут нулями
  > Для правки исходной таблицы используйте, например, `df.loc[df["bonus"] < 0, "bonus"] = 0`: отбор строк и присваивание выполняются одной операцией.
- [ ] Все значения столбца `bonus` станут нулями
  > Присваивание вообще не дойдёт до `df`.
- [ ] Выполнение прервётся синтаксической ошибкой
  > Синтаксис допустим. Исходный df не меняется, а pandas 3 выдаёт предупреждение ChainedAssignmentError. Для изменения используйте одно присваивание через .loc.
:::

::: quiz 09-project
К анкетам гостей присоединили статистику заказов: `clients.merge(stats, on="client_id", how="left")`. Что эта таблица **не** покажет?

- [x] Карты из заказов без соответствующей анкеты
  > LEFT JOIN оставляет все строки левой таблицы — анкеты. Карты-«сироты» из заказов в результат не попадут; их ищут отдельно, разностью множеств номеров.
- [ ] Анкеты гостей, не сделавших ни одного заказа
  > Они останутся: без совпадения в stats появится NaN. Нулём можно заполнить число заказов и сумму, если отсутствие строки действительно означает отсутствие заказов; неизвестные показатели не превращают в ноль автоматически.
- [ ] Выручку тех гостей, чьи анкеты есть в `clients`
  > Она как раз и пришла из `stats`.
- [ ] Строки анкет с присоединёнными данными заказов
  > Если `client_id` в `stats` уникален, строк ровно столько, сколько анкет.
:::
