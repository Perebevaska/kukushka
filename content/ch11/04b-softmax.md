## Много классов: softmax и кросс-энтропия

До сих пор выход был один — вероятность класса 1. Если классов $K$ (например, цифры 0–9 в проекте этой главы), выходной слой выдаёт $K$ чисел — **логитов**. **Softmax** превращает их в вероятности, которые в сумме дают 1:

$$
\mathrm{softmax}(z)_k = \frac{e^{z_k}}{\sum_j e^{z_j}}
$$

Здесь $z_k$ — логит класса $k$, а сумма в знаменателе идёт по всем $K$ классам: экспонента делает все числа положительными, деление на сумму — так, чтобы они складывались в 1.

Потеря — **кросс-энтропия**: $-\log(\text{вероятность правильного класса})$, усреднённая по объектам. Если модель дала правильному классу 0.9 — штраф 0.1, если 0.01 — штраф 4.6.

```python
import numpy as np

def softmax(Z):
    Z = Z - Z.max(axis=1, keepdims=True)        # для устойчивости: сдвиг не меняет результат
    E = np.exp(Z)
    return E / E.sum(axis=1, keepdims=True)

logits = np.array([[2.0, 1.0, 0.1],
                   [0.5, 2.5, 0.3]])
P = softmax(logits)
y = np.array([0, 2])                            # правильные классы
print(P.round(3))
print("суммы строк:", P.sum(axis=1))
print("кросс-энтропия:", round(float(-np.log(P[np.arange(2), y]).mean()), 3))
```

Посчитаем руками первую строку: логиты 2.0, 1.0, 0.1. Экспоненты: e² ≈ 7.389, e¹ ≈ 2.718, e⁰·¹ ≈ 1.105, сумма ≈ 11.21. Вероятности: 7.389 / 11.21 ≈ **0.659**, 2.718 / 11.21 ≈ **0.242**, 1.105 / 11.21 ≈ **0.099**. Правильный класс 0 получил 0.659, штраф −log 0.659 ≈ 0.42.

::: figure nn-softmax
Softmax для первой строки: экспонента делает логиты положительными, деление на сумму превращает их в доли, которые складываются в 1. Кросс-энтропия смотрит только на вероятность правильного класса.
:::

**Что здесь происходит в коде:**

- `Z.max(axis=1, keepdims=True)` — максимум каждой строки; вычитаем его, чтобы `np.exp` не переполнился на больших логитах (вероятности от этого не меняются: сдвиг сокращается в дроби).
- `E / E.sum(axis=1, keepdims=True)` — делим каждую строку на её сумму.

`P[np.arange(2), y]` — «из каждой строки взять вероятность правильного класса»: строка 0, столбец 0 и строка 1, столбец 2. Для второго объекта модель ошиблась (самая большая вероятность у класса 1), и именно он даёт основную часть потери.

В PyTorch это `nn.CrossEntropyLoss()` — она принимает логиты и сама применяет softmax. В sklearn `MLPClassifier` переключается на softmax автоматически, если классов больше двух.

::: warn Типичные ошибки
- **Softmax в модели и `nn.CrossEntropyLoss`.** Потеря применит softmax второй раз, и вероятности сплющатся: для логитов 2.0, 1.0, 0.1 вместо 0.659, 0.242, 0.099 получится 0.448, 0.296, 0.256. Сеть учится, но медленнее и хуже — так же, как с двойной сигмоидой в бинарной задаче (раздел «Выход и потеря под тип задачи» ниже). В модели оставляют логиты.
- **Softmax без вычитания максимума.** Для логитов 1000 и 999 `np.exp` переполняется, и «наивный» softmax выдаёт `[nan, nan]`; со сдвигом на максимум — честные 0.731 и 0.269.
- **Softmax ради прогноза класса.** Softmax не меняет порядок чисел, поэтому `logits.argmax(axis=1)` даёт тот же класс, что `P.argmax(axis=1)`. Вероятности нужны, только когда важна уверенность — например, чтобы отдать сомнительные ответы человеку.
:::

## Выход и потеря под тип задачи

**Зачем.** Softmax — один из вариантов выхода сети. Скрытые слои у сетей для разных задач «Зерна» почти одинаковые — ReLU между линейными слоями. Различаются только две вещи на самом конце: какая активация стоит на выходе и какую потерю минимизируют. Перепутать их — частая причина, по которой сеть «обучилась», а прогнозы бессмысленные.

::: sql
Это как выбрать агрегат в отчёте: для суммы выручки — `SUM`, для доли вернувшихся — `AVG` по флагу 0/1, для самой популярной категории — `MODE`. Данные одни, а вопрос определяет, чем их сворачивать. У сети вопрос определяет выход и потерю.
:::

| задача | пример в «Зерне» | чисел на выходе | активация на выходе | потеря | в PyTorch |
|---|---|---|---|---|---|
| регрессия | минуты доставки, выручка дня | 1 | нет (линейный выход) | MSE (глава 10); при выбросах — MAE или Huber | `nn.MSELoss()`, `nn.L1Loss()`, `nn.HuberLoss()` |
| бинарная классификация | уйдёт ли гость | 1 | сигмоида | логистическая (BCE) | `nn.BCEWithLogitsLoss()` — сигмоида внутри |
| многоклассовая | какая цифра в анкете, 0–9 | K | softmax | кросс-энтропия (раздел выше) | `nn.CrossEntropyLoss()` — softmax внутри |
| многометочная | что купит гость: кофе, десерт, сэндвич — любые вместе | K | сигмоида на каждом выходе отдельно | BCE по каждому выходу, среднее | `nn.BCEWithLogitsLoss()` |
| счётчик | сколько заказов придёт за час | 1 | экспонента — выход всегда больше 0 | пуассоновская | `nn.PoissonNLLLoss()` — экспонента внутри |

Как читать таблицу: «чисел на выходе» — сколько нейронов в последнем слое; «активация на выходе» превращает их в ответ нужного вида (любое число, вероятность, распределение по классам); потеря сравнивает этот ответ с правдой. В многоклассовой задаче класс у объекта ровно один, и softmax заставляет вероятности делить единицу между классами. В многометочной каждый выход — отдельный вопрос «да/нет», вероятности независимы, и их сумма может быть любой.

::: figure nn-heads
Тело сети одинаковое, а «голова» — число выходов, активация на выходе и потеря — выбирается по типу задачи.
:::

**Игрушечный пример руками.** Пусть сеть уже выдала сырые выходы (логиты), посчитаем ответ и потерю для трёх «голов»:

- *регрессия:* прогнозы 28, 41 и 35 минут, факт 30, 38 и 35. Квадраты ошибок 4, 9 и 0, MSE = 13 / 3 ≈ **4.333**;
- *бинарная:* логиты 2.0 и −1.0; первый гость ушёл (1), второй остался (0). Сигмоида: 0.881 и 0.269. Штрафы: $-\log 0.881 = 0.127$ и $-\log(1 - 0.269) = 0.313$, среднее **0.220**;
- *многометочная:* один гость, логиты 3.0, 0.5 и −2.0 для кофе, десерта и сэндвича, купил кофе и десерт. Сигмоиды: 0.953, 0.622, 0.119 — в сумме 1.694, и это нормально. Штрафы 0.049, 0.474 и 0.127, среднее **0.217**.

```python
import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

z_reg = np.array([28.0, 41.0, 35.0]); y_reg = np.array([30.0, 38.0, 35.0])
print("регрессия, MSE:", round(float(np.mean((z_reg - y_reg) ** 2)), 3))

z_bin = np.array([2.0, -1.0]); y_bin = np.array([1, 0])
p = sigmoid(z_bin)
bce = -np.mean(y_bin * np.log(p) + (1 - y_bin) * np.log(1 - p))
print("бинарная, p:", p.round(3), "BCE:", round(float(bce), 3))

Z_ml = np.array([[3.0, 0.5, -2.0]]); Y_ml = np.array([[1, 1, 0]])      # кофе, десерт, сэндвич
P = sigmoid(Z_ml)                                                     # сигмоида на каждом выходе
bce_ml = -np.mean(Y_ml * np.log(P) + (1 - Y_ml) * np.log(1 - P))
print("многометочная, p:", P.round(3), "сумма:", round(float(P.sum()), 3), "BCE:", round(float(bce_ml), 3))
```

**Что здесь происходит:**

- Для регрессии выход сети и есть прогноз: никакой активации, потеря — средний квадрат ошибки.
- Для бинарной задачи `sigmoid(z_bin)` превращает логит в вероятность ухода, потеря — логистическая из урока «Обучение сети: обратное распространение ошибки».
- Для многометочной `sigmoid(Z_ml)` применяется к каждому из трёх выходов отдельно; `np.mean` усредняет штрафы по всем клеткам «гость × категория».

**Почему в PyTorch потерю считают по логитам.** Если логит большой, сигмоида в компьютере округляется ровно до 1, и $\log(1 - p)$ превращается в $\log 0 = -\infty$. Тот же штраф можно переписать без вычисления $p$: $\log(1 + e^z) - y \cdot z$ — это алгебраически та же логистическая потеря, но без деления и без логарифма нуля. В numpy $\log(1 + e^z)$ устойчиво считает `np.logaddexp(0, z)`:

```python
import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

z, y = 40.0, 0                                       # сеть уверена «уйдёт», а гость остался
with np.errstate(divide="ignore"):                   # не печатать предупреждение о log(0)
    naive = -(y * np.log(sigmoid(z)) + (1 - y) * np.log(1 - sigmoid(z)))
stable = np.logaddexp(0, z) - y * z
print(sigmoid(z) == 1.0, naive, stable)
```

**Что получилось:** `sigmoid(40)` равна 1.0 ровно, «наивная» потеря — `inf`, и один такой объект превращает среднюю потерю и все градиенты в `inf`/`nan`. Формула по логитам даёт честные 40.0 — большой, но конечный штраф. Поэтому `nn.BCEWithLogitsLoss` и `nn.CrossEntropyLoss` принимают логиты, а не вероятности, и последний слой сети в PyTorch обычно оставляют без активации.

::: warn Типичные ошибки
- **Сигмоида на выходе регрессии.** Прогноз минут доставки не может превысить 1, MSE огромная и почти не падает. Симптом — все прогнозы около 1.0. Исправление — линейный выход.
- **Сигмоида дважды.** В модели последний слой `nn.Sigmoid()`, а потеря — `nn.BCEWithLogitsLoss()`, которая применяет сигмоиду ещё раз. Ошибки нет, сеть учится, но хуже и медленнее: вероятности сжаты в 0.5…0.73. Либо убрать `nn.Sigmoid()` из модели, либо взять `nn.BCELoss()` — первое надёжнее.
- **Softmax для многометочной задачи.** Softmax заставляет категории конкурировать: если гость берёт и кофе, и десерт, обе вероятности не могут быть близки к 1. Для «любые вместе» — сигмоида на каждом выходе.
:::

## Мини-батчи и эпохи

Мини-батчи и эпохи вы уже видели: в главе 10 (стохастический спуск) и в уроке «Граф вычислений, инициализация и обрезка градиента», где обрезку проверяли на батчах по 32. Напомним коротко: градиент считают не по всем объектам, а по небольшому случайному куску — **мини-батчу** — и сразу делают шаг; проход по всем данным кусками — **эпоха**. Наша сеть в уроке «Обучение сети: обратное распространение ошибки» делала каждый шаг по **всем** 400 точкам. Здесь — как нарезать батчи своими руками и как размер батча меняет обучение сети.

Например, 400 объектов и батч 64: за эпоху — 7 шагов (6 по 64 и один из 16 оставшихся). За 100 эпох — 700 шагов, хотя каждый объект использован лишь 100 раз.

::: figure nn-minibatch
Эпоха: объекты перемешиваются, режутся на батчи, и по каждому батчу делается свой шаг спуска.
:::

```python
import numpy as np

def batches(X, y, size, rng):
    order = rng.permutation(len(y))                  # перемешиваем каждую эпоху
    for start in range(0, len(y), size):
        idx = order[start:start + size]
        yield X[idx], y[idx]

X = np.arange(10).reshape(10, 1)
y = np.arange(10)
for Xb, yb in batches(X, y, 4, np.random.default_rng(0)):
    print(yb)
```

**Что здесь происходит:**

- `rng.permutation(len(y))` — случайный порядок номеров объектов; каждая эпоха — новый порядок.
- `yield` делает функцию **генератором**: она выдаёт батчи по одному, и цикл `for` получает их по очереди.
- Последний батч короче — в нём остаток.

Зачем батчи, кроме экономии памяти: шагов за то же число эпох больше, а шум градиента от случайного батча помогает не застревать. На полумесяцах за 100 эпох: полный батч (100 шагов) — около 0.89 верных, батч 64 (700 шагов) — около 0.95, батч 16 (2500 шагов) — около 0.96. В PyTorch батчи нарезает `DataLoader`; в `MLPClassifier` за это отвечает параметр `batch_size`.

::: quiz
На полумесяцах за 100 эпох батч 64 дал около 0.95 верных, а полный батч — около 0.89. Главная причина?

- [x] За те же 100 эпох батчи по 64 дают 700 шагов спуска вместо 100, а шум случайного батча помогает не застревать
  > Эпоха — это проход по данным, а не один шаг. Чем меньше батч, тем больше шагов за эпоху.
- [ ] Градиент по батчу точнее, чем по всем данным
  > Наоборот: градиент по 64 случайным объектам — шумная оценка градиента по всем 400. Выигрыш — в числе шагов, а не в точности каждого.
- [ ] С батчами каждый объект используется больше раз
  > За 100 эпох каждый объект использован ровно 100 раз при любом размере батча.
- [ ] Батч случайно выключает часть нейронов, и сеть меньше переобучается
  > Батч выбирает объекты для шага, а не нейроны; все нейроны сети работают на каждом шаге.
:::

::: warn Типичные ошибки
- **Батчи без перемешивания.** Если выгрузка отсортирована — например, сначала все оставшиеся гости, потом все ушедшие, — первые батчи целиком из одного класса, и каждый шаг тянет модель в свою сторону. Перемешивают перед *каждой* эпохой: `rng.permutation`, в PyTorch — `DataLoader(..., shuffle=True)`.
- **Сумма по батчу вместо среднего.** Если градиент не делить на размер батча (`(p - y) / len(yb)`), величина шага зависит от размера батча: батч в 4 раза больше — шаг примерно в 4 раза длиннее, и подобранный `lr` перестаёт подходить.
- **Сравнение по эпохам при разных батчах.** 100 эпох с полным батчем — 100 шагов, с батчем 16 на 400 объектах — 2500. Сравнивая настройки, смотрите и на число шагов, и на время.
:::

### starter
```python
import numpy as np
Z = np.array([[1.0, 3.0, 0.5],
              [2.0, 2.0, 4.0],
              [1000.0, 999.0, 998.0]])

```

### check
```python
import numpy as _np
Z0 = _np.array([[1.0, 3.0, 0.5], [2.0, 2.0, 4.0], [1000.0, 999.0, 998.0]])
E = _np.exp(Z0 - Z0.max(axis=1, keepdims=True)); w = E / E.sum(axis=1, keepdims=True)
P = _np.asarray(need('P'))
assert not _np.isnan(P).any(), 'В P есть nan — без сдвига на максимум e^1000 переполняется.'
assert _np.allclose(P, w), f'P = {P.round(3)}.'
assert list(_np.asarray(need('pred'))) == [1, 2, 0], f'pred = {need("pred")}.'
```

### hint
Softmax применяется к каждой строке отдельно: все суммы и максимумы — с `axis=1, keepdims=True`.

### hint
`Z = Z - Z.max(axis=1, keepdims=True)`, затем `np.exp` и деление на сумму по строке. Номер максимума — `P.argmax(axis=1)`.

### solution
```python
import numpy as np
Z = np.array([[1.0, 3.0, 0.5],
              [2.0, 2.0, 4.0],
              [1000.0, 999.0, 998.0]])

def softmax(Z):
    Z = Z - Z.max(axis=1, keepdims=True)
```

```python
import numpy as np
X = np.arange(20).reshape(10, 2)
y = np.arange(10)

def batches(X, y, size, rng):
    order = rng.permutation(len(y))
    for start in range(0, len(y), size):
        idx = order[start:start + size]
        yield X[idx], y[idx]

parts = list(batches(X, y, 4, np.random.default_rng(0)))
sizes = [len(b) for _, b in parts]
covered = sorted(np.concatenate([b for _, b in parts]).tolist()) == list(range(10))
```

### explain
`yield` превращает функцию в генератор: она отдаёт батч, ставит работу на паузу и продолжает с того же места, когда цикл попросит следующий. Данные при этом не копируются целиком в память — так `DataLoader` справляется с наборами, которые не влезают в неё. 10 строк по 4 дают батчи размером 4, 4 и 2: последний короче, и обучение должно это учитывать (градиент делят на `len(batch)`, а не на 4). `covered` проверяет главное свойство эпохи: каждая строка увидена ровно один раз.

```python
    steps = 0
```

```python
        for Xb, yb in batches(X, y, size, rng):
            Z1 = Xb @ W1 + b1
            H = np.maximum(0, Z1)
            p = 1 / (1 + np.exp(-(H @ w2 + b2)))
            d2 = (p - yb) / len(yb)
            g_w2, g_b2 = H.T @ d2, d2.sum()
            dH = np.outer(d2, w2) * (Z1 > 0)
            W1 = W1 - lr * (Xb.T @ dH); b1 = b1 - lr * dH.sum(axis=0)
            w2 = w2 - lr * g_w2; b2 = b2 - lr * g_b2
            steps += 1
    return W1, b1, w2, b2, steps

res = {}
for size in [400, 64, 16]:
    W1, b1, w2, b2, steps = train_batches(size)
    H = np.maximum(0, X @ W1 + b1)
    p = 1 / (1 + np.exp(-(H @ w2 + b2)))
    loss = -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))
    res[size] = (round(float(loss), 3), round(float(((p > 0.5) == y).mean()), 3), steps)
best_size = min(res, key=lambda k: res[k][0])
print(res, best_size)
```

### explain
За те же 100 эпох полный батч сделал всего 100 шагов и недоучился (около 0.89 верных), батч 64 — 700 шагов (около 0.95), батч 16 — 2500 шагов (около 0.96). Дело не только в числе шагов: маленький батч даёт шумный градиент, и этот шум помогает выбираться из неудачных мест. Цена — больше шагов, а значит, больше времени на эпоху; на видеокарте большие батчи считаются параллельно, поэтому на практике выбирают 32–256.

## task: softmax-net | Многоклассовая сеть на numpy | star

### solution
```python
import numpy as np
from sklearn.datasets import make_blobs
X, y = make_blobs(300, centers=3, cluster_std=1.5, random_state=0)
X = (X - X.mean(axis=0)) / X.std(axis=0)
Y = np.eye(3)[y]

def softmax(Z):
    Z = Z - Z.max(axis=1, keepdims=True)
    E = np.exp(Z)
    return E / E.sum(axis=1, keepdims=True)

rng = np.random.default_rng(0)
W1 = rng.normal(size=(2, 16)) * 0.5
b1 = np.zeros(16)
W2 = rng.normal(size=(16, 3)) * 0.5
b2 = np.zeros(3)
for _ in range(500):
    Z1 = X @ W1 + b1
    H = np.maximum(0, Z1)
    P = softmax(H @ W2 + b2)
    D = (P - Y) / len(y)
    dH = D @ W2.T * (Z1 > 0)
    W2 = W2 - 0.5 * H.T @ D
    b2 = b2 - 0.5 * D.sum(axis=0)
    W1 = W1 - 0.5 * X.T @ dH
    b1 = b1 - 0.5 * dH.sum(axis=0)
P = softmax(np.maximum(0, X @ W1 + b1) @ W2 + b2)
acc = round((P.argmax(axis=1) == y).mean(), 3)
```

### explain
Формула градиента «P − Y» та же, что для двух классов («p − y»), только теперь это матрица. Именно поэтому softmax и кросс-энтропию всегда используют вместе: в паре они дают простой и устойчивый градиент. Эту сеть вы и обучите на цифрах в проекте.
