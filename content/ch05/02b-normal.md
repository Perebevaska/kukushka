## Нормальное распределение

**Нормальное распределение** — знаменитый «колокол»: значения скапливаются вокруг среднего и симметрично редеют в обе стороны. Его задают два числа: среднее (`loc`) и стандартное отклонение $\sigma$ (`scale`).

```python
import numpy as np
from scipy import stats
import matplotlib.pyplot as plt

x = np.linspace(0, 24, 200)
fig, ax = plt.subplots(figsize=(8, 3.5))
ax.plot(x, stats.norm.pdf(x, loc=12, scale=3))
ax.set_title("Время сборки заказа: нормальное, среднее 12 мин, σ = 3")
ax.set_xlabel("минут")
```

`np.linspace(0, 24, 200)` — 200 равномерно расставленных точек от 0 до 24, чтобы нарисовать гладкую кривую. `pdf` — плотность: высота колокола в точке. Сама по себе высота — не вероятность; вероятности — это площади под кривой, и их даёт `cdf`:

```python
from scipy import stats
sborka = stats.norm(loc=12, scale=3)
print("быстрее 9 мин:     ", round(sborka.cdf(9), 3))
print("дольше 18 мин:     ", round(sborka.sf(18), 3))
print("от 9 до 15 мин:    ", round(sborka.cdf(15) - sborka.cdf(9), 3))
print("90 % быстрее, чем: ", round(sborka.ppf(0.9), 1), "мин")
```

`stats.norm(loc=12, scale=3)` — «замороженное» распределение: параметры задаются один раз. `ppf` — обратная к `cdf` функция: по доле возвращает значение (квантиль).

### Правило 68–95–99.7

У нормального распределения:

- в пределах $\pm 1\sigma$ от среднего — 68 % значений;
- в пределах $\pm 2\sigma$ — 95 %;
- в пределах $\pm 3\sigma$ — 99.7 %.

::: figure norm-689599
Время сборки заказа со средним 12 минут и σ = 3: в полосу 9–15 минут попадают 68 % заказов, в 6–18 — 95 %, в 3–21 — 99.7 %.
:::

```python
from scipy import stats
for k in (1, 2, 3):
    print(k, "σ:", round(stats.norm.cdf(k) - stats.norm.cdf(-k), 4))
print("квантиль 0.975:", round(stats.norm.ppf(0.975), 2))
```

Без параметров `stats.norm` — **стандартное** нормальное распределение: среднее 0, $\sigma = 1$. Число 1.96 (квантиль 0.975) встретится нам ещё много раз: между −1.96 и 1.96 лежит ровно 95 %.

::: predict
```python static

```

- [x] `0.5`
- `0.68`

Почему: распределение симметрично относительно среднего 0, слева от нуля ровно половина площади.
:::

## Нормальное приближение

**Зачем.** Интервалы для доли (урок «Доверительные интервалы») и тесты для долей (z-тест для двух долей появится в уроке «Проверка гипотез: логика и p-value», дальше он работает в A/B-тестах) считают вероятности не по биномиальному распределению, а по нормальному. Это **нормальное приближение**: при большом n биномиальное распределение почти совпадает с колоколом с тем же средним n · p и тем же σ = √(n · p · (1 − p)). Важно понимать, когда такая замена честная, а когда врёт.

::: tip Аналогия
Лестница издалека выглядит как гладкий пандус. Чем больше ступенек и чем они мельче, тем точнее пандус повторяет лестницу. Биномиальное распределение — лестница из столбиков, нормальное — пандус. При трёх ступеньках (маленькое n · p) пандус проходит мимо углов.
:::

### Игрушечный пример: 200 доставок за неделю

За неделю 200 доставок, p = 0.24. Какова вероятность 60 и больше опозданий?

1. Среднее: 200 × 0.24 = **48**.
2. σ: √(200 × 0.24 × 0.76) = √36.48 ≈ **6.04**.
3. Точно по биномиальному: `stats.binom.sf(59, 200, 0.24)` = **0.0307**.
4. По нормальному: биномиальное считает целые числа, и столбик «60» на гладкой кривой занимает отрезок от 59.5 до 60.5. Поэтому «60 и больше» — это площадь правее **59.5** (поправка на непрерывность): `stats.norm.sf(59.5, 48, 6.04)` = **0.0285**.

Без поправки (правее 60) вышло бы 0.0235 — заметно хуже. Разница 0.0307 против 0.0285 для решения «бывает ли такая неделя» не важна: обе вероятности — около 3 %.

```python
from scipy import stats
import math

n, p, k = 200, 0.24, 60
mu = n * p
sigma = math.sqrt(n * p * (1 - p))
print("точно:              ", round(stats.binom.sf(k - 1, n, p), 4))
print("нормальное, k − 0.5:", round(stats.norm.sf(k - 0.5, mu, sigma), 4))
print("нормальное, без поправки:", round(stats.norm.sf(k, mu, sigma), 4))
```

Что здесь происходит:

- `stats.binom.sf(k - 1, n, p)` — точная вероятность «k и больше»;
- `stats.norm.sf(k - 0.5, mu, sigma)` — площадь под колоколом правее k − 0.5 с теми же средним и σ;
- третья строка показывает, сколько теряет приближение без поправки.

### Когда приближению можно верить

Сравним точную вероятность «выше среднего на 2σ и больше» с нормальной для разных n и p:

```python
from scipy import stats
import math

for n, p in [(40, 0.05), (20, 0.24), (200, 0.24), (2000, 0.24)]:
    mu, s = n * p, math.sqrt(n * p * (1 - p))
    k = math.ceil(mu + 2 * s)                  # порог: среднее + 2σ, вверх до целого
    exact = stats.binom.sf(k - 1, n, p)
    approx = stats.norm.sf(k - 0.5, mu, s)
    err = abs(approx - exact) / exact          # относительная ошибка
    print(n, p, "n·p =", round(mu, 1), "| точно", round(exact, 4), "| нормальное", round(approx, 4), "| ошибка", round(err, 2))
```

| n | p | n · p | точно | нормальное | ошибка |
|---|---|---|---|---|---|
| 40 | 0.05 | 2 | 0.0480 | 0.0349 | 27 % |
| 20 | 0.24 | 4.8 | 0.0320 | 0.0264 | 18 % |
| 200 | 0.24 | 48 | 0.0212 | 0.0192 | 9 % |
| 2000 | 0.24 | 480 | 0.0226 | 0.0219 | 3 % |

Как читать результат: при n · p = 2 (40 доставок, редкое событие) колокол занижает хвост на 27 %, при n · p = 4.8 — на 18 %, при 48 — на 9 %, при 480 — на 3 %. Отсюда практическое правило: **нормальным приближением пользуются, когда n · p ≥ 10 и n · (1 − p) ≥ 10** — и успехов, и неудач ожидается хотя бы по десятку. В A/B-тестах на тысячах гостей это выполняется с запасом; для доли жалоб по 40 заказам — нет, там считают точно через `binom`.

Пуассоновское распределение при большом $\lambda$ тоже становится похоже на колокол — со средним $\lambda$ и σ = $\sqrt{\lambda}$; то же правило: $\lambda$ от 10 и выше.

::: quiz
В кофейне за месяц 40 доставок, доля жалоб — 5 %. Аналитик оценивает вероятность «5 жалоб и больше» по нормальному приближению. Что не так?

- [x] Ожидается всего 40 × 0.05 = 2 жалобы — меньше десяти, колокол заметно занизит хвост; здесь нужен точный `binom.sf`
  > При n · p = 2 распределение сильно скошено вправо, а колокол симметричен. В примере выше ошибка — 27 %.
- [ ] Всё в порядке: нормальное приближение работает при любом n больше 30
  > Важен не сам размер n, а ожидаемое число успехов n · p. При редком событии и 40 попыток мало.
- [ ] Нормальное приближение для долей нельзя использовать никогда
  > Можно и нужно, когда n · p и n · (1 − p) не меньше 10, — на этом стоят z-тесты для конверсий.
- [ ] Надо было взять «5 и больше» как площадь правее 5.5
  > Поправка — в другую сторону: столбик «5» начинается с 4.5. Но главная беда не в поправке, а в малом n · p.
:::

::: warn Типичные ошибки
- **Без поправки на непрерывность.** «60 и больше» — `norm.sf(59.5, ...)`, а не `norm.sf(60, ...)`; иначе теряется половина столбика «60».
- **σ вместо дисперсии.** `scale` в `stats.norm` — стандартное отклонение √(n·p·(1−p)), а не n·p·(1−p).
- **Приближение при малом n · p.** Редкие события (жалобы, возвраты) на десятках заказов считайте точно через `binom` или `poisson`.
:::

## z-оценка

**z-оценка** показывает, на сколько стандартных отклонений значение отстоит от среднего:

$$
z = \frac{x - \text{среднее}}{\sigma}
$$

Она позволяет сравнивать несравнимое. Рекорд по числу доставок — 31 за день, рекорд по выручке доставки — 18 992 ₽. Что необычнее? Штуки и рубли напрямую не сравнить, а их z-оценки — можно:

```python
import pandas as pd
d = pd.read_csv("deliveries.csv", parse_dates=["created"])
by_day = d.groupby(d["created"].dt.date)
count = by_day.size()                 # доставок за день
revenue = by_day["amount"].sum()      # выручка доставки за день

z_count = (count - count.mean()) / count.std()
z_rev = (revenue - revenue.mean()) / revenue.std()
print("рекорд по доставкам:", count.idxmax(), count.max(), "z =", round(z_count.max(), 2))
print("рекорд по выручке:", revenue.idxmax(), revenue.max(), "z =", round(z_rev.max(), 2))
```

Как читать результат: 10 октября — 31 доставка, это 2.84σ выше среднего (20.6 в день); 6 сентября — 18 992 ₽, 2.72σ выше среднего (12 423 ₽). Оба дня необычны, но рекорд по доставкам чуть необычнее. И ещё деталь: в день-рекордсмен по доставкам выручка поднялась лишь на 1.96σ — заказы в тот день были мельче обычного.

$z$ больше 2 или меньше −2 — повод посмотреть на день внимательнее (для нормально распределённых данных такие дни встречаются примерно в 5 % случаев).

## Нормальны ли наши данные?

Нормальное распределение удобно, но реальные данные не обязаны ему подчиняться. Наложим на гистограмму времени доставки нормальную кривую с тем же средним и $\sigma$:

```python
import numpy as np
import pandas as pd
from scipy import stats
import matplotlib.pyplot as plt

d = pd.read_csv("deliveries.csv")
t = d.loc[d["actual_min"].between(1, 299), "actual_min"]
x = np.linspace(0, 100, 300)

fig, ax = plt.subplots(figsize=(8, 3.5))
ax.hist(t, bins=50, range=(0, 100), density=True, color="lightgray", label="данные")
ax.plot(x, stats.norm.pdf(x, t.mean(), t.std()), color="tab:red", label="нормальное")
ax.legend()
ax.set_title("Время доставки — не совсем нормальное")
```

Данные несимметричны: слева горб круче, справа хвост длиннее, чем у колокола. Нормальная модель недооценит долгие доставки — а именно они важны.

Для данных с хвостом вправо (время, деньги, расстояния) часто помогает логарифм: `np.log(t)` сжимает большие значения сильнее маленьких, и распределение становится ближе к симметричному.

::: warn Типичные ошибки
- **Плотность как вероятность.** `pdf(12)` — высота кривой, а не P(ровно 12 минут); вероятности — площади, `cdf`.
- **Нормальная модель для хвостатых данных.** Время и деньги часто скошены вправо — нормальная модель занизит долю долгих доставок.
:::

::: deep Почему нормальное распределение так популярно
Не потому, что все данные нормальны — это не так. А потому, что **средние** больших выборок почти всегда распределены нормально, даже если исходные данные — нет. Это центральная предельная теорема, и именно на ней стоят доверительные интервалы и статистические тесты. Урок «Выборки и центральная предельная теорема» — про неё.
:::

::: quiz
Время доставки скошено вправо. Аналитик оценил долю доставок дольше часа по нормальному распределению с тем же средним и σ, что у данных. Что получится?

- [x] Доля будет занижена: у колокола хвост тоньше, чем у настоящих данных
  > Нормальная модель симметрична и быстро «гаснет» вдали от среднего, а у времени доставки длинный правый хвост. Долгих доставок на деле больше, чем обещает колокол.
- [ ] Доля будет точной: среднее и σ подобраны по данным
  > Совпадают только центр и разброс, а форма — нет. Хвосты нормальная модель описывает плохо именно у скошенных данных.
- [ ] Доля будет завышена: нормальная модель всегда осторожнее данных
  > Для правого хвоста скошенных данных всё наоборот — модель недооценивает редкие долгие доставки.
- [ ] Ответ зависит только от размера выборки: на большой выборке данные станут нормальными
  > Сами данные с ростом выборки не становятся нормальными — нормальными становятся средние (об этом следующий урок).
:::

## task: norm-approx | Месяц большой кофейни | base

За месяц кофейня делает 500 доставок, p = 0.24. Сохраните `exact` — точную вероятность 140 и более опозданий (`binom`, 4 знака), `approx` — ту же вероятность по нормальному приближению с поправкой на непрерывность (4 знака), `rel_err` — относительную ошибку приближения `|approx − exact| / exact` (по неокруглённым числам, 3 знака) и `rule_ok` — `True`, если выполнено правило n·p ≥ 10 и n·(1 − p) ≥ 10 (посчитайте n·p и n·(1 − p) кодом из `n` и `p`).

### starter
```python
import math
from scipy import stats
n, p, k = 500, 0.24, 140

```

### check
```python
import math as _m
from scipy import stats as _st
_mu, _s = 500 * 0.24, _m.sqrt(500 * 0.24 * 0.76)
_e = _st.binom.sf(139, 500, 0.24)
_a = _st.norm.sf(139.5, _mu, _s)
assert close(need('exact'), round(_e, 4)), f'exact = {need("exact")}. «140 и больше» = binom.sf(139, n, p).'
ap = need('approx')
if close(ap, round(_st.norm.sf(140, _mu, _s), 4)):
    raise AssertionError('Это приближение без поправки. Столбик «140» начинается с 139.5 — возьмите norm.sf(k - 0.5, …).')
if close(ap, round(_st.norm.sf(139.5, _mu, _s ** 2), 4)):
    raise AssertionError('scale — это σ, а не дисперсия: σ = √(n·p·(1−p)).')
assert close(ap, round(_a, 4)), f'approx = {ap}. Нормальное со средним n·p и σ = √(n·p·(1−p)), правее k − 0.5.'
assert close(need('rel_err'), round(abs(_a - _e) / _e, 3), 0.0011), f'rel_err = {need("rel_err")}. |approx − exact| / exact по неокруглённым значениям.'
assert need('rule_ok') is True or need('rule_ok') == True, 'n·p = 120 и n·(1 − p) = 380 — оба не меньше 10, rule_ok должно быть True.'
assert not has_literal(120) and not has_literal(380), 'Посчитайте n·p и n·(1 − p) кодом, а не впишите числа.'
```

### hint
Среднее и σ — как у биномиального: `n * p` и `math.sqrt(n * p * (1 - p))`.

### hint
Точно: `stats.binom.sf(k - 1, n, p)`. Приближённо: `stats.norm.sf(k - 0.5, mu, sigma)`.

### hint
`rel_err = round(abs(a - e) / e, 3)`, где `e` и `a` — неокруглённые; `rule_ok = n * p >= 10 and n * (1 - p) >= 10`.

### solution
```python
import math
from scipy import stats
n, p, k = 500, 0.24, 140
mu = n * p
sigma = math.sqrt(n * p * (1 - p))
e = stats.binom.sf(k - 1, n, p)
a = stats.norm.sf(k - 0.5, mu, sigma)
exact = round(e, 4)
approx = round(a, 4)
rel_err = round(abs(a - e) / e, 3)
rule_ok = n * p >= 10 and n * (1 - p) >= 10
```

### explain
Точная вероятность — 0.0219, приближённая — 0.0206, ошибка около 6 %. Ожидается 120 опозданий и 380 доставок вовремя — правило выполнено с запасом, и для решения «такой месяц — редкость, около 2 %» приближения хватает. Без поправки на непрерывность вышло бы 0.0181 — ошибка уже 17 %. А если взять в `scale` дисперсию (91.2) вместо σ (9.55), колокол станет в десять раз шире, и вероятность выйдет абсурдной — около 0.4. Такие «странно большие» хвосты — верный признак перепутанного σ.

## task: pilot50 | Подозрительный пилот | base

Новая кофейня за первую неделю сделала 50 доставок, и 20 из них опоздали. Если бы она опаздывала так же, как сеть (p = 0.24), насколько редко такое случалось бы? Сохраните `expected` — ожидаемое число опозданий, `p_20plus` — вероятность 20 и более опозданий из 50 (4 знака) и `z` — z-оценку результата по формулам биномиального распределения (2 знака).

### starter
```python
from scipy import stats
n, p, observed = 50, 0.24, 20

```

### check
```python
from scipy import stats as _st
assert close(need('expected'), 12), f'expected = {need("expected")}. Среднее — n · p.'
assert close(need('p_20plus'), round(_st.binom.sf(19, 50, 0.24), 4), 0.00011), f'p_20plus = {need("p_20plus")}. «20 и более» = sf(19, …).'
zz = round((20 - 12) / (50 * 0.24 * 0.76) ** 0.5, 2)
assert close(need('z'), zz, 0.011), f'z = {need("z")}, а нужно {zz}.'
```

### hint
Ожидаемое — `n * p`. Хвост «20 и более» — `stats.binom.sf(19, n, p)`.

### hint
z = (наблюдение − среднее) / σ, где σ = √(n · p · (1 − p)).

### solution
```python
from scipy import stats
n, p, observed = 50, 0.24, 20
expected = n * p
p_20plus = round(stats.binom.sf(observed - 1, n, p), 4)
z = round((observed - expected) / (n * p * (1 - p)) ** 0.5, 2)
```

### explain
Ожидалось 12 опозданий, случилось 20 — на 2.6 стандартных отклонения больше. При обычной для сети частоте 20+ опозданий из 50 случаются примерно в 1 % недель. Это сильный сигнал, что у новой кофейни что-то не так (далёкие адреса, новый курьер), — но не доказательство: в сети из десятков кофеен раз в несколько недель такое случится и просто так. Как отличать сигнал от случайности строго — уроки «Проверка гипотез: логика и p-value»–6.

## task: tails | Хвост суммы заказа | plus

### hint
Кривая: `x = np.linspace(0, 2000, 300)`, `ax.plot(x, stats.norm.pdf(x, m, s))`; гистограмма — `ax.hist(a, bins=40, density=True)`.

### solution
```python
import numpy as np
import pandas as pd
from scipy import stats
import matplotlib.pyplot as plt

d = pd.read_csv("deliveries.csv")
a = d["amount"]
m, s = a.mean(), a.std()
tail = (a > m + 2 * s).mean()
real_tail = round(tail, 4)
normal_tail = round(stats.norm.sf(2), 4)
ratio = round(tail / stats.norm.sf(2), 1)

x = np.linspace(0, 2000, 300)
fig, ax = plt.subplots(figsize=(8, 3.5))
ax.hist(a, bins=40, density=True, color="lightgray")
ax.plot(x, stats.norm.pdf(x, m, s), color="tab:red")
```

### explain
Дорогих заказов (дороже 602 + 2 × 364 ≈ 1 330 ₽) в данных 5.3 %, а колокол обещает 2.3 % — в 2.3 раза меньше. У времени доставки тот же порог превышают 4.5 % доставок — хвост денег даже тяжелее. Слева же колокол ошибается в другую сторону: «среднее − 2σ» для денег отрицательно, и нормальная модель отводит почти 5 % заказов на суммы дешевле нуля. Деньги, время и расстояния почти всегда скошены вправо — поэтому выводы о них строят на квантилях, бутстрэпе или логарифме, а не на правиле 68–95–99.7.
