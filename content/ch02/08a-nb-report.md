## Блокнот, который читают

Зачем: блокнот читают руководитель, ревьюер и вы сами через месяц. Читают сверху вниз и останавливаются, как только становится непонятно. Если выводы спрятаны в выводе ячеек или в голове автора, до них никто не дочитает.

::: tip Аналогия
Блокнот-отчёт устроен как статья в деловой газете: заголовок, первый абзац о главном, разделы с подзаголовками и в конце — что из этого следует. Код в нём — как таблицы в приложении к статье: без них нельзя, но читают их не первыми. В отличие от газеты, читатель блокнота может перезапустить его и проверить каждую цифру. Это сила блокнота, если он воспроизводим.
:::

Скелет блокнота-отчёта:

| часть | что внутри | ячейки |
|---|---|---|
| `#` Заголовок и цель | бизнес-вопрос, какие данные, за какой период | markdown |
| `##` Данные | импорты, загрузка, первая проверка (`shape`, `head`, пропуски) | код + вывод |
| `##` Предобработка | что исправили и почему | код + вывод |
| `##` Анализ — по разделу на вопрос | расчёт, таблица или график | код + вывод |
| `##` Общий вывод | что сделали → что нашли (с цифрами) → что предлагаем | markdown |

Под «выводом» здесь понимается markdown-ячейка из 1–3 предложений **с числами** сразу после кода раздела.

Правила, которые проверяет любой ревьюер:

1. **Порядок ячеек = порядок чтения = порядок выполнения.** Ничего не используется раньше, чем создано.
2. **Одна ячейка — одно действие.** Загрузка, проверка и расчёт в одной ячейке на 40 строк — не читаются.
3. **Заголовки — через `#`, `##`, `###`, а не жирным текстом.** Из них JupyterLab строит оглавление (левая панель, значок списка).
4. **После каждого раздела — вывод с цифрами.** «Выручка выросла» — не вывод; «выручка ноября 256 198 ₽, +9.6 % к октябрю» — вывод.
5. **Не печатайте таблицу целиком.** `head()`, агрегаты, `value_counts()` — да; 2 089 строк заказов — нет.

### Разберём вместе: общий вывод из трёх частей

Общий вывод — последняя ячейка, а часто и единственная, которую прочитает руководитель. Удобная форма — три части:

- **Что сделали** — какие данные, за какой период, сколько строк;
- **Что нашли** — 2–4 факта с цифрами;
- **Что предлагаем** — действие или следующий вопрос.

Игрушечный пример. Плохой вывод: «Посчитали выручку, вроде растёт». В нём нет ни данных, ни цифр, ни действия. Хороший вывод собираем из трёх частей по шагам:

1. Что сделали: 2 089 заказов, 6 кофеен, сентябрь–ноябрь.
2. Что нашли: выручка ноября — 256 198 ₽, это +9.6 % к октябрю; заказов стало больше на 5.4 %, средний чек вырос на 4.0 %.
3. Что предлагаем: проверить, сохранится ли рост чека после сезона, — сравнить декабрь с ноябрём.

Цифры в таком выводе не вписывают руками, а собирают из посчитанных переменных — тогда при новой выгрузке текст обновится сам:

```python
import pandas as pd
df = pd.read_csv("orders_3m.csv", parse_dates=["datetime"])

m = df.groupby(df["datetime"].dt.to_period("M"))["amount"].agg(["sum", "size", "mean"])
growth = (m.iloc[-1] / m.iloc[-2] - 1) * 100       # ноябрь к октябрю, в процентах

conclusion = (
    f"**Что сделали:** разобрали {len(df)} заказов {df['shop_id'].nunique()} кофеен за сентябрь–ноябрь.\n"
    f"**Что нашли:** выручка ноября — {m['sum'].iloc[-1]} ₽, {growth['sum']:+.1f} % к октябрю; "
    f"заказов {growth['size']:+.1f} %, средний чек {growth['mean']:+.1f} %.\n"
    f"**Что предлагаем:** сравнить декабрь с ноябрём — сохранится ли рост чека после сезона."
)
print(conclusion)
```

Что здесь происходит:

- `agg(["sum", "size", "mean"])` — по месяцам сразу выручка, число заказов и средний чек;
- `m.iloc[-1] / m.iloc[-2] - 1` делит строку последнего месяца на предпоследний — сразу для трёх столбцов; результат — Series с процентами;
- `{growth['sum']:+.1f}` — формат «со знаком и одним знаком после точки»: `+9.6`;
- `\n` переносит строку: `print` выведет три строки.

Как показать такой вывод **как markdown** — с жирным шрифтом и абзацами, — а не как простой текст? В своём Jupyter для этого есть `Markdown` из модуля `IPython.display` (IPython — «движок» Jupyter, он стоит вместе с ним):

```python static
from IPython.display import Markdown
Markdown(conclusion.replace("\n", "\n\n"))   # последняя строка ячейки — Jupyter покажет её как markdown
```

- `Markdown(текст)` — объект «покажи этот текст как markdown». Как и любое последнее выражение ячейки, он выводится под ней.
- `.replace("\n", "\n\n")` нужен потому, что в markdown одиночный перенос склеивает строки в один абзац; новый абзац начинается после пустой строки.

В браузере курса IPython нет, поэтому здесь этот пример не запускается — в задачах достаточно собрать строку.

::: predict
```python static
growth = 9.63
print(f"{growth:+.1f} %")
```

- `9.6 %`
- [x] `+9.6 %`
- `+9.63 %`

Почему: `+` в формате печатает знак и у положительных чисел, `.1f` оставляет один знак после точки, а 9.63 округляется до 9.6.
:::

Как читать результат: в одной ячейке руководитель видит масштаб данных, два рычага роста (заказы и чек) и следующий шаг. Никаких «вроде».

::: warn Типичные ошибки
- **Вывод описывает действие, а не находку.** «Сгруппировали по месяцам» → «в ноябре +9.6 %».
- **Цифры вписаны руками и устарели.** Так в черновике `zerno_draft.ipynb` из прошлого урока и появилось «710 195 ₽ доставки». Собирайте текст из переменных.
- **Заголовки жирным шрифтом.** `**Анализ**` оглавление не видит; нужен `## Анализ`.
- **Свалка в конце блокнота.** Неудачные попытки и закомментированный код удаляют, а не оставляют «на всякий случай» (для истории есть git — урок «Git: коммиты, история, ветки и .gitignore»).
:::

## Хорошие привычки

Зачем: блокнот-отчёт живёт дольше, чем кажется. Его перезапускают на новой выгрузке, открывают у коллеги, дописывают через месяц. Четыре привычки экономят часы на каждом таком шаге:

- **Импорты и загрузка данных — в первых ячейках**, чтобы было видно, откуда всё берётся.
- **Пути — относительные**: `pd.read_csv("data/orders_3m.csv")`, а не `/Users/имя/...`. Тогда проект запустится у коллеги (как собирать пути через `pathlib` — в прошлом уроке).
- **Не храните результаты только в голове**: короткий вывод текстом после каждого раздела.
- **Блокнот — не свалка**: неудавшиеся эксперименты удаляйте, повторяющийся код выносите в функции.

### Функция вместо копий ячейки

Типичная картина черновика: три ячейки подряд считают одно и то же для PRM-1, KZN-1 и UFA-1, и отличаются копии только кодом кофейни. Исправили формулу в одной — две другие молча считают по-старому, и в выводах появляются числа, посчитанные по-разному.

::: tip Аналогия
Копии ячейки — как три одинаковые формулы в Excel, набранные руками в разных листах: поправите одну и забудете про остальные. Функция — как одна формула, протянутая на все строки: правка в одном месте меняет всё.
:::

Лечится функцией в отдельной ячейке и одной строкой вызова на каждую кофейню:

```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")

def revenue_share(df, shop_id):
    """Доля кофейни в выручке сети, %."""
    shop = df.loc[df["shop_id"] == shop_id, "amount"].sum()
    return round(shop / df["amount"].sum() * 100, 1)

for shop_id in ["PRM-1", "KZN-1", "UFA-1"]:
    print(shop_id, revenue_share(df, shop_id))
```

Что здесь происходит:

- `def revenue_share(df, shop_id)` — расчёт описан один раз; таблица и код кофейни приходят параметрами, поэтому функция работает и с другой выгрузкой.
- Строка в тройных кавычках — описание функции (глава 1): его покажет `revenue_share?` в Jupyter.
- Цикл `for` заменяет три копии ячейки: чтобы добавить кофейню, достаточно дописать её код в список.

::: predict
```python static
def share(part, total):
    return round(part / total * 100, 1)

print(share(25, 200), share(1, 3))
```

- `0.125 0.333`
- [x] `12.5 33.3`
- `12.5 0.3`

Почему: функция умножает долю на 100 и округляет до одного знака: 25 / 200 = 0.125 → 12.5, 1 / 3 ≈ 0.333 → 33.3.
:::

::: warn Типичные ошибки
- **Функция читает глобальную таблицу, а не параметр.** Если внутри написать `df_oct[...]` вместо параметра `df`, функция «работает», но всегда по октябрю — что бы ей ни передали.
- **Функция объявлена ниже первого вызова.** После Restart & Run All ячейка с вызовом упадёт с `NameError`: ячейку с `def` ставят выше всех, кто её использует.
- **Функция печатает, но не возвращает.** `print` внутри функции нельзя положить в таблицу или в текст вывода; нужен `return` (урок «Функции» главы 1).
:::

## task: md-report | Вывод для markdown-ячейки | base

Блокнот читают как отчёт. Соберите строку `report` — три строки текста для markdown-ячейки по данным `orders_3m.csv`:

```text
**Выручка:** 710195 ₽
**Заказов:** 2089
**Средний чек:** 339.97 ₽
```

Числа должны считаться из таблицы, а не вписываться руками. Строки разделены символом `\n`.

### starter
```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")

```

### check
```python
import pandas as _pd
a = _pd.read_csv('orders_3m.csv')['amount']
want = f"**Выручка:** {a.sum()} ₽\n**Заказов:** {len(a)}\n**Средний чек:** {round(a.mean(), 2)} ₽"
assert need('report') == want, f'report = {need("report")!r}, а нужно {want!r}.'
assert '710195' not in _code, 'Не вписывайте числа руками — считайте из df.'
```

### hint
Три f-строки, склеенные через `"\n"`: `f"**Выручка:** {df['amount'].sum()} ₽"` и так далее.

### hint
Средний чек — `round(df["amount"].mean(), 2)`; число заказов — `len(df)`.

### solution
```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")
revenue = df["amount"].sum()
report = (f"**Выручка:** {revenue} ₽\n"
          f"**Заказов:** {len(df)}\n"
          f"**Средний чек:** {round(df['amount'].mean(), 2)} ₽")
```

### explain
Текст отчёта, собранный из данных, пересчитывается сам при новой выгрузке — никто не забудет обновить цифру в абзаце. В своём Jupyter такую строку показывают через `Markdown(report)` из `IPython.display` (пример — в разделе «Блокнот, который читают»), и она выглядит как обычный текст отчёта.

## task: conclusion | Общий вывод из трёх частей | base

Три части отвечают на три вопроса читателя: «на чём основано?», «что важного?», «что делать?». def has_conclusion(last):
```python
    return last is not None and last[0] == "markdown" and not last[1].startswith("#")

def missing_conclusions(cells):
    result, title, last = [], None, None
    for kind, text in cells:
        if kind == "markdown" and text.startswith("## "):
```

```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")

def shop_kpi(df, shop_id):
    t = df[df["shop_id"] == shop_id]["amount"]
    return {"orders": len(t), "revenue": t.sum(), "avg_check": round(t.mean(), 1)}

rows = []
for shop in df["shop_id"].unique():
    row = shop_kpi(df, shop)          # словарь одной кофейни
    row["shop_id"] = shop
    rows.append(row)
kpi = pd.DataFrame(rows).set_index("shop_id")
best_check = kpi["avg_check"].idxmax()
kpi
```

### explain
Лучший средний чек — у PRM-1 (355.3 ₽). Функция, написанная один раз, превратила три копии кода в один цикл. Есть и короче: словарь словарей `pd.DataFrame({shop: shop_kpi(df, shop) for shop in ...})`. Но в нём внешние ключи становятся **столбцами**, и таблицу приходится перевернуть `.T` — транспонирование, строки и столбцы меняются местами, как ТРАНСП в Excel. Забыли `.T` — `kpi.loc["UFA-1"]` упадёт с `KeyError`: кофейни ещё в столбцах. И ещё одна мелочь: в словаре словарей столбцом сначала была кофейня, а в ней лежат и целые, и дробные числа. Поэтому после `.T` все столбцы становятся дробными: 524 заказа превратятся в `524.0`. У списка словарей этих ловушек нет: каждый столбец сохраняет свой тип. Тот же отчёт даёт и `groupby(...).agg(...)` — в pandas почти всегда есть короткий путь, но функция полезна, когда расчёт сложнее одного агрегата.
