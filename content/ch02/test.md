**До выбора вариантов.** Выручку сгруппировали по кодам магазинов, а справочник магазинов отсортирован по названию. Как перенести выручку в справочник так, чтобы она попала к нужному магазину? Объясните до просмотра вариантов.

::: quiz 01-dataframe
Что вернёт `df.shape` для таблицы из 2089 заказов и 9 столбцов?

- [x] `(2089, 9)`
  > `shape` — атрибут без скобок: сначала строки, потом столбцы.
- [ ] `2089`
  > Это `len(df)` — только число строк.
- [ ] `(9, 2089)`
  > Порядок другой: строки идут первыми.
- [ ] `(2089, 9, 1)`
  > У DataFrame две оси: строки и столбцы. Третья координата в shape здесь лишняя.
:::

::: quiz 02-select
Чем `df[df["channel"].isin(["доставка", "с собой"])]` удобнее двух условий через `|`?

- [x] Проверка вхождения в список вместо цепочки «или»
  > `isin` принимает список значений и даёт маску: True там, где значение из списка.
- [ ] Автоматически исключает пропуски во всей таблице
  > Пропуск не входит в список ни в одном из способов.
- [ ] Заодно сортирует результат по выбранному столбцу
  > Порядок строк не меняется.
- [ ] Позволяет фильтровать там, где `|` недопустим
  > Можно, просто длиннее: `(… == "доставка") | (… == "с собой")`.
:::

::: quiz 03-columns
`df.sort_values("amount", ascending=False).head(5)` — что получится?

- [x] Пять самых дорогих заказов
  > Сортировка по убыванию, затем первые пять строк — аналог `ORDER BY amount DESC LIMIT 5`.
- [ ] Пять самых дешёвых заказов
  > Для этого `ascending=True` (по умолчанию).
- [ ] Первые пять строк в исходном порядке
  > `head` берёт первые строки уже отсортированной таблицы.
- [ ] Таблица `df` изменится навсегда
  > `sort_values` возвращает новую таблицу; `df` прежняя, пока не присвоите результат.
:::

::: quiz 04-groupby
Чем `size()` отличается от `count()` после `groupby`?

- [x] `size` — строки; `count` — без пропусков
  > Если в столбце есть пропуски, цифры разойдутся. Число заказов — `size()`.
- [ ] Оба метода считают только непустые значения
  > При пропусках результаты разные.
- [ ] `size` — строки, `count` — разные значения
  > Уникальные — `nunique()`.
- [ ] `size` — группы, `count` — строки таблицы
  > После группировки оба возвращают значения по группам.
:::

::: quiz 04a-guest-metrics
Доля повторных гостей за три месяца — 97.3 %, а за один сентябрь — 59.2 %. Что из этого следует?

- [x] Из разных окон ухудшение возвратности не следует
  > Доля повторных всегда пишется с периодом. За квартал почти любой владелец карты зайдёт дважды, за месяц — нет.
- [ ] В сентябре возвратность гостей заметно ухудшилась
  > Сравниваются разные окна: квартал и месяц. Для вывода о сентябре нужна доля за другой месяц.
- [ ] Разница окон не влияет: одна из долей ошибочна
  > Может и должна: знаменатель и окно разные.
- [ ] Общий показатель возвратности — среднее двух долей
  > Среднее двух долей за разные окна не отвечает ни на один вопрос.
:::

::: quiz 04b-pivot
`pd.pivot_table(df, index="shop_id", columns="channel", values="amount")` — что окажется в ячейках?

- [x] Среднее значение `amount`

- [ ] Сумма значений `amount`
  > Сумма будет только с `aggfunc="sum"`.
- [ ] Количество значений `amount`
  > Для числа заказов нужен `aggfunc="count"` или `"size"`.
- [ ] Ошибка из-за отсутствия `aggfunc`
  > Параметр необязательный: без него pandas считает среднее.
:::

::: quiz 06-dates
Зачем `pd.to_datetime` для столбца с датой из CSV?

- [x] Для календарных частей даты и сравнения периодов
  > Текстовые даты из CSV нужно преобразовать в datetime — через parse_dates при чтении или to_datetime после него. Тогда доступны календарные части даты и операции с периодами.

  > Нужен для любых дат.

::: quiz 06b-timezones
В выгрузке приложения столбец `ts` — числа вида `1791167205892`. Как получить местное время пермской кофейни (UTC+5)?

- [x] `pd.to_datetime(ts, unit="ms", utc=True).dt.tz_convert("+05:00")`
  > 13 цифр — миллисекунды. Unix-время всегда в UTC: сначала приписываем пояс UTC, потом переводим.
- [ ] `pd.to_datetime(ts, unit="s", utc=True).dt.tz_convert("+05:00")`
  > Здесь исходное Unix-время задано в миллисекундах, не секундах. utc=True задаёт пояс правильно, но не исправляет неверную единицу.
- [ ] `pd.to_datetime(ts, unit="ms").dt.tz_localize("+05:00")`
  > `tz_localize` не сдвигает часы, а только подписывает пояс: время UTC объявлено пермским, момент сдвинут на 5 часов.
- [ ] `pd.to_datetime(ts, unit="ms", utc=True).dt.tz_convert("UTC")`
  > Эта цепочка оставляет время в UTC. Для местного времени Перми нужен перевод в UTC+5.
:::

::: quiz 07-duckdb
Нужна выручка сети одним числом: `duckdb.sql("SELECT SUM(amount) FROM df")`. Как достать из результата само число?

- [ ] Вызвать `.fetchone()`
  > Он возвращает строку результата — кортеж, пусть и из одного значения.
- [ ] Использовать результат `duckdb.sql` напрямую
  > `duckdb.sql` возвращает объект-результат; его ещё нужно «достать» одним из методов.

::: quiz 07s-subqueries-cte
Запрос `SELECT COUNT(DISTINCT client_id) FROM df WHERE client_id NOT IN (SELECT client_id FROM df WHERE channel = 'доставка')` вернул 0, хотя гости без доставок точно есть. Почему?

- [x] `NULL` в подзапросе меняет результат `NOT IN`
  > `NOT IN` раскрывается в цепочку `<>` через `AND`, и одно «неизвестно» отбрасывает каждую строку. Лечится `AND client_id IS NOT NULL` в подзапросе или `NOT EXISTS`.
- [ ] `COUNT(DISTINCT …)` несовместим с подзапросом
  > Работает: дело в содержимом списка, а не в агрегате.
- [ ] Подзапрос допустим только в секции `FROM`
  > Список значений в `WHERE … IN (…)` — обычное место для подзапроса.
- [ ] Условие по клиенту должно стоять в `HAVING`
  > `HAVING` фильтрует группы, а здесь условие на отдельные заказы.
:::

::: quiz 07a-sql-python
`pd.read_sql_query("SELECT * FROM shops WHERE city = ?", con, params=("Казань"))` падает с `Incorrect number of bindings supplied`. Что исправить?

- [x] Передать кортеж `params=("Казань",)`
  > Без запятой это просто строка в скобках; SQLite перебирает её по буквам и видит шесть значений на один `?`.

- [ ] Передать строку города: `params="Казань"`
  > Строка — последовательность символов, а нужен один параметр. Передайте кортеж из одного элемента: ("Казань",).
- [ ] Передать пустой кортеж: `params=()`
  > Пустой кортеж не содержит значения для единственного плейсхолдера ?.

::: quiz 07b-sql-windows
SQL-запрос с `LAG(revenue) OVER (PARTITION BY shop_id ORDER BY month)` дал правильный рост месяц к месяцу, а «тот же» расчёт в pandas `m.groupby("shop_id")["revenue"].shift(1)` — странные цифры. Какая причина самая вероятная?

- [x] `shift` использует порядок строк, не сортировку по месяцу
  > У `LAG` порядок — часть окна (`ORDER BY month`). У `shift` своего порядка нет, поэтому перед ним нужен `sort_values(["shop_id", "month"])`.
- [ ] В pandas положительный сдвиг берёт следующий месяц
  > `shift(1)` сдвигает значения вниз: в строке оказывается значение из предыдущей. Следующую дал бы `shift(-1)`.
- [ ] В pandas сдвиг не поддерживает разбиение на группы
  > Можно: `groupby(...).shift` сдвигает внутри каждой группы и не перескакивает между ними.
- [ ] В pandas пропуск первого месяца заменяется нулём
  > В обоих случаях у первого месяца пусто: `NaN` в pandas и `NULL` в SQL.
:::

  > Причинный вывод из наблюдения. Если удержание объясняется тем, кто выбирает приложение, перевод остальных его не поднимет.

  > Когорты одинаковые по месяцам, но доли вернувшихся внутри них у источников разные.
