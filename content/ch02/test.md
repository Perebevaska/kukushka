::: quiz 01-dataframe
Что вернёт `df.shape` для таблицы из 2089 заказов и 9 столбцов?

- [x] `(2089, 9)` — число строк и число столбцов
  > `shape` — атрибут без скобок: сначала строки, потом столбцы.
- [ ] `2089`
  > Это `len(df)` — только число строк.
- [ ] `(9, 2089)`
  > Порядок другой: строки идут первыми.
- [ ] Ошибку: нужно `df.shape()`
  > `shape` — атрибут, а не метод; скобки вызовут ошибку.
:::

::: quiz 02-select
Чем `df[df["channel"].isin(["доставка", "с собой"])]` удобнее двух условий через `|`?

- [x] Одна проверка вместо цепочки «или»: это аналог `IN (...)` в SQL
  > `isin` принимает список значений и даёт маску: True там, где значение из списка.
- [ ] Только `isin` учитывает пропуски
  > Пропуск не входит в список ни в одном из способов.
- [ ] `isin` сортирует результат
  > Порядок строк не меняется.
- [ ] С `|` такой фильтр написать нельзя
  > Можно, просто длиннее: `(… == "доставка") | (… == "с собой")`.

- [ ] Первые пять строк в исходном порядке

::: quiz 04-groupby
Чем `size()` отличается от `count()` после `groupby`?

- [x] `size()` считает все строки группы, `count()` — только непустые значения столбца
  > Если в столбце есть пропуски, цифры разойдутся. Число заказов — `size()`.
- [ ] Ничем, это синонимы
  > При пропусках результаты разные.
- [ ] `count()` считает уникальные значения
  > Уникальные — `nunique()`.
- [ ] `size()` возвращает таблицу, а `count()` — число
  > После группировки оба возвращают значения по группам.
:::

::: quiz 06b-timezones
В выгрузке приложения столбец `ts` — числа вида `1791167205892`. Как получить местное время пермской кофейни (UTC+5)?

- [x] `pd.to_datetime(ts, unit="ms")`, затем `.dt.tz_localize("UTC").dt.tz_convert("+05:00")`
  > 13 цифр — миллисекунды. Unix-время всегда в UTC: сначала приписываем пояс UTC, потом переводим.
- [ ] `pd.to_datetime(ts, unit="s")`, затем `.dt.tz_convert("+05:00")`
  > С `unit="s"` получится 58729 год, а `tz_convert` у времени без пояса падает с ошибкой.
- [ ] `pd.to_datetime(ts, unit="ms").dt.tz_localize("+05:00")`
  > `tz_localize` не сдвигает часы, а только подписывает пояс: время UTC объявлено пермским, момент сдвинут на 5 часов.
- [ ] Ничего не делать: сервер пишет время по местным часам кофейни
  > Сервер один на все города и пишет время в UTC.

::: quiz 07-duckdb
Нужна выручка сети одним числом: `duckdb.sql("SELECT SUM(amount) FROM df")`. Как достать из результата само число?

- [x] `.fetchone()[0]` — первая строка кортежем, из неё первое значение

- [ ] `.df()` — результат сразу станет числом
  > `.df()` всегда даёт DataFrame, даже из одной строки и одного столбца.
- [ ] `.fetchone()` — он и есть число
  > Он возвращает строку результата — кортеж, пусть и из одного значения.
- [ ] Ничего не нужно: `duckdb.sql` возвращает число
  > `duckdb.sql` возвращает объект-результат; его ещё нужно «достать» одним из методов.

::: quiz 07s-subqueries-cte
Запрос `SELECT COUNT(DISTINCT client_id) FROM df WHERE client_id NOT IN (SELECT client_id FROM df WHERE channel = 'доставка')` вернул 0, хотя гости без доставок точно есть. Почему?

- [x] Среди доставок есть заказы без карты: в списке подзапроса оказался `NULL`, а сравнение с `NULL` даёт «неизвестно»
  > `NOT IN` раскрывается в цепочку `<>` через `AND`, и одно «неизвестно» отбрасывает каждую строку. Лечится `AND client_id IS NOT NULL` в подзапросе или `NOT EXISTS`.
- [ ] `COUNT(DISTINCT …)` не работает с подзапросами
  > Работает: дело в содержимом списка, а не в агрегате.
- [ ] Подзапрос должен стоять в `FROM`, а не в `WHERE`
  > Список значений в `WHERE … IN (…)` — обычное место для подзапроса.
- [ ] Нужно `HAVING` вместо `WHERE`
  > `HAVING` фильтрует группы, а здесь условие на отдельные заказы.
:::

::: quiz 07b-sql-windows
SQL-запрос с `LAG(revenue) OVER (PARTITION BY shop_id ORDER BY month)` дал правильный рост месяц к месяцу, а «тот же» расчёт в pandas `m.groupby("shop_id")["revenue"].shift(1)` — странные цифры. Какая причина самая вероятная?

- [x] Таблица `m` не отсортирована по месяцу: `shift` берёт соседнюю строку таблицы, а в SQL порядок задан внутри окна

- [ ] `shift(1)` берёт следующую строку, а не предыдущую
  > `shift(1)` сдвигает значения вниз: в строке оказывается значение из предыдущей. Следующую дал бы `shift(-1)`.
- [ ] В pandas нельзя сдвигать внутри групп
  > Можно: `groupby(...).shift` сдвигает внутри каждой группы и не перескакивает между ними.
- [ ] В pandas у первого месяца будет 0, а в SQL — `NULL`
  > В обоих случаях у первого месяца пусто: `NaN` в pandas и `NULL` в SQL.
:::
