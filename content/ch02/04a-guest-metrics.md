## Метрики на гостя: выручка на гостя, повторные, конверсия

В уроке «Группировки: GROUP BY и HAVING» знаменателем были **заказы**: выручка на заказ — средний чек. Но руководителя сети часто интересует другой вопрос — сколько приносит **один гость** и возвращается ли он. Средний чек может расти, пока гостей становится меньше; выручка на гостя и доля повторных это покажут. Для таких метрик сначала собирают таблицу «одна строка — один гость», а уже потом считают по ней.

::: tip Аналогия
Средний чек — сколько гость тратит за один визит в магазин. Выручка на гостя — сколько он потратил за квартал. Один и тот же человек может брать дешёвый кофе, но заходить каждый день — и приносить больше, чем любитель дорогого рафа раз в месяц.
:::

**Пример руками.** Шесть заказов трёх гостей с картой:

| гость | заказы | сумма |
|---|---|---|
| A | 300, 400 | 700 |
| B | 250 | 250 |
| C | 500, 200, 350 | 1 050 |

1. **Средний чек** — на заказ: 2 000 / 6 = **333.33**.
2. **Выручка на гостя** (её часто называют ARPU — *average revenue per user*) — та же выручка, но делим на гостей: 2 000 / 3 = **666.67**.
3. **Заказов на гостя** — 6 / 3 = **2**.
4. **Доля повторных гостей** — гости, сделавшие хотя бы два заказа: A и C, 2 из 3 = **66.7 %**.

::: figure per-guest
Шесть заказов сворачиваются в таблицу «одна строка — один гость», и метрики на гостя считаются уже по ней. Средний чек — по исходным заказам.
:::

Код повторяет эти шаги: сначала `groupby` по гостю — таблица «гость → заказы, выручка», потом обычные агрегаты по ней:

```python
import pandas as pd
t = pd.DataFrame({"client_id": ["A", "A", "B", "C", "C", "C"],
                  "amount": [300, 400, 250, 500, 200, 350]})

per_guest = t.groupby("client_id").agg(orders=("amount", "size"), revenue=("amount", "sum"))
print(per_guest)
print("средний чек:", round(t["amount"].mean(), 2))
print("выручка на гостя:", round(per_guest["revenue"].mean(), 2))
print("доля повторных:", round((per_guest["orders"] >= 2).mean(), 3))
```

Что здесь происходит:

- `per_guest` — промежуточная таблица, по строке на гостя. Это главный шаг: все «метрики на гостя» считаются по ней, а не по заказам.
- `per_guest["revenue"].mean()` — среднее по гостям, то есть сумма выручки, делённая на число гостей.
- `(per_guest["orders"] >= 2).mean()` — знакомый приём: среднее от True/False — доля True.

**На реальных данных.** В `orders_3m.csv` гость известен только у заказов по карте лояльности — их и берём:

```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")

loyal = df[df["client_id"].notna()]
per_guest = loyal.groupby("client_id").agg(orders=("order_id", "count"),
                                           revenue=("amount", "sum"))
print("гостей:", len(per_guest))
print("выручка на гостя за 3 месяца:", round(per_guest["revenue"].mean(), 2))
print("заказов на гостя:", round(per_guest["orders"].mean(), 2))
print("доля повторных:", round((per_guest["orders"] >= 2).mean(), 3))
```

Как читать: 260 гостей с картой принесли в среднем по 1 645.96 ₽ за три месяца, 4.8 заказа на человека. Доля повторных — 97.3 %, но не обольщайтесь: за длинный период почти любой владелец карты успеет зайти дважды. Доля повторных зависит от окна: внутри одного сентября она уже 57.6 % (118 из 205 гостей). Поэтому в отчёте всегда пишут период: «доля повторных за месяц».

### Конверсия

**Конверсия** — доля тех, кто сделал целевое действие, среди тех, кто мог его сделать. Знаменатель — все, кто «вошёл в воронку», числитель — дошедшие до цели. Например: из всех зарегистрированных в программе лояльности — доля сделавших хотя бы один заказ.

Пример руками: зарегистрировались 4 гостя — A, B, C, D; заказы есть у A и C. Конверсия = 2 / 4 = **50 %**. Кодом — тот же приём «среднее от True/False», а True/False даёт `isin`: есть ли гость среди заказавших.

В базе программы лояльности «Зерна» (`zdb_guests.csv` — регистрации, `zdb_orders.csv` — заказы за март–август) посчитаем конверсию в первый заказ и сравним источники регистрации:

```python
import pandas as pd
guests = pd.read_csv("zdb_guests.csv")
orders = pd.read_csv("zdb_orders.csv")

guests["ordered"] = guests["guest_id"].isin(orders["guest_id"])   # True, если заказ был
print("конверсия в заказ:", round(guests["ordered"].mean(), 3))
guests.groupby("source")["ordered"].agg(["mean", "sum", "size"]).round(3)
```

Что здесь происходит:

- `isin(orders["guest_id"])` — для каждого зарегистрированного гостя: встречается ли он в заказах. Получается столбец True/False.
- `mean()` по нему — конверсия, 0.946: из 1 510 зарегистрированных заказали 1 429.
- `groupby("source")` — та же конверсия отдельно по источнику: `mean` — доля, `sum` — сколько заказали, `size` — сколько зарегистрировалось.

Как читать: у кассы конверсия 100 % — и это не успех, а особенность процесса: на кассе карту оформляют в момент покупки, заказ есть всегда. У приложения 87.5 %: 81 гость из 646 скачал приложение, зарегистрировался и так ничего и не заказал. Вот где искать рост.

::: deep HEART: из чего собирают метрики продукта
Метрики на гостя удобно раскладывать по полкам. Одна из известных схем — HEART, её описали исследователи Google в 2010 году: пять букв — пять вопросов о продукте. Вот как они могли бы выглядеть для приложения «Зерна»:

| буква | вопрос | метрика «Зерна» |
|---|---|---|
| H — Happiness | довольны ли гости? | средняя оценка заказа в приложении |
| E — Engagement | как часто пользуются? | заказов на гостя за месяц |
| A — Adoption | начинают ли пользоваться? | конверсия регистрации в первый заказ |
| R — Retention | возвращаются ли? | доля повторных за месяц |
| T — Task success | получается ли то, ради чего пришли? | доля заказов, выданных к обещанному времени |

Все пять сразу считать не обязательно: берут те полки, которые относятся к задаче, и для каждой заранее договариваются, какое значение считать хорошим.
:::

### Чьё это среднее: заказа, гостя или кофейни

Одно слово «средний» прячет разные знаменатели. Две кофейни: в A — четыре заказа по 300 ₽ (1 200 ₽), в B — один заказ на 600 ₽.

| метрика | знаменатель | расчёт | значение |
|---|---|---|---|
| средний чек сети | заказы | 1 800 / 5 | **360** |
| средняя выручка кофейни | кофейни | 1 800 / 2 | **900** |
| среднее средних чеков кофеен | кофейни | (300 + 600) / 2 | **450** |

Все три числа «правильные» — это ответы на разные вопросы. Ошибка — подписать одно, а посчитать другое. На наших данных: средний чек — 339.97 ₽ (на заказ), средняя выручка кофейни за три месяца — 118 365.83 ₽, выручка на гостя с картой — 1 645.96 ₽.

```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")

print("на заказ:", round(df["amount"].sum() / len(df), 2))
print("на кофейню:", round(df["amount"].sum() / df["shop_id"].nunique(), 2))
print("на гостя с картой:", round(df.loc[df["client_id"].notna(), "amount"].sum() / df["client_id"].nunique(), 2))
```

Правило: в подписи метрики называйте знаменатель — «на заказ», «на гостя за месяц», «на кофейню».

::: warn Типичные ошибки
- **Выручка на гостя по заказам.** `df["amount"].mean()` — средний чек, а не выручка на гостя. Сначала `groupby` по гостю, потом среднее.
- **Гости без карты в знаменателе.** Заказы без `client_id` нельзя отнести к гостю. `nunique()` их пропустит, а `len(df)` — нет: делите выручку **гостей с картой** на число гостей с картой.
- **Конверсия без периода и знаменателя.** «Конверсия 87 %» — из кого в что и за какой срок? Пишите: «из регистраций в приложении в первый заказ, март–август».
- **Доля повторных за разные окна.** За три месяца она всегда выше, чем за месяц: сравнивайте только одинаковые окна.
:::

::: quiz
В отчёте написано: «средняя выручка на гостя — 340 ₽». Посчитано как `df["amount"].mean()`. Что не так?

- [x] Это средний чек — среднее по заказам; выручка на гостя считается после группировки по гостю
  > `mean()` по столбцу заказов делит выручку на число заказов. У гостя в среднем 4.8 заказа, и выручка на гостя — около 1 646 ₽, почти в пять раз больше.
- [ ] Всё верно: каждый заказ сделал какой-то гость
  > Да, но гость делает несколько заказов. Знаменатель «заказы» и знаменатель «гости» дают разные числа.
- [ ] Надо было взять медиану вместо среднего
  > Медиана тоже посчитается по заказам. Ошибка в знаменателе, а не в виде среднего.
- [ ] Надо было разделить на число кофеен
  > Тогда получится средняя выручка кофейни — третья, другая метрика.
:::

## task: per-guest | Выручка на гостя | base

По заказам гостей с картой лояльности (`client_id` не пустой) посчитайте:

- `arpu` — среднюю выручку на гостя за три месяца, округлённую до двух знаков;
- `orders_per_guest` — среднее число заказов на гостя, тоже до двух знаков.

### starter
```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")

```

### check
```python
import pandas as _pd
_d = _pd.read_csv('orders_3m.csv')
_l = _d[_d['client_id'].notna()]
_pg = _l.groupby('client_id').agg(orders=('order_id', 'count'), revenue=('amount', 'sum'))
_a = round(_pg['revenue'].mean(), 2)
_o = round(_pg['orders'].mean(), 2)
_got = need('arpu')
assert not close(_got, round(_d['amount'].mean(), 2), 0.01), f'arpu = {_got} — это средний чек: среднее по заказам. Сначала сгруппируйте заказы по гостю.'
assert close(_got, _a, 0.01), f'arpu = {_got}, а нужно {_a}. Выручка гостей с картой, делённая на число гостей.'
assert close(need('orders_per_guest'), _o, 0.01), f'orders_per_guest = {need("orders_per_guest")}, а нужно {_o}.'
```

### hint
Сначала таблица «одна строка — один гость»: оставьте заказы с картой и сгруппируйте по `client_id`. Метрики на гостя считаются по ней.

### hint
`per_guest = loyal.groupby("client_id").agg(orders=("order_id", "count"), revenue=("amount", "sum"))`, где `loyal = df[df["client_id"].notna()]`.

### hint
```python
loyal = df[df["client_id"].notna()]
per_guest = loyal.groupby("client_id").agg(orders=(..., "count"), revenue=(..., "sum"))
arpu = round(per_guest["revenue"].mean(), 2)
orders_per_guest = round(per_guest[...].mean(), 2)
```

### solution
```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")
loyal = df[df["client_id"].notna()]
per_guest = loyal.groupby("client_id").agg(orders=("order_id", "count"),
                                           revenue=("amount", "sum"))
arpu = round(per_guest["revenue"].mean(), 2)
orders_per_guest = round(per_guest["orders"].mean(), 2)
```

### explain
Гость с картой приносит за три месяца 1 645.96 ₽ и делает 4.8 заказа. Обратите внимание, что 1 645.96 ≈ 343.18 × 4.8: выручка на гостя — это средний чек его заказов, умноженный на частоту. Отсюда два рычага роста — чек и частота. Типичная ошибка — `loyal["amount"].mean()`: получится 343.18, средний чек, а не выручка на гостя.

Какая доля гостей с картой, заходивших в **октябре 2026**, сделала в октябре хотя бы два заказа? Сохраните в `repeat_oct` долю в процентах с одним знаком после запятой.

### starter
```python
import pandas as pd
df = pd.read_csv("orders_3m.csv")

```

### check
```python
import pandas as _pd
_d = _pd.read_csv('orders_3m.csv')
_o = _d[_d['datetime'].str.startswith('2026-10') & _d['client_id'].notna()]
```

В октябре заходили 208 гостей с картой, и 58.2 % из них — хотя бы дважды. В сентябре было 59.2 %, в ноябре — 61.2 %: октябрь чуть ниже соседей, но разница в 1–3 пункта на двух сотнях гостей — это несколько человек, а не тренд. Если считать по всем трём месяцам, получится 97.3 % — красивое, но бесполезное для сравнения число: чем длиннее окно, тем больше гостей успевают вернуться. Поэтому доля повторных всегда пишется с периодом.

## task: conversion | Конверсия по источникам | plus

В программе лояльности гость регистрируется на кассе или в приложении (`source` в `zdb_guests.csv`). Посчитайте конверсию регистрации в хотя бы один заказ (`zdb_orders.csv`):

- `conv_all` — по всем гостям, доля с тремя знаками;
- `conv` — **словарь** «источник → конверсия», тоже доли с тремя знаками;
- `lost_app` — сколько гостей из приложения зарегистрировались, но ни разу не заказали.

### starter
```python
import pandas as pd
guests = pd.read_csv("zdb_guests.csv")
orders = pd.read_csv("zdb_orders.csv")

```

### check
```python
import pandas as _pd
_g = _pd.read_csv('zdb_guests.csv')
_o = _pd.read_csv('zdb_orders.csv')
_g['_ok'] = _g['guest_id'].isin(_o['guest_id'])
_want_all = round(_g['_ok'].mean(), 3)
_by = _g.groupby('source')['_ok'].mean().round(3).to_dict()
_ca = need('conv_all')
assert not close(_ca, round(_o['guest_id'].notna().mean(), 3), 0.0005), f'conv_all = {_ca} — это доля заказов с гостем, а не доля гостей с заказом. Знаменатель — зарегистрированные гости.'
assert close(_ca, _want_all, 0.0005), f'conv_all = {_ca}, а нужно {_want_all}. Для каждого гостя проверьте, есть ли он среди заказов (isin), и возьмите среднее.'
_c = {str(k): float(v) for k, v in dict(need('conv')).items()}
assert set(_c) == set(_by), f'Ключи conv: {sorted(_c)}, а нужны источники {sorted(_by)}.'
for _k, _v in _by.items():
    assert close(_c[_k], _v, 0.0005), f'Конверсия для «{_k}» — {_c[_k]}, а нужно {_v}.'
_lost = int(((_g['source'] == 'приложение') & ~_g['_ok']).sum())
assert need('lost_app') == _lost, f'lost_app = {need("lost_app")}, а нужно {_lost}. Гости из приложения, которых нет в заказах.'
```

### hint
Знаменатель конверсии — зарегистрированные гости, поэтому считаем по `guests`. Для каждого гостя нужен признак «заказывал ли» — True/False.

### hint
`guests["ordered"] = guests["guest_id"].isin(orders["guest_id"])`. Конверсия — `mean()` этого столбца; по источникам — `groupby("source")["ordered"].mean()`. Не заказавшие — `~guests["ordered"]`.

### hint
```python
guests["ordered"] = guests["guest_id"].isin(orders["guest_id"])
conv_all = round(guests["ordered"].mean(), 3)
conv = guests.groupby("source")["ordered"].mean().round(3).to_dict()
lost_app = int(((guests["source"] == ...) & ~guests["ordered"]).sum())
```

### solution
```python
import pandas as pd
guests = pd.read_csv("zdb_guests.csv")
orders = pd.read_csv("zdb_orders.csv")
guests["ordered"] = guests["guest_id"].isin(orders["guest_id"])
conv_all = round(guests["ordered"].mean(), 3)
conv = guests.groupby("source")["ordered"].mean().round(3).to_dict()
lost_app = int(((guests["source"] == "приложение") & ~guests["ordered"]).sum())
```

### explain
Общая конверсия — 94.6 %, но она складывается из двух очень разных частей: касса — 100 % (карту оформляют при покупке), приложение — 87.5 %, и 81 гость из приложения так и не сделал заказ. Средняя по всем скрывает проблему одного канала — поэтому конверсию почти всегда разбивают по источникам. Частая ошибка — взять знаменателем заказы: `orders["guest_id"].notna().mean()` (0.657) — это доля заказов, сделанных по карте, совсем другая метрика.
