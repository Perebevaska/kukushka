## Бриф

> Коллеги, у нас есть время не более чем на 150 звонков удержания за квартал. Для сравнения берите действующие офисы по возрастанию `revenue_trend` — нормированного изменения нетто-выручки за два соседних окна по 90 дней. При равенстве раньше идёт меньший `client_id`. В CRM нет журнала назначений звонков, поэтому это воспроизводимый ориентир.
>
> Нужен список на квартал: кому звонить и в каком порядке. При звонке менеджер предлагает скидку **10 % на 2 месяца**. Для сценарного расчёта предполагаем, что звонок удерживает **половину** офисов, которые иначе ушли бы. В этой CRM назначение звонка и его контроль не наблюдались; причинный эффект 0.5 здесь не измерен. Час менеджера с подготовкой обходится нам в **1 500 ₽** на звонок. Маржа направления — **35 %** от выручки, сохранённую маржу в сценарии считаем за **12 месяцев** при постоянной месячной выручке.
>
> Сравните стратегии при одной мощности и укажите расходы каждой. Что мы вправе рекомендовать сейчас, какие связи стоит исследовать и что потребуется измерить в пилоте? Следующий квартальный список должен уметь пересчитать другой аналитик.
>
> *Руководитель направления B2B*

Выгрузка из CRM сделана **1 октября 2026 года**: база SQLite `office.db`, пять таблиц. Это последний обязательный проект основного пути: его делают после урока «Итоговый проект: от базы данных до рекомендаций» главы 8. Из главы 15 для него нужен урок «Модель как артефакт: файл, паспорт, контрольный набор»; как написать пакетный скрипт, сказано в справке у шага 8. Бустинг здесь — та же третья модель, что в итоговом проекте главы 8 (там о нём короткая справка). Проект — итог всего курса: в нём встречаются SQL и pandas (главы 2–3), анализ и статистика (4–5), модели и метрики (6–10), деньги и риск (8), тексты (13) и выпуск модели (15).

**Происхождение и границы данных.** Это синтетическая CRM на 01.10.2026. У файла `office.db` этого выпуска SHA-256 `ec4fae8730a68fb4f2508ece2003efc017f19ff5457c1c87eee12dcb083c019f`. Генератор сначала моделирует состояние офиса по месяцам до расторжения или конца наблюдения. Затем при создании прошлых недельных заказов он использует последнее состояние `health` и уменьшает интенсивность перед уже выбранной датой ухода. Поэтому для одной прошлой недели возможны разные интенсивности при разных последующих состояниях. Отбор по дате, календарный тест и проверку доступности признаков можно выполнить на этой CRM. Величина и направление отличия результата от будущих реальных кварталов неизвестны. Для оценки влияния звонка понадобятся реальные назначения и контроль.

## Критерии приёмки

Проект принят, если выполнено **всё** из обязательного списка. Дополнительные пункты — для сильной работы и собеседования.

**Обязательно:**

1. Блокнот выполняется с чистого ядра сверху вниз без ошибок: `python check_notebook.py final_project.ipynb --timeout 1800` — нет пунктов «Надо исправить».
2. Структура шаблона: цель → данные → предобработка → анализ и модели → выводы; после каждого раздела с кодом — markdown-вывод своими словами.
3. Тестовые клиенты, отменённые заказы и дубли обращений обработаны, и каждое решение объяснено.
4. Цель и признаки строятся на дату среза. На трёх ранних срезах измерьте однопризнаковое качество на одинаковых групповых фолдах. Для категорий обучение кодирования происходит внутри фолда. Объясните направление связи самого сильного признака и покажите по первичным датам, когда он доступен. Измените одно событие после среза и сверьте всю строку по ID.
5. Кросс-валидация — `GroupKFold` по `client_id`; три класса моделей и ориентир сравниваются на одних фолдах; выбор — по кросс-валидации; тест на срезе 30.06.2026 открыт один раз, после выбора.
6. Сравните модель, ориентир по `revenue_trend` и отказ при одном лимите. Укажите число контактов, стоимость контактов, скидки всем адресатам, сценарную удержанную маржу и чистый результат в рублях. «Позвонить всем» посчитайте справочно и отметьте превышение мощности. Чувствительность 30/50/70 % обязательна для зафиксированной очереди и нового отбора.
7. Артефакт: `model.joblib`, `passport.json` (версия, срез данных, признаки, метрики CV и теста, параметры экономики, md5 базы, версии Python и sklearn), контрольный набор; `score.py` строит список на 30.09.2026 той же функцией признаков, что при обучении.
8. Для руководителя укажите действие, дату отбора и горизонт денег. Сошлитесь на наблюдаемые связи, предложите проверяемые гипотезы о причинах и укажите условия пилота.

**Для сильной работы:**

- подбор параметров `GridSearchCV` с `GroupKFold` и калибровка вероятностей (`CalibratedClassifierCV`) с проверкой — меняется ли от неё список звонков;
- признаки из текстов обращений (TF-IDF + логистическая регрессия поверх, глава 13) — и честный ответ, помогли ли они;
- интервал для прибыли списка бутстрэпом (глава 8) как дополнительная оценка неопределённости;
- дизайн A/B-теста для проверки доли удержанных 0.5: сколько офисов в контрольную группу и сколько кварталов ждать (глава 5);
- тесты для `score.py`: срез без клиентов, клиент без заказов, база без таблицы (глава 15).

## Перенос на выездной сервис

Сервис может посетить не больше трёх объектов. Модель оценивает риск поломки за ближайшие три месяца. Ущерб в таблице относится к одной поломке за этот же период. Один визит стоит 300 ₽. Для предварительного расчёта руководитель предполагает, что визит предотвращает половину поломок, которые случились бы без него; наблюдений эффекта визитов пока нет.

| Объект | Вероятность поломки | Ущерб одной поломки, ₽ |
|---|---:|---:|
| A1 | 0,8 | 1 250 |
| B2 | 0,2 | 10 000 |
| C3 | 0,5 | 2 000 |
| D4 | 0,5 | 2 000 |
| E5 | 0,9 | 200 |

Составьте очередь по ожидаемой чистой пользе визита, при равенстве — по ID. Назовите объекты и порядок, объясните, почему вероятность сама по себе не определяет очередь. Какую короткую проверку вы включите в передачу модели коллеге, чтобы он воспроизвёл список при лимитах три и два без переобучения? Все шаги проекта читают данные из `office.db` одной и той же схемой из трёх действий: открыть подключение, прочитать запрос в DataFrame, закрыть подключение.

```python
import sqlite3
import pandas as pd

con = sqlite3.connect("office.db")       # 1. подключение к файлу базы
names = pd.read_sql("SELECT name FROM sqlite_master WHERE type = 'table'", con)["name"].tolist()
orders = pd.read_sql("SELECT * FROM orders", con, parse_dates=["order_date"])   # 2. запрос → DataFrame
con.close()                              # 3. база больше не нужна

print(names)
print(orders.shape, orders["order_date"].max().date())
```

**Что здесь происходит:**

- `sqlite3.connect("office.db")` открывает файл базы и возвращает подключение `con` — «линию», по которой идут запросы.
- `pd.read_sql(текст_запроса, con)` отправляет SQL в базу и складывает ответ в DataFrame: столбцы — как в `SELECT`. `sqlite_master` — служебная таблица SQLite со списком таблиц базы.
- `parse_dates=["order_date"]` — SQLite хранит даты строками `ГГГГ-ММ-ДД`; так pandas сразу превратит их в даты.
- `con.close()` закрывает подключение. Прочитанные таблицы остаются в памяти, а новый запрос через закрытое `con` упадёт с `Cannot operate on a closed database` — откройте подключение заново.

## Постановка: срезы во времени

**Зачем.** Модель будет работать так: в последний день квартала берём всех действующих клиентов и по их истории оцениваем, кто расторгнет договор в следующие три месяца. Обучающие данные должны выглядеть **точно так же** — иначе модель учится не на той задаче.

::: tip Аналогия
Срез — как фотография офиса на дату: всё, что было до неё, на фото есть, всего, что случилось после, — нет. Цель — подпись под фотографией, которую мы узнаём через три месяца: «ушёл» или «остался». Для обучения нужны старые фотографии с уже известными подписями; для работы — свежая фотография, подпись к которой ещё предстоит угадать.
:::

Игрушечный пример — один офис, договор с 10 марта 2025, расторгнут 14 февраля 2026:

| срез | действует на дату среза? | ушёл в следующие 3 месяца? | строка в данных |
|---|---|---|---|
| 30.09.2025 | да | нет (до 31.12 договор действует) | признаки на 30.09, цель 0 |
| 31.12.2025 | да | да (14.02 ≤ 31.03) | признаки на 31.12, цель 1 |
| 31.03.2026 | нет — уже ушёл | — | строки нет |

Один клиент дал две строки обучения. Срезы проекта:

| срез | роль | горизонт цели |
|---|---|---|
| 30.09.2025, 31.12.2025, 31.03.2026 | обучение и кросс-валидация | следующие 3 месяца |
| 30.06.2026 | отложенная проверка (тест), открываем один раз | июль–сентябрь 2026 |
| 30.09.2026 | работа: список звонков на IV квартал | неизвестна |

::: figure snapshot-cutoffs
Все срезы проекта на одной шкале: для каждой даты признаки считаются по окну до среза, цель — по трём месяцам после. Три ранних среза — обучение, 30.06.2026 — тест, 30.09.2026 — работа: его цель ещё неизвестна.
:::

```python
import sqlite3
import pandas as pd

con = sqlite3.connect("office.db")
base = pd.read_sql("""
    SELECT c.client_id, c.city, c.employees, k.plan, k.start_date, k.end_date
    FROM clients c JOIN contracts k USING (client_id)
    WHERE c.is_test = 0
""", con, parse_dates=["start_date", "end_date"])
con.close()

def build_target(cutoff, months=3):
    c = pd.Timestamp(cutoff)
    active = base[(base["start_date"] <= c) & (base["end_date"].isna() | (base["end_date"] > c))]
    if c + pd.offsets.MonthEnd(months) > pd.Timestamp("2026-09-30"):
        return pd.Series(pd.NA, index=active["client_id"].values, dtype="Int64", name="churn")
    left = active["end_date"].notna() & (active["end_date"] <= c + pd.offsets.MonthEnd(months))
    return pd.Series(left.astype(int).values, index=active["client_id"].values, name="churn")

for cut in ["2025-09-30", "2025-12-31", "2026-03-31"]:
    y = build_target(cut)
    print(cut, "действующих:", len(y), "ушли за 3 месяца:", int(y.sum()), "доля:", round(y.mean(), 3))
```

**Что здесь происходит:**

- SQL-запрос соединяет клиентов с договорами и сразу отбрасывает тестовых — фильтр в базе дешевле, чем в pandas.
- `active` — договор начался не позже среза и на дату среза не расторгнут (`end_date` пусто или позже среза).
- `left` — договор расторгнут до конца третьего месяца после среза включительно. `pd.offsets.MonthEnd(3)` от 30.09 даёт 31.12, от 31.03 — 30.06: окно совпадает с кварталом. Простое `pd.DateOffset(months=3)` от 30.09 дало бы 30.12, и уход 31 декабря выпал бы из цели.
- Результат — Series «клиент → 0/1» для действующих на срез клиентов.

::: warn Типичные ошибки постановки
- **Один срез «на сегодня»** и цель «ушёл когда-нибудь». Ушедшие давно и действующие сравниваются по разным периодам жизни, признаки «последних 90 дней» у ушедших — нули по определению. Модель выучит «нет заказов — ушёл», а это следствие ухода, а не предвестник.
- **Признаки по всей таблице без фильтра по дате.** `orders.groupby("client_id")` без `order_date <= cutoff` тянет заказы из будущего — проверка в задаче «Утечка через дату».
- **Перемешанный KFold по строкам.** Проверьте пересечение `client_id` обучения и проверки для каждого фолда. У одного офиса есть разные квартальные строки; в `GroupKFold` они остаются вместе. Направление ошибки при перемешивании зависит от данных и модели.
:::

Точные правила, по которым посчитаны контрольные числа (по ним же работает эталон в задачах ниже):

- **Окна.** «За 90 дней» — даты в полуинтервале (срез − 90 дней; срез], то есть день среза входит. «Предыдущие 90» для `revenue_trend` — (срез − 180 дней; срез − 90 дней].
- **Заказы.** Отменённые не считаем нигде; возвраты входят в число заказов и в выручку со знаком минус. `revenue_trend` = (выручка 90 − выручка предыдущих 90) / (выручка 90 + выручка предыдущих 90 + 1). При нулевом знаменателе соглашение этого выпуска — 0. При ненулевом сохраните результат полной формулы, включая значения за пределами [−1, 1].
- **`days_since_order`** — дней от последнего неотменённого заказа (до среза включительно) до среза; если заказов не было — `tenure_days`.
- **`late_share_90`** — среди заказов за 90 дней со статусом «доставлен» доля с `late_min > 0`. Если доставленных заказов нет — 0.
- **Обращения** — после `drop_duplicates("ticket_id")`, по `created_at` в окне 90 дней.
- **`pay_late_last3`.** Берём счета с `due_date` не позже среза. Оплату после среза считаем неизвестной: `paid_date` → пусто. Просрочка счёта = (дата оплаты, а если её нет — дата среза) − `due_date` в днях, отрицательная → 0: оплата раньше срока — это 0 дней. «Три последних» — по `due_date`. Признак — среднее по ним; у клиента без счетов — 0.
- **`overdue_now`** — счета с `due_date` раньше даты среза, не оплаченные на дату среза.

Здесь 0.5 — доля удержанных среди собиравшихся уйти, 0.35 · 12 · R — маржа за год, 1 500 ₽ — час менеджера, 0.2 · R — скидка 10 % на 2 месяца, которую получает каждый, кому позвонили. Звоним тем, у кого ожидаемая прибыль положительна, по убыванию, не больше 150.

```python
    act = active_at(c).set_index("client_id")
```
```python
    f = act[["employees", "has_manager", "own_machine", "plan", "city"]].copy()
```

```python
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import GroupKFold, cross_val_score
from sklearn.metrics import roc_auc_score

X, y, groups = train[CAT + NUM], train["churn"], train["client_id"]
models = {
    "logreg": make_pipeline(_pre(), LogisticRegression(max_iter=2000)),
    "boosting": make_pipeline(ColumnTransformer([("cat", OneHotEncoder(handle_unknown="ignore"), CAT)], remainder="passthrough"),
                              HistGradientBoostingClassifier(max_depth=3, learning_rate=0.05, max_iter=200, random_state=42)),
    "knn": make_pipeline(_pre(), KNeighborsClassifier(n_neighbors=25)),
}
cv = GroupKFold(n_splits=5)
cv_auc = {k: round(float(cross_val_score(m, X, y, groups=groups, cv=cv, scoring="roc_auc").mean()), 3)
          for k, m in models.items()}
best = max(cv_auc, key=cv_auc.get)
final = models[best].fit(X, y)
from sklearn.model_selection import cross_val_predict
# Каждая вероятность получена моделью, для которой этот офис был отложен целиком.
oof = cross_val_predict(models[best], X, y, groups=groups, cv=cv, method="predict_proba")[:, 1]
past = train.assign(risk=oof, bin=pd.qcut(oof, 5, duplicates="drop"))
oof_calibration = past.groupby("bin", observed=True).agg(offices=("client_id", "size"), risk=("risk", "mean"), churn=("churn", "mean"))
r = past["revenue_90"] / 3
gain = past["risk"] * .5 * .35 * 12 * r - 1500 - .2 * r
historical_budget = past.assign(eligible=gain.gt(0), expected=gain).groupby("cutoff").apply(
    lambda quarter: quarter.loc[quarter["eligible"], "expected"].nlargest(150).sum())
print(oof_calibration.round(3), historical_budget.round())
test_auc = round(float(roc_auc_score(test["churn"], final.predict_proba(test[CAT + NUM])[:, 1])), 3)
print(cv_auc, best, test_auc)
```

```python
def active_at(cutoff):
    c = pd.Timestamp(cutoff)
    return base[(base["start_date"] <= c) & (base["end_date"].isna() | (base["end_date"] > c))]

def build_target(cutoff, months=3):
    c = pd.Timestamp(cutoff)
    act = active_at(c)
    if c + pd.offsets.MonthEnd(months) > pd.Timestamp('2026-09-30'):
        return pd.Series(pd.NA,index=act['client_id'].values,dtype='Int64',name='churn')
    y = act["end_date"].notna() & (act["end_date"] <= c + pd.offsets.MonthEnd(months))
    return pd.Series(y.astype(int).values, index=act["client_id"].values, name="churn")

def build_features(cutoff):
    c = pd.Timestamp(cutoff)
    act = active_at(c).set_index("client_id")
    f = act[["employees", "has_manager", "own_machine", "plan", "city"]].copy()
    f["industry"] = act["industry"].fillna("нет данных")
    f["tenure_days"] = (c - act["start_date"]).dt.days
    o = orders[(orders["order_date"] <= c) & (orders["status"] != "отменён")]
    o90 = o[o["order_date"] > c - pd.Timedelta(days=90)]
    prev = o[(o["order_date"] > c - pd.Timedelta(days=180)) & (o["order_date"] <= c - pd.Timedelta(days=90))]
    f["orders_90"] = o90.groupby("client_id").size().reindex(f.index, fill_value=0)
    f["revenue_90"] = o90.groupby("client_id")["amount"].sum().reindex(f.index, fill_value=0)
    rev_prev = prev.groupby("client_id")["amount"].sum().reindex(f.index, fill_value=0)
    den = f["revenue_90"] + rev_prev + 1
    f["revenue_trend"] = ((f["revenue_90"] - rev_prev) / den).where(den.ne(0), 0)
    last = o.groupby("client_id")["order_date"].max().reindex(f.index)
    f["days_since_order"] = (c - last).dt.days.fillna(f["tenure_days"])
    late = (o90[o90["status"] == "доставлен"]["late_min"] > 0).groupby(o90["client_id"]).mean()
    f["late_share_90"] = late.reindex(f.index).fillna(0)
    t90 = tickets[(tickets["created_at"] <= c) & (tickets["created_at"] > c - pd.Timedelta(days=90))]
    f["tickets_90"] = t90.groupby("client_id").size().reindex(f.index, fill_value=0)
    f["tickets_bill_90"] = t90[t90["category"] == "счёт"].groupby("client_id").size().reindex(f.index, fill_value=0)
    iv = invoices[invoices["due_date"] <= c].sort_values("due_date").copy()
    paid = iv["paid_date"].where(iv["paid_date"] <= c)
    iv["days_late"] = (paid.fillna(c) - iv["due_date"]).dt.days.clip(lower=0)
    iv["overdue"] = (paid.isna() & (iv["due_date"] < c)).astype(int)
    f["pay_late_last3"] = iv.groupby("client_id").tail(3).groupby("client_id")["days_late"].mean().reindex(f.index).fillna(0)
    f["overdue_now"] = iv.groupby("client_id")["overdue"].sum().reindex(f.index, fill_value=0)
    return f
```

### setup
```python
import sqlite3
import numpy as np
import pandas as pd
_con = sqlite3.connect("office.db")
clients = pd.read_sql("SELECT * FROM clients", _con)
contracts = pd.read_sql("SELECT * FROM contracts", _con, parse_dates=["start_date", "end_date"])
orders = pd.read_sql("SELECT * FROM orders", _con, parse_dates=["order_date"])
tickets = pd.read_sql("SELECT * FROM tickets", _con, parse_dates=["created_at"]).drop_duplicates("ticket_id")
invoices = pd.read_sql("SELECT * FROM invoices", _con, parse_dates=["due_date", "paid_date"])
_con.close()
base = clients[clients["is_test"] == 0].merge(contracts, on="client_id")

def active_at(cutoff):
    c = pd.Timestamp(cutoff)
    return base[(base["start_date"] <= c) & (base["end_date"].isna() | (base["end_date"] > c))]

def build_target(cutoff, months=3):
    c = pd.Timestamp(cutoff)
    act = active_at(c)
    if c + pd.offsets.MonthEnd(months) > pd.Timestamp('2026-09-30'):
        return pd.Series(pd.NA,index=act['client_id'].values,dtype='Int64',name='churn')
    y = act["end_date"].notna() & (act["end_date"] <= c + pd.offsets.MonthEnd(months))
    return pd.Series(y.astype(int).values, index=act["client_id"].values, name="churn")

def build_features(cutoff):
    c = pd.Timestamp(cutoff)
    act = active_at(c).set_index("client_id")
    f = act[["employees", "has_manager", "own_machine", "plan", "city"]].copy()
    f["industry"] = act["industry"].fillna("нет данных")
    f["tenure_days"] = (c - act["start_date"]).dt.days
    o = orders[(orders["order_date"] <= c) & (orders["status"] != "отменён")]
    o90 = o[o["order_date"] > c - pd.Timedelta(days=90)]
    prev = o[(o["order_date"] > c - pd.Timedelta(days=180)) & (o["order_date"] <= c - pd.Timedelta(days=90))]
    f["orders_90"] = o90.groupby("client_id").size().reindex(f.index, fill_value=0)
    f["revenue_90"] = o90.groupby("client_id")["amount"].sum().reindex(f.index, fill_value=0)
    rev_prev = prev.groupby("client_id")["amount"].sum().reindex(f.index, fill_value=0)
    den = f["revenue_90"] + rev_prev + 1
    f["revenue_trend"] = ((f["revenue_90"] - rev_prev) / den).where(den.ne(0), 0)
    last = o.groupby("client_id")["order_date"].max().reindex(f.index)
    f["days_since_order"] = (c - last).dt.days.fillna(f["tenure_days"])
    late = (o90[o90["status"] == "доставлен"]["late_min"] > 0).groupby(o90["client_id"]).mean()
    f["late_share_90"] = late.reindex(f.index).fillna(0)
    t90 = tickets[(tickets["created_at"] <= c) & (tickets["created_at"] > c - pd.Timedelta(days=90))]
    f["tickets_90"] = t90.groupby("client_id").size().reindex(f.index, fill_value=0)
    f["tickets_bill_90"] = t90[t90["category"] == "счёт"].groupby("client_id").size().reindex(f.index, fill_value=0)
    iv = invoices[invoices["due_date"] <= c].sort_values("due_date").copy()
    paid = iv["paid_date"].where(iv["paid_date"] <= c)
    iv["days_late"] = (paid.fillna(c) - iv["due_date"]).dt.days.clip(lower=0)
    iv["overdue"] = (paid.isna() & (iv["due_date"] < c)).astype(int)
    f["pay_late_last3"] = iv.groupby("client_id").tail(3).groupby("client_id")["days_late"].mean().reindex(f.index).fillna(0)
    f["overdue_now"] = iv.groupby("client_id")["overdue"].sum().reindex(f.index, fill_value=0)
    return f

def snapshot(cutoff):
    f = build_features(cutoff)
    if pd.Timestamp(cutoff) + pd.offsets.MonthEnd(3) <= pd.Timestamp("2026-09-30"):
        f["churn"] = build_target(cutoff).reindex(f.index)
    f["cutoff"] = pd.Timestamp(cutoff)
    return f.reset_index()

CAT = ["plan", "city", "industry"]
NUM = ["employees", "has_manager", "own_machine", "tenure_days", "orders_90", "revenue_90", "revenue_trend",
       "days_since_order", "late_share_90", "tickets_90", "tickets_bill_90", "pay_late_last3", "overdue_now"]
train = pd.concat([snapshot(c) for c in ["2025-09-30", "2025-12-31", "2026-03-31"]], ignore_index=True)
test = snapshot("2026-06-30")
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.linear_model import LogisticRegression
def _pre():
    return ColumnTransformer([("cat", OneHotEncoder(handle_unknown="ignore"), CAT), ("num", StandardScaler(), NUM)])
```

### hint
Обучение на всех размеченных данных: `full = pd.concat([train, test], ignore_index=True)`. После `joblib.dump(model, "model.joblib")` загрузите файл `joblib.load` и считайте прогноз **загруженной** моделью — так проверяется, что артефакт рабочий.

### hint
Срез для работы — `s = snapshot("2026-09-30")`. Уходы следующего квартала в день отбора ещё неизвестны. Для рабочего прогноза используются признаки на дату среза. Список — как в шаге 6, только с `p_churn` вместо `p`; запись — `to_csv("call_list.csv", index=False)`. Отпечаток данных — `hashlib.md5(open("office.db", "rb").read()).hexdigest()`.

### hint
`json.dump` не понимает типы numpy: `train_rows`, `n_calls`, `expected_profit` приведите к `int`. Пишите с `ensure_ascii=False`, чтобы русские названия остались читаемыми.

### solution
```python
import hashlib
import json
import joblib
import pandas as pd

full = pd.concat([train, test], ignore_index=True)
model = make_pipeline(_pre(), LogisticRegression(max_iter=2000)).fit(full[CAT + NUM], full["churn"])
joblib.dump(model, "model.joblib")
loaded = joblib.load("model.joblib")

s = snapshot("2026-09-30")
s["p_churn"] = loaded.predict_proba(s[CAT + NUM])[:, 1]
golden = s[["client_id", *CAT, *NUM]].head(20).copy()
golden["expected"] = s["p_churn"].head(20)
golden.to_csv("golden.csv", index=False)
R = s["revenue_90"] / 3
s["exp_profit"] = s["p_churn"] * 0.5 * 0.35 * 12 * R - 1500 - 0.2 * R
calls = s[s["exp_profit"] > 0].sort_values("exp_profit", ascending=False).head(150)
out = calls[["client_id", "city"]].assign(p_churn=calls["p_churn"].round(3), exp_profit=calls["exp_profit"].round())
out.to_csv("call_list.csv", index=False)

passport = {
    "model": "office_churn: логистическая регрессия, one-hot + StandardScaler",
    "version": "1.0",
    "cutoff": "2026-09-30",
    "features": CAT + NUM,
    "train_rows": int(len(full)),
    "n_calls": int(len(out)),
    "expected_profit": int(round(float(calls["exp_profit"].sum()))),
    "data_md5": hashlib.md5(open("office.db", "rb").read()).hexdigest(),
}
with open("passport.json", "w", encoding="utf-8") as fh:
    json.dump(passport, fh, ensure_ascii=False, indent=2)
print(out.head(), passport["n_calls"], passport["expected_profit"], out["city"].value_counts().to_dict())
```
