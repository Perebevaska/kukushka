**Основной маршрут** охватывает вопросы 1–3 и 16–17; на полном маршруте добавляются вопросы 4–15.

**До выбора вариантов.** Сервис после обновления получает суммы в копейках вместо рублей. Какие проверки помогут обнаружить смену единиц и почему смена версии модели сама по себе её не исправит?

::: quiz 01-artifact
Две выгрузки одинаковы по размеру. В паспорте исходного запуска сохранён SHA-256 файла. Как проверить данные для повторного запуска?

- [x] Пересчитать SHA-256 новой выгрузки и сравнить с паспортом
  > Совпадение даёт сильное свидетельство совпадения байтов. Доверие к происхождению самого паспорта проверяют отдельно.
- [ ] Сверить число строк и заголовки колонок с исходным отчётом
  > Структура может сохраниться при изменении одного значения.
- [ ] Сопоставить время последней записи и имя файла
  > Копирование меняет время, а один путь может указывать на другую версию.
- [ ] Сравнить AUC переобученной модели с паспортной
  > Близкое значение метрики возможно у разных наборов данных.
:::

::: quiz 01-artifact
Что из этого должно быть в паспорте модели из урока?

- [x] Версия, схема признаков, порог, метрики, хеш и библиотеки
  > Паспорт отвечает на вопросы «что это за модель, на чём обучена и как её вызывать».
- [ ] Файл модели, её название и фамилия автора без схемы входа
  > Из файла не видно, на каких данных модель обучена и какой порог решения выбран.
- [ ] Название модели, один AUC и решение о выпуске без данных
  > Без признаков и порога сервис не сможет правильно вызвать модель.
- [ ] Полная таблица обучения вместо версии и описания модели
  > Данные хранят отдельно, а в паспорт кладут их отпечаток.
:::

::: quiz 01-artifact
Прокат велосипедов перенёс модель прогноза спроса на другой компьютер. Версия модели в паспорте совпадает. Как проверить, что прогноз вычисляется по-прежнему?

- [x] Сравнить прогнозы полного пути на контрольных строках
  > Это проверяет поведение данных, подготовки и загруженной модели вместе.
- [ ] Проверить только текстовую версию в паспорте модели
  > Одинаковая метка не выявляет изменённую подготовку, порядок полей или подменённый файл.
- [ ] Сравнить только размер перенесённого файла в байтах
  > Файлы одинакового размера могут иметь разное содержимое и прогнозы.
- [ ] Вычислить accuracy на train без контрольных прогнозов
  > Обучающая метрика не проверяет сохранение прогноза конкретных входов после переноса.
:::

::: quiz 02-service
Зачем в сервисе проверять `isinstance(x, bool)` отдельно от проверки целого числа?

- [x] В Python `bool` является подклассом целого типа `int`
  > `isinstance(True, int)` возвращает `True`, поэтому `bool` отсекают явно.
- [ ] `json.loads` превращает JSON true в строку `"true"`
  > `json.loads` даёт настоящий `True` — потому и нужна отдельная проверка.
- [ ] `pd.DataFrame` не принимает bool при создании таблицы
  > Таблица построится — и модель молча посчитает `True` как 1.
- [ ] `bool` проверяют только в полях-флагах, не в числовых
  > Ловушка касается любого целого поля: `true` пройдёт и в `visits_90d`.
:::

::: quiz 02b-service-run
Зачем пакетному обработчику запросов не падать на одной плохой записи?

- [x] Чтобы вернуть результаты и отдельные ошибки по строкам
  > Клиент видит, какие записи исправить, а остальные гости получают решения.
- [ ] Чтобы молча исключать плохие строки из ответа сервиса
  > Ошибки не прячут: каждая плохая запись получает свой ответ 422 с причиной.
- [ ] Чтобы гарантированно ускорить пакетное вычисление модели
  > Скорость пакета — отдельная тема; здесь речь о надёжности.
- [ ] Чтобы повторно отправлять целиком весь исходный пакет
  > Повторять пакет не нужно: хорошие записи уже получили ответы.
:::

::: quiz 02b-service-run
За час обработали 100 запросов. Медиана задержки — 8 мс, p95 — 96 мс. Какое утверждение следует из этих чисел с учётом возможных одинаковых задержек?

- [x] Не менее 50 ответов заняли не больше 8 мс, не менее 95 — не больше 96 мс
  > В упорядоченном ряду медиана находится между 50-м и 51-м значениями. При обычной линейной интерполяции p95 находится между 95-м и 96-м. Ответы с задержкой, равной границе, тоже засчитываются.
- [ ] Ровно 50 ответов заняли не больше 8 мс, ровно 95 — не больше 96 мс
  > Совпадения могут увеличить оба числа. Если 94 ответа заняли 8 мс и ещё 6 — 96 мс, в первую границу уложились 94 ответа, во вторую — все 100.
- [ ] Средняя задержка равна 8 мс, а самый медленный запрос занял 96 мс
  > Среднее требует суммы всех задержек, максимум — последнего значения упорядоченного ряда.
- [ ] В 95 запросах задержка равна 96 мс, остальные 5 занимают больше 96 мс
  > По p95 нельзя определить, сколько задержек равны ему. В примере с шестью ответами по 96 мс ни один запрос не оказался медленнее p95.
:::

::: quiz 03-experiments
В двух выпусках агрегируют одни заказы разным кодом. Какой комплект позволит повторить выбранный запуск и сверить результат?

- [x] Версии кода и данных, правила разбиения и seed, параметры, окружение и метрики
  > Версия кода восстанавливает агрегацию, данные и разбиение задают вход, сохранённые метрики дают ориентир для сверки.
- [ ] Время начала, длительность, имя модели и график метрик
  > Эти поля помогают найти запуск, но по ним нельзя восстановить правила агрегации.
- [ ] Отпечаток готовой таблицы и таблица итоговых AUC
  > Они позволяют сравнить результаты, но не воспроизвести подготовку и обучение.
- [ ] Версия Python, число офисов и итоговый файл прогнозов
  > Для повторения нужны также исходная версия данных, код и настройки обучения.
:::

::: quiz 03-experiments
Почему после выбора максимума из 50 оценок на одной валидации результат победителя может быть оптимистичным?

- [x] Лучший результат отчасти отобран за случайную удачу
  > Честная оценка — на отложенных данных, которые в выборе не участвовали.
- [ ] Смена seed обязательно увеличивает качество каждого запуска
  > Зерно добавляет шум в обе стороны; завышение даёт именно выбор максимума.
- [ ] Кросс-валидация всегда завышает результат относительно теста
  > Смещение отдельной CV зависит от схемы разбиения. Здесь дополнительный оптимизм создаёт выбор максимума из шумных оценок.
- [ ] Пятидесяти запусков недостаточно для любой надёжной оценки
  > Дополнительные попытки дают больше возможностей отобрать удачную оценку; окончательное качество проверяют отдельно.
:::

::: quiz 04-deploy
Что означает строка расписания cron `0 3 * * *`?

- [x] Каждый день в 03:00
  > Поля: минута, час, день месяца, месяц, день недели.
- [ ] Каждые 3 минуты
  > Это было бы `*/3 * * * *`.
- [ ] 3-го числа каждого месяца
  > Это `0 0 3 * *`.
- [ ] Каждые 3 часа
  > Это `0 */3 * * *`.
:::

::: quiz 04-deploy
Пакетный скрипт за 7 декабря упал на середине, его запустили ещё раз. Какой способ записи результата правильный?

- [x] Заменить старый результат за 7 декабря, без дублей
  > Тогда повторный запуск даёт тот же результат — скрипт идемпотентен.
- [ ] Дописать весь результат в общий файл без удаления дублей
  > Каждый перезапуск добавит дубли, и гость попадёт в список дважды.
- [ ] Пропустить повторный запуск, если файл за дату существует
  > Файл после падения может быть неполным — его надо пересчитать.
- [ ] Создать новый результат с текущим временем вместо даты
  > Появятся два файла за одну дату, и непонятно, какой верный.

::: quiz 04-deploy
Почему в `Dockerfile` пояснения пишут на отдельных строках, а не в конце команды?

- [x] Хвост `# …` может стать частью аргументов команды
  > `EXPOSE 8000  # порт` сломает сборку: «#» и «порт» станут лишними словами команды.
- [ ] Отдельные строки с пояснениями уменьшают размер образа
  > Комментарии в образ не попадают при любом способе записи.
- [ ] Пояснения в конце команды запрещают кеширование слоя
  > Кеш зависит от команд и файлов, а не от места комментария.
- [ ] Размещение пояснения не влияет на разбор команды
  > Нет: комментарий в конце строки ломает команды вроде `FROM` и `EXPOSE`.
:::

::: quiz 04-deploy
Журнал сервиса хранится в формате JSON Lines. Почему версию модели лучше читать через `json.loads`, а не `pd.read_json(..., lines=True)` без параметров?

- [x] Чтобы сохранить строковые версии без автоопределения чисел
  > `json.loads` сохраняет строку как есть; у `read_json` можно задать `dtype={"model_version": str}`.
- [ ] Потому что pandas не поддерживает формат JSON Lines
  > Умеет — с `lines=True`; проблема в угадывании типов.
- [ ] Потому что json.loads быстрее на любых больших журналах
  > Дело не в скорости, а в искажении значений.
- [ ] Потому что pandas теряет любой вложенный словарь payload
  > Вложенный словарь остаётся в столбце; разложить его помогает `json_normalize`.
:::

::: quiz 05-project
В позднем эксперименте чек приложения перевели из рублей в копейки. У выбранной обученной логистической модели вес стандартизованного чека положителен. Что проверить на тех же запросах?

- [x] Сравнить балл и долю решений до/после исправления единиц
  > При прочих равных положительный вес увеличивает балл с ростом чека; с отрицательным знаком направление сменилось бы. Сравнение касается расчётных решений на запросах.
- [ ] Принять рост расчётной доли за фактический рост затрат
  > Для затрат нужны реальные показы, использование скидки и её стоимость.
- [ ] Считать, что вероятность увеличилась у каждого уникального гостя
  > У гостя бывают повторные запросы, есть пропуски и насыщение вероятности.
- [ ] Считать долю неизменной, поскольку вход проходит масштабирование
  > Масштабирование использует параметры обучения, а ошибка ×100 сохраняет влияние на балл.
:::

::: quiz 06-final-project
В панели есть (A, сентябрь), (B, сентябрь), (A, декабрь), (B, декабрь). Как использовать все строки в групповой проверке переноса на другие офисы?

- [x] Разделять по client_id; проверять пустое пересечение ID обучения и проверки в каждом фолде
  > В примере из двух офисов можно поставить A в обучение, B в проверку и поменять их на следующем фолде.
- [ ] Разделять случайно отдельные строки, сохраняя долю уходов
  > Даты одного и того же офиса могут попасть в обе части.
- [ ] Обучиться на сентябре и проверить на декабре, не сверяя ID
  > Так проверяют перенос во времени, пересечение офисов останется возможным.
- [ ] Группировать по паре «client_id, дата»
  > Каждая запись получит свою группу и не свяжет разные даты одного офиса.
:::

::: quiz 06-final-project
На 30.09.2026 есть прогнозы и ресурс до 150 звонков. Как выбрать рабочую очередь и проверить финансовое утверждение?

- [x] Взять до 150 положительных по убыванию ожидаемой пользы; зафиксировать ID и допущения
  > Тест 30.06 оценивают по известным к 30.09 уходам и сценарной годовой марже. Рабочий список ждёт исходов IV квартала; эффект звонка измеряют с контролем.

  > Риск не определяет величину удержанной выручки, а годовую ценность нужно отличать от квартала отбора.
- [ ] Посмотреть уходы IV квартала и оставить реально ушедших
  > На дату отбора этих исходов ещё нет.
- [ ] Заказать звонок каждому офису со снижением выручки
  > У ориентира по тренду те же ограничения мощности; положительная чистая польза каждого контакта не гарантирована.
