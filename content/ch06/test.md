**До выбора вариантов.** Модель обучается на нескольких заказах каждого клиента, а применять её будут к новым клиентам. Как разделить данные для честной оценки и какую утечку это предотвращает?

::: quiz 01-what-is-ml
Что в задаче «опоздает ли доставка» является ответом (целевым признаком)?

- [x] Факт опоздания доставки
  > Модель учится предсказывать именно его по остальным признакам.
- [ ] Расстояние до получателя
  > Это признак — то, по чему предсказываем.
- [ ] Название модели прогноза
  > Модель — результат обучения, а не столбец данных.
- [ ] Время оформления заказа
  > Тоже признак.
:::

::: quiz 02-split
На тесте из 461 доставки дерево набрало 79 %, а соседняя модель — 80.5 %. Что можно сказать?

- [x] Двух accuracy недостаточно для уверенного выбора
  > Обе модели проверены на одних доставках. Для оценки надёжности разницы нужны их предсказания по каждой строке: важно, на каких доставках они расходятся. Стандартная ошибка одной accuracy не оценивает ошибку разницы.
- [ ] Вторая надёжно лучше: её accuracy выше на тесте
  > Выше на этом тесте, но две итоговые доли не показывают надёжность разницы. При подборе моделей можно сравнить результаты на одинаковых валидационных фолдах; финальный тест оставляют для оценки принятого решения.
- [ ] Первая переобучена: она проиграла на тестовой части
  > О переобучении говорит разрыв между обучением и тестом, а не разница двух моделей на тесте.
- [ ] Нужно найти seed с большей разницей между моделями
  > Это подгонка под тест: оценка станет оптимистичной и бесполезной.
:::

::: quiz 03-tree
Как ограничить переобучение дерева?

- [x] Ограничить глубину, увеличить минимум строк листа
  > Глубину ограничивают сверху, а минимальное число строк в листе увеличивают. Дерево меньше запоминает отдельные шумные наблюдения.
- [ ] Добавить ещё несколько признаков клиента
  > Добавление признаков само по себе не ограничивает сложность дерева; лишние шумные признаки могут усилить переобучение.
- [ ] Обучить дерево также на тестовых строках
  > Тест не для обучения.
- [ ] Исключить сравнение с базовой моделью
  > Базовая модель — точка отсчёта, на переобучение она не влияет.
:::

::: quiz 04-categorical
Почему погоду не кодируют числами «ясно = 0, облачно = 1, дождь = 2, снег = 3»?

- [x] Возникают искусственные порядок и расстояния
  > Для категорий без порядка делают флаги (one-hot).
- [ ] Целые числа требуют слишком много памяти
  > Наоборот, флаги занимают больше.
- [ ] Целые числа не поддерживаются в sklearn
  > Принимает, но смысл кодировки неверный.
- [ ] Становится невозможен расчёт среднего значения
  > Дело не в среднем, а в ложном порядке.
:::

::: quiz 04-categorical
Модель обучили на флагах погоды, а в новых данных появилась «гроза». Что сделать?

- [x] Сохранить прежние столбцы, для «грозы» поставить нули
  > Модель знает только столбцы обучения — новые данные приводят к той же форме.
- [ ] Добавить столбец «гроза» только в новые данные
  > Модель такого столбца не знает — будет ошибка.
- [ ] Дообучить модель на единственной строке с грозой
  > Одна новая строка не решает задачу согласования столбцов с уже обученной моделью. Новую категорию при переобучении учитывают по достаточным размеченным данным.
- [ ] Исключить из новых данных все заказы во время грозы
  > Прогноз для них всё равно нужен.
:::

::: quiz 05-forest
Что делает `n_estimators` у случайного леса?

- [x] Число деревьев случайного леса
  > Больше деревьев — стабильнее результат, но дольше обучение; после некоторого числа выигрыш почти исчезает.
- [ ] Максимальную глубину деревьев
  > Глубина — `max_depth`.
- [ ] Число признаков для обучения
  > Признаки модели те же; `max_features` лишь задаёт, сколько из них дерево рассматривает при каждом разбиении.
- [ ] Долю строк тестовой выборки
  > Разбиение делается отдельно.
:::

::: quiz 06-logistic
Чем `predict_proba` полезнее `predict` для акции удержания?

- [x] Даёт ранжирование и выбор порога под бюджет
  > `predict` уже применил порог 0.5 и спрятал степень уверенности.
- [ ] Автоматически повышает accuracy той же модели
  > Получение вероятностей само по себе не повышает accuracy. Другой порог может изменить её, но улучшение не гарантировано; порог выбирают на валидации под цель кампании.
- [ ] Можно предсказывать без предварительного обучения
  > Требует обученной модели, как и `predict`.
- [ ] Можно получить только готовый список уходящих
  > Возвращает вероятности для всех.
:::

::: quiz 06b-probabilities
Модель ранжирует 1 000 заказов, опаздывают 200. Среди 100 заказов с наибольшей вероятностью опоздали 60. Чему равен лифт этого списка?

- [x] 3: отношение 60 % к 20 %
  > Лифт — отношение доли события в отобранной группе к доле во всех данных: 0.6 / 0.2.
- [ ] 0.3: отношение 60 к 200
  > Это охват — какую долю всех опозданий увидел список. Лифт сравнивает доли, а не делит пойманные на все.
- [ ] 0.6: отношение 60 к 100
  > Это доля в списке; лифт показывает, во сколько раз она выше средней.
- [ ] 6: отношение 60 к 10
  > При случайном выборе 100 заказов ожидается 100 × 0.2 = 20 опозданий. Отношение 60 к 20 равно 3; знаменатель 10 здесь не обоснован.
:::

::: quiz 06b-probabilities
В большой проверочной группе заказов с вероятностью опоздания около 0.7 фактически опоздала половина. Что показывает это расхождение?

- [x] Модель завышает риск этой группы: 0.7 вместо 0.5
  > Калибровка — согласие вероятностей с фактическими долями. Если группа большая, расхождение в 20 пунктов — повод не верить числам; для ранжирования модель при этом может оставаться полезной.
- [ ] Accuracy всей модели обязательно ниже 50 %
  > Калибровка и accuracy — разные свойства: модель может часто угадывать класс и при этом завышать вероятности.
- [ ] Исправление требует только смены порога 0.5
  > Порог — решение поверх вероятностей. Здесь вопрос к самим вероятностям.
- [ ] Калибровка верна: 0.7 не гарантирует опоздание
  > Отдельному заказу не обещает, но из многих заказов с 0.7 должны опоздать около 70 %, а не половина.
:::

::: quiz 07-regression
Модель прогнозирует минуты доставки с MAE = 6. Что это значит?

- [x] В среднем абсолютный промах равен 6 минутам
  > MAE — средний модуль ошибки в единицах ответа.
- [ ] Доля ошибочных прогнозов — 6 процентов
  > MAE — не доля ошибок.
- [ ] Абсолютный промах каждого прогноза — 6 минут
  > Это среднее; отдельные ошибки разные.
- [ ] Выигрыш относительно базовой модели — 6 минут
  > Сравнение с базовой — отдельная цифра.
:::

::: quiz 07-regression
У двух моделей прогноза минут одинаковая MAE = 5, но у первой RMSE = 6, а у второй RMSE = 12. Что это значит?

- [x] У второй выше средний квадрат ошибки
  > Средние квадраты ошибок равны 36 и 144 мин². Крупные промахи сильнее влияют на эту метрику. Для подсчёта их числа нужны сами ошибки и заданная граница.
- [ ] У второй средний абсолютный промах вдвое больше
  > В среднем по модулю они ошибаются одинаково — это и есть MAE = 5.
- [ ] Первая переобучена из-за слишком низкого RMSE
  > Метрики на одном наборе о переобучении не говорят — нужно сравнение обучения и теста.
- [ ] Первая неверна: RMSE обязан быть вдвое выше MAE
  > RMSE не меньше MAE, но их отношение зависит от распределения ошибок. MAE = 5 и RMSE = 6 совместимы; обязательного множителя 2 нет.
:::

::: quiz 08-validation
Почта выбирает глубину дерева для прогноза опозданий. Есть данные для обучения, валидации и финальной проверки. По какой части выбрать глубину?

- [x] По валидации, оставив финальную часть для оценки
  > Валидация участвует в выборе. Финальная часть оценивает уже принятое решение.
- [ ] По финальной части, где оценка самая честная
  > После сравнения глубин эта часть участвует в настройке и перестаёт быть независимой итоговой проверкой.
- [ ] По обучающей части, максимизируя её accuracy
  > Глубокое дерево может запомнить обучение и хуже работать на новых строках.
- [ ] По всем трём частям, предварительно их объединив
  > Тогда не остаётся независимых данных для оценки выбранной модели.
:::

::: quiz 08-validation
Чем кросс-валидация лучше одного разбиения на train и validation?

- [x] Меньше зависимость оценки от одного разбиения
  > Видно и среднее качество, и его разброс.
- [ ] Меньше время обучения тех же самых моделей
  > Обучение идёт k раз — медленнее.
- [ ] Не требуется откладывать данные для проверки
  > Каждый фолд по очереди служит проверкой.
- [ ] Не требуется отдельная финальная тестовая часть
  > Тест всё равно нужен для итоговой оценки.
:::

::: quiz 08b-groups-speed
Модель предсказывает, возьмёт ли гость десерт, и её будут показывать в том числе новым гостям. У каждого гостя в данных много заказов. Как честно оценить модель?

- [x] Все заказы гостя в одном фолде `GroupKFold`
  > Так проверка отвечает на вопрос «как модель работает на незнакомом госте». Обычное разбиение пускает заказы одного гостя в обе части, и модель «узнаёт» его.
- [ ] Перемешать строки через обычный `KFold`
  > При таком разбиении заказы одного гостя могут оказаться и в обучении, и в проверке. Это создаёт риск завышенной оценки для новых гостей.
- [ ] Уравнять долю десертов через `stratify=y`
  > Стратификация выравнивает доли классов, но не мешает одному гостю попасть в обе части.
- [ ] Удалить `guest_id`, затем перемешать строки
  > Гостя может выдать и другой признак — например, точное расстояние до его адреса. Удаление ID не обеспечивает разделение гостей между обучением и проверкой.
:::

::: quiz 09-project
В проекте оттока признак `card_blocked` даёт дереву 98 % правильных ответов. В таблицу взяли состояние карты на конец 60 дней после среза: её блокируют после 60 дней без визитов. Ответ — «не пришёл за 60 дней после среза». Что делать с признаком?

- [x] Убрать: признак будущего недоступен на дату среза
  > Это утечка: признак заполняется по итогам того же периода, за который считается отток. В момент решения о бонусе он бесполезен.
- [ ] Оставить: он обеспечивает максимальную accuracy
  > Точность получена на данных, где признак уже знает ответ. В работе модели такого значения не будет.
- [ ] Оставить с ограниченной глубиной дерева
  > Глубина не лечит утечку: признак всё равно подсказывает ответ.
- [ ] Взять значение за прошлый месяц без проверки даты
  > Прошлое значение могло бы быть законным признаком, но его тоже надо проверить: известно ли оно на дату среза.
:::
