::: quiz 01-resample
Что делает `s.resample("D").sum()` для часового ряда заказов?

- [x] Складывает часы в сутки: получается ряд заказов по дням
  > resample — группировка по периодам времени.
- [ ] Берёт одно значение в день
  > Для этого есть `asfreq`, а `sum` складывает.
- [ ] Сглаживает ряд скользящим окном
  > Это `rolling`.
- [ ] Сдвигает ряд на день
  > Это `shift`.
:::

::: quiz 02-decompose
Из каких частей состоит ряд в классическом разложении?

- [x] Тренд, сезонность и остаток
  > Тренд — долгое движение, сезонность — повторяющийся ритм, остаток — всё прочее.
- [ ] Среднее, медиана и мода
  > Это описательные статистики.
- [ ] Обучение, валидация и тест
  > Это части данных для модели.
- [ ] Лаги 1, 24 и 168
  > Это признаки, а не части ряда.
:::

::: quiz 02-decompose
Ряд называют стационарным, когда…

- [x] его среднее и разброс не меняются со временем
  > Многие классические методы требуют стационарности; разности помогают её получить.
- [ ] он не меняется вообще
  > Значения меняются, неизменны их свойства.
- [ ] в нём нет пропусков
  > Пропуски — отдельный вопрос.
- [ ] он растёт с постоянной скоростью
  > Ряд с трендом нестационарен.
:::

::: quiz 03-features
Какие лаги можно использовать для прогноза на час вперёд?

- [x] Значения 1 час, 24 часа и неделю назад — всё, что уже известно в момент прогноза
  > Признак законен, если его можно посчитать до наступления прогнозируемого часа.
- [ ] Значение через час
  > Это будущее — утечка.
- [ ] Среднее за весь день, включая прогнозируемый час
  > Окно захватывает ответ — утечка.
- [ ] Любые, лаги не бывают утечкой
  > Утечкой становится лаг из будущего.
:::

::: quiz 03b-time-split
Почему для рядов используют TimeSeriesSplit, а не KFold?

- [x] Каждый фолд обучается на прошлом и проверяется на следующем периоде — как в работе
  > KFold перемешивает время, и модель учится на будущем.
- [ ] TimeSeriesSplit быстрее
  > Скорость тут ни при чём.
- [ ] KFold не работает с датами
  > Технически работает, но оценка будет нечестной.
- [ ] TimeSeriesSplit даёт больше данных для обучения
  > Наоборот, в первых фолдах их меньше.
:::

::: quiz 04-forecast
Зачем сравнивать модель с наивными прогнозами («как вчера», «как неделю назад»)?

- [x] Если модель их не обыгрывает, она не нужна: наивный прогноз бесплатный
  > Сильный наивный ориентир для рядов с недельным ритмом — значение неделю назад или среднее за 4 недели.
- [ ] Наивные прогнозы всегда хуже
  > Не всегда — поэтому и сравнивают.
- [ ] Чтобы обучить модель
  > Наивный прогноз ничему не учится.
- [ ] Так требует метрика
  > Метрика к этому не обязывает.
:::

::: quiz 04-forecast
Прогноз делают накануне вечером на весь завтрашний день. Какие лаги допустимы?

- [x] Только те, что известны к 20:00 накануне: для 23:00 завтра это не меньше 28 часов, поэтому на практике берут лаги 48, 168 и т. д.
  > Значение «час назад» для завтрашнего 15:00 ещё неизвестно, а для 20:00–23:00 завтра неизвестен даже лаг 24 (последний известный час — 19:00 сегодня).
- [ ] Любые, начиная с часа назад
  > Для горизонта «завтра» это утечка.
- [ ] Только календарь, лаги нельзя
  > Лаги можно, если они достаточно старые.
- [ ] Только значение ровно год назад
  > Можно и ближе, если оно уже известно.
:::

::: quiz 04-forecast
Чем WAPE удобнее MAPE для часовых заказов?

- [x] WAPE делит сумму ошибок на сумму фактов и не взрывается на часах с нулём заказов
  > MAPE делит каждую ошибку на свой факт, и малые значения раздувают его.
- [ ] WAPE всегда меньше
  > Дело не в величине, а в устойчивости.
- [ ] WAPE не требует факта
  > Требует.
- [ ] MAPE нельзя посчитать в Python
  > Можно, но на нулях он не определён.
:::

::: quiz 05-project
Почему модель выбирают на июле, а не на августе?

- [x] Август — тест для итоговой оценки; если выбирать по нему, оценка станет завышенной
  > Июль — валидация для выбора, август — проверка один раз.
- [ ] В августе меньше данных
  > Размер тут ни при чём.
- [ ] Июль важнее для бизнеса
  > Дело в роли периодов, а не в их важности.
- [ ] Так решили случайно
  > Это стандартная схема train / valid / test по времени.
:::

::: quiz 05-project
Зачем строить план смен по квантилю 0.8 прогноза, а не по среднему?

- [x] Нехватка людей в час пик дороже лишнего бариста; квантиль даёт запас, чтобы людей хватало в большинстве часов
  > Это переводит прогноз в решение с учётом цены ошибок.
- [ ] Квантиль точнее среднего
  > Он не точнее, а осторожнее.
- [ ] Среднее нельзя перевести в число людей
  > Можно, но тогда в половине часов людей не хватит.
- [ ] Так требует модель
  > Модель умеет оба варианта.
:::
