**До выбора вариантов.** Прогноз на весь следующий день выпускают сегодня в 18:00. Будет ли фактическое число заказов за 17:00 завтрашнего дня допустимым признаком для 18:00 завтра? Объясните по моменту доступности.

::: quiz 01-resample
Что делает `s.resample("D").sum()` для часового ряда заказов?

- [x] Суммирует все часовые значения в каждых сутках
  > resample — группировка по периодам времени.
- [ ] Выбирает одно часовое значение в каждых сутках
  > Для этого есть `asfreq`, а `sum` складывает.
- [ ] Усредняет значения скользящим суточным окном
  > Это `rolling`.
- [ ] Сдвигает каждый часовой заказ на следующие сутки
  > Это `shift`.
:::

::: quiz 02-decompose
Из каких частей состоит ряд в классическом разложении?

- [x] Тренд, сезонность и остаток
  > Тренд — долгое движение, сезонность — повторяющийся ритм, остаток — всё прочее.
- [ ] Среднее, медиана и мода
  > Это описательные статистики.
- [ ] Обучение, валидация и тест
  > Это части данных для модели.
- [ ] Лаги 1, 24 и 168
  > Это признаки, а не части ряда.
:::

::: quiz 02-decompose
У ряда конечная дисперсия. Какая формулировка даёт общее определение слабой стационарности?

- [x] Среднее постоянно, ковариация зависит только от лага
  > При лаге 0 ковариация равна дисперсии. При любом фиксированном лаге ковариация должна быть одинаковой в разные даты.
- [ ] Все его значения одинаковы в любой момент времени
  > Постоянный ряд — стационарный частный случай. Общее определение допускает и меняющиеся значения, если среднее постоянно, а ковариация зависит только от лага.
- [ ] В его наблюдениях нет ни одного пропущенного значения
  > Пропуски — отдельный вопрос.
- [ ] Его значения увеличиваются с постоянной скоростью
  > Ряд с трендом нестационарен.
:::

::: quiz 02-decompose
Автокорреляция часовых заказов: лаг 1 — 0.72, лаг 24 — 0.71, лаг 168 — 0.74. Что из этого следует?

- [x] Похожесть на прошлое делает лаги 1, 24 и 168 кандидатами в признаки
  > Большая автокорреляция может отражать инерцию, сезонный ритм или тренд. Эти лаги стоит проверить как кандидаты на честной временной валидации.
- [ ] Ряд стационарен: это следует из высоких корреляций
  > Высокая автокорреляция сама по себе не устанавливает стационарность. ADF проверяет единичный корень при выбранных настройках; он не проверяет все свойства стационарности.
- [ ] Заказы растут каждый час, каждые сутки и каждую неделю
  > Автокорреляция говорит о похожести, а не о росте.
- [ ] Лага 168 достаточно: остальные не добавят информации
  > Разница 0,74 против 0,72 не показывает добавочную пользу признака. Сравните наборы лагов на одинаковых временных фолдах.
:::

::: quiz 03-features
В часовом ряду `s[t]` — число заказов за прогнозируемый час t. К выпуску известны только `s[t−1]` и более ранние значения. Как посчитать для строки t среднее за предыдущие 24 часа?

- [x] `s.shift(1).rolling(24).mean()`
  > Для строки t окно содержит s[t−24]…s[t−1]; самого ответа s[t] в нём нет.
- [ ] `s.rolling(24).mean()`
  > Окно заканчивается на текущем часе — в признак попадает сам ответ.
- [ ] `s.rolling(24, center=True).mean()`
  > Центрированное окно включает значения после t. На момент выпуска они неизвестны: в признак попадает будущее.
- [ ] `s.shift(-1).rolling(24).mean()`
  > `shift(-1)` сдвигает в обратную сторону: окно заходит на час вперёд, это ещё большая утечка.
:::

::: quiz 03-features
Какие лаги можно использовать для прогноза на час вперёд?

- [x] Лаги 1, 24 и 168 часов, известные к выпуску прогноза
  > Признак допустим, если все значения для его расчёта доступны к моменту выпуска прогноза.
- [ ] Будущее значение через час и текущий календарный час
  > Календарный час допустим: он известен заранее. Но будущее фактическое число заказов ещё неизвестно, поэтому этот набор использовать нельзя.
- [ ] Среднее текущих суток, включая прогнозируемый час
  > Окно захватывает ответ — утечка.
- [ ] Только лаги от суток: более короткие дают утечку
  > При часовом горизонте lag1 допустим, если предыдущий час уже завершён и данные доступны. Для прогноза на завтра граница зависит от времени выпуска.
:::

::: quiz 03b-time-split
Почему для рядов используют TimeSeriesSplit, а не KFold?

- [x] Обучение на прошлом, проверка на следующем периоде
  > Обычный KFold, даже без перемешивания, по очереди делает тестом каждый кусок ряда — и в обучение попадают куски после теста: модель учится на будущем.
- [ ] Обучение быстрее благодаря специальному формату дат
  > Скорость тут ни при чём.
- [ ] Обычный KFold не может работать с датами в таблице
  > Технически работает, но оценка будет нечестной.
- [ ] Каждый фолд получает больше обучающих строк, чем KFold
  > Наоборот, в первых фолдах их меньше.
:::

::: quiz 04-forecast
Зачем сравнивать модель с наивными прогнозами («как вчера», «как неделю назад»)?

- [x] Чтобы проверить выигрыш над дешёвым базовым решением
  > Сильный наивный ориентир для рядов с недельным ритмом — значение неделю назад или среднее за 4 недели.
- [ ] Чтобы сравнить модель за август с ориентиром за июль
  > Периоды могут различаться по уровню спроса и сложности. Чтобы сравнить методы, оцените оба на одних и тех же часах и по одной метрике.
- [ ] Чтобы использовать наивный прогноз как ответ для обучения
  > Цель обучения — фактические заказы. Если заменить их наивным прогнозом, модель будет воспроизводить ориентир; это не проверит её точность относительно факта.
- [ ] Чтобы подобрать параметры по выигрышу на итоговом тесте
  > Подбор параметров по итоговому тесту использует его ответы для выбора. Сравнивайте кандидатов с ориентиром на валидации, а итоговый тест оставьте для оценки выбранного решения.
:::

::: quiz 04-forecast
В 20:00 сегодня выпускают почасовой прогноз на весь завтрашний день. Последний известный факт — за 19:00 сегодня. Какие лаги доступны для каждого завтрашнего часа?

- [x] Лаги 48 и 168: их значения уже известны к выпуску
  > Да. Даже для последнего завтрашнего часа оба значения находятся до последнего известного факта.
- [ ] Лаги 1 и 24: достаточно, что они раньше целевого часа
  > Для завтрашнего 15:00 lag1 — завтра в 14:00. Он раньше целевого часа, но позже сегодняшнего выпуска.
- [ ] Только календарь: факты нельзя использовать на завтра
  > Прошлые факты допустимы, если они известны к выпуску. Lag48 и lag168 отвечают этому условию.
- [ ] Лаги от 24: каждый целевой час отстоит хотя бы на сутки
  > Для 23:00 завтра lag24 — 23:00 сегодня, а известны только часы до 19:00. При этой сетке единый минимальный лаг для всех часов равен 28.
:::

::: quiz 04-forecast
Чем WAPE удобнее MAPE для часовых заказов?

- [x] Делит сумму модулей ошибок на общий фактический спрос
  > WAPE не делит на факт каждого часа, поэтому нулевые часы сохраняются в сумме ошибок. Общая сумма фактического спроса должна быть положительной.
- [ ] Всегда даёт меньшую ошибку, чем любая оценка MAPE
  > Дело не в величине, а в устойчивости.
- [ ] Не требует фактических значений для подсчёта ошибки
  > Требует.
- [ ] Сначала исключает часы с нулём, затем считает среднюю долю
  > Это меняет выборку и теряет ошибки в нулевые часы. WAPE сохраняет их: суммирует все модули ошибок и делит на сумму всех фактов.
:::

::: quiz 05-project
В проекте к 31 июля в 20:00 семейство модели выбрали по 740 известным июльским ответам, параметры — временной кросс-валидацией на доступных данных. Как использовать августовские ответы для независимой итоговой оценки?

- [x] Август оставлен для итоговой оценки после выбора модели
  > К 31 июля 20:00 известны июльские ответы только по 19:00 включительно: 740 из 744 часов. Их и временную кросс-валидацию используют для выбора. Августовские результаты не используют для последующего подбора модели; иначе оценка перестаёт быть независимой.
- [ ] На всех августовских ответах дообучают модель перед оценкой
  > Тогда ответы оцениваемых часов попадут в обучение до получения прогноза. Для итоговой оценки прогнозы зафиксированной модели получают до присоединения соответствующих фактов.
- [ ] На августе выбирают лучший из июльских наборов параметров
  > Выбор среди готовых наборов тоже использует августовские ответы для подбора. Оценка победителя на том же августе уже не независима от выбора.
- [ ] На августе уточняют параметры, сохраняя список признаков
  > Фиксированный список признаков не защищает от подбора по тестовым ответам. Параметры также фиксируют до итоговой оценки на августе.
:::

::: quiz 05-project
В проекте модель точнее правила «среднее за 4 недели» по RMSE (4,216 против 4,353), но рабочих часов с нехваткой бариста у неё около 30 %, а у правила — 29 %. Какой вывод корректен?

- [x] RMSE симметричен, а нехватка возникает только при недоборе
  > Уменьшение RMSE не гарантирует уменьшения доли часов с нехваткой. Квантильная версия модели дала около 15 % нехватки рабочих часов после перевода прогноза в целый штат. Целевой квантиль 0,8 не гарантирует ни 80 % фактического покрытия, ни 80 % обеспеченных людьми часов.
- [ ] Ошибка в расчёте: меньший RMSE гарантирует меньше нехватки
  > Не всегда: RMSE одинаково штрафует ошибки вверх и вниз, а нехватка — только ошибки вниз в рабочие часы.
- [ ] Это доказывает, что модель переобучилась на августовских данных
  > Из двух агрегированных метрик нельзя установить переобучение. Они измеряют разные свойства: величину ошибки прогноза и наличие нехватки после перевода в людей.
- [ ] Модель с меньшим RMSE выгоднее после округления штата
  > Округление переводит прогноз в людей, но не задаёт цену недостающего и лишнего бариста-часа. Для выбора выгодного плана сравните обе эти величины при заранее выбранных ставках.
:::

::: quiz 05-project
У музейной кассы было 2,2,2 и 10 посетителей по часам. План по среднему выделил одного сотрудника мощностью 6 посетителей в час. Как оценить, выгоден ли дополнительный сотрудник в последний час?

- [x] Сопоставить цену часа и ущерб очереди из 4 посетителей
  > Дефицит возник в одном из четырёх часов. Запас оправдан, когда предотвращённые потери превышают стоимость дополнительного часа.
- [ ] Добавить сотрудника в половину часов независимо от очереди
  > Здесь дефицит только в последнем часе: среднее и округление не задают универсальную долю 50 %.
- [ ] Отказаться от сотрудника: среднего спроса 4 всегда достаточно
  > Среднее 4 не отменяет спрос 10 при мощности 6 в конкретный час.
- [ ] Выбрать штат только по сравнению RMSE двух прогнозов
  > RMSE не выражает цену очереди и лишней смены; для решения нужны затраты.
:::
