**До выбора вариантов.** В таблице есть длина в метрах и та же длина в сантиметрах. Почему второй столбец не добавляет информации для обычной линейной регрессии?

::: quiz 01-vectors
Что такое скалярное произведение вектора количеств (чашек) на вектор цен?

- [x] Общая выручка по всем позициям
  > Скалярное произведение — «взвешенная сумма», та же операция, что прогноз линейной модели.
- [ ] Средняя цена проданной чашки
  > Среднюю цену получим, если ещё разделить на число чашек.
- [ ] Вектор выручки по позициям
  > Результат — одно число.
- [ ] Расстояние между двумя векторами
  > Расстояние считается иначе — через разности.
:::

::: quiz 01-vectors
Почему перед расчётом расстояний между гостями признаки масштабируют?

- [x] Чтобы масштаб рублей не подавлял меньший масштаб визитов
  > Расстояние складывает разности; разница в 500 ₽ «весит» больше разницы в 5 визитов.
- [ ] Чтобы получить целочисленные расстояния между гостями
  > Целым оно от этого не станет.
- [ ] Чтобы исходные численные расстояния остались прежними
  > Масштабирование обычно меняет численные расстояния по сравнению с сырыми признаками. При повторной стандартизации сама смена единиц, напротив, может не менять итоговые расстояния.
- [ ] Чтобы применять только косинусное сходство между гостями
  > Косинус как раз меньше страдает от масштаба целого вектора.
:::

::: quiz 01-vectors
Две кофейни продают капучино, латте и раф в пропорции 3 : 2 : 1, но одна продаёт в десять раз больше другой. Какая мера скажет, что «вкусы гостей» у них одинаковые?

- [x] Косинусное сходство: результат 1
  > Косинус сравнивает направление векторов, а не длину: умножение вектора на 10 направление не меняет.
- [ ] Евклидово расстояние равно 0
  > Расстояние большое — один вектор в десять раз длиннее другого.
- [ ] Манхэттенское расстояние равно 0
  > Манхэттенское расстояние тоже зависит от размера продаж, а не от пропорций.
- [ ] Скалярное произведение равно 1
  > Скалярное произведение растёт вместе с объёмами продаж, к единице оно не привязано.
:::

::: quiz 01-vectors
Курьер едет по городу с прямоугольной сеткой улиц: 3 км на восток и 4 км на север. Какое расстояние честнее для оценки пути?

- [x] Манхэттенское: 7 км
  > По кварталам напрямую не проехать, путь — сумма модулей разностей по осям.
- [ ] Евклидово: 5 км
  > Это расстояние «по прямой», через дворы и дома.
- [ ] Косинусное: 1 км
  > Косинус сравнивает направления, а не длину пути.
- [ ] Произведение: 12 км
  > Произведение разностей расстоянием не является.
:::

::: quiz 02-matrices
`X` — (100, 3), `W` — (3, 2). Какой формы будет `X @ W`?

- [x] (100, 2)
  > Внутренние размеры (3 и 3) совпадают и «съедаются», остаются внешние.
- [ ] (3, 3)
  > Это форма `W @ W.T`.
- [ ] (100, 3)
  > Число столбцов результата берётся от `W`.
- [ ] Ошибка
  > Формы стыкуются: 3 и 3.
:::

::: quiz 02-matrices
Что делает транспонирование `X.T`?

- [x] Меняет строки и столбцы местами
  > Форма (n, k) становится (k, n).
- [ ] Находит обратную матрицу для исходной
  > Обратная — `np.linalg.inv`.
- [ ] Сортирует строки по первому столбцу
  > Порядок значений не меняется, меняется ориентация.
- [ ] Умножает матрицу на единичную
  > Умножение на единичную ничего не меняет.
:::

::: quiz 03b-own-model
В своём классе модели, совместимом со sklearn, что должен сделать fit, чтобы следующий predict применил выученные веса?

- [x] Записать веса в `self` и вернуть `self`
  > Атрибуты живут в объекте между вызовами методов, и `predict` их читает. `return self` позволяет писать `.fit(X, y).predict(X_new)`.
- [ ] Вернуть веса без записи в атрибуты объекта
  > `predict` не видит, что вернул `fit`. Он знает только сам объект (`self`) и его атрибуты.
- [ ] Оставить веса в локальной переменной `fit`
  > Обычная переменная исчезает, как только `fit` заканчивает работу. `predict` упадёт с `AttributeError`.
- [ ] Передать обучение весов методу `predict`
  > У `predict` нет ответов `y`, учиться ему не на чем. Его дело — применить выученное.
:::

::: quiz 02b-vectorize
Нужно посчитать сумму к оплате для 2 миллионов чеков. Какой вариант — скрытый цикл по строкам?

- [x] `df.apply(lambda r: r["amount"] * r["rate"], axis=1)`
  > apply(axis=1) вызывает Python-функцию отдельно для каждой строки. Это сохраняет накладные расходы перебора; точное время сравнивают измерением.
- [ ] `df["amount"] * df["rate"]`
  > Векторная операция над числовыми столбцами выполняет поэлементную арифметику без вашей Python-функции на каждой строке.
- [ ] `np.where(df["amount"] > 500, df["amount"] * 0.9, df["amount"])`
  > Условие и выбор заданы сразу для массива; явного Python-перебора строк здесь нет. Внутренние проходы по элементам остаются.
- [ ] `X @ w`
  > Матричное умножение — одна операция numpy.
:::

::: quiz 02b-vectorize
Вы замерили цикл и векторный вариант по одному разу и получили ускорение «в 15 раз», а у коллеги — «в 70». Что сделать?

- [x] Повторить замеры и сверить результаты вычислений
  > Первый вызов может включать подготовку, а любой замер — постороннюю нагрузку. Сначала проверьте совпадение результатов, затем повторите замеры реальных вызовов в одной среде. Минимум повторов оценивает время с наименьшей наблюдавшейся помехой, но не гарантирует фиксированного ускорения.
- [ ] Использовать первый запуск как наиболее честный
  > Первый вызов как раз часто самый медленный — в нём есть подготовка.
- [ ] Усреднить заявленные ускорения 15 и 70 раз
  > Замеры на разных компьютерах и в разных условиях не усредняют; повторяют замер у себя.
- [ ] Отказаться от векторизации из-за разных замеров
  > Разные одиночные замеры ещё не доказывают ни корректность расчётов, ни стабильное ускорение. Это повод проверить результаты и повторить измерение.
:::

::: quiz 02b-vectorize
km и p — одномерные массивы длины больше 1. Чем заменить поэлементное правило `if km > 8: p += 100`?

- [x] `p = np.where(km > 8, p + 100, p)`
  > Условие проверяется для всего массива, и для каждой строки выбирается одно из двух значений.
- [ ] `if (km > 8).any(): p += 100`
  > Надбавку получат все доставки, если хоть одна дальняя.
- [ ] `p = p + 100 * km`
  > Это не условие, а надбавка за каждый километр.
- [ ] `if km > 8: p = p + 100`
  > if с булевым массивом длины больше 1 не выбирает результат для каждой строки и вызывает ошибку неоднозначной истинности.
:::

::: quiz 03b-own-model
Свою модель-правило «всем одно среднее» прогнали через `cross_val_score` рядом с линейной регрессией. Зачем это делают?

- [x] Для сравнения с базовым решением на тех же фолдах
  > Сравнение показывает, даёт ли регрессия выигрыш по выбранной метрике относительно простого правила на тех же фолдах.
- [ ] Для сокращения времени обучения линейной регрессии
  > Правило на обучение регрессии не влияет.
- [ ] Для выполнения требования иметь ровно две модели
  > Работает и с одной.
- [ ] Для заполнения пропусков средним значением ответа
  > Это другая задача — `SimpleImputer`.
:::

::: quiz 03-normal-equation
Обычная линейная регрессия без штрафа минимизировала сумму квадратов ошибок на обучающих строках. Что значит «остатки перпендикулярны признакам»?

- [x] Остатки не содержат линейного вклада признаков
  > В оптимуме X₁ᵀ(y − X₁w)=0, где X₁ включает столбец единиц, если модель обучена со свободным членом. Поэтому линейным изменением весов сумму квадратов уже не уменьшить.
- [ ] Остатки для всех обучающих строк равны нулю
  > Остатки могут быть ненулевыми: ортогональность означает нулевые скалярные произведения со столбцами X₁, а не нулевой вектор остатка.
- [ ] Все признаки статистически независимы друг от друга
  > Это про остатки, а не про признаки.
- [ ] Остатки доказывают переобучение линейной модели
  > Это свойство оптимума обычного МНК на обучении, а не свидетельство переобучения.
:::

::: quiz 03-normal-equation
В таблице квартир указаны площадь в м² и та же площадь в см². Что произойдёт с наилучшей ошибкой обычной линейной регрессии на этих строках, если убрать второй столбец?

- [x] Останется прежней: столбец см² выражается через м²
  > Множество достижимых прогнозов не изменяется: коэффициент второго столбца можно перенести в первый.
- [ ] Обязательно вырастет из-за уменьшения числа признаков
  > Дублирующая колонка не добавляет независимого направления для прогноза.
- [ ] Обязательно станет нулевой после удаления второго столбца
  > Зависимость столбцов не гарантирует, что линейная модель точно объясняет цель.
- [ ] Станет неопределённой из-за потери одного из столбцов
  > Прогнозы и ошибку вычислить можно; неоднозначными были коэффициенты двух зависимых колонок.
:::

::: quiz 04-transform
На X и X @ P с обратимой P обучают обычную линейную регрессию без штрафа и дерево. Свободный член у регрессии обрабатывается одинаково. Сравниваем качество на тех же обучающих строках, пренебрегая погрешностью вычислений. Какой вывод верен?

- [x] У регрессии без штрафа сохранится, у дерева может меняться
  > Обратимая P сохраняет множество достижимых прогнозов, поэтому оптимальные прогнозы МНК на обучении одинаковы. Дерево делит по отдельным признакам, и после смешивания его качество может измениться. На любых новых строках два независимых fit дополнительно требуют единственности решения; со свободным членом достаточно полного ранга [1, X]. Явный перенос весов P⁻¹w сохраняет прогноз любой строки и без этого требования.
- [ ] У обеих моделей сохранится: обратимость гарантирует прежние прогнозы
  > Дерево чувствительно к таким смесям признаков.
- [ ] Качество обеих моделей обязательно ухудшится
  > Для обычного МНК без штрафа оптимальные прогнозы на этих обучающих строках сохраняются.
- [ ] У регрессии ухудшится, у дерева сохранится
  > Наоборот.
:::

::: quiz 05-project
Почему простое масштабирование каждого признака своим ненулевым множителем плохо прячет анкеты?

- [x] Множители восстанавливаются из известных пар значений
  > Одной строки достаточно, если все четыре координаты ненулевые; иначе нужны дополнительные строки. Смесь случайной матрицей прячет лучше, но и её вскрывают по нескольким известным строкам.
- [ ] Масштабирование обязательно ухудшает точность модели
  > У обычного МНК без штрафа минимум ошибки на обучении сохраняется: ненулевое масштабирование обратимо. Для других моделей и штрафов такой общей гарантии нет.
- [ ] Масштабирование нельзя обратить даже со знанием ключа
  > Масштабирование ненулевыми числами обратимо.
- [ ] Умножение обязательно делает все скрытые данные целыми
  > Нет.
:::

  > Линейное преобразование вскрывается линейной алгеброй.

  > Одна строка даёт мало уравнений для 16 неизвестных.
