## Таблица — это матрица

Матрица — прямоугольная таблица чисел. Таблица признаков `X` из прошлых глав — матрица: строки — объекты, столбцы — признаки.

```python
import numpy as np
X = np.array([
    [1.0, 2, 1],     # км, позиций, пеший курьер
    [4.0, 1, 0],
    [6.0, 4, 0],
])
print(X.shape)       # (строк, столбцов)
print(X[1])          # вторая строка — вектор одной доставки
print(X[:, 0])       # первый столбец — расстояния всех доставок
```

`X[:, 0]` читается «все строки, столбец 0». В pandas то же было `df.iloc[:, 0]`, а `df.values` превращает DataFrame в такую матрицу.

## Матрица на вектор: прогноз для всех

В прошлом уроке мы считали прогноз для одной доставки: `x @ w + b`. Для всей таблицы сразу — **умножение матрицы на вектор**: каждая строка `X` скалярно умножается на `w`.

```python
import numpy as np
X = np.array([
    [1.0, 2, 1],
    [4.0, 1, 0],
    [6.0, 4, 0],
])
w = np.array([3.9, 1.7, 18.5])
b = 8.0
print((X @ w + b).round(1))
```

Распишем первую строку: 1 · 3.9 + 2 · 1.7 + 1 · 18.5 + 8 = 3.9 + 3.4 + 18.5 + 8 = **33.8**. Вторая: 4 · 3.9 + 1 · 1.7 + 0 + 8 = **25.3**. Третья: 6 · 3.9 + 4 · 1.7 + 0 + 8 = **38.2**.

::: figure matvec
Пример из урока: три доставки, три веса и свободный член. Каждая строка превращается в один прогноз.
:::

Правило формы: (3 × **3**) @ (**3**,) → (3,) — три строки, в каждой столько же чисел, сколько весов.

Получился вектор из трёх прогнозов — по одному на строку. Ровно это делает `model.predict(X)` у линейной регрессии.

::: sql
`SELECT km * 3.9 + items * 1.7 + walk * 18.5 + 8 AS forecast FROM deliveries` — это и есть X @ w + b: одна и та же взвешенная сумма для каждой строки.
:::

## Матрица на матрицу

Пример из жизни кофейни. Рецепты: сколько граммов кофе, мл молока и граммов сиропа идёт на один напиток. Цены: сколько стоит грамм/мл у двух поставщиков.

```python
import numpy as np
recipes = np.array([       # кофе, г | молоко, мл | сироп, г
    [18, 150, 0],          # капучино
    [18, 220, 0],          # латте
    [18, 120, 25],         # раф
])
prices = np.array([        # поставщик А | поставщик Б
    [2.40, 2.10],          # кофе, ₽ за г
    [0.09, 0.11],          # молоко, ₽ за мл
    [0.80, 0.60],          # сироп, ₽ за г
])
cost = recipes @ prices
print(cost.round(2))
print(cost.shape)
```

Результат — таблица 3 × 2: себестоимость каждого напитка у каждого поставщика. Элемент в строке $i$, столбце $j$ — скалярное произведение **строки $i$** рецептов на **столбец $j$** цен. Например, капучино у поставщика А: 18 · 2.40 + 150 · 0.09 + 0 · 0.80 = 56.7 ₽.

::: figure matmul-cell
Как получается одна клетка результата: строка «капучино» из рецептов умножается на столбец «поставщик А» из цен — ингредиент на ингредиент, и всё складывается. Остальные пять клеток считаются так же, каждая по своей паре «строка — столбец».
:::

**Что здесь происходит:**

- `recipes` — 3 напитка × 3 ингредиента; `prices` — 3 ингредиента × 2 поставщика. Ингредиенты в обеих матрицах идут в одном порядке — без этого произведение бессмысленно.
- `recipes @ prices` — для каждой пары «напиток, поставщик» скалярное произведение строки рецепта на столбец цен.

Правило формы: (3 × **3**) @ (**3** × 2) → (3 × 2). Внутренние размеры (число ингредиентов) должны совпадать — иначе непонятно, что с чем перемножать.

::: predict
```python static
import numpy as np
A = np.ones((4, 3))
B = np.ones((3, 5))
print((A @ B).shape)
```

- `(3, 3)`
- [x] `(4, 5)`
- `Ошибка ValueError`

Почему: (4 × 3) @ (3 × 5) — внутренние размеры 3 и 3 совпадают, результат берёт внешние: 4 × 5.
:::

::: quiz
В результате `cost = recipes @ prices` возьмём элемент в строке «раф» и столбце «поставщик Б». Что это за число?

- [x] Себестоимость одного рафа, если все ингредиенты покупать у поставщика Б
  > Это скалярное произведение строки рецепта рафа (граммы и миллилитры) на столбец цен Б: каждый ингредиент × его цена, всё сложено.
- [ ] Цена сиропа у поставщика Б
  > Цена сиропа — элемент самой матрицы `prices`. В произведении каждый элемент собирает все ингредиенты напитка.
- [ ] Себестоимость всех трёх напитков у поставщика Б
  > Это была бы сумма всего столбца Б в `cost`. Один элемент — один напиток у одного поставщика.
- [ ] Сколько граммов сиропа идёт в раф
  > Это элемент матрицы `recipes`. В произведении количества уже умножены на цены — получаются рубли.
:::

## Порядок важен

С числами 2 · 3 = 3 · 2. С матрицами — нет. `prices @ recipes` — это (3 × 2) @ (3 × 3): внутренние размеры 2 и 3 не совпадают, и numpy выдаст ошибку:

```python error
import numpy as np
recipes = np.ones((3, 3))
prices = np.ones((3, 2))
print(prices @ recipes)
```

Даже когда оба порядка определены (квадратные матрицы), результаты обычно разные. Поэтому формулы с матрицами читают строго слева направо.

::: figure shape-rule
Пять произведений из урока. Выделены внутренние размеры: они обязаны совпасть, по ним идёт сумма. Внешние размеры становятся формой ответа.
:::

::: sql
Произведение матриц — это `JOIN` двух таблиц по общему ключу и `SUM` с группировкой: `SELECT r.drink, p.supplier, SUM(r.amount * p.price) FROM recipes r JOIN prices p ON r.ingredient = p.ingredient GROUP BY r.drink, p.supplier`. Общий ключ (ингредиент) — это и есть «внутренний размер», который должен совпадать.
:::

::: quiz
`X` имеет форму (1841, 3), `w` — (3,). Что получится при `w @ X`?

- [x] Ошибка: у `w` 3 элемента, а у `X` 1841 строка — формы не стыкуются
  > Умножение идёт «строка первого на столбец второго»: внутренние размеры должны совпадать. `X @ w` — (1841, 3) @ (3,) — работает.
- [ ] То же, что `X @ w`
  > Матричное умножение не перестановочно: порядок меняет и смысл, и формы.
- [ ] Вектор из 3 чисел
  > Получился бы из `v @ X`, где `v` — вектор из 1841 числа. А `w @ X.T` даёт те же 1841 прогноз, что и `X @ w`.
- [ ] Матрица 3 × 3
  > Такая форма у `X.T @ X`, а не у этого произведения.
:::

## Транспонирование и единичная матрица

**Транспонирование** `A.T` меняет строки и столбцы местами: матрица 3 × 2 становится 2 × 3. Пригодится в следующем уроке: в формуле линейной регрессии стоит `X.T @ X`.

**Единичная матрица** `np.eye(n)` — единицы на диагонали, нули вокруг. Это «единица» в мире матриц: `A @ np.eye(n)` равно `A`. Она понадобится в следующем уроке: через неё определяется обратная матрица, $A^{-1} A = I$ — так же, как $3 \cdot \frac{1}{3} = 1$.

::: figure transpose-eye
Слева: `A.T` для `A = [[1, 2], [3, 4], [5, 6]]` — каждая строка `A` становится столбцом, форма 3 × 2 превращается в 2 × 3. Справа: `A @ np.eye(2)` — (3 × 2) @ (2 × 2) → (3 × 2); клетка [1, 0] = 3·1 + 4·0 = 3: единица забирает «свой» элемент строки, ноль гасит остальные, и получается снова `A`.
:::

```python
import numpy as np
A = np.array([[1, 2], [3, 4], [5, 6]])
print(A.T)
print(A.T.shape)
print((A @ np.eye(2) == A).all())
```

**Что здесь происходит:**

- `A.T` — строки становятся столбцами: из 3 × 2 получается 2 × 3.
- `np.eye(2)` — единичная матрица 2 × 2; `A @ np.eye(2)` — (3 × 2) @ (2 × 2) → (3 × 2), и это снова `A`.
- `(... == A).all()` — все элементы совпали.

## Разберём вместе: выручка сети одной формулой

Матричное умножение особенно удобно, когда расчёт надо сделать «для всех сразу». Пусть есть продажи трёх напитков в четырёх кофейнях за неделю и цены. Нужны: выручка каждой кофейни, выручка по каждому напитку и общая.

```python
import numpy as np

sales = np.array([         # капучино, латте, раф — продано за неделю
    [420, 310, 90],        # PRM-1
    [260, 280, 40],        # PRM-2
    [510, 330, 120],       # KZN-1
    [300, 200, 60],        # UFA-1
])
price = np.array([190, 210, 260])

by_shop = sales @ price                    # (4 × 3) @ (3,) → (4,)
by_drink = sales.sum(axis=0) * price       # сначала штуки по сети, потом × цена
total = by_shop.sum()
print("по кофейням:", by_shop)
print("по напиткам:", by_drink)
print("всего:", total, "| сходится:", total == by_drink.sum())
```

**Что здесь происходит:**

- `sales @ price` — каждая строка (кофейня) скалярно умножается на цены: выручка кофейни.
- `sales.sum(axis=0)` — сумма по столбцам: сколько каждого напитка продано по сети; `* price` — поэлементно, выручка по напитку.
- Общая выручка двумя путями — по кофейням и по напиткам — должна совпасть; это быстрая проверка, что формулы верные.

**Что получилось:** одна строка `sales @ price` заменяет цикл по кофейням и суммы по напиткам. С тем же успехом в `sales` могло бы быть 300 кофеен и 40 напитков — код не изменится. Так же устроен и прогноз модели: `X @ w` для миллиона строк — одна операция. Почему одна операция настолько быстрее цикла по строкам и как это замерить — в следующем уроке, «Без циклов: векторизация и замер времени».

## task: network | Выручка сети | base

### hint
Выручка кофеен — `sales @ price`; по напиткам — `sales.sum(axis=0) * price`.

### hint
Прирост — та же формула, только вместо цен — вектор изменений цен: `(sales @ np.array([10, 10, 0])).sum()`.

### solution
```python
import numpy as np

by_shop = sales @ price
by_drink = sales.sum(axis=0) * price
best_shop = int(by_shop.argmax())
share_raf = round(float(by_drink[2] / by_drink.sum()), 3)
growth = int((sales @ np.array([10, 10, 0])).sum())
print(by_shop, by_drink, best_shop, share_raf, growth)
```

### explain
Прирост выручки считается той же формулой, что и выручка, — только вместо цен подставлен вектор изменений цен. Это свойство линейности: (цены + изменения) @ продажи = цены @ продажи + изменения @ продажи. Поэтому линейные модели так удобны для «что будет, если…»: эффект изменения можно посчитать отдельно, не пересчитывая всё. (При условии, что продажи от цены не изменятся, — а это уже вопрос не алгебры, а эластичности спроса.)

## task: by-hand | Элемент произведения руками | base

Для матриц `A` (2 × 3) и `B` (3 × 2) посчитайте произведение `C = A @ B`, а элемент `C[1, 0]` — ещё и вручную, как сумму произведений строки 1 матрицы `A` на столбец 0 матрицы `B` (через цикл или `sum`, без `@`). Сохраните `C` и `c10`.

### starter
```python
import numpy as np
A = np.array([[1, 2, 3], [4, 5, 6]])
B = np.array([[7, 8], [9, 10], [11, 12]])

```

### check

### hint
Элемент (i, j) произведения — скалярное произведение строки i первой матрицы на столбец j второй.

### hint
Строка 1 — `A[1]`, столбец 0 — `B[:, 0]`. Сумма произведений: `sum(a * b for a, b in zip(A[1], B[:, 0]))`.

### solution
```python
import numpy as np
A = np.array([[1, 2, 3], [4, 5, 6]])
B = np.array([[7, 8], [9, 10], [11, 12]])
C = A @ B
c10 = sum(a * b for a, b in zip(A[1], B[:, 0]))
```

### explain
`C[1, 0]` — это строка 1 матрицы `A` (4, 5, 6), умноженная на столбец 0 матрицы `B` (7, 9, 11): 4·7 + 5·9 + 6·11 = 28 + 45 + 66 = 139. Так считается каждый элемент: строка первой матрицы «встречается» со столбцом второй, поэтому число столбцов `A` (3) должно совпадать с числом строк `B` (3). Результат имеет форму 2 × 2: строк — как у `A`, столбцов — как у `B`.

## task: gram | Что внутри X.T @ X | plus

В следующем уроке в формуле регрессии появится `X.T @ X`. Разберёмся, что это. Возьмите из доставок признаки `distance_km` и `items` (заготовка: `X`, n строк). Посчитайте `G = X.T @ X` и проверьте, что диагональ — суммы квадратов столбцов, а элемент (0, 1) — сумма произведений `distance_km · items`: `diag_ok`, `off_ok` (`True/False`). Затем центрируйте столбцы (вычтите средние) — `Xc` — и сравните `Xc.T @ Xc / (n − 1)` с ковариационной матрицей `np.cov(X, rowvar=False)`: `cov_ok`. **Ковариация** двух признаков — средний «совместный размах» их отклонений от средних; это корреляция до деления на разбросы: corr = cov / (σ₁ · σ₂). Ковариационная матрица — таблица ковариаций всех пар признаков, на диагонали — дисперсии. `rowvar=False` говорит `np.cov`, что признаки лежат в столбцах (по умолчанию она ждёт их в строках). В `corr` — корреляцию расстояния и числа позиций из этой матрицы (3 знака).

### setup
```python
import numpy as np
import pandas as pd
_d = pd.read_csv("deliveries.csv")
X = _d[["distance_km", "items"]].values.astype(float)
n = len(X)
```

### starter
```python
import numpy as np

G = X.T @ X

```

### check
```python
import numpy as _np
X0, n0 = need('X'), need('n')
assert bool(need('diag_ok')) and bool(need('off_ok')), 'diag_ok и off_ok должны быть True — проверьте сравнение через np.isclose.'
assert bool(need('cov_ok')), 'cov_ok должно быть True: Xc.T @ Xc / (n - 1) совпадает с np.cov(X, rowvar=False).'
C = _np.cov(X0, rowvar=False)
assert close(need('corr'), round(float(C[0, 1] / _np.sqrt(C[0, 0] * C[1, 1])), 3), 0.0011), f'corr = {need("corr")}.'
```

### hint
Суммы квадратов столбцов — `(X ** 2).sum(axis=0)`; сравнение с диагональю — `np.allclose(np.diag(G), ...)`. Сумма произведений — `(X[:, 0] * X[:, 1]).sum()`.

### hint
Центрирование — `Xc = X - X.mean(axis=0)`. Ковариация из матрицы: `C = Xc.T @ Xc / (n - 1)`; корреляция — `C[0, 1] / np.sqrt(C[0, 0] * C[1, 1])`.

### solution
```python
import numpy as np

G = X.T @ X
diag_ok = bool(np.allclose(np.diag(G), (X ** 2).sum(axis=0)))
off_ok = bool(np.isclose(G[0, 1], (X[:, 0] * X[:, 1]).sum()))
Xc = X - X.mean(axis=0)
C = Xc.T @ Xc / (n - 1)
cov_ok = bool(np.allclose(C, np.cov(X, rowvar=False)))
corr = round(float(C[0, 1] / np.sqrt(C[0, 0] * C[1, 1])), 3)
print(G.round(1), C.round(3), corr, sep="\n")
```

### explain
`X.T @ X` — это таблица «как признаки связаны друг с другом»: на диагонали — насколько велик каждый признак, вне диагонали — насколько признаки меняются вместе. Если столбцы центрировать, это (с точностью до деления на n − 1) ковариационная матрица. В формуле линейной регрессии эта матрица отвечает за то, чтобы веса признаков не «делили» одну и ту же информацию дважды: если признаки сильно связаны, как увидим в уроке «Как обучается линейная регрессия», задача становится неустойчивой. Здесь корреляция около нуля: расстояние и число позиций в заказе почти не связаны, и с такой парой признаков формула работает спокойно.

import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression

d = pd.read_csv("deliveries.csv")
