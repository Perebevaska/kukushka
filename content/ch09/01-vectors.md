## Строка таблицы — это вектор

Возьмём гостя из главы 7: 5 визитов за квартал, 12 дней с последнего визита, 1 жалоба. Эти три числа в фиксированном порядке — **вектор**. В numpy это одномерный массив:

```python
import numpy as np
guest = np.array([5, 12, 1])     # визиты, дней с визита, жалобы
print(guest, guest.shape)
```

`shape` = `(3,)` — три числа, одно измерение. Порядок важен: `[5, 12, 1]` и `[12, 5, 1]` — разные гости.

Так устроена любая таблица признаков: каждая строка `X` — вектор, а сама `X` — набор векторов (матрица, следующий урок).

## Действия с векторами

Векторы одинаковой длины складываются и вычитаются **поэлементно**, а умножение на число умножает каждый элемент:

```python
import numpy as np
q1 = np.array([120, 80, 30])     # продажи капучино, латте, раф в 1-й кофейне
q2 = np.array([90, 110, 20])     # то же во 2-й
print(q1 + q2)                   # продажи сети
print(q1 - q2)                   # разница кофеен
print(1.1 * q1)                  # план на +10 %
```

**Что здесь происходит:**

- `q1 + q2` — складываются элементы на одинаковых местах: 120 + 90, 80 + 110, 30 + 20 → `[210 190 50]`.
- `q1 - q2` → `[30 -30 10]`: первая кофейня продаёт на 30 капучино больше, на 30 латте меньше.
- `1.1 * q1` → каждый элемент умножен на 1.1.
- Векторы разной длины так складывать нельзя: numpy выдаст ошибку о несовпадении форм.

::: sql
Это то же, что арифметика столбцов в SELECT: `SELECT a + b, a * 1.1 FROM t` — только здесь «строка» одна, а операция применяется к каждому её элементу.
:::

## Скалярное произведение

Главная операция ML. **Скалярное произведение** двух векторов — сумма произведений элементов на одинаковых местах: $a \cdot b = a_1 b_1 + a_2 b_2 + \ldots$ В numpy — оператор `@` (или `np.dot`).

```python
import numpy as np
qty = np.array([120, 80, 30])            # продано чашек
price = np.array([190, 210, 260])        # цена чашки
print(qty @ price)                       # выручка: 120·190 + 80·210 + 30·260
```

Руками: 120 · 190 = 22 800, 80 · 210 = 16 800, 30 · 260 = 7 800; сумма — **47 400** ₽.

::: figure dot-pairs
Скалярное произведение в два шага: пары «количество × цена» на одинаковых местах перемножаются, а произведения складываются в одно число — выручку.
:::

Выручка = количество × цена по каждому напитку, сложенное вместе — это и есть скалярное произведение. Тот же смысл у прогноза линейной модели из главы 6: **прогноз = признаки @ веса + свободный член**.

```python
import numpy as np
x = np.array([3.5, 2, 1])        # км, позиций в заказе, пеший курьер (1/0)
w = np.array([3.9, 1.7, 18.5])   # минут на км, на позицию, надбавка пешему
b = 8.0                          # свободный член
print(round(x @ w + b, 2), "минут")
```

Руками: 3.5 · 3.9 + 2 · 1.7 + 1 · 18.5 + 8 = 13.65 + 3.4 + 18.5 + 8 = **43.55** минуты — именно так модель из главы 6 считает прогноз для каждого заказа.

::: tip Аналогия
Скалярное произведение похоже на подсчёт баллов на конкурсе бариста: за вкус, подачу и скорость ставят оценки, у каждого критерия свой вес, а итог — сумма «оценка × вес». Вектор оценок у каждого участника свой, а вектор весов один на всех — как веса модели одни на все заказы. Отличие одно: в скалярном произведении оба вектора равноправны, и если поменять их местами, результат не изменится.
:::

::: predict
```python static
import numpy as np
a = np.array([1, 2, 3])
b = np.array([4, 0, -1])
print(a @ b)
```

- `[4, 0, -3]`
- [x] `1`
- `9`

Почему: 1·4 + 2·0 + 3·(−1) = 4 + 0 − 3 = 1. Поэлементное произведение `a * b` дало бы `[4, 0, -3]`, а `@` ещё и складывает.
:::

::: quiz
Модель считает прогноз как `x @ w + b`. Почему признаки в `x` должны идти строго в том же порядке, что и веса в `w`?

- [x] `@` перемножает элементы на одинаковых местах: если поменять порядок, километры умножатся на вес «за позицию», и прогноз станет бессмысленным
  > Скалярное произведение не знает названий — только позиции. Каждому весу достаётся тот признак, что стоит на его месте.
- [ ] Не обязательно: от перестановки слагаемых сумма не меняется
  > Сумма не меняется, если переставить **пары** «признак × вес» вместе. Если переставить только признаки, пары станут другими.
- [ ] Иначе numpy выдаст ошибку о несовпадении форм
  > Формы те же — три числа и три числа. numpy молча посчитает неверный результат, ошибки не будет.
- [ ] Порядок важен только для свободного члена `b`
  > `b` — одно число, у него нет порядка. Порядок важен именно для пар в `x @ w`.
:::

## Длина и расстояние

**Длина** (норма) вектора — корень из суммы квадратов элементов, по теореме Пифагора: `np.linalg.norm(a)`. Для трёх и более координат формула та же: это Пифагор, применённый несколько раз (сначала диагональ по двум осям, потом она — катет вместе с третьей осью). **Расстояние** между двумя векторами — длина их разности. Именно так kNN из главы 7 искал «соседей»:

```python
import numpy as np
a = np.array([5, 12])            # визиты, дней с визита
b = np.array([2, 40])
print(np.linalg.norm(a - b))     # √((5−2)² + (12−40)²)
```

Руками: разность (3, −28), квадраты 9 и 784, сумма 793, корень ≈ **28.2**.

Расстояние почти целиком определяет давность (28 дней разницы), а визиты (3) почти не влияют — поэтому перед kNN признаки масштабировали.

### Манхэттенское расстояние

Расстояние «по прямой» подходит не всегда. Курьер «Зерна» не летит над крышами, а едет по улицам: сначала вдоль одной, потом, после поворота, вдоль другой. Если выбирать курьера по прямой, можно отправить того, кому на деле ехать дальше.

::: tip Аналогия
Город с прямоугольной сеткой улиц похож на шахматную доску, по которой ходит ладья: только по горизонтали и вертикали. Её путь — сумма ходов по каждой оси, срезать по диагонали нельзя. Аналогия хромает в том, что настоящие улицы не идеально прямые, поэтому это приближение, а не точный маршрут.
:::

Игрушечный пример. Кофейня стоит в точке (0, 0), заказ — в 3 км к востоку и 4 км к северу, то есть в точке (3, 4).

- По прямой (как раньше): разности 3 и 4, квадраты 9 и 16, сумма 25, корень — **5 км**.
- По улицам: 3 км на восток плюс 4 км на север — **7 км**.

::: figure manhattan-grid
Одна и та же пара точек, два расстояния. Синяя стрелка — по прямой, 5 км. Красный путь — по улицам, 7 км; любой путь «ступеньками» вверх-вправо даёт те же 7 км.
:::

Второе число называют **манхэттенским расстоянием** (по сетке кварталов Манхэттена). Это сумма модулей разностей по всем координатам:

$$
d_1(a, b) = |a_1 - b_1| + |a_2 - b_2| + \ldots + |a_n - b_n|
$$

Здесь $a$ и $b$ — два вектора, $a_1, b_1$ — их первые элементы и так далее, $|\ldots|$ — модуль (число без знака). Обычное расстояние по прямой называют **евклидовым**.

```python
import numpy as np
shop = np.array([0.0, 0.0])          # кофейня
order = np.array([3.0, 4.0])         # заказ: 3 км на восток, 4 км на север
diff = order - shop

print("по прямой:", np.linalg.norm(diff))
print("по улицам:", np.abs(diff).sum())
print("то же через norm:", np.linalg.norm(diff, ord=1))

a = np.array([5, 12])                # гости из примера выше
b = np.array([2, 40])
print("гости:", round(float(np.linalg.norm(a - b)), 1), int(np.abs(a - b).sum()))
```

**Что здесь происходит:**

- `np.abs(diff)` — модуль каждого элемента: отрицательные разности становятся положительными.
- `.sum()` — складываем пути по осям: 3 + 4 = 7.
- `np.linalg.norm(diff, ord=1)` — то же самое встроенной функцией. Параметр `ord=1` выбирает манхэттенскую длину. По умолчанию `ord=2`, это обычная евклидова.
- Последняя строка — для гостей `a` и `b`: евклидово ≈ 28.2, манхэттенское 3 + 28 = 31.

**Как читать результат.** Манхэттенское расстояние никогда не меньше евклидова. Они совпадают, только если векторы отличаются по одной координате, когда ехать надо строго по одной улице. В kNN его включают параметром: `KNeighborsRegressor(metric="manhattan")`. Названия L1 (манхэттенское) и L2 (евклидово) ещё встретятся: так же называют штрафы в регуляризации Lasso и Ridge.

::: predict
```python static
import numpy as np
a = np.array([1, 5])
b = np.array([4, 2])
print(np.abs(a - b).sum(), (a - b).sum())
```

- `6 6`
- [x] `6 0`
- `0 0`

Почему: разности −3 и 3. С модулем получается 3 + 3 = 6, а без модуля −3 + 3 = 0, будто точки совпадают.
:::

::: warn Типичные ошибки
- **Забыли модуль.** `(a - b).sum()` вместо `np.abs(a - b).sum()`: разности с разными знаками гасят друг друга. Симптом — «расстояние» отрицательное или нулевое между разными точками.
- **Ждут, что другая метрика решит проблему масштаба.** Манхэттенское расстояние, как и евклидово, складывает дни с визитами. Без масштабирования признаков оно тоже смотрит в основном на самый «крупный» признак.
:::

## Похожесть направлений: косинус

Иногда важен не размер, а **состав**. Две кофейни продают капучино, латте и раф в пропорции 3 : 2 : 1, но одна в десять раз больше другой. По расстоянию они далеки, а по «вкусам гостей» одинаковы. Для этого есть **косинусное сходство**:

$$
\cos(a, b) = \frac{a \cdot b}{|a| \cdot |b|}
$$

Оно равно 1, если векторы смотрят в одну сторону, 0 — если «перпендикулярны» (ничего общего), −1 — если противоположны.

::: tip Аналогия
Косинус сравнивает рецепты, а не размер порции. Маленький и большой латте сделаны по одному рецепту: молока и кофе в той же пропорции, просто всего больше. Расстояние скажет «очень разные напитки», а косинус — «одинаковые». Но у продаж бывают и отрицательные «направления» (например, отклонения от плана), и тогда косинус уходит ниже нуля, а у рецепта отрицательных долей не бывает.
:::

```python
import numpy as np
small = np.array([30, 20, 10])
big = np.array([300, 200, 100])
other = np.array([10, 10, 50])

def cos(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

print(round(float(np.linalg.norm(small - big)), 1), round(float(cos(small, big)), 3))
print(round(float(np.linalg.norm(small - other)), 1), round(float(cos(small, other)), 3))
```

**Что здесь происходит:**

- `cos(a, b)` — скалярное произведение, делённое на произведение длин. Деление убирает размер: у `big` и `small` длины отличаются в 10 раз, но это сокращается.
- Для каждой пары печатаем расстояние и косинус.

Маленькая и большая кофейни: расстояние огромное, косинус 1. Кофейня с упором на раф ближе к маленькой по расстоянию, но по косинусу заметно отличается. Косинус лежит в основе рекомендаций («гостям с похожими вкусами нравится…») и поиска похожих текстов (глава 13).

::: figure cosine-shares
Те же три кофейни как доли напитков. У маленькой и большой полоски совпадают — косинус 1, хотя расстояние между ними 336.7. Кофейня с упором на раф ближе по расстоянию (45.8), но состав другой — косинус 0.514.
:::

::: quiz
Две кофейни продают латте, капучино и раф в пропорции 5 : 3 : 2, но одна в десять раз больше другой. Что покажут расстояние и косинус между векторами их продаж?

- [x] Расстояние большое, косинус равен 1: направление одинаковое, разный только масштаб
  > Косинус сравнивает пропорции, а не объёмы. Поэтому им ищут похожие вкусы, а не похожие размеры.
- [ ] Оба покажут, что кофейни непохожи
  > Расстояние — да, а косинус увидит одинаковый вкус.
- [ ] Расстояние нулевое
  > Векторы различаются в десять раз, расстояние между ними большое.
- [ ] Косинус равен 0
  > Ноль — у перпендикулярных векторов, то есть совсем разных пропорций.
:::

## Разберём вместе: масштаб меняет «соседей»

Вернёмся к расстоянию между гостями. Если один признак измеряется в днях (десятки), а другой — в визитах (единицы), расстояние фактически смотрит только на дни. Проверим на трёх гостях, кто кому «ближе» до и после масштабирования.

```python
import numpy as np

guests = np.array([
    [5, 12],     # гость A: 5 визитов, 12 дней с визита
    [1, 14],     # гость B: почти тот же срок, но визитов мало
    [6, 30],     # гость C: визиты как у A, но давно не был
], dtype=float)

def nearest_to_A(X):
    d = np.linalg.norm(X[1:] - X[0], axis=1)      # расстояния от A до B и до C
    return ["B", "C"][d.argmin()], d.round(2)

print("без масштаба:", nearest_to_A(guests))
spread = np.array([3.0, 25.0])          # типичный разброс по всем гостям: визиты ±3, дни ±25
scaled = guests / spread
print("с масштабом: ", nearest_to_A(scaled))

d = np.array([4.47, 18.03, 0.5, 9.1])   # расстояния до четырёх гостей
print(np.argsort(d)[:2].tolist())        # номера двух ближайших
```

**Что здесь происходит:**

- `guests` — таблица 3 × 2: три гостя, два признака. Такие двумерные массивы подробно разберём в следующем уроке; здесь хватит того, что `X[0]` — первая строка, а `X[1:]` — все строки, кроме первой.
- `["B", "C"][d.argmin()]` — `argmin` даёт номер наименьшего расстояния (0 или 1), а по нему берём имя гостя из списка.
- `X[1:] - X[0]` — из каждой строки (B и C) вычитается вектор A; numpy сам «размножает» A на обе строки.
- `np.linalg.norm(..., axis=1)` — длина каждой строки разности, то есть расстояние до A.
- `np.argsort(d)` — номера элементов в порядке возрастания: сначала номер самого маленького расстояния, потом следующего. `[:2]` оставляет двух ближайших: здесь `[2, 0]` — гость с номером 2 (0.5), затем гость 0 (4.47). `argmin` даёт одного ближайшего, `argsort(...)[:k]` — k ближайших. `.tolist()` печатает обычные числа вместо `np.int64(...)`.
- Масштабирование: делим каждый признак на его типичный разброс по всем гостям — теперь «один шаг» по визитам и по дням весит одинаково. (StandardScaler делает то же самое, только разброс и среднее считает по обучающей выборке.)

**Что получилось:** без масштаба ближайший к A — гость B: разница в 2 дня перевешивает разницу в 4 визита. После масштабирования ближе становится C. Какой ответ правильный, решает задача, а не формула: важнее ли для оттока частота визитов или давность. Но выбор должен быть осознанным — а без масштаба его делает единица измерения.

::: figure scale-neighbors
Три гостя на плоскости в одинаковом масштабе по осям. Слева в исходных единицах: дни растянуты, визиты сжаты, и ближе к A оказывается B (4.47 против 18.03). Справа после деления на типичный разброс ближе C (0.79 против 1.34).
:::

## task: revenue | Выручка через скалярное произведение | warmup

Сохраните в `revenue` выручку кофейни за день: продано `qty` чашек по ценам `price`. Используйте `@`.

```python
import numpy as np
qty = np.array([140, 95, 40, 60])
price = np.array([190, 210, 260, 150])

```

### check

```python
assert need('revenue') == 140 * 190 + 95 * 210 + 40 * 260 + 60 * 150, f'revenue = {need("revenue")}.'
assert '@' in _code or calls('dot'), 'Посчитайте через скалярное произведение: qty @ price.'
```

### hint
Скалярное произведение — оператор `@` между двумя векторами одинаковой длины.

### hint
`revenue = qty @ price`.

### solution
```python

    [5.2, 3.0],

])
```
