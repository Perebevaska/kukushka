Итоговый тест: pandas — таблицы как в SQL

13 вопросов по всей главе — на понимание, без кода. После каждого ответа — объяснение всех вариантов, в конце — итог и уроки, которые стоит повторить.

Вопрос 1

Что вернёт df.shape для таблицы из 2089 заказов и 9 столбцов?

  • [x] (2089, 9) — число строк и число столбцов

    shape — атрибут без скобок: сначала строки, потом столбцы.

  • [ ] 2089

    Это len(df) — только число строк.

  • [ ] (9, 2089)

    Порядок другой: строки идут первыми.

  • [ ] Ошибку: нужно df.shape()

    shape — атрибут, а не метод; скобки вызовут ошибку.

Вопрос 2

Чем df[df["channel"].isin(["доставка", "самовывоз"])] удобнее двух условий через |?

  • [x] Одна проверка вместо цепочки «или»: это аналог IN (...) в SQL

    isin принимает список значений и даёт маску: True там, где значение из списка.

  • [ ] Только isin учитывает пропуски

    Пропуск не входит в список ни в одном из способов.

  • [ ] isin сортирует результат

    Порядок строк не меняется.

  • [ ] С | такой фильтр написать нельзя

    Можно, просто длиннее: (… == "доставка") | (… == "самовывоз").

Вопрос 3

df.sort_values("amount", ascending=False).head(5) — что получится?

  • [x] Пять самых дорогих заказов

    Сортировка по убыванию, затем первые пять строк — аналог ORDER BY amount DESC LIMIT 5.

  • [ ] Пять самых дешёвых заказов

    Для этого ascending=True (по умолчанию).

  • [ ] Первые пять строк в исходном порядке

    head берёт первые строки уже отсортированной таблицы.

  • [ ] Таблица df изменится навсегда

    sort_values возвращает новую таблицу; df прежняя, пока не присвоите результат.

Вопрос 4

Чем size() отличается от count() после groupby?

  • [x] size() считает все строки группы, count() — только непустые значения столбца

    Если в столбце есть пропуски, цифры разойдутся. Число заказов — size().

  • [ ] Ничем, это синонимы

    При пропусках результаты разные.

  • [ ] count() считает уникальные значения

    Уникальные — nunique().

  • [ ] size() возвращает таблицу, а count() — число

    После группировки оба возвращают значения по группам.

Вопрос 5

После merge(orders, shops, how="left") у части заказов город — NaN. Что это значит?

  • [x] Для их shop_id нет строки в справочнике кофеен

    left сохраняет все заказы, а там, где пары нет, ставит пропуски. Проверьте справочник и написание кодов.

  • [ ] merge сломался

    Так и работает левое соединение.

  • [ ] Нужно было how="right"

    Тогда пропали бы заказы без пары, а проблема в справочнике осталась бы.

  • [ ] Это дубли в заказах

    Дубли размножили бы строки, а не дали пропуски.

Вопрос 6

Зачем pd.to_datetime для столбца с датой из CSV?

  • [x] Без него дата — просто текст: нет .dt.month, resample и правильного сравнения периодов

    Из CSV всё приходит строками; parse_dates или to_datetime делают настоящие даты.

  • [ ] Чтобы дата красивее печаталась

    Дело не во внешнем виде, а в операциях с датами.

  • [ ] Чтобы ускорить чтение файла

    Разбор дат, наоборот, немного замедляет чтение.

  • [ ] Он нужен только для дат до 2000 года

    Нужен для любых дат.

Вопрос 7

В чём преимущество DuckDB для аналитика, который знает SQL?

  • [x] Можно писать обычный SQL прямо по датафрейму или CSV, без сервера базы данных

    Выбираете, что удобнее: часть шагов — SQL, часть — pandas.

  • [ ] DuckDB заменяет pandas целиком

    Это дополнение: результат запроса — снова датафрейм.

  • [ ] Без DuckDB SQL в Python недоступен

    Есть и другие способы, но DuckDB — самый простой для работы с датафреймами.

  • [ ] DuckDB нужна только для больших данных

    Удобна и на маленьких таблицах — ради знакомого языка.

Вопрос 8

SQL-запрос с LAG(revenue) OVER (PARTITION BY shop_id ORDER BY month) дал правильный рост месяц к месяцу, а «тот же» расчёт в pandas m.groupby("shop_id")["revenue"].shift(1) — странные цифры. Какая причина самая вероятная?

  • [x] Таблица m не отсортирована по месяцу: shift берёт соседнюю строку таблицы, а в SQL порядок задан внутри окна

    У LAG порядок — часть окна (ORDER BY month). У shift своего порядка нет, поэтому перед ним нужен sort_values(["shop_id", "month"]).

  • [ ] shift(1) берёт следующую строку, а не предыдущую

    shift(1) сдвигает значения вниз: в строке оказывается значение из предыдущей. Следующую дал бы shift(-1).

  • [ ] В pandas нельзя сдвигать внутри групп

    Можно: groupby(...).shift сдвигает внутри каждой группы и не перескакивает между ними.

  • [ ] В pandas у первого месяца будет 0, а в SQL — NULL

    В обоих случаях у первого месяца пусто: NaN в pandas и NULL в SQL.

Вопрос 9

Как проверить, что блокнот действительно воспроизводим?

  • [x] Перезапустить ядро и выполнить все ячейки сверху вниз (Restart & Run All)

    Так блокнот проходит путь, который пройдёт коллега, открыв его заново.

  • [ ] Посмотреть, что во всех ячейках есть вывод

    Вывод мог остаться от старого запуска в другом порядке.

  • [ ] Сохранить блокнот дважды

    Сохранение ничего не проверяет.

  • [ ] Запустить последнюю ячейку

    Она может работать только благодаря переменным из прошлых запусков.

Вопрос 10

%timeit вывел для двух способов 4.1 ms ± 90 μs и 620 μs ± 15 μs. Что из этого следует?

  • [x] Второй способ быстрее примерно в 6–7 раз: 4.1 мс — это 4 100 мкс

    Перед сравнением время приводят к одним единицам: 4 100 / 620 ≈ 6.6.

  • [ ] Первый способ быстрее: 4.1 меньше 620

    Числа в разных единицах: миллисекунда в тысячу раз больше микросекунды.

  • [ ] Способы равны: разброс после ± перекрывает разницу

    Разброс — 90 и 15 мкс, а разница между средними — около 3 500 мкс.

  • [ ] Ничего: %timeit показывает время одного случайного запуска

    Это %time. %timeit повторяет код много раз и печатает среднее и разброс.

Вопрос 11

Чек с картой выше чека без карты на 2.4 %, а порог гипотезы, назначенный заранее, — 5 %. Как честно записать вывод?

  • [x] «Гипотеза не подтвердилась: разница 2.4 % меньше порога 5 %»

    Вердикт выносится по правилу, записанному до расчёта. «Не подтвердилась» — полноценный результат, его не прячут.

  • [ ] «Гипотеза подтвердилась: чек с картой всё-таки выше»

    Так подтверждается любая гипотеза. Для этого порог и назначают заранее.

  • [ ] Снизить порог до 2 %, чтобы гипотеза подтвердилась

    Подгонка порога под результат лишает проверку смысла.

  • [ ] Не упоминать эту гипотезу в отчёте

    Тогда читатель не узнает, что карта почти не влияет на чек, — а это полезный для бизнеса ответ.

Вопрос 12

Вы перезапустили блокнот, ничего не меняя в коде, а git diff показывает десятки изменённых строк. Почему?

  • [x] В .ipynb хранятся номера запусков и выводы — они поменялись при перезапуске

    Блокнот — это JSON, где рядом с кодом лежат execution_count и outputs. nbstripout вырезает их при коммите, и в diff остаются только правки кода и текста.

  • [ ] git неправильно читает файлы на русском

    Кодировка тут ни при чём: меняются служебные поля блокнота.

  • [ ] Jupyter при перезапуске переписывает код ячеек

    Код остаётся прежним. Меняются только номера запусков и выводы.

  • [ ] Перезапуск ядра создаёт новый коммит

    Коммит создаёт только git commit. Jupyter ничего не знает о git.

Вопрос 13

Гости, зарегистрированные через приложение, удерживаются заметно лучше гостей с кассы. Что можно честно написать в отчёте?

  • [x] Гости из приложения удерживаются лучше; но приложение могли выбрать те, кто и так собирался ходить часто, поэтому это не доказывает, что удерживает именно приложение

    Это сравнение групп, которые сами себя выбрали (самоотбор). Чтобы измерить влияние приложения, нужен эксперимент, например предложить приложение случайной половине гостей.

  • [ ] Приложение повышает удержание — переведём всех гостей в приложение

    Причинный вывод из наблюдения. Если удержание объясняется тем, кто выбирает приложение, перевод остальных его не поднимет.

  • [ ] Разницы нет: удержание считается по когортам, а когорты у источников общие

    Когорты одинаковые по месяцам, но доли вернувшихся внутри них у источников разные.

  • [ ] Сравнивать нельзя: в приложении больше гостей без заказов

    Гости без заказов — отдельная метрика (воронка до первого заказа). Удержание считают среди тех, кто сделал первый заказ.
