2. Переменные и числа

Что запомнить
  • Переменная — имя для значения: revenue = cups * price. Знак = значит «положить в», а не «равно».
  • Имена — латиницей, в нижнем регистре, слова через _: avg_check. Регистр важен.
  • int — целые числа, float — дробные (с точкой: 3.5). Проверить тип — type(x).
  • / всегда даёт дробное число, // — целую часть, % — остаток, ** — степень.
  • round(x, 2) округляет до двух знаков. int("185") и float("3.5") превращают текст в число.
к уроку →
Как в SQL · Арифметика

В SQL Server и PostgreSQL деление целых чисел отбрасывает дробную часть: SELECT 7 / 2 вернёт 3. В Python 7 / 2 — это 3.5. Если нужно поведение «как в SQL», используйте //. Это частый источник расхождений, когда цифры из базы сверяют с цифрами из Python.

3. Строки и f-строки

Что запомнить
  • len(s) — длина строки. Индексы начинаются с 0, s[-1] — последний символ.
  • Срез s[a:b] берёт символы с a по b не включая b. s[:3] — первые три, s[-2:] — последние два.
  • Методы .strip(), .lower(), .upper(), .title(), .replace(a, b) возвращают новую строку — исходная не меняется.
  • подстрока in s даёт True или False; .startswith() и .endswith() — проверка начала и конца.
  • f-строка: f"Выручка: {revenue:,.2f} ₽". Внутри {} — любое выражение, после : — формат.
к уроку →
Как в SQL · Срезы: кусок строки

В SQL SUBSTRING('ZRN-2026', 1, 3) начинает счёт с единицы и берёт три символа. В Python то же самое — s[0:3]: счёт с нуля, второе число — где остановиться, а не сколько взять. Удобное правило: длина среза s[a:b] равна b − a.

4. Списки

Что запомнить
  • Список — [1, 2, 3]. Индексы и срезы работают как у строк: days[0], days[-1], days[-7:].
  • Список можно менять: lst[0] = …, lst.append(x), lst.remove(x).
  • lst.insert(i, x) — вставить на позицию, lst.extend(other) — добавить все элементы другого списка, lst.pop(i) — удалить и вернуть элемент (без i — последний), lst.index(x) — позиция значения.
  • len, sum, min, max — длина и агрегаты, как COUNT, SUM, MIN, MAX в SQL.
  • sorted(lst) возвращает новый отсортированный список, reverse=True — по убыванию. lst.sort() сортирует сам список и возвращает None.
  • s.split(";") режет строку в список, ", ".join(lst) склеивает список строк в одну строку.

5. Цикл for

Что запомнить
  • for x in список: — повторить блок для каждого элемента. Тело цикла сдвинуто на 4 пробела.

6. Условия и цикл while

Что запомнить
  • Сравнения ==, !=, <, >, <=, >= дают True или False (тип bool). = — присваивание, == — сравнение.
  • if условие: … elif другое: … else: — выполняется первая подходящая ветка.
  • and — оба условия, or — хотя бы одно, not — наоборот. Диапазон можно писать цепочкой: 300 <= x < 600.
  • Цикл + if = фильтр (WHERE), подсчёт по условию (COUNT … CASE WHEN), поиск максимума.
  • while условие: повторяет, пока условие истинно. break прерывает любой цикл.

8. Словари — GROUP BY своими руками

Что запомнить

11. Кортежи и множества

Что запомнить
  • Кортеж — ("Пермь", 412): как список, но изменить нельзя. Удобен для записей и для возврата нескольких значений из функции: return lo, hi.
  • Распаковка: city, cups = row; обмен значениями: a, b = b, a.
  • Кортеж может быть ключом словаря: sales[("Пермь", "сентябрь")] — группировка по двум полям.
  • Множество — {"Пермь", "Казань"} или set(список): только уникальные значения, порядка нет. len(set(x)) — это COUNT(DISTINCT x).
  • a & b — общие (INTERSECT), a | b — все (UNION), a - b — есть в a, нет в b (EXCEPT). Для вывода по порядку — sorted(...).

12. Генераторы списков, zip, sorted

Что запомнить
  • Генератор списка: [round(p * 1.1) for p in prices]; с фильтром: [r for r in revenue if r > 50000].

13. Исключения — как не падать на грязных данных

6. Сводные таблицы: широкий и длинный формат

Что запомнить

12. Подзапросы, CTE и порядок выполнения SQL

Что запомнить
  • Топ-1 в каждой группе: ROW_NUMBER() OVER (PARTITION BY группа ORDER BY … DESC, второй_ключ) и WHERE rn = 1 во внешнем запросе. Остальные оконные функции — в уроке «Оконные функции SQL».
  • Подзапрос — запрос в скобках: одно число в WHERE x > (…), список в IN (…), таблица в FROM (…). CTE WITH имя AS (…) — тот же подзапрос с именем; шаги через запятую.
  • NOT IN со списком, где есть NULL, не пропускает ни одной строки: добавьте в подзапрос IS NOT NULL или пишите NOT EXISTS.

  • EXPLAIN запрос показывает план выполнения; читают снизу вверх, от чтения таблицы к результату.

14. Оконные функции SQL: ранги, доли, соседние строки

Что запомнить
  • Окно: функция() OVER (PARTITION BY группа ORDER BY порядок рамка). В отличие от GROUP BY, строки не сворачиваются: результат встаёт рядом с каждой строкой.
  • Доля от итога: x / SUM(x) OVER () — от всей таблицы, x / SUM(x) OVER (PARTITION BY g) — от своей группы.
  • Ранги на ничьих: ROW_NUMBER — 1, 2, 3, 4 (ничью разрывает случай — добавляйте второй ключ сортировки); RANK — 1, 2, 2, 4; DENSE_RANK — 1, 2, 2, 3.
  • NTILE(4) делит упорядоченные строки на 4 почти равные группы; лишние строки достаются первым группам.
  • LAG(x) — значение из предыдущей строки, LEAD(x) — из следующей; у краёв — NULL.
  • WHERE выполняется до окон: фильтр по оконной функции — в QUALIFY (DuckDB) или во внешнем запросе (CTE).
  • WINDOW w AS (...) даёт окну имя, OVER w использует его в нескольких функциях.
  • Аналоги оконных функций в pandas — в шпаргалке в конце урока; в задачах они не нужны.
к уроку →
Как в SQL · Окно: итог рядом с каждой строкой

Если вы считали доли в SQL Server через подзапрос amount / (SELECT SUM(amount) FROM t), окно SUM(amount) OVER () делает то же самое, но читается проще и легко превращается в долю внутри группы — достаточно добавить PARTITION BY.

Как в SQL · Нумерация и ранги

QUALIFY есть в DuckDB, Snowflake, BigQuery и Teradata, но нет в PostgreSQL и SQL Server. Там то же самое пишут через CTE: окно считают внутри WITH ranked AS (...), а WHERE drnk <= 3 — снаружи. Результат одинаковый.

15. Рамки окна SQL: накопительные итоги и скользящие средние

Что запомнить
  • С ORDER BY окно по умолчанию — от начала до текущей строки и всех строк с тем же значением (RANGE). Для накопительного итога по уникальному ключу это то, что нужно; при повторах в ключе пишите ROWS.
  • Скользящее среднее: ROWS BETWEEN 6 PRECEDING AND CURRENT ROW — 7 строк, RANGE BETWEEN INTERVAL 6 DAYS PRECEDING AND CURRENT ROW — 7 календарных дней (с пропусками это разные вещи).
  • LAST_VALUE с ORDER BY и без явной рамки возвращает текущую строку (и её соседей по значению). Нужна рамка ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING.
  • Фильтр периода в WHERE срабатывает до окна, и края периода считаются по неполной рамке. Сначала окно в CTE, потом фильтр снаружи.
  • Один запрос может держать несколько окон: WINDOW by_month AS (...), by_shop AS (...) — доля и место по месяцу, рост к прошлому месяцу по кофейне.
  • Аналоги в pandas: cumsum(), rolling(7) и rolling("7D"), transform("first")/("last") — в шпаргалке урока; в задачах они не нужны.

2. Пропуски

Что запомнить
  • Пропуск в pandas — NaN. Проверка — isna() / notna(), количество — isna().sum().
  • Замаскированные пропуски («не указано», «—») превращают в NaN при чтении: pd.read_csv(..., na_values=["не указано", "—"]). Числа с пробелом внутри — thousands=" ".
  • sum, mean, count, median пропуски пропускают. Среднее считается только по известным значениям.
  • Механизм пропуска: MCAR — случайно, MAR — зависит от другого известного столбца, MNAR — от самого пропавшего значения. Проверка MAR: s.isna().groupby(df["столбец"]).mean().
  • groupby выбрасывает строки с NaN в ключе. Чтобы пропуск стал группой — groupby("city", dropna=False). Сверка: сумма по группам = общая сумма.
  • Удалить: df.dropna(subset=["phone"]) — строки, где нет телефона. Без subset удалятся строки с любым пропуском.
  • Заполнить: fillna("не указано") для категорий; fillna(0) — только если пусто действительно значит ноль.
  • Заполнение по группе: s.fillna(df.groupby("city")["bonus"].transform("median")).
  • Перед заполнением сохраните флаг: df["bonus_missing"] = df["bonus"].isna().

Глава 5. Статистика и проверка гипотез

1. Вероятность: частота и симуляция

Что запомнить
  • Вероятность события — доля случаев, в которых оно происходит, если повторять опыт много раз. По данным: (условие).mean().
  • Закон больших чисел: чем больше опытов, тем ближе наблюдаемая доля к настоящей вероятности. На малых выборках доли «прыгают».
  • Условная вероятность P(A | B) — доля A среди строк, где выполнено B: df[B][A].mean(). Это и есть срез.
  • События независимы, если P(A и B) = P(A) × P(B). Иначе они связаны.
  • «Хотя бы один раз из n»: 1 − (1 − p)ⁿ.
  • Симуляция: rng = np.random.default_rng(42); rng.random(n) < p — n опытов с вероятностью успеха p. seed (42) делает случайность воспроизводимой.
к уроку →

2. Распределения: мат. ожидание, биномиальное, Пуассона

Что запомнить
  • Случайная величина — число, которое станет известно после события. Мат. ожидание E[X] = Σ значение × вероятность — средний результат «в долгую»; ожидание суммы равно сумме ожиданий.
  • Биномиальное распределение — число успехов в n независимых попытках с вероятностью p. Среднее n·p, стандартное отклонение √(n·p·(1−p)).
  • from scipy import stats; stats.binom.pmf(k, n, p) — P(X = k), cdf(k, n, p) — P(X ≤ k), sf(k, n, p) — P(X > k).
  • Распределение Пуассона — число независимых событий за интервал (гостей за 5 минут) при постоянной частоте: stats.poisson.pmf(k, mu), sf(k, mu). Среднее и дисперсия равны λ — так и проверяют, подходит ли модель.

3. Нормальное распределение, приближение и z-оценка

Что запомнить
  • Нормальное распределение — «колокол», задаётся средним и стандартным отклонением: stats.norm.cdf(x, loc=среднее, scale=σ).
  • ppf(q) — квантиль, обратное к cdf: stats.norm.ppf(0.975) ≈ 1.96.
  • Правило 68–95–99.7: в пределах 1, 2 и 3 σ от среднего лежит 68 %, 95 % и 99.7 % значений нормального распределения.
  • Нормальное приближение биномиального: среднее n·p, σ = √(n·p·(1−p)), «k и больше» — norm.sf(k − 0.5, …). Пользуются, когда n·p ≥ 10 и n·(1 − p) ≥ 10.
  • z-оценка: (x − среднее) / σ — на сколько стандартных отклонений значение отстоит от среднего.
  • Реальные данные часто не нормальны (время, деньги — хвост вправо). Проверяйте гистограммой; логарифм нередко делает распределение ближе к нормальному.

4. Выборки и центральная предельная теорема

Что запомнить
  • Генеральная совокупность — все объекты, о которых хотим сделать вывод; выборка — то, что у нас есть. Среднее выборки — оценка неизвестного среднего совокупности.
  • Разные выборки дают разные средние. Их разброс — стандартная ошибка: SE = σ / √n.
  • Центральная предельная теорема: средние достаточно больших выборок распределены почти нормально — даже если сами данные не нормальны.
  • Точность растёт как √n: чтобы уменьшить ошибку вдвое, нужно в 4 раза больше данных.
  • Для доли: SE = √(p·(1 − p) / n).
  • Смещение — систематическая ошибка способа отбора (опрос в зале, в приложении, «кто ответил»). SE и интервалы его не видят, а рост выборки не лечит: оценка всё точнее попадает не туда.
  • Выборка: s.sample(n, random_state=1) или rng.choice(arr, size=n).

5. Доверительные интервалы

Что запомнить
  • 95 %-й доверительный интервал: если повторять сбор данных много раз, 95 % таких интервалов накроют настоящее значение.
  • Для среднего: среднее ± t · SE, где SE = s / √n, t = stats.t.ppf(0.975, n − 1) (≈ 1.96 при больших n). Готовая функция: stats.t.interval(0.95, n − 1, loc=среднее, scale=SE).
  • Для доли: p ± 1.96 · √(p(1−p)/n) или точнее — proportion_confint(успехов, n, method="wilson") из statsmodels.
  • Бутстрэп — интервал для чего угодно (медиана, квантиль): много раз перевыбрать данные с возвращением и взять 2.5-й и 97.5-й перцентили статистики.
  • Разница двух долей: (p₁ − p₂) ± 1.96 · √(p₁q₁/n₁ + p₂q₂/n₂). Если ноль не внутри интервала — разница, скорее всего, не случайна.
  • Шире интервал — меньше данных или выше уровень доверия. Сужается как √n.

6. Проверка гипотез: логика и p-value

Что запомнить
  • Нулевая гипотеза H₀ — «эффекта нет, разница случайна». Альтернатива H₁ — «эффект есть». Тест проверяет, насколько данные совместимы с H₀.
  • p-value — вероятность получить разницу не меньше наблюдаемой, если H₀ верна. Маленькое p — данные плохо объясняются случайностью.
  • Порог α (обычно 0.05) выбирают заранее. p < α — отвергаем H₀; p ≥ α — не отвергаем (это не доказательство, что эффекта нет).
  • Перестановочный тест: перемешать метки групп много раз и посмотреть, как часто случайная разница не меньше настоящей.
  • Ошибка I рода — найти эффект, которого нет (вероятность α). Ошибка II рода — не найти эффект, который есть. Мощность = 1 − P(ошибки II рода).
  • Двусторонний тест — «отличается в любую сторону»; односторонний — «больше» (или «меньше»), решать до просмотра данных.

7. Статистические тесты: какой выбрать

Что запомнить
  • Средние двух групп: stats.ttest_ind(a, b, equal_var=False) — t-тест Уэлча (не требует равных дисперсий).
  • Среднее против числа: stats.ttest_1samp(a, 45). Пары «до/после» на одних объектах: stats.ttest_rel(after, before).
  • Доли двух групп: proportions_ztest([успехов_a, успехов_b], [n_a, n_b]) из statsmodels.
  • Связь двух категорий: stats.chi2_contingency(pd.crosstab(a, b)) — хи-квадрат.
  • Скошенные данные или порядковые оценки (1–5): stats.mannwhitneyu(a, b) — сравнивает распределения по рангам.
  • Односторонний тест — параметр alternative="greater" или "less" (о первом аргументе относительно второго); в statsmodels — "larger"/"smaller". Направление фиксируют до данных и только если обратный эффект не важен; иначе — "two-sided".
  • Каждый тест возвращает статистику и p-value: res.pvalue. К p-value всегда добавляйте размер эффекта — разницу и её интервал.

8. A/B-тест: от дизайна до решения

Что запомнить
  • A/B-тест: гостей случайно делят на группы; A — контроль (как было), B — изменение. Случайность делает группы одинаковыми во всём, кроме изменения.
  • Дизайн до запуска: гипотеза, главная метрика, защитные метрики, единица рандомизации, минимальный интересный эффект (MDE), размер выборки и длительность.
  • Размер выборки: NormalIndPower().solve_power(proportion_effectsize(p_b, p_a), alpha=0.05, power=0.8) — на группу.
  • Первая проверка данных — SRM (разбалансировка групп): stats.chisquare([n_a, n_b]). Маленькое p — сломалась рандомизация, результатам верить нельзя.
  • Конверсия: proportions_ztest + интервал разницы. Деньги на пользователя (скошены, много нулей): t-тест Уэлча + бутстрэп-интервал.
  • Решение = значимость + размер эффекта (интервал) + защитные метрики + стоимость внедрения.

9. Ловушки статистики

Что запомнить
  • Подглядывание: проверять p каждый день и остановиться на первом «значимом» — ложных находок не 5 %, а в разы больше. Размер и срок теста фиксируют заранее.
  • Множественные сравнения: из m проверок без эффекта в среднем m·α «значимых». Поправки: Бонферрони (α/m) или Холм — multipletests(pvals, method="holm").
  • Сегменты после теста — для новых гипотез, а не для выводов: в маленьких сегментах мощности мало, различия между сегментами чаще всего шум.
  • Значимо ≠ важно: на миллионах наблюдений значим и крошечный эффект. Решает размер эффекта и его интервал.
  • Регрессия к среднему: худшие в одном периоде в следующем обычно «улучшаются» сами — без всяких мер.
  • Выводы делают по той выборке, которую тестировали: если оценки ставит только часть гостей, это их мнение, а не всех.

10. Проект: новое обещание доставки

Что запомнить

  • Главная метрика отвечает на вопрос «сработало ли», защитные — «чем заплатили».

  • Сегменты, заданные заранее, — часть дизайна; найденные после теста — повод для нового теста.
  • Решение — правило, записанное до анализа, плюс честный рассказ о неопределённости.
  • Защитная метрика проверяется порогом допустимого ухудшения δ: «значимо не упала» не доказывает, что вреда нет.

1. Что такое машинное обучение

Что запомнить
  • Объект — строка (доставка). Признаки X — то, что известно заранее. Целевой признак y — то, что хотим предсказать.
  • Классификация — предсказываем категорию (опоздает / нет). Регрессия — число (сколько минут).
  • Типы задач: классификация, регрессия, прогноз ряда (с учителем — ответ есть в данных) и кластеризация (без учителя — ответа нет).
  • Снятие запроса — шесть вопросов до кода: какое решение, что объект, момент прогноза, целевой признак, с чем сравниваем, как поймём, что стало лучше. Один запрос может дать разные постановки — выбирает решение.
  • scikit-learn: model = DecisionTreeClassifier(...), model.fit(X, y) — обучение, model.predict(X_new) — предсказание.
  • Доля правильных ответов — accuracy: accuracy_score(y, pred).
  • Сначала — базовая модель (baseline): самый частый ответ или простое правило. Модель полезна, только если её превосходит.
  • Признаки — только то, что известно до события. Фактическое время доставки нельзя использовать, чтобы предсказать опоздание.

2. Обучающая и тестовая выборки

Что запомнить
  • Оценивать модель на данных, на которых она училась, нельзя: оценка завышена. Честная оценка — на отложенной тестовой выборке.
  • X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42) — 75 % на обучение, 25 % на тест; random_state делает разбиение повторяемым.
  • stratify=y сохраняет долю классов одинаковой в обеих частях.
  • model.score(X, y) — доля правильных ответов классификатора, то же, что accuracy_score(y, model.predict(X)).
  • Переобучение: на обучении отлично, на тесте плохо — модель запомнила шум. Недообучение: плохо и там и там — модель слишком простая.
  • Кривая «сложность → качество на train и test» показывает, где модель начинает переобучаться.
  • Оценка на тесте — тоже выборочная: при другом разбиении она сдвигается на несколько п.п. (стандартное отклонение — около 2 п.п.). Разница между моделями в 1–2 п.п. может быть случайностью.

3. Решающее дерево изнутри

Что запомнить
  • Дерево — вложенные вопросы «признак ≤ порог?». В каждом листе ответ — класс большинства среди обучающих объектов, попавших в лист.

  • Дерево перебирает все признаки и пороги и выбирает вопрос, после которого взвешенная неоднородность частей меньше всего.
  • export_text(model, feature_names=...) — дерево текстом, plot_tree(model, feature_names=..., filled=True) — картинкой.

  • Против переобучения: max_depth (глубина), min_samples_leaf (минимум объектов в листе), max_leaf_nodes (число листьев).
  • model.feature_importances_ — насколько каждый признак уменьшил неоднородность; в сумме 1.

4. Категориальные признаки и утечки

Что запомнить
  • Модели sklearn принимают только числа. Категорию превращают в столбцы-флаги 0/1: pd.get_dummies(df, dtype=int) — по столбцу на каждое значение (one-hot кодирование).
  • Коды 0/1/2 для категорий без естественного порядка придумывают порядок, которого нет: модель ищет пороги «больше-меньше» и путается. Особенно страдают линейные модели.
  • drop_first=True убирает один флаг из каждой группы: он однозначно восстанавливается из остальных. Нужен линейной модели без регуляризации; деревьям — не обязательно (подробнее — в уроке «Логистическая регрессия и вероятности»).
  • Новые данные кодируют так же, а затем выравнивают по столбцам обучения: X_new.reindex(columns=X_train.columns, fill_value=0).
  • Утечка — признак, который известен только после события (rating, actual_min) или пересчитан с подглядыванием в тест. Всё, что считается по данным (доли, средние, заполнение пропусков), считают только по обучающей части.
  • Подозрительно хорошее качество — повод проверить важность признаков и спросить про каждый: «знаем ли мы это в момент прогноза?»

5. Случайный лес

Что запомнить
  • Бутстрэп-выборка — случайный выбор строк с возвращением того же размера: df.sample(frac=1, replace=True). В неё попадает около 63 % разных строк.
  • Случайный лес = много деревьев, каждое на своей бутстрэп-выборке и со случайным набором признаков на каждом разбиении. Ответ — усреднение (голосование) деревьев.
  • RandomForestClassifier(n_estimators=..., max_depth=..., min_samples_leaf=..., random_state=0): n_estimators — число деревьев, остальное — как у дерева.
  • Лес переобучается намного меньше одного глубокого дерева: на обучении почти 100 %, но и на тесте заметно выше дерева.
  • feature_importances_ у леса — средняя важность по всем деревьям, устойчивее, чем у одного дерева.
  • Сложная модель должна выиграть у простого правила на нескольких разбиениях, а не на одном. На опозданиях лес лишь чуть лучше правила «пеший — опоздает».

6. Логистическая регрессия и вероятности

8. Регрессия: сколько минут

Что запомнить
  • Регрессия предсказывает число. Базовая модель — всегда отвечать медианой (или средним) обучающей выборки.
  • LinearRegression: прогноз = intercept_ + Σ coef_ · признак. Вес расстояния — «сколько минут добавляет километр при прочих равных».
  • DecisionTreeRegressor и RandomForestRegressor отвечают средним по похожим объектам и сами ловят взаимодействия признаков (пеший × расстояние).
  • MAE — средняя ошибка в минутах: mean_absolute_error. RMSE — mean_squared_error(...) ** 0.5, сильнее штрафует крупные промахи.
  • R² (r2_score) — какая доля разброса объяснена: 1 — идеально, 0 — не лучше среднего, меньше 0 — хуже среднего.
  • Остаток = факт − прогноз. График «факт против прогноза» и таблица крупнейших ошибок показывают, где модель ошибается.
  • Регрессию можно превратить в классификацию: «прогноз минут > обещания» — значит, опоздание.

9. Честное сравнение моделей

  • Три части данных: обучающая (train) — учим модель, валидационная (valid) — выбираем настройки и модель, тестовая (test) — один раз проверяем итог. 60/20/20 — два вызова train_test_split.

Глава 7. Признаки, метрики и Pipeline

1. Матрица ошибок

Что запомнить
  • При дисбалансе классов accuracy обманывает: модель «никто не уйдёт» на наших гостях права в 78 % случаев и не находит ни одного уходящего.
  • DummyClassifier(strategy="most_frequent") — базовая модель, которая всегда отвечает самым частым классом. Любая модель должна быть заметно лучше неё.
  • Четыре исхода: TP — бонус уходящему, FP — лишний бонус оставшемуся, FN — пропустили уходящего, TN — верно не тронули оставшегося.
  • confusion_matrix(y_true, y_pred) — таблица [[TN, FP], [FN, TP]]: строки — факт, столбцы — прогноз; .ravel() раскладывает её в tn, fp, fn, tp.
  • Доли ошибок по типам: FN / (FN + TP) — какую долю уходящих пропустили, FP / (FP + TN) — какой доле оставшихся дали лишний бонус. normalize="true" считает их сразу.
  • Ошибки стоят по-разному: лишний бонус дешевле потерянного гостя, поэтому модели сравнивают по матрице и по деньгам, а не только по accuracy.

2. Precision, recall и F1

Что запомнить
  • Точность (precision) = TP / (TP + FP): какая доля бонусов досталась тем, кто действительно уходил. Не путать с accuracy — долей всех правильных ответов.
  • Полнота (recall) = TP / (TP + FN): какую долю уходящих модель нашла. Полнота = 1 − доля пропущенных из урока «Матрица ошибок».
  • precision_score, recall_score, f1_score из sklearn.metrics принимают (факт, прогноз); если модель никого не назвала положительным, точность не определена — zero_division=0 делает её нулём без предупреждения.
  • F1 = 2·P·R / (P + R) — гармоническое среднее: оно близко к меньшей из двух метрик, поэтому «бонус всем» не получает высокий балл за полноту 1.
  • classification_report(y_true, y_pred) печатает точность, полноту и F1 для каждого класса, support — сколько объектов класса в данных; output_dict=True возвращает то же словарём.
  • Дорог FP (лишнее действие) — следим за точностью; дорог FN (пропуск) — за полнотой. Обычно одну метрику держат не ниже планки, а другую делают как можно больше.
  • F-beta (fbeta_score) — F1 с перекосом: β > 1 важнее полнота, β < 1 — точность.

3. Порог, PR- и ROC-кривые

Что запомнить
  • Порог — решение бизнеса, а не свойство модели: pred = p >= t. Ниже порог — выше полнота и ниже точность.
  • precision_recall_curve(y_true, p) → precision, recall, thresholds; в precision и recall на одну точку больше, чем порогов.
  • ROC-кривая: по оси X — доля ложных тревог FPR = FP / (FP + TN), по оси Y — полнота TPR. roc_curve(y_true, p) → fpr, tpr, thresholds.
  • roc_auc_score(y_true, p) — площадь под ROC-кривой. 0.5 — монетка, 1 — идеальное ранжирование. Не зависит от порога.
  • AUC = вероятность, что случайный ушедший гость получит оценку выше случайного оставшегося (ничьи — за половину).

5. Дисбаланс классов

Что запомнить
  • Дисбаланс классов — один класс встречается намного реже другого. Модель снижает общее число ошибок, поэтому смещается к частому классу: полнота по редкому классу проседает.
  • class_weight="balanced" — ошибка на редком классе весит больше: вес класса = n / (2 × n_класса). Работает у LogisticRegression, деревьев и леса.
  • Upsampling — повторить строки редкого класса (sample(n=..., replace=True)) до размера частого; downsampling — случайно оставить из частого класса столько строк, сколько в редком.
  • Балансируют только обучающую часть, после разбиения. Размножение до разбиения кладёт копии одних и тех же гостей и в train, и в test — метрики завышены.
  • Балансировка двигает precision, recall и F1 (полнота растёт, точность падает), а ROC-AUC почти не меняет: порядок гостей по риску остаётся прежним.
  • Тот же эффект даёт сдвиг порога у обычной модели. Вероятности после балансировки завышены — для расчёта денег им верить как числам нельзя.

6. Масштабирование и ближайшие соседи

Что запомнить
  • Масштаб важен моделям, которые считают расстояния или складывают взвешенные признаки (ближайшие соседи, логистическая регрессия). Деревьям и лесу он почти безразличен.
  • StandardScaler: z = (x − среднее) / стандартное отклонение. Учим (fit) только на train, применяем (transform) и к train, и к test — иначе утечка.

10. Pipeline: предобработка и модель вместе

Что запомнить
  • Предобработка тоже «учится» на данных: заполнитель пропусков запоминает значение, масштабирование — среднее и разброс, кодировщик — список категорий. Учить её можно только на обучающей части.
  • SimpleImputer(strategy=...) заполняет пропуски, OneHotEncoder(handle_unknown="ignore") делает флаги категорий и не падает на новых значениях (у новой категории все флаги — 0).
  • ColumnTransformer([(имя, обработка, столбцы), ...]) применяет разную обработку к разным столбцам и склеивает результат.
  • Pipeline([("prep", ...), ("model", ...)]) — цепочка шагов: fit учит все шаги по очереди, predict прогоняет новые строки через те же шаги. make_pipeline придумывает имена шагов сам.
  • Конвейер принимает «сырую» таблицу — такую, какой её выгружают из базы. Новые гости обрабатываются ровно так же, как обучающие.
  • cross_val_score(pipe, X, y, cv=kf) переобучает всю предобработку на каждом фолде — утечки из проверочной части нет.

13. Проект: какие заявки довести до договора

Что запомнить
  • При сильном дисбалансе доля правильных ничего не говорит: «никто не купит» права в 87 % случаев. Смотрите на полноту, F1, AUC и на метрику, которая повторяет решение бизнеса.
  • Метрика под задачу: если менеджеры успевают вести 30 % заявок, качество модели — доля договоров, которые попадают в верхние 30 % её списка.
  • Пропуск — тоже сигнал: заявки без размера компании и без бюджета конвертируются хуже. Категориальный пропуск удобно сделать отдельной категорией «не указан».
  • Столбец, который заполняется только после результата (сумма договора), — утечка, даже если выглядит как обычное число.
  • Из даты-времени получаются признаки: час, день недели, флаг вечерней заявки. Их можно посчитать по каждой строке отдельно, без утечки.
  • Конвейер + GridSearchCV на обучающей части, затем одна проверка на тесте — схема, которая не обманывает.
  • Модель находит связь, а не причину: то, что быстрые ответы чаще заканчиваются договором, ещё не доказывает, что ускорение ответа даст договоры. Это проверяет только эксперимент.

Глава 8. ML для бизнес-решений

1. Из прогноза — в деньги

Что запомнить
  • Каждой клетке матрицы ошибок можно назначить цену. Ожидаемая прибыль кампании = выгода × TP − расход × FP.
  • Бонус выгоден гостю с вероятностью ухода p, если p × (доля удержанных × ценность гостя) > цена бонуса. Отсюда порог безубыточности.
  • Порог 0.5 — соглашение библиотеки, а не бизнес-решение. Порог выбирают по прибыли.
  • Прибыль считают и для простых стратегий: «никому», «всем», правило аналитика. Модель нужна, только если зарабатывает больше них.
  • Формула порога работает, когда вероятности модели похожи на настоящие доли (калибровка) — это проверяют по группам.
  • Допущения (сколько гостей удержит бонус) — самое шаткое место. Проверяют, как от них меняются порог и прибыль.

4. Когда бюджет ограничен

Что запомнить
  • При ограниченном бюджете берут k гостей с наибольшим прогнозом: s.nlargest(k) или сортировка.
  • Точность в топ-k (precision@k) — доля уходящих среди k выбранных; охват (recall@k) — доля всех уходящих, попавших в топ-k.
  • Кривая охвата: по оси X — доля гостей, которым отправили бонус, по Y — доля пойманных уходящих. Чем выше над диагональю, тем лучше ранжирование.
  • Случайный выбор ловит уходящих пропорционально бюджету — это базовая линия.
  • Бюджет не обязательно тратить целиком: если в топ-k попадают гости ниже порога безубыточности, они приносят убыток.
  • Модели сравнивают при одинаковом бюджете — так сравнение честное.

5. Риск: сколько можно потерять

Что запомнить
  • Прибыль на тесте — оценка по одной выборке. Бутстрэп (глава 5) показывает, как она менялась бы на других выборках гостей.
  • Схема: много раз выбрать строки с возвращением → посчитать прибыль → смотреть среднее, 2.5-й и 97.5-й процентили, долю убыточных повторов.
  • У результата несколько источников случайности: какие гости придут, сработает ли бонус, верно ли допущение об эффекте. Их можно добавить в симуляцию по очереди.
  • Маленький пилот рискованнее большой кампании: разброс прибыли относительно среднего тем больше, чем меньше гостей.
  • Решение формулируют через риск: «запускаем, если вероятность убытка меньше 2.5 %» или «если нижняя граница интервала выше нуля».
  • Фиксируйте генератор (np.random.default_rng(0)), чтобы расчёт повторялся.

6. Модель в работе: мониторинг

Что запомнить
  • После запуска модель проверяют регулярно (например, раз в месяц) по трём группам признаков здоровья: входы, выходы, качество.
  • Входы: доли пропусков, медианы и распределения признаков, новые категории — сравнивают с обучающей выборкой.
  • Выходы: средний прогноз и доля заявок выше порога. Резкий скачок — повод разбираться, даже если ответов ещё нет.
  • Качество (AUC, калибровка «прогноз против факта») можно считать только когда известны ответы — часто с задержкой.
  • AUC меряет порядок внутри месяца и может не заметить, что вероятности «уехали»: решения по порогу уже сломаны.
  • Частая причина поломки — не мир, а данные: смена единиц измерения, формы, справочника. Проверки входов ловят её в первый же день.
  • Переобучение на свежих данных полезно, но только после того, как найдена и исправлена причина сбоя.

8. Объяснить модель бизнесу

Что запомнить
  • Два вопроса — два инструмента: «от чего зависит прогноз в целом» (глобальное объяснение) и «почему такой прогноз у этого гостя» (локальное).
  • Зависимость прогноза от признака (partial dependence): всем гостям ставим одно значение признака, считаем средний прогноз, повторяем для сетки значений.
  • У логистической регрессии на масштабированных признаках вклад признака в оценку гостя = вес × (значение − среднее) / стандартное отклонение.
  • «Что если» (what-if): меняем признак у конкретных гостей и смотрим, как меняется прогноз модели.

Глава 9. Линейная алгебра для ML

1. Векторы

Что запомнить
  • Вектор — упорядоченный набор чисел: строка признаков объекта. В numpy — одномерный массив np.array([...]).
  • Сложение векторов и умножение на число — поэлементные: a + b, 3 * a.
  • Скалярное произведение a @ b = сумма попарных произведений. Это «взвешенная сумма»: прогноз линейной модели — скалярное произведение признаков на веса.
  • Длина вектора np.linalg.norm(a), расстояние между векторами — длина их разности. На расстояниях работает kNN.
  • Манхэттенское расстояние np.abs(a - b).sum() — сумма модулей разностей, путь «по улицам». Оно не меньше евклидова; в kNN — metric="manhattan".
  • Косинусное сходство = (a @ b) / (|a| · |b|): похожесть направлений, не зависящая от масштаба. От −1 до 1.

2. Матрицы

Что запомнить
  • Матрица — прямоугольная таблица чисел: m строк × n столбцов. В numpy — двумерный массив, форма A.shape == (m, n).
  • Матрица @ вектор: скалярное произведение каждой строки на вектор. X @ w — прогнозы линейной модели для всех объектов сразу.
  • Матрица @ матрица: элемент (i, j) результата — строка i первой матрицы @ столбец j второй.
  • Правило формы: (m × n) @ (n × k) → (m × k). Внутренние размеры обязаны совпадать.
  • Умножение матриц не перестановочно: A @ B ≠ B @ A (а часто B @ A вообще не определено).
  • Транспонирование A.T меняет строки и столбцы местами; единичная матрица np.eye(n) при умножении ничего не меняет.

3. Без циклов: векторизация и замер времени

Что запомнить
  • Векторизация — операция над целым массивом (X @ w, np.where, арифметика столбцов) вместо цикла по строкам. На сотнях тысяч строк — в десятки раз быстрее; apply(axis=1) — скрытый цикл.

4. Как обучается линейная регрессия

Что запомнить
  • Обратная матрица A⁻¹: A⁻¹ @ A = I. Есть только у квадратных невырожденных матриц. np.linalg.inv(A).
  • Система линейных уравнений A @ x = b решается np.linalg.solve(A, b) — точнее и быстрее, чем inv(A) @ b.
  • Линейная регрессия выбирает веса, при которых сумма квадратов ошибок минимальна. Решение: w = (XᵀX)⁻¹ Xᵀ y, где в X добавлен столбец единиц.
  • Если один признак выражается через другие (метры и километры, все флаги get_dummies + свободный член), XᵀX вырождена: решений бесконечно много, веса теряют смысл.
  • np.linalg.matrix_rank(X) меньше числа столбцов — признак вырожденности. Лечится удалением лишнего признака (drop_first=True) или регуляризацией.

6. Преобразовать признаки матрицей

Что запомнить
  • X @ P — новая таблица: каждый новый признак — взвешенная сумма старых (столбец P — веса смеси).
  • Масштабирование — частный случай: умножение на диагональную матрицу (и сдвиг на среднее).
  • Если P обратима, исходные данные восстанавливаются: X = (X @ P) @ P⁻¹. Информация не теряется.
  • Линейная регрессия на X @ P даёт те же прогнозы, что на X: веса просто становятся P⁻¹ @ w.
  • Деревья, kNN и важности признаков к таким преобразованиям чувствительны: у них другие пороги и расстояния.
  • Необратимая P (например, выкинуть столбец) теряет информацию, и качество может упасть.

7. Проект: спрятать анкеты и не потерять модель

Что запомнить
  • Умножение признаков на случайную обратимую матрицу P прячет значения, но сохраняет всю информацию: с ключом P данные восстанавливаются.
  • Линейная регрессия на X @ P даёт те же прогнозы и то же качество, что на X: оптимальные веса просто становятся P⁻¹ @ w.
  • Ключ проверяют на обратимость (ранг) и обусловленность: почти вырожденная P портит точность вычислений.
  • Вырожденный ключ безвозвратно теряет информацию, и качество модели падает.
  • Это защита от случайного взгляда, а не криптография: зная несколько пар «исходная строка — спрятанная», P восстанавливается решением системы.

Глава 10. Градиентный спуск и бустинг

1. Градиентный спуск: шаг за шагом к минимуму

Что запомнить
  • Функция потерь (loss) — число, которое показывает, насколько модель ошибается при данных весах. Обучение = поиск весов с минимальной потерей.
  • Производная потери по весу — наклон: показывает, в какую сторону и как быстро растёт ошибка.
  • Шаг градиентного спуска: w ← w − η × производная. η (learning rate, шаг обучения) — длина шага.
  • Слишком маленький шаг — долго идём; слишком большой — перепрыгиваем минимум и можем «улететь».
  • Для нескольких весов производные собираются в вектор — градиент. Спуск идёт против градиента по всем весам сразу.
  • Производную можно проверить численно: (L(w + ε) − L(w − ε)) / 2ε.
к уроку →

2. Численные методы: цена формулы и деление пополам

Что запомнить
  • Сложность: нормальное уравнение — около n·d² + d³ операций, спуск — 2·n·d на шаг. Формула выгоднее, пока признаков меньше, чем шагов спуска; при десятках тысяч признаков она проигрывает и по времени, и по памяти (XᵀX — d × d чисел).
  • Деление пополам (бисекция) ищет ноль функции одной переменной: если на краях отрезка знаки разные, середина говорит, в какой половине ответ. Шагов — log₂(длина / допуск), разойтись метод не может.

3. Спуск для многих признаков

Что запомнить
  • Градиент MSE для линейной модели: 2/n · Xᵀ(Xw − y). Одна строка numpy считает производные по всем весам.
  • Признаки разного масштаба делают «яму» вытянутой: шаг, безопасный для одного веса, взрывает другой. Масштабирование (StandardScaler) выравнивает яму.
  • nan в весах или растущая ошибка — почти всегда слишком большой шаг или немасштабированные признаки.
  • Стохастический спуск (SGD) считает градиент по случайной порции строк (mini-batch). Шаги шумные, зато дешёвые; один проход по всем данным — эпоха.
  • В sklearn: make_pipeline(StandardScaler(), SGDRegressor()) — линейная регрессия, обученная стохастическим спуском.

4. Оптимизаторы: инерция, Adam и затухание весов

Что запомнить
  • Инерция: v ← β·v + g, w ← w − η·v — на пологих склонах шаги разгоняются. Adam добавляет деление на сглаженный размер градиента √ŝ: у каждого веса свой шаг, разный масштаб признаков не страшен; первый шаг — ровно η.
  • L2-штраф λ·Σw² добавляет к градиенту 2λw (кроме свободного члена): веса «затухают» на каждом шаге. Спуск со штрафом приходит к Ridge с alpha = λ·n.

5. Бустинг: каждое дерево исправляет ошибки предыдущих

Что запомнить
  • Бустинг — сумма многих слабых моделей (обычно неглубоких деревьев), построенных последовательно.
  • Старт — константа (среднее). Каждое следующее дерево обучается предсказывать остатки: факт − текущий прогноз.
  • Прогноз обновляется маленьким шагом: прогноз += learning_rate × прогноз дерева. Маленький шаг + много деревьев = точнее и устойчивее.
  • Остатки — это антиградиент MSE: бустинг — градиентный спуск, где шаг делается не по весам, а «деревьями».
  • В sklearn: GradientBoostingRegressor(n_estimators, learning_rate, max_depth); для классификации — GradientBoostingClassifier.
  • Лес снижает разброс (усредняет переобученные деревья), бустинг снижает смещение (наращивает недообученные).

Глава 11. Нейросети

1. Нейрон и слои

Что запомнить
  • Нейрон: z = x @ w + b, затем активация a = f(z). С сигмоидой это ровно логистическая регрессия.
  • Популярные активации: сигмоида (0…1), ReLU = max(0, z) (обнуляет отрицательное), tanh (−1…1).
  • Слой — много нейронов сразу: Z = X @ W + b, где у W столько столбцов, сколько нейронов.
  • Без нелинейной активации несколько слоёв схлопываются в один линейный: (X @ W1) @ W2 = X @ (W1 @ W2).
  • Скрытый слой строит новые признаки из старых — поэтому сеть может решать задачи, где классы не разделяются прямой.
  • Прямой проход (forward) — вычисление прогноза слой за слоем.
  • Начальные веса сети — маленькие случайные числа. Их масштаб важен; как его выбрать (Xavier и He), разбираем в уроке «Граф вычислений, инициализация и обрезка градиента».
к уроку →

2. Обучение сети: обратное распространение ошибки

Что запомнить
  • Для классификации потеря — логистическая (кросс-энтропия): −mean(y·log p + (1−y)·log(1−p)).
  • Для сигмоиды на выходе с кросс-энтропией градиент по оценке z простой: p − y.
  • Обратное распространение (backprop): градиент выходного слоя → через веса передаётся в скрытый слой → умножается на производную активации → градиенты весов скрытого слоя.
  • Каждый шаг обучения: прямой проход → потеря → обратный проход → шаг спуска по всем весам.
  • Начальные веса — маленькие случайные числа: если все одинаковые, нейроны слоя навсегда останутся одинаковыми.
  • Правильность градиентов проверяют численно, как в главе 10.

3. Граф вычислений, инициализация и обрезка градиента

Что запомнить
  • Граф вычислений: каждая операция знает свою локальную производную; backward идёт от потери к входам, умножает градиенты на локальные производные и складывает вклады разных путей (отсюда zero_grad в PyTorch).
  • Каждый слой умножает разброс сигнала примерно на √n_in · s, где s — отклонение весов. Начальные веса берут по He: s = √(2 / n_in) для ReLU, или по Xavier: s = √(1 / n_in) для tanh и сигмоиды — тогда сигнал не взрывается и не гаснет по слоям.
  • Взрыв и затухание градиента: в глубокой сети множители слоёв перемножаются. Защита — инициализация He и обрезка по норме: g · min(1, max_norm / ‖g‖) между backward и step.

4. Нейросеть в sklearn: MLP

Что запомнить
  • MLPClassifier(hidden_layer_sizes=(32,), alpha=..., max_iter=...) — сеть со скрытыми слоями; (64, 32) — два слоя по 64 и 32 нейрона.
  • Сеть учится градиентным спуском (по умолчанию Adam — спуск с «умным» шагом), поэтому признаки обязательно масштабируют: make_pipeline(StandardScaler(), MLPClassifier(...)).
  • alpha — L2-регуляризация весов, как C в логистической регрессии наоборот: больше alpha — проще модель, меньше переобучения.
  • early_stopping=True откладывает часть обучающих данных и останавливает обучение, когда качество на них перестаёт расти.
  • loss_curve_ — потеря по эпохам; n_iter_ — сколько эпох прошло. ConvergenceWarning — «не дошёл до минимума за max_iter».
  • На табличных данных сети редко обгоняют бустинг. Их сила — изображения, звук, тексты, где признаки нужно строить из «сырых» данных.

5. PyTorch: то же самое, но в промышленном масштабе

Что запомнить
  • Тензор (torch.tensor) — массив numpy, который умеет запоминать операции и считать градиенты.
  • loss.backward() — автоматический обратный проход: градиенты всех весов появляются в .grad.
  • nn.Module описывает сеть, nn.Linear(n_in, n_out) — слой X @ W + b, nn.ReLU() — активация.
  • Цикл обучения: optimizer.zero_grad() → прогноз → loss → loss.backward() → optimizer.step().

6. Softmax, выход под задачу и мини-батчи

Что запомнить
  • Для многих классов выход — K чисел (логиты); softmax превращает их в вероятности, кросс-энтропия штрафует за малую вероятность правильного класса.
  • Выход и потеря — под задачу: регрессия — линейный выход и MSE; бинарная — сигмоида и BCE; многоклассовая — softmax и кросс-энтропия; многометочная — сигмоида на каждом выходе и BCE. В PyTorch классификационные потери (BCEWithLogitsLoss, CrossEntropyLoss) принимают логиты: так log(0) не случается.
  • Мини-батч — небольшой случайный кусок данных, по которому делают один шаг спуска; эпоха — проход по всем данным батчами. Перед каждой эпохой данные перемешивают, градиент делят на размер батча.

1. Временной ряд: индекс-дата, resample и скользящие окна

Что запомнить
  • Ряд удобно хранить как Series с индексом-датой: pd.read_csv(..., parse_dates=[...], index_col=...). Индекс должен быть отсортирован.
  • Срез по датам: s['2026-06'], s['2026-06-01':'2026-06-07'].
  • s.resample('D').sum() — переход к другой частоте с агрегацией (как GROUP BY по началу дня). Частоты: 'h', 'D', 'W', 'MS'.
  • s.rolling(7).mean() — скользящее среднее по 7 последним значениям; сглаживает шум и показывает тренд.
  • s.shift(1) — значение на шаг раньше; s.diff() — разница с предыдущим значением; s.pct_change() — та же разница в долях: s.diff() / s.shift(1).
  • Части индекса-даты — s.index.hour, s.index.dayofweek, s.index.date; по ним группируют: s.groupby(s.index.hour).mean().
  • Аномалии (сбои, акции) видны на графике и в разности с типичным значением — их отмечают перед моделированием.

2. Тренд, сезонность и остаток

Что запомнить

3. Признаки для прогноза ряда

Что запомнить
  • Календарные признаки: час, день недели, выходной, праздник, акция — известны заранее на любой срок.
  • Лаги: s.shift(k) — значение k шагов назад. Для часовых заказов полезны лаги 1, 24 и 168.
  • Скользящие статистики считают по прошлому: s.shift(1).rolling(24).mean(). Без shift(1) в окно попадает текущее значение — утечка.
  • Строки с пропусками в начале ряда (нет истории для лагов) удаляют.
  • Подозрительно хорошее качество на временном ряде — почти всегда признак из будущего.

  • Для проверки в этом уроке — маска по дате: обучение до августа, тест — август. Подробно о проверке по времени — в следующем уроке.

4. Проверка по времени: хвост ряда и TimeSeriesSplit

5. Прогноз: ориентиры, горизонт и метрики

Что запомнить
  • Наивные прогнозы: «как час назад», «как вчера в этот час», «как неделю назад», «среднее за этот час в 4 прошлые недели». Модель должна их обгонять.
  • MAE — средняя ошибка в штуках, RMSE — сильнее штрафует большие промахи, WAPE = сумма |ошибок| / сумма факта — доля в процентах, не ломается на нулях.
  • MAPE (средняя ошибка в процентах по строкам) делит на факт и взрывается при нулевых значениях — для рядов с нулями не годится.
  • Горизонт прогноза определяет признаки: на час вперёд можно взять лаг 1, на завтра с отсечкой в полночь — только лаги от 24, с решением в 20:00 — от 28.
  • Хороший наивный прогноз полезно добавить в модель признаком — модель будет его уточнять.

6. Проект: сколько бариста поставить на смену

Что запомнить
  • Требование к модели формулируют заранее: метрика, порог и наивный прогноз, который нужно обогнать.
  • Момент прогноза задаёт признаки: при решении в 20:00 последний известный час — 19:00, и для 23:00 завтра законны только лаги ≥ 28 — здесь лаги 48, 168 и среднее s.shift(28).rolling(24).

1. Текст как данные: очистка и токены

Что запомнить

2. Леммы и словарь исключений

Что запомнить
  • Лемматизация приводит слово к начальной форме (сырники → сырник). Для русского — библиотеки pymorphy3 или natasha; в браузере их нет, поэтому используем стемминг или заранее посчитанную таблицу лемм review_lemmas.csv.
  • pymorphy3 знает слова из словаря (привезли → привезти, лучший → хороший), а лемму незнакомого слова угадывает по окончанию и на меню ошибается (капучино → капучиный). Частые незнакомые слова просматривают и правят словарём исключений на уровне лемм.

5. Качество разметки: голосование, каппа, золотой набор

6. Эмбеддинги: векторы слов и отзывов

Что запомнить
  • Эмбеддинг — плотный вектор фиксированной длины (сотни чисел) вместо разреженного вектора длиной в словарь.
  • Близость векторов меряют косинусом: a @ b / (|a| · |b|); 1 — одно направление, 0 — ничего общего.
  • Вектор текста из векторов слов — среднее (mean pooling); после нормировки косинус — это просто скалярное произведение.
  • LSA (TruncatedSVD поверх TF-IDF) — эмбеддинги «на коленке»: ловят совместную встречаемость, но не смысл (дороговато ≈ недорого).
  • word2vec учит векторы слов на учебной задаче «по слову угадай соседей» (пары в окне ±k + случайные отрицательные пары). Слова с одинаковым окружением получают близкие векторы — и антонимы тоже.
  • Предобученные модели (например, rubert-tiny2 через transformers) дают смысловые эмбеддинги; их кладут в обычный классификатор или поиск по сходству.

7. Внутри трансформера: токены, маска, пулинг

Что запомнить
  • Внимание — взвешенное среднее векторов всех токенов текста с весами, которые модель считает сама (softmax оценок); маска ставит вес заполнителей в 0.
  • BERT-подобные модели дают вектор каждому токену в контексте. Путь: токенизатор (подслова WordPiece, [CLS], [SEP], [UNK]) → дополнение [PAD] до общей длины + attention_mask → векторы токенов → пулинг.
  • Mean pooling считают только по настоящим токенам: (H * mask[:, :, None]).sum(1) / mask.sum(1, keepdims=True). Без маски вектор текста зависит от соседей по пакету.
  • Эмбеддинги дорого считать — их кэшируют на диск вместе с отпечатком текстов и именем модели; сортировка текстов по длине перед разбивкой на пакеты убирает почти все заполнители.

9. Проект: о чём жалуются гости

Что запомнить
  • Модель для разметки обучают на старых размеченных данных и честно оценивают на отложенной части; для работы её переобучают на всех данных.

  • Перенос на новый источник — риск: тексты могут отличаться. Перед выводами читают примеры и смотрят, правдоподобна ли разметка.

  • Причину ищут в разрезе: структура жалоб по темам до и после и сравнение с остальными точками.
  • Доля по модели смещена её ошибками. Зная полноту (TPR) и долю ложных срабатываний (FPR), долю исправляют: (p − FPR) / (TPR − FPR).

1. Картинка — это массив чисел

Что запомнить
  • Чёрно-белое изображение — матрица (высота, ширина) чисел яркости; цветное — (высота, ширина, 3): красный, зелёный, синий.

3. Свёртка и фильтры

Что запомнить
  • Свёртка: окно k × k проходит по картинке; в каждой позиции — сумма произведений пикселей окна на веса фильтра. Без дополнения краёв выход меньше: n − k + 1.
  • scipy.ndimage.correlate(img, kernel, mode='nearest') — то же быстро и с дополнением краёв (размер не меняется). В нейросетях «свёрткой» называют именно эту операцию.
  • Размытие (среднее по окну) подавляет шум; фильтры Собеля откликаются на перепады яркости — края; модуль градиента np.hypot(gx, gy) — сила края.
  • На шумной картинке края находит и шум: сначала размывают, потом ищут края.
  • Пулинг (max-pooling) берёт максимум в каждом блоке s × s: картинка уменьшается, а признаки становятся терпимее к сдвигу.
  • Свёртка → модуль → пулинг → таблица признаков: логистическая регрессия на таких признаках заметно точнее, чем на сырых пикселях.

4. Модели на пикселях: ошибки, аугментация, устойчивость

Что запомнить

  • Аугментация — добавить в обучение изменённые копии (отражения, сдвиги, яркость). Применяется только к обучающей части; тест не трогают.

5. Свёрточные нейросети

Что запомнить
  • Свёрточный слой: C_out фильтров размера k × k × C_in + сдвиги; параметров (k·k·C_in + 1)·C_out — не зависит от размера картинки.

  • Форма тензора в PyTorch: (батч, каналы, высота, ширина); чёрно-белая картинка — 1 канал, цветная — 3.
  • Свёрточная сеть устойчивее к сдвигу и освещению, чем модели на пикселях, но не неуязвима: проверка на изменённых данных обязательна.

1. Модель как артефакт: файл, паспорт, контрольный набор

Что запомнить
  • Артефакт модели = файл модели (joblib) + паспорт (JSON: версия, признаки, порог, метрики, отпечаток данных, версия sklearn) + контрольный набор (несколько строк и ожидаемые ответы).
