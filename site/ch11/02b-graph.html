Граф вычислений, инициализация и обрезка градиента

Обратный проход для двухслойной сети мы вывели руками. Теперь разбираем, как его считают библиотеки — графом вычислений, — и что нужно, чтобы глубокая сеть вообще училась: правильный масштаб начальных весов (Xavier и He) и обрезка градиента, которая спасает от редких огромных шагов.

Продолжение урока «Обучение сети: обратное распространение ошибки». Там мы вывели формулы обратного прохода для одной конкретной сети и обучили её на полумесяцах. Здесь три темы, которые нужны, когда сеть становится больше: как обратный проход устроен внутри библиотек, какими брать начальные веса и как не дать одному неудачному батчу испортить обучение.

Граф вычислений: как backprop устроен внутри

Зачем. Формулы обратного прохода в прошлом уроке мы вывели руками для одной конкретной сети. Поменяйте активацию или добавьте слой — выводить заново. Библиотеки поступают иначе: записывают вычисление как граф — цепочку маленьких операций — и прогоняют по нему одно и то же правило. Поняв граф, вы поймёте, что делает loss.backward() в PyTorch (урок «PyTorch: то же самое, но в промышленном масштабе»), и почему там нужен zero_grad().

Аналогия

Это как техкарта напитка в «Зерне»: эспрессо → добавить молоко → добавить сироп → цена. Если поднять цену зерна на рубль, на сколько вырастет себестоимость латте? Идём по карте с конца: каждый шаг знает только своё «если вход вырос на 1, выход вырос на столько-то», и эти коэффициенты перемножаются. Только в сети коэффициенты шагов зависят от текущих чисел (у умножения — от второго множителя), поэтому граф пересчитывают на каждом шаге обучения.

Игрушечный пример руками. Потеря одного объекта в линейной модели: L = (w \cdot x + b - y)^2 при x = 2, w = 3, b = 1, y = 10. Разобьём на узлы:

Вперёд — считаем значения узлов: u = w \cdot x = 6, z = u + b = 7, e = z - y = -3, L = e^2 = 9.

Назад — у каждого узла своя локальная производная: у квадрата 2e, у сложения 1, у вычитания по y — минус 1, у умножения w \cdot x по w — второй множитель x. Градиент, пришедший сверху, умножается на локальную производную:

  1. \partial L / \partial e = 2e = -6;
  2. \partial L / \partial z = -6 \cdot 1 = -6, и столько же получает b: \partial L / \partial b = -6;
  3. \partial L / \partial u = -6 \cdot 1 = -6;
  4. \partial L / \partial w = -6 \cdot x = -12, \partial L / \partial x = -6 \cdot w = -18.

Проверка по формуле из главы 10: \partial L / \partial w = 2(wx + b - y) \cdot x = 2 \cdot (-3) \cdot 2 = -12. Сходится.

Второе правило — пути складываются. Если значение используется дважды, например f = w \cdot w, градиент приходит к w по двум путям (w как первый множитель и как второй), и вклады суммируются: 3 + 3 = 6 = 2w.

Напишем этот механизм сами — маленький класс-число, который помнит, из чего получен. В коде две вещи Python, которых в курсе ещё не было, — разберём их до кода:

  • __add__, __sub__, __mul__ — методы со «служебными» именами. Когда Python видит a + b для наших объектов, он вызывает a.__add__(b); так мы сами решаем, что значит +: здесь — посчитать сумму и запомнить, из чего она получена.
  • visit вызывает сама себя (рекурсия): чтобы поставить узел в список, она сначала ставит туда всех его родителей. В итоге родители идут раньше детей, а reversed даёт обратный порядок — от потери к входам. seen хранит уже обойдённые узлы, чтобы узел, к которому ведут два пути, не попал в список дважды.

Пользоваться классом можно и как чёрным ящиком — задача после раздела требует только строить граф обычными +, -, * и вызывать backward().

class Value:
    """Число, которое помнит, из чего получено, и умеет считать градиенты."""
    def __init__(self, data, parents=(), local_grads=()):
        self.data = data                # значение узла
        self.grad = 0.0                 # dL / d(узел), заполнит backward
        self.parents = parents          # из каких узлов получен
        self.local_grads = local_grads  # производные узла по каждому родителю

    def __add__(self, other):
        return Value(self.data + other.data, (self, other), (1.0, 1.0))

    def __sub__(self, other):
        return Value(self.data - other.data, (self, other), (1.0, -1.0))

    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), (other.data, self.data))

    def backward(self):
        order, seen = [], set()
        def visit(v):                   # порядок «родители раньше детей»
            if id(v) not in seen:
                seen.add(id(v))
                for p in v.parents:
                    visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0                 # dL / dL = 1
        for v in reversed(order):       # от потери к листьям
            for p, g in zip(v.parents, v.local_grads):
                p.grad += v.grad * g    # цепное правило; += — вклады путей складываются

w, x, b, y = Value(3.0), Value(2.0), Value(1.0), Value(10.0)
e = w * x + b - y                   # строим граф обычными операциями
L = e * e
L.backward()
print(L.data, w.grad, b.grad, x.grad)

w = Value(3.0)
f = w * w                           # w используется дважды
f.backward()
print(w.grad)

Что здесь происходит:

  • __add__, __sub__, __mul__ — Python вызывает их для +, -, *. Каждая операция создаёт новый узел и запоминает родителей и локальные производные: у суммы (1, 1), у разности (1, −1), у произведения — «второй множитель» для каждого из множителей.
  • visit обходит граф и выстраивает узлы так, чтобы каждый шёл после своих родителей (этот порядок называют топологическим). reversed(order) — наоборот, от потери к входам.
  • self.grad = 1.0 — производная потери по самой себе.
  • p.grad += v.grad * g — цепное правило: градиент узла × локальная производная. Именно +=, а не =: если узел — родитель нескольких узлов, вклады складываются.

Как читать результат: первая строка 9.0 -12.0 -6.0 -18.0 — потеря и градиенты по w, b, x, ровно как в разборе руками. Вторая — 6.0: два пути к w сложились. PyTorch делает то же самое, только узлы — целые тензоры, а локальные производные известны для сотен операций. И та же += объясняет его особенность: градиенты копятся в .grad между вызовами backward(), поэтому перед каждым шагом их обнуляют optimizer.zero_grad().

Типичные ошибки
  • Градиенты не обнулили. В PyTorch, если дважды посчитать потерю и вызвать backward(), не обнулив градиенты, w.grad для нашего примера станет −24 вместо −12: второй вклад прибавился к первому. В цикле обучения это и есть забытый optimizer.zero_grad() — каждый шаг тащит за собой сумму всех прошлых градиентов, и обучение идёт вразнос.
  • = вместо += при обходе. Тогда для f = w \cdot w получится 3 вместо 6: второй путь затрёт первый. Числовая проверка градиента (раздел «Проверка градиентов» прошлого урока) ловит такую ошибку сразу.

Какими брать начальные веса: Xavier и He

Зачем. До обучения веса сети — случайные числа. Кажется, неважно, какие именно: обучение всё равно их поправит. Но в сети из 10–20 слоёв неудачный масштаб весов ломает прямой проход ещё до первого шага: сигнал на выходе либо улетает в миллионы, либо гаснет почти до нуля. В первом случае потеря сразу inf или nan, во втором сеть ничему не учится: обратный проход умножает сигнал ошибки на те же веса, что и прямой (вспомните np.outer(d2, w2)), и он тоже гаснет. Как это выглядит на обратном пути, увидим в следующем разделе.

Аналогия

Представьте цепочку из десяти кассиров, где каждый пересчитывает выручку предыдущего и случайно чуть-чуть ошибается в одну сторону: если каждый завышает на 10 %, к концу цепочки сумма вырастет в 2.6 раза, а если занижает на 10 % — упадёт до трети. Каждый слой сети так же умножает «громкость» сигнала на свой множитель, и множители перемножаются. Отличие: множитель слоя — не ошибка, а следствие размера весов, и его можно заранее сделать близким к единице.

Игрушечный пример руками. Нейрон складывает n слагаемых x_i w_i. Пусть входы x_i — случайные числа со стандартным отклонением 1 (признаки после StandardScaler), а веса — случайные со стандартным отклонением s. У суммы независимых случайных слагаемых складываются дисперсии (квадраты отклонений), поэтому:

  • у одного слагаемого x_i w_i дисперсия 1 \cdot s^2 = s^2;
  • у суммы n таких слагаемых — n \cdot s^2;
  • стандартное отклонение суммы — \sqrt{n} \cdot s.

Для n = 100 входов: при s = 1 выход нейрона разбросан в \sqrt{100} \cdot 1 = 10 раз сильнее входа, при s = 0.01 — сжат до 10 \cdot 0.01 = 0.1, а при s = 0.1 остаётся около 1. Проверим на 10 000 случайных объектах:

import numpy as np
rng = np.random.default_rng(0)
x = rng.normal(size=(10000, 100))          # 10 000 объектов, 100 входов, отклонение 1
for s in [1.0, 0.1, 0.01]:
    w = rng.normal(size=100) * s           # веса нейрона с отклонением s
    print(s, round(float((x @ w).std()), 2))

Что здесь происходит:

  • x — таблица 10 000 × 100: в каждом столбце случайные числа со средним 0 и отклонением 1.
  • rng.normal(size=100) * s — 100 случайных весов, растянутых до отклонения s.
  • (x @ w).std() — разброс выхода нейрона по 10 000 объектам. Получается 11.22, 0.97 и 0.11 — около \sqrt{n} \cdot s = 10, 1 и 0.1 (отличие — случайность конкретных весов).

Один слой умножает разброс на \sqrt{n} \cdot s, десять слоёв — на (\sqrt{n} \cdot s)^{10}. При множителе 10 это 10^{10}, при множителе 0.1 — 10^{-10}. Отсюда два правила масштаба:

\text{Xavier: } s = \sqrt{\frac{1}{n_{in}}}, \qquad \text{He: } s = \sqrt{\frac{2}{n_{in}}}

Здесь n_{in} — число входов слоя (строк в его матрице W), s — стандартное отклонение, с которым генерируют веса. Xavier (его ещё называют инициализацией Глорот, по фамилии автора) делает множитель слоя равным 1 и подходит для tanh и сигмоиды; в исходной статье стоит среднее числа входов и выходов, \sqrt{2 / (n_{in} + n_{out})}, — для квадратных слоёв это то же самое. He (по фамилии Каймина Хэ) добавляет двойку для ReLU: ReLU обнуляет примерно половину значений, средний квадрат сигнала падает вдвое, и двойка это возмещает.

На реальной сети. Пропустим 500 объектов через 10 слоёв по 100 нейронов с ReLU при четырёх масштабах весов и посмотрим, какой разброс остаётся после 1-го, 5-го и 10-го слоя:

import numpy as np
rng = np.random.default_rng(0)
X = rng.normal(size=(500, 100))            # 500 объектов, 100 признаков в одном масштабе

def signal(scale, layers=10, width=100):
    """Стандартное отклонение выхода после каждого слоя ReLU."""
    r = np.random.default_rng(1)           # одни и те же случайные числа для всех масштабов
    A, stds = X, []
    for _ in range(layers):
        W = r.normal(size=(width, width)) * scale
        A = np.maximum(0, A @ W)
        stds.append(A.std())
    return stds

for name, scale in [("N(0, 1)", 1.0), ("× 0.01", 0.01),
                    ("Xavier √(1/n)", np.sqrt(1 / 100)), ("He √(2/n)", np.sqrt(2 / 100))]:
    s = signal(scale)
    print(f"{name:14} слой 1: {s[0]:.3g}   слой 5: {s[4]:.3g}   слой 10: {s[9]:.3g}")

Что здесь происходит:

  • signal(scale) строит 10 слоёв подряд; у всех веса из одного и того же генератора, умноженные на scale, — сравниваем только масштаб.
  • A = np.maximum(0, A @ W) — слой с ReLU, как в разделе «Слой — матричное умножение» урока «Нейрон и слои»; выход слоя — вход следующего.
  • stds.append(A.std()) — запоминаем, насколько «громкий» сигнал после каждого слоя.
  • f"{...:.3g}" — три значащие цифры: так видны и миллионы, и миллиардные доли.

Как читать результат:

веса после слоя 1 после слоя 5 после слоя 10
N(0, 1) 5.87 13 500 221 000 000
× 0.01 0.0587 0.00000135 0.00000000000221
Xavier 0.587 0.135 0.0221
He 0.829 0.762 0.708

Почему у He после первого слоя 0.829, а не ровно 1? Двойка в формуле выравнивает средний квадрат выхода, а std считает разброс вокруг среднего. После ReLU все числа неотрицательны, среднее выхода больше нуля, поэтому std меньше корня из среднего квадрата. Важно другое: множитель слоя не растёт и не падает от слоя к слою.

С весами N(0, 1) сигнал за 10 слоёв вырос до сотен миллионов — первая же сигмоида на выходе выдаст ровно 0 или 1, а логистическая потеря — бесконечность. С весами «× 0.01» он угас до 10^{-12}: все объекты для сети выглядят одинаково. Xavier с ReLU тоже медленно гасит сигнал (каждый слой теряет примерно \sqrt{2}), а He держит его около 0.7–0.8 на всех слоях. Для «Зерна» вывод практический: в сети с ReLU берите He. Как это записать в PyTorch, понадобится только в уроке «PyTorch: то же самое, но в промышленном масштабе», сейчас достаточно идеи; для справки: He — nn.init.kaiming_normal_(layer.weight), Xavier — nn.init.xavier_normal_(layer.weight), где layer — слой сети. Собственная схема слоёв PyTorch по умолчанию — равномерные числа от -1/\sqrt{n_{in}} до 1/\sqrt{n_{in}}, она ближе к «осторожной» стороне.

Взрыв и затухание градиента, обрезка

Зачем. В глубокой сети градиент для первого слоя — произведение множителей всех слоёв над ним (цепное правило из прошлого урока). Если множители в среднем больше 1, градиент растёт с глубиной — взрыв градиента: шаги огромные, веса улетают, потеря скачет или становится nan. Если меньше 1 — затухание: первые слои почти не учатся. Похожий удар бывает и в мелкой сети: один батч с аномалией в данных даёт градиент в десятки раз больше обычного, и один шаг портит то, чему сеть училась сотни шагов.

Аналогия

Это как испорченный телефон в длинной очереди: каждый передаёт фразу чуть громче (или чуть тише), чем услышал. Через 30 человек шёпот превратится в крик или в тишину. Но в сети «громкость» каждого звена известна — это веса и производные активаций, — поэтому её можно заранее выставить около 1 (инициализация He из прошлого раздела) и подстраховать ограничителем.

Игрушечный пример руками. 30 слоёв, каждый умножает сигнал ошибки на одно и то же число:

  • множитель 1.5: 1.5^{30} \approx 191\,751 — к первому слою приходит градиент в 190 тысяч раз больше;
  • множитель 0.5: 0.5^{30} \approx 9.3 \cdot 10^{-10} — приходит почти ноль.

Проверим на сети из 30 слоёв ReLU по 64 нейрона. Веса — по He из прошлого раздела, умноженные на 0.7, 1.0 или 1.3. Прогоним объекты вперёд, а затем сигнал ошибки назад и сравним его силу (норму) у последнего и у первого слоя:

import numpy as np

def error_signal(mult, depth=30, width=64):
    """Норма сигнала ошибки на входе каждого слоя: от первого к последнему."""
    rng = np.random.default_rng(0)
    A = rng.normal(size=(128, width))
    Ws, Zs = [], []
    for _ in range(depth):                                  # прямой проход
        W = rng.normal(size=(width, width)) * mult * np.sqrt(2 / width)
        Z = A @ W
        A = np.maximum(0, Z)
        Ws.append(W); Zs.append(Z)
    dA = np.ones_like(A) / A.size                           # потеря = среднее выходов
    norms = []
    for W, Z in zip(reversed(Ws), reversed(Zs)):            # обратный проход
        dA = (dA * (Z > 0)) @ W.T                           # через ReLU и веса слоя
        norms.append(np.linalg.norm(dA))
    return norms[::-1]

for mult in [0.7, 1.0, 1.3]:
    n = error_signal(mult)
    print(f"He × {mult}: у последнего слоя {n[-1]:.3g}, у первого {n[0]:.3g}, отношение {n[0] / n[-1]:.3g}")

Что здесь происходит:

  • Прямой проход запоминает веса Ws и оценки Zs каждого слоя — они нужны на обратном пути.
  • dA = np.ones_like(A) / A.size — градиент простой потери «среднее выходов»: каждому выходу достаётся 1/(число элементов).
  • (dA * (Z > 0)) @ W.T — один шаг назад: через производную ReLU, затем через веса слоя (как dH = np.outer(d2, w2) * (Z1 > 0) в уроке «Обучение сети: обратное распространение ошибки», только для матрицы).
  • np.linalg.norm(dA) — «сила» сигнала ошибки: корень из суммы квадратов всех его чисел.

Как читать результат: при весах «He × 0.7» к первому слою доходит в 7 тысяч раз меньше, чем было у последнего (отношение 0.000146), — первые слои почти стоят. При «He × 1.3» — в 9 тысяч раз больше: первые слои делают гигантские шаги. При He сигнал за 30 слоёв меняется всего в 4.5 раза. Отсюда первая защита — правильная инициализация. Вторая — обрезка градиента (gradient clipping).

Обрезка по норме. Если норма градиента больше порога max_norm, весь вектор градиента уменьшают в одно и то же число раз, чтобы его норма стала ровно max_norm:

g \leftarrow g \cdot \min\left(1, \frac{\text{max\_norm}}{\lVert g \rVert}\right)

Здесь g — вектор градиентов всех весов, \lVert g \rVert — его норма (корень из суммы квадратов), max_norm — порог. Пример: g = (30, 40), норма \sqrt{900 + 1600} = 50, порог 5 — умножаем на 5 / 50 = 0.1 и получаем (3, 4). Направление шага то же, длина ограничена. Маленький градиент (0.3, 0.4) с нормой 0.5 не трогаем.

На данных «Зерна». В выгрузке доставок осталось 5 ошибочных записей — 735, 784, 914, 987 и 1281 минут. Учим линейную модель «минуты ∼ расстояние + число позиций» мини-батчами по 32, как SGD в главе 10, с шагом 0.3 и после каждого шага меряем MAE на нормальных доставках. Батч, в который попала аномалия, даёт градиент в десятки раз больше обычного:

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

d = pd.read_csv("deliveries.csv")
d = d[d["actual_min"] > 0]                      # убрали пустые и отрицательные, ошибочные > 700 минут остались
X = d[["distance_km", "items"]].to_numpy(float)
X = (X - X.mean(axis=0)) / X.std(axis=0)
y = d["actual_min"].to_numpy(float)
normal = y < 300                                 # по нормальным доставкам меряем качество

def sgd(lr, max_norm=None, epochs=5, batch=32):
    rng = np.random.default_rng(0)
    w, b = np.zeros(2), 0.0
    mae, norms = [], []
    for _ in range(epochs):
        order = rng.permutation(len(y))
        for start in range(0, len(y), batch):
            i = order[start:start + batch]
            err = X[i] @ w + b - y[i]
            g = np.append(2 * X[i].T @ err / len(i), 2 * err.mean())   # градиент MSE по (w1, w2, b)
            norms.append(np.linalg.norm(g))
            if max_norm is not None and norms[-1] > max_norm:
                g = g * (max_norm / norms[-1])                      # обрезка по норме
            w, b = w - lr * g[:2], b - lr * g[2]
            mae.append(np.abs(X[normal] @ w + b - y[normal]).mean())
    return np.array(mae), np.array(norms)

mae_raw, norms = sgd(0.3)
mae_clip, _ = sgd(0.3, max_norm=20)
half = len(mae_raw) // 2
print("норма градиента: медиана", round(float(np.median(norms)), 1), "максимум", round(float(norms.max()), 1))
print("худшая MAE во второй половине: без обрезки", round(float(mae_raw[half:].max()), 2),
      "с обрезкой", round(float(mae_clip[half:].max()), 2))

fig, ax = plt.subplots(figsize=(7, 3.5))
ax.plot(mae_raw, lw=1, label="без обрезки")
ax.plot(mae_clip, lw=1, label="обрезка, max_norm = 20")
ax.set_xlabel("шаг"); ax.set_ylabel("MAE на нормальных доставках, мин")
ax.set_ylim(0, 40); ax.legend()
plt.show()

Что здесь происходит:

  • g = np.append(...) — градиент MSE по двум весам и сдвигу на текущем батче, как в главе 10.
  • norms.append(np.linalg.norm(g)) — запоминаем норму до обрезки, чтобы увидеть, какими бывают градиенты.
  • if ... norms[-1] > max_norm: g = g * (max_norm / norms[-1]) — обрезка по норме, формула выше.
  • mae после каждого шага — качество на нормальных доставках: то, что важно бизнесу.

Что получилось: обычная норма градиента — около 8, а батч с аномалией даёт до 122.6. Без обрезки такой шаг выбрасывает модель далеко от хорошего решения: во второй половине обучения MAE подскакивает до 31.59 минуты (на графике — пики). С обрезкой на 20 худшая MAE — 10.33: аномальный батч всё ещё толкает модель, но не дальше обычного шага. В PyTorch обрезка — одна строка между loss.backward() и optimizer.step(): torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0).

Типичные ошибки
  • Обрезка каждого числа отдельно вместо нормы. np.clip(g, -5, 5) для g = (30, 0.4) даёт (5, 0.4) — направление шага изменилось. Обрезка по норме даёт (5, 0.067) — направление прежнее. В PyTorch первое — clip_grad_value_, второе — clip_grad_norm_; по умолчанию берут норму.
  • Обрезкой лечат слишком большой шаг. Если градиенты большие на каждом шаге, обрезка срабатывает всегда и превращает спуск в шаги постоянной длины — модель не может точно подойти к минимуму. Обрезка — страховка от редких выбросов; при постоянном взрыве уменьшайте lr и проверяйте инициализацию.
  • Обрезка до backward() или после step(). До backward() градиентов ещё нет, после step() веса уже сдвинуты. Её место — строго между.

Сеть для чёрно-белых картинок 28 × 28 пикселей устроена так: sizes = [784, 128, 64, 10] — 784 входа, слои по 128 и 64 нейрона с ReLU и 10 выходов. Слоёв с весами три: 784 → 128, 128 → 64, 64 → 10. Сохраните:

  • he — список из трёх чисел: масштаб He \sqrt{2 / n_{in}} для каждого слоя (3 знака);
  • mult_he — множитель разброса каждого слоя \sqrt{n_{in}} \cdot s, если у каждого слоя свой масштаб из he (3 знака);
  • mult_one — тот же множитель, если ошибиться и взять для всех слоёв один масштаб — первого слоя he[0] без округления (3 знака);
  • shrink — во сколько раз сигнал на выходе сети с одним масштабом слабее, чем с правильным: произведение mult_one, делённое на произведение mult_he (3 знака, считайте по неокруглённым множителям).

Посложнее

Данные доставок с пятью ошибочными записями уже подготовлены (X, y, normal — как в теории). В заготовке — функция sgd из теории без обрезки. Допишите её: если задан max_norm и норма градиента больше порога, обрежьте градиент по норме, а в clipped считайте, сколько раз это случилось. Функция должна возвращать (mae, norms, clipped).

Запустите её с lr=0.1 для порогов None (без обрезки), 50, 20 и 5. Сохраните:

  • res — словарь {порог: (худшая MAE во второй половине шагов, MAE после последнего шага, доля шагов с обрезкой)}, MAE — 2 знака, доля — 3 знака; «вторая половина» — mae[len(mae) // 2:];
  • safest — порог с наименьшей худшей MAE. «Безопаснее» по этой метрике ещё не значит «лучше»: что не так с самым низким порогом, смотрите в разборе;
  • median_norm — медиану norms без обрезки (1 знак).

Что запомнить

  • Граф вычислений: каждая операция знает свою локальную производную; backward идёт от потери к входам, умножает градиенты на локальные производные и складывает вклады разных путей (отсюда zero_grad в PyTorch).
  • Каждый слой умножает разброс сигнала примерно на √n_in · s, где s — отклонение весов. Начальные веса берут по He: s = √(2 / n_in) для ReLU, или по Xavier: s = √(1 / n_in) для tanh и сигмоиды — тогда сигнал не взрывается и не гаснет по слоям.
  • Взрыв и затухание градиента: в глубокой сети множители слоёв перемножаются. Защита — инициализация He и обрезка по норме: g · min(1, max_norm / ‖g‖) между backward и step.
