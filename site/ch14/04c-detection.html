Регрессия по фото, детекция и сегментация

Сеть умеет не только называть класс. Она может оценить по фото число — вес порции или заполненность подноса, найти на кадре все объекты рамками (детекция) или отметить их пиксели (сегментация). Разбираем, что меняется в сети для каждой задачи, и главное для аналитика — как проверять результат: IoU, сопоставление рамок, точность и полнота детектора.

0 из 5

Регрессия по фото опирается на дообучение готовой сети из урока «Перенос обучения и дообучение»: меняются только голова и функция потерь. Детекцию и сегментацию в браузере не обучить, зато проверку их результата — IoU, сопоставление рамок, точность и полноту — можно посчитать руками.

Регрессия по фото

Сеть может предсказывать не класс, а число: сколько граммов в порции, какая доля ячейки витрины заполнена, сколько людей в очереди на кадре. Идея та же, что при переходе от логистической регрессии к линейной (главы 6–7):

классификация регрессия
последний слой nn.Linear(512, число_классов) nn.Linear(512, 1)
выход вероятности через softmax одно число как есть
функция потерь nn.CrossEntropyLoss() nn.MSELoss() или nn.L1Loss() (MAE)
метрика доля правильных, F1 MAE, RMSE 
model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)
model.fc = nn.Linear(model.fc.in_features, 1)          # одно число на фото
loss_fn = nn.L1Loss()                                  # MAE: ошибка в тех же единицах, что ответ
pred = model(xb).squeeze(1)                            # (пакет, 1) → (пакет,)
loss = loss_fn(pred, yb.float())                       # yb — граммы, доли, штуки

Без PyTorch идея проверяется тем же путём, что в уроке «Модели на пикселях: ошибки, аугментация, устойчивость»: признаки картинки (пиксели, отклики фильтров, эмбеддинги ResNet) → Ridge или HistGradientBoostingRegressor. Подводные камни — как у любой регрессии: ответ стоит масштабировать (например, доли 0–1, а не граммы в тысячах), смотреть на остатки по группам (ночные кадры, другая камера) и сравнивать с наивным прогнозом «среднее по обучению».

Проверьте себя

Вы учите сеть оценивать по фото вес порции салата в граммах. Что поменять в сети-классификаторе витрины?

  • [x] Последний слой — один выход без softmax, потери — MSE или MAE, метрика — ошибка в граммах

    Классы превратились в число: голова выдаёт одно значение, и сравнивают его с ответом по расстоянию, а не по вероятности класса.

  • [ ] Ничего: разбить вес на классы «100 г», «110 г», … и оставить классификацию

    Так можно, но модель не будет знать, что 110 г ближе к 100 г, чем к 300 г: ошибка «на соседний класс» штрафуется так же, как «через весь диапазон».

  • [ ] Заменить свёрточные слои на полносвязные: регрессии свёртки не нужны

    Свёртки извлекают признаки картинки — они нужны и для классификации, и для регрессии. Меняется только голова и функция потерь.

  • [ ] Оставить softmax, но с одним выходом

    Softmax одного числа всегда равен 1 — сеть будет выдавать одну и ту же «вероятность» для любого фото.

Практика — в своём блокноте

В данных витрины нет числового ответа, поэтому задачи на регрессию по фото в браузере нет. Когда появятся свои фото с числом (вес порции, заполненность подноса), проверьте модель по шагам:

  1. Ориентир. Наивный прогноз — среднее ответа по обучению; его MAE на тесте — планка, которую модель обязана перепрыгнуть.
  2. Ошибка в единицах ответа. MAE модели на тесте — «ошибаемся в среднем на N граммов» — и сравнение с ориентиром.
  3. Остатки по группам. MAE отдельно для дня и вечера, для каждой камеры: средняя ошибка может прятать одну плохую группу.

Тот же разбор — ориентир, MAE и остатки по группам — был в уроке «Регрессия: сколько минут» главы 6; меняются только признаки: вместо столбцов таблицы — эмбеддинги фото.

Детекция и сегментация: где на кадре и IoU

Классификатор отвечает на вопрос «что на картинке». Для витрины целиком нужно больше:

  • детекция — «что и где»: модель выдаёт прямоугольные рамки (x1, y1, x2, y2), класс и уверенность для каждого найденного объекта. Так считают выпечку на подносе без нарезки на ячейки;
  • сегментация — «какие пиксели»: для каждого пикселя — класс (маска). Так оценивают, какая доля подноса занята.

Обе задачи учат готовыми архитектурами (детекция — семейства YOLO и Faster R-CNN, сегментация — U-Net, DeepLab), обычно дообучая предобученную сеть на своей разметке. Аналитику важнее понять, как проверять результат. Главная мера — IoU (intersection over union, «пересечение на объединение»): насколько найденная рамка совпала с настоящей.

Аналогия

IoU — как совпадение двух брони на одну переговорку: общие часы, делённые на все часы, занятые хотя бы одной бронью. Совпали полностью — 1, не пересеклись — 0. Если одна бронь накрывает другую целиком, но вдвое длиннее, IoU — 0.5: «попали», но с запасом.

Игрушечный пример: настоящая рамка A = (0, 0, 4, 4), найденная B = (2, 2, 6, 6).

  • Пересечение: по x от max(0, 2) = 2 до min(4, 6) = 4, по y так же — квадрат 2 × 2 = 4.
  • Объединение: площадь A + площадь B − пересечение = 16 + 16 − 4 = 28 (пересечение иначе посчитается дважды).
  • IoU = 4 / 28 ≈ 0.14 — рамка задела объект, но это промах.
IoU = \frac{|A \cap B|}{|A \cup B|} = \frac{|A \cap B|}{|A| + |B| - |A \cap B|}

|A| — площадь рамки A, |A \cap B| — площадь пересечения. Обычно найденную рамку засчитывают как попадание при IoU ≥ 0.5.

def iou(a, b):
    """IoU двух рамок (x1, y1, x2, y2); x1 < x2, y1 < y2."""
    w = min(a[2], b[2]) - max(a[0], b[0])          # ширина пересечения
    h = min(a[3], b[3]) - max(a[1], b[1])          # высота пересечения
    inter = max(0, w) * max(0, h)                   # не пересеклись — 0, а не «минус»
    area = lambda r: (r[2] - r[0]) * (r[3] - r[1])
    return inter / (area(a) + area(b) - inter)

print(round(iou((0, 0, 4, 4), (2, 2, 6, 6)), 3))   # пример выше
print(round(iou((0, 0, 4, 4), (1, 0, 4, 4)), 3))   # B внутри A, на четверть уже
print(round(iou((0, 0, 4, 4), (5, 5, 6, 6)), 3))   # не пересекаются

Что здесь происходит:

  • min(a[2], b[2]) - max(a[0], b[0]) — пересечение по горизонтали: правая граница — меньшая из правых, левая — большая из левых.
  • max(0, w) — если рамки не пересекаются, ширина выходит отрицательной; без max две отрицательные стороны дали бы положительную «площадь».
  • Объединение — сумма площадей минус пересечение.

Для масок формула та же, только площадь — число пикселей: (m1 & m2).sum() / (m1 | m2).sum() для булевых массивов.

import numpy as np

yy, xx = np.mgrid[0:32, 0:32]
true_mask = (yy - 16) ** 2 + (xx - 16) ** 2 <= 10 ** 2   # разметчик обвёл круглый маффин
pred_mask = (yy - 18) ** 2 + (xx - 15) ** 2 <= 9 ** 2    # маска модели: чуть сдвинута и меньше
inter = (true_mask & pred_mask).sum()
union = (true_mask | pred_mask).sum()
print(inter, union, round(inter / union, 3))

Что получилось: рамки, сдвинутые на половину размера, дают IoU всего 0.14; рамка внутри настоящей и на четверть уже — 0.75; маска модели, сдвинутая на пару пикселей и чуть меньше, — около 0.7. IoU строгий: небольшой сдвиг маленького объекта сильно его снижает.

Поверх IoU строятся метрики детекции: найденные рамки сопоставляют с настоящими (по убыванию уверенности, каждая настоящая — не больше одного раза), и считают точность и полноту, как в главе 7. Лишняя рамка на уже найденном объекте — ложное срабатывание; чтобы их не было, детекторы удаляют пересекающиеся рамки одного класса (NMS, non-maximum suppression). Правило NMS простое: рамки перебирают по убыванию уверенности, самую уверенную оставляют, а каждую следующую выбрасывают, если её IoU с какой-нибудь уже оставленной выше порога (обычно 0.5). Итоговая метрика соревнований — mAP: средняя по классам площадь под кривой «точность — полнота».

Типичные ошибки
  • Перепутан формат рамки. Бывает (x1, y1, x2, y2), а бывает (x, y, ширина, высота) — у COCO и многих разметчиков — или центр и размер, как у YOLO, да ещё в долях от размера кадра. IoU по рамкам разных форматов — бессмыслица без ошибки. Приводите к одному формату до сравнения.
  • Отрицательное пересечение. Без max(0, …) у непересекающихся рамок «площадь» пересечения бывает положительной (минус на минус).
  • Одна настоящая рамка засчитана дважды. Две рамки модели на одном круассане с IoU > 0.5 — это одно попадание и одно ложное срабатывание, а не два попадания.
  • Маски из JPEG. На границах появятся промежуточные значения (урок «Файлы картинок и память»); маску приводят к булевой: mask > 127.

Маска из вероятностей

База
↑ К теории: Детекция и сегментация: где на кадре и IoU

Модель сегментации выдаёт для каждого пикселя вероятность «здесь выпечка» — массив prob 32 × 32. Маска получается порогом: prob > t. Настоящая маска — true_mask. Для порогов [0.3, 0.5, 0.7] посчитайте IoU маски модели с настоящей и сохраните iou_by_t — словарь {порог: IoU} (3 знака), best_t — порог с наибольшим IoU, а также occ_true и occ_best — долю кадра, занятую выпечкой, по настоящей маске и по маске модели при лучшем пороге (3 знака).

Убрать дубли рамок

Со звёздочкой

Напишите nms(dets, thr=0.5) — подавление дублей, как в уроке: перебирайте рамки по убыванию уверенности; рамку оставляйте, если её IoU с каждой уже оставленной не больше thr, иначе выбрасывайте. Функция возвращает список оставленных пар (рамка, уверенность) в порядке убывания уверенности. Затем сопоставьте оставленные рамки с настоящими, как в той задаче (функция match готова), и сохраните precision и recall (3 знака).

Что запомнить

  • Регрессия по фото — та же сеть с одним выходом и потерей MSE/MAE.
  • Детекция — рамки, сегментация — маски. Совпадение меряют IoU = пересечение / объединение; попадание — обычно IoU ≥ 0.5, каждая настоящая рамка засчитывается один раз.
