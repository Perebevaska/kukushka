## Подтверждённый дефект актуальности

**P1. Универсальный шаблон temperature = 0 несовместим с частью актуальных моделей.** [content/ch13/04c-llm.md:23](</Users/dmitriikormin/Documents/Projects/ds-course/content/ch13/04c-llm.md:23>) предлагает выбрать имя из документации провайдера, но `:34` безусловно передаёт temperature = 0. На дату аудита [Claude Messages API](https://platform.claude.com/docs/en/api/messages/create) прямо запрещает значения, отличные от совместимого 1.0, для моделей, выпущенных после Opus 4.6: запрос получает 400. Поэтому следование инструкции с новой моделью может сломать пример. Это условная несовместимость, а не утверждение, что все модели и все провайдеры не работают.

Там же `:57` обещает воспроизводимость ответов при нуле, хотя официальный API отдельно предупреждает, что полной детерминированности он не гарантирует.

**Изменение:** выбрать проверенную конкретную модель и дату проверки, передавать только поддерживаемые параметры; убрать гарантию воспроизводимости. Приёмка: конфигурация для современной модели формируется без недопустимого temperature; повторные ответы оцениваются по контракту и golden-набору, а не обязаны совпадать побайтно. Реальный оплачиваемый smoke-запрос должен оставаться отдельной проверкой окружения.

## Рекомендуемое обновление

**Использовать схему ответа там, где она поддерживается.** Текущий PROMPT + json.loads ([content/ch13/04c-llm.md:25–47](</Users/dmitriikormin/Documents/Projects/ds-course/content/ch13/04c-llm.md:25>)) полезен для обучения устойчивому разбору, но актуальные интерфейсы уже поддерживают structured outputs: Claude через output_config.format ([официальная документация](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)), LM Studio через response_format ([официальная документация](https://lmstudio.ai/docs/developer/openai-compat/structured-output)). Показать один вариант со схемой sentiment/topic и enum, сохранив исходный fallback для неподдерживаемых моделей.

Это расширение, не исправление несуществующего обещания безошибочного JSON. Схема контролирует форму и значения, но не правильность темы. Сохранить человеческий golden-набор, учёт отказов, усечения и ошибок транспорта. Приёмка: невалидная структура не превращается в размеченный отзыв; семантические ошибки по-прежнему учитываются отдельно.

## Ограничения

Официальные API проверены чтением документации на дату аудита; доступность конкретного аккаунта и качество платной модели не тестировались. Штатные проверки не исполняют необязательные внешние запросы. Общая NLP-программа остаётся актуальной; выявленный риск локализован в конфигурации интеграции и обещании детерминизма.
