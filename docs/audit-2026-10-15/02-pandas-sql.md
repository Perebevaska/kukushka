Приёмка: учебная последовательность приводит к читаемому GitHub-артефакту с результатами; исходный блокнот остаётся воспроизводимым.

2. **P2. Аналогии merge с SQL требуют оговорки о пустых ключах.** [content/ch02/05-merge.md:59–61](</Users/dmitriikormin/Documents/Projects/ds-course/content/ch02/05-merge.md:59>) показывает прямой SQL-эквивалент; `:124–135` защищает уникальность справочника через many_to_one, но не объясняет семантику пустого ключа. pandas соединяет null с null, в отличие от обычного SQL JOIN — это отдельно выделено в [официальной документации merge](https://pandas.pydata.org/docs/reference/api/pandas.merge.html). В представленных примерах нарушение результата не подтверждено: замечание касается неполноты правила переноса на рабочие данные. Добавить мини-пример с пустым ключом и договорённость: ключи справочника обязательны либо отсутствующие обрабатываются отдельно. Приёмка: ученик различает проверку кардинальности и проверку валидности ключей; обе проверяются независимо.

## Что улучшить без расширения программы

Сохранить плотность темы, но сделать карту обязательных результатов: «таблица → проверенные JOIN → отчёт → чистый перезапуск → опубликованный артефакт». Для SQL-углублений достаточно продолжать явно отмечать необязательность. В замерах времени отдельно учитывать установку локального окружения и создание первого репозитория: скорость этих действий зависит от платформы и исходной подготовки.
