# Карточка ученика после глав 1–3

Я пришёл с опытом SQL/Excel и фрагментарным знанием Python. После первой главы умею пройти по строкам выгрузки, работать с типами, словарями и функциями. После второй — перенести аналитику на pandas, использовать сводные, соединения, периоды, SQL-окна, параметризованные запросы и проверять блокнот из чистого ядра. Вторая глава дала мне привычку заранее назвать единицу анализа и знаменатель.

| Теперь умею | Как проверено в главе 3 |
|---|---|
| Осмотреть сырую таблицу и объяснить потери | Сверил форму, типы, варианты строк, пропуски и дубли. Журнал проекта сохранил числа 307 → 299 → 293 и смысл двух сокращений. |
| Выбрать обработку пропуска под вопрос | Сравнил неизвестный и нулевой баланс. Сохранил группу заказов без карты, нулевые заказы у существующих анкет и отдельный знаменатель для доли покупок в своём городе. По известным признакам умею искать связь с пропусками. |
| Найти ошибку преобразования типа | Явно разобрал две формы рождения. Ошибку первого решения нашёл по конкретной строке из обратной связи. Одинаковая итоговая медиана может скрывать неверные даты. |
| Извлечь и сверить числа из Excel | Нашёл шапку на каждом листе, отдельно прочитал месяцы, исключил строки итога из расчёта и сверил суммы. |
| Свести строки и обнаружить аномалии | Нормализовал карту до удаления повторов, выбрал свежую анкету, сверил названия со справочником, разделил заглушку, пропуск и подозрительный настоящий заказ. Посчитал примеры для тикета без имён и телефонов. |
| Сдать повторяемый анализ | Организовал очистку в функции, записал допустимые значения и уникальный ключ как проверки, собрал отчёт для маркетинга. Повторил отчёт на копии с другим именем. Блокнот прошёл опубликованную самопроверку. |

Дополнительные задания тоже пройдены. Статистические выводы о причинах пропусков, идентичность людей по общему номеру телефона и корректность обработки любого будущего значения не считать доказанными на основании одного файла. Публикацию GitHub и ручные действия в графическом JupyterLab не считать подтверждёнными навыками.

Для итогового интервью: пример с 68 неверно разобранными датами заставил меня сверять значения до группировки. Ошибиться в доле можно, даже если pandas выполнил все строки без предупреждений. По-прежнему важно показывать размер группы рядом с её средним. Текущая граница прохождения — завершённая глава 3.
