# Как воспроизвести прохождение

Команды запускаются из корня репозитория. Примеры ниже для главы 2, с временным каталогом `/tmp/ku-audit`. Подставьте нужный номер. Сохранённые журналы в папке главы — первичное свидетельство; повторный запуск использует копии. Ученику до ответа доступны только его порядок уроков, очищенные материалы, публичные данные и карточка знаний.

1. Создайте `/tmp/ku-audit`. Запустите `.venv/bin/python tools/build.py --check --export /tmp/ku-audit/tasks.json`. Это технический экспорт с решениями; не передавайте его ученику.
2. Выполните `.venv/bin/python docs/audit-2026-11-13/checks/prepare.py ch02` и тем же интерпретатором `checks/route.py ch02` из этой папки проверок. Ученик читает `/tmp/ku-audit/ch02/student/` и сохраняет свои ответы в соседние `submissions.jsonl` (lesson, id, code) и `answers.jsonl` (lesson, kind, index, choice; оба номера от 1). Вопросы перемешаны; `choices.json` нужен только координатору. Для подсказки — `help.py ch02 УРОК ID 1` (затем 2, если доступна); `solution` означает открытие разбора. Скрипт ведёт отдельный журнал помощи.
3. `node docs/audit-2026-11-13/checks/submit.mjs ch02` проверяет собственные попытки в Pyodide курса; `node tools/verify.mjs /tmp/ku-audit/tasks.json ch02/` отдельно проверяет авторские задачи, примеры и predict. Это разные результаты.
4. Для независимой проверки в браузере используйте `node docs/audit-2026-11-13/checks/replay.cjs ch02` (необязательный второй аргумент — ID урока). Нужны Playwright и Chromium; при внешней установке задайте `PLAYWRIGHT_MODULE` и `CHROME_BIN`. Скрипт открывает новый профиль и читает только локальную статическую копию сайта. В кодовом редакторе используется буквальный ответ ученика. Для сборки из выданных строк сохраняется также фактическая строка интерфейса, если отличалась только запись эквивалентного выражения.
5. `python3 docs/audit-2026-11-13/checks/coverage.py ch02 /tmp/ku-audit` требует совпадения всех ID, ответов на вопросы и числа попыток. Лишь после успешной сверки создаёт долговременные журналы и coverage.json. Для повторного исполнения из уже сохранённого student.jsonl разделите строки по наличию поля code: они образуют submissions.jsonl и answers.jsonl соответственно. Для учёта использованной помощи перенесите также help.jsonl, если он есть.

Когда четыре роли завершили работу, команда `.venv/bin/python docs/audit-2026-11-13/checks/accept.py ch02` проверяет комплект, ссылки, две первые секции и покрытие замечаний ученика рецензентом. Координатор дополнительно читает оценки, правки и свидетельства; после ручной сверки передаёт её результат третьим аргументом той же команде. Она сохраняет acceptance.md и обновляет progress.md.

Для сводной сверки используйте `.venv/bin/python docs/audit-2026-11-13/checks/course_totals.py`. Скрипт перечитывает задания из Markdown и журналы всех глав, проверяет полноту и пересчитывает число отправок, принятых задач и правильных ответов. Оценки подачи считает отдельно по пяти строкам каждого отчёта. Для промежуточной сверки добавьте номер последней закрытой главы.

В папках `notebooks/` лежат исполненные ученические копии с сохранённым выводом. У дополнительных практикумов 11 и 13 первоначальная рабочая структура — `notebooks/extra/` и соседняя с `notebooks/` папка `data/`: для повторения скопируйте тетради во временную папку с такой структурой и укажите в `data/` файлы из `site/data/` курса. У авторского эксперимента ученика по ResNet в главе 14 перед переносом на другой компьютер укажите в первой ячейке путь к своему `site/data/showcase.npz`. Это сохранённые первичные работы; относительные воспроизводящие расчёты эксперта лежат в папках соответствующих глав.
