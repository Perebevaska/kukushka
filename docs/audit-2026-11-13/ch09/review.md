### S09-01 · 04-transform / 05-project, область применимости · Подтвердить · P2

Обратимая замена координат сохраняет множество прогнозов обычной линейной регрессии, но слова «для линейных моделей» охватывают и модели со штрафом. В Ridge преобразование масштаба меняет цену коэффициента. При одной точке x=1, y=1, α=1 и без свободного члена модель даёт прогноз 0,5. Если умножить признак на 2 при обучении и прогнозировании, получится 0,8. В обоих случаях преобразование обратимо. В ученическом опыте с учебными анкетами и α=1000 разница тоже наблюдалась. [Объяснение](../../../content/ch09/04-transform.md), [выводы проекта](../../../content/ch09/05-project.md).

**Правка.** Рядом с равенством записать «Доказательство относится к обычному методу наименьших квадратов без штрафа. Для Ridge произвольное изменение координат меняет штраф. Поворот ортогональной матрицей сохраняет евклидову норму, растяжение оси — обычно нет». Сохранить вывод через перенос весов между системами координат. **Приёмка.** Ученик прогнозирует, почему удвоение одной колонки может изменить Ridge, и проверяет это на новом наборе отдельно от OLS.

### S09-02 · 05-project и два последних вопроса итогового теста · Подтвердить · P2

При отдельных множителях один ненулевой исходный элемент восстанавливает множитель соответствующего столбца. Если наблюдаемая координата всегда равна 0, отношение неопределённо. Например, оригинал (0, 1) и маска (0, 2) совместимы с диагоналями (1, 2) и (3, 2). В общем случае нужны известные строки, матрица которых имеет ранг числа признаков. Четыре копии строки (1, 0, 0, 0) имеют ранг 1 и одинаково маскируются единичным ключом и диагональю (1, 2, 3, 4). При численном восстановлении также важна обусловленность. Ранее урок уже показывает проверку независимости на трёх признаках. [Пример атаки](../../../content/ch09/04-transform.md), [итоговые ответы](../../../content/ch09/test.md).

**Правка.** В тесте про множители ответить «хватит одной анкеты, если все нужные координаты ненулевые, либо нескольких, покрывающих такие координаты». Для полного ключа — «нужны как минимум четыре линейно независимые известные строки исходных признаков и соответствующие им спрятанные версии». Сохранить связь атаки с решением линейной системы. **Приёмка.** Ученик отличает четыре зависимые анкеты от четырёх независимых, объясняет, какие коэффициенты остались неопределёнными, и показывает, какую новую строку запросить.

### S09-03 · 04-transform / 05-project, прогноз на новых строках · Подтвердить · P2

На обучении OLS минимизирует ошибку по одному и тому же пространству достижимых прогнозов. При линейной зависимости признаков оптимальных весов несколько. Отдельное обучение в разных координатах может выбрать разные решения минимальной нормы. Мой пример с обычным свободным членом: для x = (0,0), (1,1), (2,2) и y = 0, 1, 2 sklearn нашёл веса (0,5, 0,5). После умножения второй колонки на 2 получились (0,2, 0,4). Обе модели предсказали на обучении 0, 1, 2. Для новой строки (2,0) исходная модель дала 1, а переобученная по преобразованным координатам — 0,4. Если вместо переобучения **явно** переносить прежние веса через обратный ключ, прогноз останется тем же на любой строке. [Доказательство и пример](../../../content/ch09/05-project.md), [предшествующий материал о неединственности](../../../content/ch09/03-normal-equation.md).

**Правка.** Развести в доказательстве существование эквивалентных весов и результат двух независимых запусков `fit`. Для гарантии одинаковых прогнозов после двух обучений на произвольных новых строках достаточно единственности решения, в случае свободного члена — полного столбцового ранга расширенной матрицы признаков. Сохранить равенство прогнозов на обучении и отметить, что на имеющихся анкетах опыт ученика воспроизводится. **Приёмка.** На данных с двойной колонкой ученик проверяет отдельно обучающие точки, новую точку на той же прямой, точку вне неё и исходные веса, перенесённые вручную.

### S09-04 · 02b-vectorize, best-of · Подтвердить · P1

Ученическая функция вызывает `f` ровно `repeats` раз и возвращает минимум разностей `time.perf_counter()`. Локальный прогон принял её. В браузере задача вернула «best_time вернула 0.0: нужно одно число — время в секундах». В проверочной функции задержка создаётся только при первом вызове. Следующие вызовы могут целиком попасть между двумя отсчётами таймера. Я повторил проверку с неизменным кодом ученика, задав длительности 0,01, 0, 0, 0 секунды. Вызовов ровно четыре, минимум 0,0. Код проверки требует строго `r > 0`. Сохранённый журнал подтверждает разные исходы одной попытки. [Задание и проверка](../../../content/ch09/02b-vectorize.md), [локальный результат](student.jsonl), [браузер](browser.jsonl).

**Правка.** Для этой мгновенной нагрузки принимать конечное неотрицательное число. Чтобы отличить корректное решение от константы 0, отдельно подать контролируемые показания часов, где минимум положителен и не совпадает ни с первым, ни со средним. Сохранить проверки числа вызовов и значения по умолчанию. **Приёмка.** Набор длительностей 4, 0, 2, 3 мс возвращает 0, а набор 4, 1, 2, 3 мс — 0,001 секунды. Константный ответ и лишний вызов проваливают проверку. На исходном браузерном примере ученик может сдать уже записанное решение без искусственной поправки к измерению.

Пример с Ridge добавляет к вопросу о ранге отдельное ограничение на функцию потерь. Для S09-04 решающими оказались разные результаты одной программы в двух средах.
