**Вывод.** SQL-аналитик с нулевым Python получает рабочее объяснение того, как программа идёт по строкам, хранит промежуточный результат и собирает группы. Более того, принятый файл оставляет без ответа два вопроса руководителя.

## Какие приёмы стоит сохранить

- **Различие между формулой и вычисленным значением показано сразу.** Ученик видит знакомое произведение, меняет `cups` и сталкивается с прежней выручкой. Вопрос о порядке выполнения здесь имеет наблюдаемый ответ. Аналогия с Excel помогает предсказать конкретную ошибку. [02-numbers](../../../content/ch01/02-numbers.md#L29-L43).
- **Цикл разобран в точке, где меняется способ мышления.** В таблице видны `total` до и после очередной цены. Затем можно переставить начальное присваивание и предсказать последнюю цену. В словарях тот же приём повторяется для нового и уже существующего ключа. Это связывает привычную агрегацию SQL с обновлением состояния в Python. [05-for](../../../content/ch01/05-for.md#L93-L134) · [08-dicts](../../../content/ch01/08-dicts.md#L162-L222).
- **Функцию сортировки вводят через уже знакомую функцию.** Сначала ученик передаёт `len`, затем читает `def second(row)`, только после этого встречает `lambda row: row[1]`. В проекте это позволяет содержательно обсудить, почему Раф и Флэт уайт при равном количестве нужно упорядочить по имени. [11-comprehensions](../../../content/ch01/11-comprehensions.md#L157-L196) · [14-project, drinks](../../../content/ch01/14-project.md#L309-L345).
- **В проекте есть договорённость о качестве данных и возможность сверки.** Авторы явно называют строку `1 250` нарушением формата и заранее договариваются о её исключении. На сентябрьской выгрузке объясняется изменение знаменателя среднего чека. Участник может проверить равенство `41 = 37 + 3 + 1`, указать причину каждого слагаемого и назвать влияние повторного заказа на выручку — 450 ₽. [13-files](../../../content/ch01/13-files.md#L221-L225) · [14-project](../../../content/ch01/14-project.md#L46-L74) · [Исходные заказы](../../../site/data/orders.csv).

## Актуальность и точность переноса из SQL

Примеры на типах Python, `csv.DictReader`, ISO-датах и исключениях соответствуют применённым операциям в учебной среде. Следующие правки важнее расширения программы новыми библиотеками.

| Приоритет и место | Наблюдаемое расхождение | Точечная правка и основание |
|---|---|---|
| P2 · [02-numbers](../../../content/ch01/02-numbers.md#L123-L125) и [07-tables, weighted](../../../content/ch01/07-tables.md#L571-L615) | При возврате или отрицательной корректировке `-7 // 2` даёт −4 в Python, а целочисленное `(-7) / 2` в PostgreSQL даёт −3. Предложенный SQL взвешенной цены на столбцах типа `integer` возвращает 200, тогда как Python ожидает 200,70. | Уточнить направление округления. В SQL явно привести числитель к дробному типу, например `SUM(cups * price)::numeric / NULLIF(SUM(cups), 0)` для PostgreSQL. [Python, числовые типы](https://docs.python.org/3.12/library/stdtypes.html#numeric-types-int-float-complex) · [PostgreSQL, деление](https://www.postgresql.org/docs/current/functions-math.html) · [PostgreSQL, тип результата SUM](https://www.postgresql.org/docs/current/functions-aggregate.html). |
| P2 · [11-comprehensions, moving](../../../content/ch01/11-comprehensions.md#L562-L591) | Python по условию выдаёт первое среднее только с третьего дня. Приведённое SQL-окно даёт значение и на первой, и на второй строке. Для первых четырёх дней из урока SQL после округления даёт 41 200, 40 050, 41 733, 41 267. Упражнение оставляет последние два. | Показать первые три строки обоих результатов. Уточнить, как во внешнем запросе оставить окна с тремя наблюдениями. [PostgreSQL, оконные функции](https://www.postgresql.org/docs/current/tutorial-window.html). |
| P2 · [14-project, SQL-аналогия](../../../content/ch01/14-project.md#L80-L82) | Ключ Python `weekday()` нумерует понедельник нулём. У PostgreSQL `EXTRACT(DOW ...)` нулём нумеруется воскресенье. Суммы групп верны, но при переносе в данный в задаче список подписей попадут под другой день. | Дать `EXTRACT(ISODOW FROM date) - 1` для совпадающих ключей. В соседнем SQL для напитков также дописать второе поле сортировки `drink ASC`, которое требует условие. [Python, weekday](https://docs.python.org/3.12/library/datetime.html#datetime.date.weekday) · [PostgreSQL, EXTRACT](https://www.postgresql.org/docs/current/functions-datetime.html#FUNCTIONS-DATETIME-EXTRACT). |
| P3 · [09b-style](../../../content/ch01/09b-style.md#L38-L62) | Фраза про «единственное место», где `=` пишется слитно, противоречит уже изученному `def rub(amount, decimals=0)`. | Показать рядом именованный аргумент вызова и параметр по умолчанию без аннотации.
