# Глава 7. Методическая оценка

**4,0 из 5 для SQL-аналитика после главы о первых моделях.** Одна и та же таблица ошибок становится несколькими осмысленными решениями. Кого отметить, если нужен охват? Сколько стоит лишний бонус? Что изменится при ограничении числа звонков? Для нового проекта ученик меняет предмет с оттока гостей на заявки, собирает Pipeline, программирует метрику и сравнивает с правилом отдела. Проект сдаётся по шагам. К очередному шагу курс восстанавливает эталонную подготовку и модель. Готовность самостоятельно применить всё к свежей выгрузке требует отдельной проверки. ## Карта навыков и переноса

| [01 Матрица ошибок](../../../content/ch07/01-confusion.md) · основной | Раскладка по факту и прогнозу → count-four, forest-cm, rule-cm → cost использует стоимость обеих ошибок. Дополнительно missed-who разбирает профиль пропущенных. |
| [02 Precision, recall и F1](../../../content/ch07/02-precision-recall.md) · основной | Расход бонусов и охват ушедших → by-hand, three-models → recall-plan и newcomers проверяют выбор модели под ограничение и качество на подгруппе. |
| [03 Порог, PR и ROC](../../../content/ch07/03-threshold.md) · основной | Движение порога и ручная ROC на пяти гостях → roc-plot, recall80 → pairs восстанавливает площадь из упорядоченных пар с половинным баллом за ничью. |
| [03b Порог по деньгам](../../../content/ch07/03b-money-threshold.md) · основной | Цена бонуса всем и выгода при TP → warm-profit, profit → budget ограничивает контакты, honest-t фиксирует порог по валидации и оценивает его на тесте. Предположение о выгоде одного попадания явно задано. |
| [04 Дисбаланс](../../../content/ch07/04-imbalance.md) · основной | Веса на десяти строках → lr-bal, upsample → leak и thr-match различают дубли до разбиения и изменение порога. Балансировка внутри каждого фолда — дополнительное cv-up. |
| [05 Масштабирование и соседи](../../../content/ch07/05-scaling.md) · основной | Расстояния в несопоставимых единицах → zscore, knn-scale → who-cares сравнивает чувствительность моделей, knn-hand углубляет ручной поиск соседей. |
| [05b Регуляризация](../../../content/ch07/05b-regularization.md) · основной | Штраф за большие веса и обратный параметр C → c-two, c-sweep → lasso проверяет качество упрощённой модели с обнулёнными весами. |
| [06 Новые признаки](../../../content/ch07/06-features.md) · основной | Связь оттока с жалобами и доставкой видна в сводной → is-new, cxd → gain и both проверяют выгоду от предложенных признаков на общих фолдах. |
| [06b Проверка признаков](../../../content/ch07/06b-feature-check.md) · основной | Логарифм или интервал → bins, combo → perm и noise-rank проверяют работу признака на отложенных строках, включая заведомый шум. Парные разницы в combo — образец для последующего выбора модели. |
| [07 Pipeline](../../../content/ch07/07-pipeline.md) · основной | Путь одного гостя через медиану, масштаб и кодировщик → prep-shape, pipe-metrics → new-guests проверяет незнакомую категорию. В cv-models меняется только модель. |
| [07b Свои шаги](../../../content/ch07/07b-own-steps.md) · углубление | Порядок лояльности из CRM и простейший класс → ord-tier, feat-step → group-ratio переносит выученную групповую статистику на новые строки. Для основной траектории собственный класс не является предпосылкой. |

**Независимые численные проверки.** Использованы исходный CSV, подготовка из setup/final и восемь вариантов логистической регрессии из grid, pandas 3.0.6 и scikit-learn 1.8.0. Данные содержат 3000 разных lead_id. В проектном тесте 99 договоров из 750, у модели топ-225 содержит 88, у простого правила 55 из 99 при 175 местах. В пяти тренировочных фолдах по 61/55/69/54/60 договоров **во всём фолде**. По среднему AUC и среднему охвату при бюджете 30% выигрывает один и тот же C=1 без весов (0,8592 и 0,7830 соответственно), стандартные отклонения 0,0167 и 0,0506. Реальный ответ хорошо объясняет выбор автора. Для иллюстрации переноса модель с теми же фиксированными параметрами переобучена на заявках до 1 августа. Среди 621 заявки за август–сентябрь 77 договоров; модель нашла 62 из них в первых 186 (0,805), AUC 0,868. Изменились обучающая часть и проверочные заявки одновременно. Это дополнительная иллюстрация, вывод о календарном снижении качества из двух чисел сделать нельзя; в CSV нет даты созревания исхода.
