**До выбора вариантов.** Один отзыв содержит слова «вкусно, но дорого», другой — «дорого, но вкусно». Чем мешок слов представит их одинаково и какую информацию он потеряет?

::: quiz 01-text-prep
Что теряет мешок слов?

- [x] Порядок следования слов внутри отзыва
  > Для тональности этого часто достаточно; порядок частично возвращают биграммы.
- [ ] Количество повторений каждого слова
  > Частоту он как раз хранит.
- [ ] Слова с малой частотой появления
  > Они остаются, хотя их можно отсечь `min_df`.
- [ ] Ничего: весь исходный текст сохраняется
  > Порядок теряется.
:::

::: quiz 01-text-prep
Зачем приводить текст к нижнему регистру перед подсчётом слов?

- [x] Чтобы объединить варианты «Кофе» и «кофе» при подсчёте
  > Иначе словарь раздувается копиями одного слова.
- [ ] Чтобы автоматически исключить служебные стоп-слова
  > Регистр к стоп-словам не относится.
- [ ] Чтобы модель автоматически распознавала смысл фраз
  > Модель понимает только числа; регистр лишь объединяет копии.
- [ ] Чтобы `[а-яё]+` находило заглавные буквы без изменения текста
  > Наоборот: шаблон из строчных букв заглавных не видит — поэтому сначала `lower()`, потом поиск. Но цель — объединить копии слова.
:::

::: quiz 01b-lemmas
В таблице лемм у слова «капучино» `known = 0`, лемма — «капучиный». Что это значит и что делать?

- [x] Лемма угадана неверно; нужен словарь исключений для лемм
  > Поправка «капучиный → капучино» ловит все формы сразу, а `known = 0` подсказывает, какие слова проверять.
- [ ] Редкое слово; исключить его из словаря признаков
  > «Капучино» встречается 181 раз — это одно из главных слов меню.
- [ ] Низкая уверенность; лемму оставить без изменений
  > Уверенность разбора — это `score`; у знакомого «кофе» она 0.214, а лемма верная. `known = 0` значит, что слова нет в словаре, и лемма — догадка.
- [ ] Перейти к стеммингу: для незнакомых слов он всегда даёт правильную основу
  > Стемминг ошибается иначе: склеивает «приветливые» и «привезли» и разделяет «привезли» и «привёз».
:::

::: quiz 02-tfidf
Почему матрица мешка слов хранится в разреженном виде?

- [x] Почти все клетки — нули, их можно не хранить
  > Разреженная матрица хранит только ненулевые значения и их координаты.
- [ ] Ускоряется только печать матрицы на экран
  > Дело в памяти и скорости вычислений.
- [ ] Sklearn не поддерживает обычные плотные массивы
  > sklearn принимает и обычные массивы, но на больших словарях они не влезут в память.
- [ ] Значения приблизительны и требуют меньше памяти
  > Значения хранятся точно.
:::

::: quiz 02-tfidf
Почему векторайзер обучают (`fit`) только на обучающих текстах?

- [x] Чтобы не переносить с теста знания о словах и их частоте
  > Как со StandardScaler: fit на train, transform на остальном.
- [ ] Чтобы ускорить обработку, качество от этого не зависит
  > Скорость тут ни при чём.
- [ ] Чтобы не векторизовать отложенные проверочные тексты
  > Можно — `transform` обученным векторайзером.
- [ ] Чтобы число признаков не выросло при любых новых словах
  > Дело не в количестве, а в утечке.
:::

::: quiz 03-classify
Классификатор тональности даёт 92 % правильных ответов, а негативных отзывов 15 %. Что проверить?

- [x] Precision и recall негатива, базовую accuracy 85 %
  > Accuracy при дисбалансе мало что говорит — важно, ловит ли модель жалобы.
- [ ] Ничего: общей accuracy 92 % достаточно для приёмки
  > Отлично или нет, видно только на редком классе.
- [ ] Только скорость: accuracy уже доказывает качество
  > Скорость — второстепенный вопрос.
- [ ] Размер словаря: он заменяет оценку редкого класса
  > Это настройка, а не проверка качества.
:::

::: quiz 03-classify
Почему в топе «негативных» слов модели оказались «но» и «не»?

- [x] Отрицания и противопоставления — сигналы жалоб
  > Список весов — быстрая проверка на здравый смысл.
- [ ] Обнаружена ошибка обучения классификатора тональности
  > Это разумная закономерность данных.
- [ ] Модель отбирает слова по количеству букв, а не частоте
  > Длина слова не влияет.
- [ ] Предобработка неверна: эти слова надо удалить всегда
  > Тогда модель потеряла бы важный сигнал.
:::

::: quiz 03b-labels
В учебной симуляции три разметчика размечали темы. На золотом наборе Аня верна в 92 % случаев, Борис — в 78 %, Вика — в 54 %, голосование трёх — в 88 %. Какой вывод верный?

- [x] Голосование с 88 % уступает Ане с 92 %; нужна перепроверка
  > На данном золотом наборе Аня точнее голосования на 4 п. п. Нужно разобрать расхождения, прежде чем выбирать правило объединения. Это результаты симуляции, а не измерение качества настоящих сотрудников.
- [ ] Голосование надёжнее Ани: три разметчика всегда точнее одного, даже при 88 %
  > На этих данных голосование (88 %) хуже Ани в одиночку (92 %). Число голосов само по себе не гарантирует качества.
- [ ] Каппа 0.47 означает 47 % правильных ответов Вики
  > Каппа меряет согласие сверх случайного, а не точность. Для точности нужны эталонные метки.
- [ ] Вика лучше: её отличие от остальных ценнее точности
  > Само отличие от остальных не доказывает качества: здесь у Вики 54 % верных ответов. Метки имитированы генератором; по этим числам нельзя установить мотивы или привычки настоящих людей.
:::

::: quiz 04-embeddings
Чем эмбеддинги отличаются от TF-IDF?

- [x] Плотные векторы похожих контекстов, включая антонимы
  > «Грубый» и «хамил» в TF-IDF не связаны, в эмбеддингах — близки. Но похожий контекст бывает и у антонимов: «дороговато» и «недорого» тоже окажутся рядом.
- [ ] Плотные векторы смысла, где антонимы всегда далеки
  > Эмбеддинги учатся по контексту, а не по смыслу: у «дороговато» и «недорого» одни и те же соседи («для такого»), и векторы у них близкие.
- [ ] Более длинные разреженные векторы, чем у TF-IDF
  > Наоборот: сотни плотных чисел против тысяч столбцов, почти целиком нулевых.
- [ ] Векторы TF-IDF после нормирования к единичной длине
  > TF-IDF тоже нормируют к длине 1, но его столбцы — слова, а у эмбеддинга — безымянные измерения, выученные по контекстам.
:::

::: quiz 04-embeddings
Как мерить похожесть двух отзывов по эмбеддингам?

- [x] Косинусом угла между векторами
  > Косинус сравнивает направления векторов и не меняется при их положительном масштабировании. Добавление слов может изменить сам эмбеддинг и его близость к другому отзыву.
- [ ] Разностью длин исходных текстов
  > Одинаковая длина текстов не означает похожее содержание.
- [ ] Количеством общих букв отзывов
  > Общие буквы не измеряют близость эмбеддингов.
- [ ] Суммой координат двух векторов
  > Сумма координат не задаёт близость направлений векторов.
:::

::: quiz 04b-transformers
Короткий отзыв дополняют PAD до максимальной длины текстов в текущем пакете. Его вектор считают средним выходных векторов всех позиций без маски. Что может произойти, если добавить в пакет более длинный отзыв?

- [x] Среднее короткого отзыва может измениться из-за PAD
  > Изменятся число PAD и знаменатель среднего. Усредняйте только позиции с `attention_mask == 1`; даже нулевые PAD без маски могут изменить среднее.
- [ ] Среднее не изменится: заполнители всегда дают нули
  > Выходные векторы PAD не обязаны быть нулевыми. Даже при нулевых PAD деление на число всех позиций вместо числа настоящих токенов меняет среднее ненулевого отзыва.
- [ ] Токенизатор иначе разобьёт слова на части из-за маски
  > Маска не меняет разбиение слов на токены; здесь меняется число добавленных позиций PAD.
- [ ] Вычисление остановится из-за несовместимых форм
  > Формы позволяют вычислить среднее по всем позициям, поэтому ошибка может остаться незамеченной.
:::

::: quiz 04c-llm
LLM вернула тему «скорость Wi-Fi», которой нет в списке разрешённых. Что делать?

- [x] Отметить негодный ответ и учесть долю таких случаев
  > Ответы LLM нужно разбирать строго и проверять формат.
- [ ] Расширить список тем новым ответом и продолжить отчёт
  > Список тем задан заранее; выдуманные темы искажают отчёт.
- [ ] Подменить неизвестную тему ближайшей разрешённой
  > Это угадывание, которое нельзя проверить.
- [ ] Повторять запрос до появления разрешённого ответа
  > Подгонка ответа — самообман.
:::

::: quiz 04c-llm
LLM верно разметила 82.5 % из 200 проверочных отзывов, а обученная модель тем на своём тесте из 600 — 79 %. Какой вывод честный?

- [x] Выигрыш не доказан: проверить на общей выборке с погрешностью
  > Разница может отражать состав разных наборов и случайный разброс. Оцените обе системы на одних отложенных ID, учитывая невалидные ответы как ошибки, и постройте интервал парной разницы. Для вывода о допустимом проигрыше заранее задайте его границу. Интервал одной accuracy не является интервалом разницы двух систем.
- [ ] LLM лучше: 82.5 % достаточно сравнить с 79 % напрямую
  > Эти доли описывают разные наборы. Простое сравнение не доказывает превосходства одной системы.
- [ ] LLM хуже: отсутствие дообучения перевешивает её метрику
  > Наличие дообучения само по себе не определяет качество. На этих разных наборах нельзя установить, какая система лучше или не хуже.
- [ ] Сравнение невозможно: LLM без выходных вероятностей нельзя оценить по accuracy
  > Для accuracy достаточно метки класса. Вероятности не обязательны; нужны сопоставимые тексты и оценка неопределённости парной разницы.
:::

::: quiz 05-project
Университет получил 100 анонимных комментариев о библиотеке. В 30 комментариях люди жалуются на шум. Какую долю можно сообщить?

- [x] 30 % этих комментариев содержат жалобы на шум
  > Единица наблюдения — комментарий; числитель 30, знаменатель 100.
- [ ] 30 % всех посетителей недовольны уровнем шума
  > Комментировавшие могут отличаться от остальных посетителей; их общий состав неизвестен.
- [ ] Ровно 30 разных читателей жалуются на шум
  > Один человек мог написать несколько анонимных комментариев.
- [ ] Шум вызвал 30 % всех проблем этой библиотеки
  > Данные фиксируют тексты, а не причины и полный перечень проблем.
:::
