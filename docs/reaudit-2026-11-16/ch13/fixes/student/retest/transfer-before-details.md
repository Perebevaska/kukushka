# Самостоятельное решение до чтения текущего 05-project

Сегодня подпишу только факт: прежний классификатор отметил 100/1000 = 10% обращений первой недели, новый 140/1000 = 14% второй; наблюдаемые сигналы различаются на 4 п.п. и 40 обращений. Это разные измерительные инструменты. Рост обоснованных жалоб и достаточность переноса сотрудника отсюда не следуют; знаменатель — обращения, не клиенты.

Численный контрпример: пусть обе недели было ровно 100 обоснованных жалоб из 1000. При TPR=0.8 обе версии ловят80. Для100сигналов старой версии достаточно20FP среди900нежалоб (FPR=20/900≈2.22%); для140 новой —60FP (FPR≈6.67%). Истинная доля постоянна10%, наблюдаемая10→14%. Значит, имеющиеся числа совместимы и с отсутствием роста.

Сейчас сохраню штат до проверки, организую выборочную ручную проверку отмеченных и неотмеченных обращений обеих недель. Для следующего решения запрошу независимую слепую разметку обеих недель по единой инструкции и исходные ID, прогон обеих версий по одной и той же партии, TP/FP/FN/TN и неопределённость по неделе/версии, объёмы и трудоёмкость реальных жалоб, SLA/длину очереди и цену снятия сотрудника с другой очереди. Затем сравню обоснованные жалобы в общей шкале и операционный эффект; одинаковые TPR/FPR не предположу без проверки.
