# Независимая приёмка исправлений главы 1

16 ноября 2026 года. Проверена рабочая редакция поверх `6201fa939fbb25f8230f8d3d9e65f7bf5875c4e6`. Критерии взяты из [исходной рецензии](../review.md) и [отчёта по главе](../report.md). Исходные 14 доработок закрыты в проверенных сценариях. Новое наблюдение UI02 и внешняя гипотеза M3 учтены отдельно.

## Что проверялось

Из текущего рабочего дерева получен экспорт из 2 454 записей. Для разрешённой главы в свежих рабочих папках прогнал каждую программную посылку адресного ученического журнала и отдельные пары корректных и ошибочных решений. Включены реальные первоначальные контрпримеры, архивные программы `parse`, повторные запуски на сменных CSV и чтение созданных файлов. В каждой среде совпал 80 из 80 ожидаемых вердиктов, включая 23 реальные программные посылки из трёх браузерных серий. В окончательном архиве 27 посылок. Ещё четыре относятся к двум вопросам итогового теста и двум встроенным вопросам уроков. Ученик сдал все четыре в Chrome. Машинные проверки повторены в CPython 3.12.14 и в Pyodide 314.0.7 с Python 3.14.2 из поставки сайта. Для UI прочёл исходник и сверил его с фактическими репликами и состояниями карточек в Chrome. ## Дополнительное наблюдение при пересдаче

**UI02 закрыто.** В первоначальном журнале после успешного переноса строки следующая посылка на 84 символа получает отказ, под которым остаётся старый автоматический разбор удачного переноса. В финальной сборке ученик лично повторил в новом профиле Chrome последовательность «зачёт → отказ → зачёт». Поле разбора содержит объяснение после первого успеха, пусто при ошибке и снова заполнено после исправления. В коде перед новой проверкой удаляется прежний автоматический разбор. Явно открытое кнопкой решение охраняет отдельное условие. Интерфейсную последовательность с ручным открытием решения этот журнал не проверяет. В той же серии повторно приняты оба проектных решения без правок и собственные варианты ученика для `cell` и `parse`.
