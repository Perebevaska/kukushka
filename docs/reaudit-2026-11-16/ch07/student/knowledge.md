- Матрица sklearn: строки факт, столбцы прогноз; ravel — TN,FP,FN,TP. Моя первая ошибка FP/FN исправлена: «предсказан уход, фактически остался» — FP. FN — пропущенный уход. Accuracy может скрывать полную бесполезность модели редкого класса.
- Precision=TP/(TP+FP), recall=TP/(TP+FN), F1 — гармоническое среднее; TN в F1 не входит. F-beta с beta2 больше учитывает полноту, beta.5 — точность. weighted avg может прятать качество редкого класса; показываю строку1 и support.
- Снижение порога расширяет набор тревог и не уменьшает полноту, точность не обязана меняться монотонно. ROC показывает TPR/FPR; AUC — доля выигранных пар положительный/отрицательный с половиной за ничью. PR при редком классе показывает цену охвата. Высокий AUC не гарантирует качество ровно первых7/30 контактов или калибровку.
- Считаю прибыль=TP×GAIN−(TP+FP)×COST. Бонус стоит и TP, и FP. Положительная ожидаемая маржа p×GAIN−COST>0 требует p>COST/GAIN при надёжных вероятностях и подходящей модели выгоды. Порог выбираю на validation/OOF, итог проверяю на test один раз. Иллюстративный подбор на test из карточек не переношу в рабочую процедуру.
- Веса balanced=n/(2nкласса), не изменение числа строк. Веса часто меняют пороговое поведение сильнее ранжирования. Upsampling до разбиения/до CV создаёт копии в обеих частях; размножаю только текущий обучающий фолд, validation/test оставляю исходными. После весов вероятности нельзя автоматически считать откалиброванными.
- StandardScaler хранит mean/scale только по fit; std имеет ddof0. На новых данных transform, не fit. Масштаб важен kNN и штрафам линейных моделей, почти не влияет на деревья. MinMax на новом значении может дать больше1. Коэффициенты сырых величин разных единиц нельзя ранжировать по модулю.
- Меньший C сильнее штрафует. L2 сжимает, L1 может обнулить коэффициенты; синтаксис l1_ratio зависит от версии sklearn. Ridge/Lasso используют alpha в прямом направлении силы штрафа. Штраф без масштаба несопоставимо обращается с разными единицами.
- Флаг новичка, взаимодействие жалобы×доставка, log1p давности и интервалы pd.cut объясняют линейной модели нелинейности. Линейный пересчёт визитов/3 после масштаба новой информации не добавляет. Варианты проверяю на общих CV-фолдах train; пороги группировок тоже выбираю только по train. Разница средних меньше SD не означает равенство; описательно смотрю парные разницы и не выдаю их за независимые эксперименты.
- Встроенная важность леса любит числовые признаки с множеством порогов, включая шум. Перестановка на validation показывает зависимость уже обученной модели от столбца, не причинность и не универсальную бесполезность признака. После просмотра test для перестановок нельзя выбирать новые признаки и называть его независимым финалом.
- Для каждого признака знаю момент доступности. Будущая сумма договора, заблокированная после ухода карта, окно событий за границей момента прогноза — утечки. Неизвестный средний чек при нуле визитов не становится фактическим нулём от технического fillna.
- Pipeline держит feature engineering, ColumnTransformer, Imputer, Scaler/OHE и модель в одной процедуре. Кросс-валидация всего Pipeline заново учит статистики каждого train-фолда. handle_unknown=ignore кодирует новую номинальную категорию нулями известных флагов. Имя признака получаю get_feature_names_out.
- OrdinalEncoder получает осмысленный порядок явно; неизвестный уровень можно кодировать−1. FunctionTransformer пригоден для построчных преобразований, а не среднего входящего пакета. Собственный класс TransformerMixin,BaseEstimator сохраняет параметры __init__ под теми же именами, учит атрибуты с подчёркиванием в fit, transform применяет их и возвращает копию. Для неизвестной группы нужен заранее определённый fallback.

В n_fits учитываю число комбинаций×фолды, итоговый refit отдельно. RandomizedSearch ограничивает бюджет, но не гарантирует глобального победителя. Сохраняю joblib всего Pipeline вместе с версией sklearn и модулем собственного класса.
