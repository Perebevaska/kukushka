# Открытый ответ до просмотра test.md

Обе модели оценивают одни и те же заявки в один момент, используя только уже доступные признаки. Фиксирую конфигурации до просмотра исходов, на общих исторических датах ранжирую по риску вниз, ID вверх при ничьих. Для каждой модели выбираю ровно 30 строк: нельзя включать всех равных пороговой вероятности, иначе бюджет окажется разным. Сохраняю обе очереди ID и после созревания меток считаю найденные проблемы, precision@30, recall@30 и стоимость ошибок на общей когорте. Долю найденных делю на все проблемы когорты, точность — на 30. Повторяю на нескольких датах и смотрю парные различия; конфигурацию выбираю на train CV/validation, финальную когорту открываю один раз. Общий AUC полезен дополнительно, но не заменяет качество первых 30. Если воздействие сотрудников меняет исход, нужен случайный контролируемый пилот, а не причинный вывод по историческим корреляциям.
