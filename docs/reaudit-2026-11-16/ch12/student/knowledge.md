# Карточка знаний после главы 12
Основание — публичные previous-knowledge.md и addendum: SQL/Excel и пройденные главы о fit/predict, holdout, MAE, обучении. Не заявляю незнание прежних инструментов.

1. resample группирует по календарным корзинам; rolling сохраняет частоту и перекрывает окна. Для 7 дней первые6 NaN. W помечен воскресеньем, крайняя корзина может быть неполной.
2. Аддитивное разложение — тренд+сезонность+остаток, period имеет единицы строк. Центрированный тренд нельзя напрямую использовать для прогноза. ADF проверяет H0 единичного корня в спецификации, не все аспекты стационарности.
3. Лаг1 честен при прогнозе на час, но не для выпуска в20:00 на весь следующий день. Последний известный час19:00; горизонт5–28; общий набор48/168 и rolling shift28 доступен. Помимо X надо отдельно ограничить labels fit.
4. Тест порчей только y[t] недостаточен для неизвестных будущих часов. Порча всего хвоста независимыми значениями ловит текущий y, shift(-1), разность двух будущих часов. Честные признаки должны совпадать с построенными только по известному префиксу.
5. В собственном проекте prefix union future пропустил четыре неизвестных промежуточных часа; shift тогда перестал означать часы. Assert реально выявил ошибку. Нужен полный регулярный index с NaN для неизвестных промежутков, а не удаление этих строк.
6. Train/validation/test по времени, TimeSeriesSplit; в проекте gap28 отделяет labels от начала следующего прогноза. Никакое имя train не отменяет проверку максимальной доступной даты.
7. Для mean4w явно требую четыре недели. Иначе mean(axis=1) молча выдаёт среднее по меньшей истории. Мой native train начинается29марта, проверка — июль/август целиком.
8. RMSE в заказах/час, WAPE в долях и устойчив к отдельным нулям; MAPE делит на нулевой факт. Сравнивать на одном периоде и горизонте.
9. Меньшая ошибка спроса не гарантирует меньше дефицита людей: нужны ceil(orders/6), рабочие07–22, минимум1, short/extra/deficit отдельно от покрытия спроса. Квантиль.8 не гарантировал80% фактического покрытия: у моего native73.39% all и68.75% work.
10. Моя зафиксированная модель не выполнила требование августа (4.374>4.3 и baseline4.353). Не подгоняю её после теста. Стоимости3/1 — сценарные единицы, а не измеренные рубли; эффект в реальных очередях неизвестен.

Браузерное принятие select после удаления cutoff не доказывает доступность labels: это диагностическое подтверждение несогласованного контракта. Штатный шаблон/теория и собственный CPython проект — разные исполнения.
