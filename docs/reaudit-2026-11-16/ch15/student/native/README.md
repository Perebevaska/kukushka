# Фактические нативные упражнения главы 15

Это упражнения по оттоку гостей, отдельно от собственного выпускного B2B. Данные — публичный `guests_churn.csv`. `common.py` и `artifact.py` собраны самостоятельно по шапке урока. `service.py`, `provided-mlflow-training.py`, `provided-mlflow-registry.py` скопированы из публичных примеров; не выдаю их за собственную разработку. `api_run.py` и `ui_run.py` — собственные локальные драйверы проверки и остановки сервера.

С окружением из аудита выполнены последовательно:

- `artifact.py`: LogReg AUC 0,896387, 1 800 обучающих строк, паспорт, модель и golden 20 строк; max diff 8,33e−17.
- `api_run.py`: настоящий uvicorn/FastAPI на 127.0.0.1:55586. `/docs` 200; нормальный запрос и `avg_check=null` 200; bool, строка вместо числа, копейки и новый город 422. После проверки сервер остановлен.
- `mlflow_run.py`: три настоящих леса по 200 деревьев, глубины 3, 6, None; CV, параметры, метрики и модели записаны в локальный SQLite/артефакты. Лучший run зарегистрирован как `churn` v1 с alias `champion`. Вероятности 20 строк после загрузки из реестра совпали точно, max diff 0.
- `ui_run.py`: настоящий локальный MLflow UI на 127.0.0.1:55587 ответил 200 (701 байт HTML), затем остановлен. Графический интерфейс мышью не исследовался.

Первый сетевой запуск FastAPI был запрещён sandbox: PermissionError. Сохранены `api-first-sandbox-error.txt` и `api-first-server.log`; повтор с разрешённым localhost успешно завершён. Это средовое препятствие, не ошибка проверки клиента. Журнал MLflow содержит предупреждения о версии pip и преобразовании URI runs→models, но регистрация и контроль прошли.

Docker CLI в среде не найден (`docker-availability.txt` пуст, exit 1), образ не собран и контейнер не запущен. Урок и Dockerfile прочитаны, успешный Docker не заявляется. Ни облачных сервисов, ни платных вызовов, ни GitHub-публикации не было.

Для повторения из этой папки используйте Python с зафиксированными версиями исходной среды (sklearn 1.8.0, MLflow 3.18.0, FastAPI 0.162.6, Pydantic 2.14.3). Примеры выполняют обучение и создают новые локальные MLflow runs. Сначала `python artifact.py`, затем `python api_run.py`, затем `python mlflow_run.py`; запускать по одному с OMP/OPENBLAS/MKL/NUMEXPR=1. Проверяющие драйверы используют только localhost и завершают свои процессы в `finally`.
