# Зерно для офиса: очередь удержания B2B

Собственный выпускной проект по пяти таблицам CRM: от временных срезов до модели, сценарной экономики и воспроизводимого списка. В разработке 2 279 офис-кварталов и 985 клиентов. На общем GroupKFold логистическая регрессия получила ROC-AUC 0,792; на позднем июньском срезе — 0,836, AP 0,530. Сравнены Dummy, логистическая регрессия, бустинг и kNN.

Начните с [выполненного блокнота](final_project.ipynb), [списка на IV квартал](reports/call_list_2026-09-30.csv) и [паспорта с экономикой](models/office_churn/1.0/passport.json). Далее: [калибровка OOF](reports/calibration-oof.csv), [сценарная чувствительность](reports/sensitivity.csv), [результаты позднего теста](reports/test-metrics.json), [решение до теста](selection-before-test.json).

## Пересчёт без блокнота

Запускайте команды из корня этого проекта. Нужен Python 3.12; база `office.db` из учебной выгрузки должна лежать в `data/office.db`. Она исключена из Git. MD5 исходной базы: `79b2a00312e346662ec6c3dc54df6b22`. Модель — доверенный собственный файл: `joblib.load` исполняет код, поэтому не подменяйте его неизвестным файлом.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python score.py --cutoff 2026-09-30
.venv/bin/python score.py --cutoff 2026-09-30 --call-limit 3
```

Второй пересчёт даёт ровно три звонка, не требует редактировать блокнот и не перезаписывает исходный выпуск. Результаты — `reports/rescore/call_list_2026-09-30_limit3.csv` и JSON с тем же именем. Для другого места используйте `--out-dir`; для базы — `--db`. `--call-limit` допускает 0–150. Если лимит не задан, используется `call_limit` паспорта.

Каждый запуск сначала загружает модель и сверяет 20 контрольных офисов: максимальная разница вероятностей меньше `1e-9`. Затем он строит признаки общей функцией `src/features.py`, проверяет порядок признаков по паспорту, считает пользу по полной точности, отбирает положительные значения, сортирует по убыванию пользы и при равенстве по `client_id`. Только при записи округляет вероятность до трёх знаков и пользу до рубля. Сумма JSON округляется один раз из исходных значений; сумма показанных целых строк может отличаться на несколько рублей.

Проверенный результат с лимитом 3: `C0115`, `C1263`, `C1247`, все из Уфы. Условное ожидание `124874` ₽, сумма полной точности `124874.40935732047`. Golden max diff `9.454242944073599e-17`. В передаче доступны ID, город, риск, польза, лимит, экономика, хеш базы, версия модели и сумма, чтобы получатель мог независимо проверить результат.

## Модель и временная постановка

Разработка: 30.09.2025, 31.12.2025, 31.03.2026. Поздний тест: 30.06.2026, один раз после фиксации выбора; чистый запуск блокнота повторяет ту же оценку, а не создаёт новый независимый тест. Работа: 30.09.2026, метки следующего квартала неизвестны. Цель — завершение действующего договора к концу третьего месяца после среза. Оплаты после среза считаются неизвестными; заказы и обращения из будущего не входят в признаки. Возвраты сохраняются со знаком минус, отмены исключаются, дубли обращений удаляются по ID.

Все три семейства сравниваются на одних пяти GroupKFold по `client_id`. Выбираем по среднему ROC-AUC, предпочитая LogReg при отставании менее 0,005; AP служит дополнительной метрикой. Политика и критерий сохранены до открытия июня. Выпускная модель затем переобучена на всех 3 244 размеченных строках; июньские метрики относятся к модели на ранних срезах. Схема признаков, версии, категории и экономика находятся в паспорте.

## Деньги и ограничения

Для месячной выручки `R = revenue_90 / 3`:

`E = p × 0.5 × 0.35 × 12 × R − 1500 − 0.2 × R`.

Удержание 50%, маржа 35%, ещё год жизни и скидка 10% на два месяца — сценарные допущения. В CRM нет назначения звонка и контроля. На июньских наблюдаемых метках очередь из 66 офисов даёт **260 021 ₽ условной годовой ценности**, правило падения выручки — −227 324 ₽, все — −2 446 569 ₽, отказ — 0. Это не измеренная прибыль звонков за квартал. Обзвон всех превышает доступную мощность и используется как ориентир.

Рабочий выпуск содержит 65 офисов с положительной ожидаемой пользой; условное ожидание 443 403 ₽. Добивать до 150 не требуется. Вероятности на июне в среднем недооценивают уход: 8,88% против 13,58%. Ещё важнее: OOF-очереди трёх ранних кварталов дают −43 033 / +25 119 / −11 919 ₽ при положительном ожидании. Поэтому выпуск — воспроизводимый сценарный приоритет для пилота, а не основание обещать прибыль. Нужны эксперимент звонок/контроль и проверка калибровки именно в дорогой очереди.

Смена доставки в Уфе и рост цены «Стандарта» — гипотезы механизма. Ассоциации города, менеджера и отрасли не устанавливают причинный эффект. Рабочие частоты следующего квартала ещё неизвестны, новые офисы проверяются отдельно от знакомых.
