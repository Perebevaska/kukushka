## Внешние подсказки и порог

[Программа подсчёта](test-counts.mjs), запуск из корня: `node docs/reaudit-2026-11-16/ch05/test-counts.mjs`. [Полный результат и SHA-256 теста](test-metrics.json). Среда подсчёта: Node v26.8.1.

- 13 вопросов × 4 варианта = **52 варианта и 52 непустых объяснения**; ровно один ключ на вопрос.
- Правильный ответ единственный самый длинный в **4/13**, самый длинный с учётом ничьей в **5/13**. Даже при удачном разрешении ничьей стратегия длины даёт максимум 5/13, значительно ниже порога. Близость длин большинства текстовых альтернатив сохранена. Наличие слов «всегда», «доказана», «только» в отдельных дистракторах помогает исключению, но отражает проверяемые заблуждения, а не обеспечивает прохождение по форме.
- В Markdown все ключи стоят первыми, но сайт перемешивает варианты через `seededShuffle` (`site/assets/lesson.js:434`); номер в исходнике не является устойчивой подсказкой в интерфейсе.
- Сайт ждёт ответа на все вопросы, затем считает `pct = Math.round(100 * ok / qs.length)` и сравнивает `pct >= 80` (`site/assets/lesson.js:483`). Это сравнение округлённого процента. Для 13 вопросов результат совпадает с точным порогом: **10/13 → 77%, не пройдено; 11/13 → 85%, пройдено**. Минимум 11, не 10. Глава 5 не имеет основного/дополнительного подмножества итогового теста.
