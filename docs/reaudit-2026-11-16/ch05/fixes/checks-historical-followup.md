# Закрытие технических остатков E05-07/08/09

После графической приёмки независимый рецензент повторил исторические случаи. Четыре из семи снова выявили расхождения. Они независимо воспроизведены до исправлений в CPython и Pyodide, с сохранением исходного кода, проверок, ошибок выполнения и реплик harness.

## Решения

| E05-08 · P2 | Авторская функция count/B при 2000 случайных перестановок возвращала ноль на полностью разделённых массивах 0…11 и 100…111. | Явный учебный контракт: MC возвращает (k+1)/(B+1), B=n_perm; полный точный перебор или точная сумма распределения — без поправки. Двусторонний хвост фиксирован через модуль статистики, с допуском 1e-12 на равные результаты. Вся MC-теория, recap, hints и решения урока 05 синхронизированы; игрушечные 8/20 сохранены. | E05-09 · P2 | ztest отвергал полное p=0,00856026498422051, принимая 0,0086, вопреки вводному обещанию. | Условие явно разрешает оба представления; допуск 0,000051 сравнивается с полной оценкой, а не с округлённым эталоном. В native acceptance добавлены rounded/raw с expected=True и содержательно неверное p с expected=False. | Обе правильные формы приняты, p=0,07 отклонено. Для снега отдельно указан статус упрощённого вычислительного упражнения при обменности доставок. По наблюдательной погоде и зависимым доставкам внутри дня нельзя обосновать причинный эффект поштучной перестановкой. Исправлена ошибочная трактовка нулевого MC-счётчика как доказательства p<1/B: 1/(B+1) — конечная оценка, а не верхняя граница истинного хвоста.

Поправка и различие MC/полного распределения сверены 16 ноября 2026 с [официальной документацией SciPy permutation_test](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.permutation_test.html). SciPy по умолчанию определяет двустороннее p как удвоенный меньший хвост; в этих упражнениях явно выбран хвост по модулю. Поэтому библиотечный результат нужно приводить к указанному определению, а не сравнивать численно разные соглашения.
