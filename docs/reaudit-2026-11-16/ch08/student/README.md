## Где поставить автоматы

Из 300 обследованных адресов выбираются 40 по прогнозу при затратах 140 тыс. ₽/автомат в год. Правило заранее: риск убытка <=2.5%, затем максимум среднего. Выбор — Екатеринбург: средняя маржа по оценкам реестра 1479 тыс. ₽/год, 95% сценариев 803–2207 тыс., доля убытков 0/1000. Это не гарантия нулевого риска. Казань: 523 тыс. ₽, риск 0.8%; Пермь: 1149 тыс. ₽, риск 0/1000. Все три города проходят ограничение.

Важно для чтения CSV: fact и profit_k — исходные оценки по похожим точкам. Поля actual в top40-comparison.csv и net_actual_k в chosen-sites.csv сохраняют прежние технические имена, но тоже считаются из этой целевой оценки; net_actual_k = profit_k − 140. Это не наблюдённая прибыль годовой эксплуатации нового автомата. Интервалы условны на качество оценок реестра. Первые установки должны проверить их по реальным выручке и затратам. Сдвиг всех прогнозов на константу изменит RMSE, но не ранг, top-40 и сценарии по тем же адресам.

Файлы: sites-project.ipynb, sites-artifacts/risk.csv, chosen-sites.csv с 40 уникальными ID, quality.csv, profile.csv, risk.png и summary.json. Сценарии конечного реестра выбирают без возвращения. Лес — предусмотренная чувствительность, не независимый новый тест выбора модели.

## Кому предлагать абонемент

Историческая дата — 2026-07-01. Область пилота: регистрация до 1 июня и заказ до 1 июля, кандидаты вне пилота. После уточнения области — 1886 кандидатов и 312 адресатов при прежнем пороге 0.22. Мощность до 419 контактов, фактический расход 46 800 ₽. Прогноз: 127.58 покупки, из них 33 без предложения; дополнительная маржа 104 533 ₽ за три месяца. Всем подходящим кандидатам — около −11 187 ₽, отказ — 0 ₽. Органическая доля выбранного контроля: 11 покупок / 104 гостя. Это условный прогноз, а не уже заработанные деньги; июньские регистрации требуют отдельного пилота.

Собственный протокол сохранён: мощность 300/1350 и минимум 20 отобранных контролей заданы до первичных расчётов; треть контроля отложена до поиска порога. В редакторском повторе сохранены ID четырёх групп и замороженная политика, EDA по покупке перенесена только на 1350 train ID, включая квартильные границы. Одна маска по ID используется для списка, портрета, расходов и письма.

Проверочная оценка исходного фиксированного протокола не изменилась: AUC 0.8683, 70 контактов, 40 выбранных контролей, оценка дополнительной маржи 29 100 ₽. Условный bootstrap 95% интервал на контакт — 193–633 ₽; он не включает подбор политики и будущий сдвиг. Эти исторические holdout-исходы уже были открыты в первом проходе: повторное исполнение не является новым независимым тестом.

В новом списке 61.86% зарегистрировались через приложение, медианная давность 7.68 дня, частота 0.449 заказа/неделю; 145 из 312 были в последние 7 дней. Это не «все недавно были» и не наблюдение маршрута на работу. Возраст не входит в модель; аудит использует явные границы новой редакции pd.cut(age,[0,29,49,200]), неизвестный возраст вне групп.

Минипроверка использует ту же order_aggregates, что основная база. Заказ 30 июня на 400 ₽ даёт 1 заказ / 400 ₽. После вставки заказа ровно 1 июля на 9000 ₽ эти значения и остальные агрегаты не меняются. Ожидание записано до запуска, assert и таблицы сохранены.

## Входы и запуск

Учебные sites.csv и final1.db должны находиться в DATA. База в локальный Git не включена. По умолчанию DATA = ../technical/data-baseline относительно student; для автономной передачи задайте COURSE_DATA. Все выходы относительны student.

```sh
python -m venv .venv
.venv/bin/pip install -r requirements.txt
COURSE_DATA=../technical/data-baseline OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python execute_notebooks.py
python /path/to/course/check_notebook.py sites-project.ipynb --no-run

```
