# План до исполнения

1. Коллега должен загрузить прежнюю модель без обучения, получить прогноз для всех 450 цифр и самостоятельно восстановить очередь 37 цифр. Это отдельные цифры, не телефонные номера.
2. Скопирую собственную прежнюю передачу; добавлю полные clean/blur пиксельные запросы (450,64), position и original_index. Порядок пикселей по строкам 8×8, диапазон после деления на 16 — [0,1], повторно масштабировать не нужно. Порядок строк связать с оценочной таблицей по position; исходный ID сохранить явно.
3. Перезагружу модель, предскажу полную партию, затем другую разбивку на батчи и перестановку с восстановлением порядка. Сверю вероятность, прогноз и очередь; повторный fit запрещён смыслом передачи.
4. Правило очереди прежнее, выбиралось до итоговых меток: не менять после неудобного результата. В браузерной новой попытке сначала записать правило и queue, затем открыть метки. Считать ошибки / цифры, пойманные / ошибки, остаток вне очереди. Из этого нельзя вывести точность всего номера.
5. Проверка на другом искажении может опровергнуть устойчивость выбранного правила. Для клиентского вывода нужны реальные документы, ID номера, порядок символов, эталон/прогноз целой строки и фактические результаты и время оператора.

Ожидаю воспроизводимость прежней модели, а не заранее известные числа качества. Результаты запишу отдельно после исполнения.
