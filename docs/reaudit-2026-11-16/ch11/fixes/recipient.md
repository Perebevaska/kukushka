## Итог передачи

**Native принят:** сохранённая `DeliveryNet(nn.Module)` воспроизводит 16 прогнозов в минутах. Максимальное абсолютное расхождение `0.0000040656947391` минуты при допуске `atol=rtol=1e-5`. Загружены та же архитектура `(64,32), dropout=0.2`, `state_dict` и `StandardScaler`; `eval()`, CPU, `float32`, один вычислительный и один interop поток. Обратное преобразование `prediction * 11.065680513048699 + 34.43659420289855` проверено. `fit`, переобучение и `optimizer.step` не выполнялись. [Проверка рантайма](recipient-evidence/native-runtime.json).

**Digits принят в части документированного inference:** 16×10 вероятностей после загрузки `KNeighborsClassifier(n_neighbors=3)` совпали с сохранёнными точно, `maxdiff=0`; классы `0..9`. Вход — 64 пикселя 8×8 в порядке строк, яркости `[0,1]`, для исходных `[0,16]` требуется деление на 16. Сохранён [фактический массив вероятностей](recipient-evidence/first-outputs/digits-control-actual-proba.npy). Точность полного набора из одного входного пакета пока не воспроизводится; остаток RCP11-01 ниже.

Для обеих моделей отдельно исполнены документированные CLI на одной строке, перестановке 16 строк и поднаборе четырёх строк. У native дополнительно переставлены столбцы CSV: код восстановил порядок по metadata. Сравнение выполнено по SHA-256 численных признаков/пикселей в фиксированном порядке столбцов, а не по текущему номеру строки. Все 16 ключей уникальны. Расхождение native при одиночном запросе `0.000003814697265625` минуты; перестановка и поднабор — `0`. Вероятности digits во всех трёх случаях совпали точно. Исходные идентификаторы доставок в контролях отсутствуют; SHA-256 является ключом самих проверяемых признаков. [Native по ключам](recipient-evidence/first-outputs/native-controls-keyed.csv), [digits по ключам](recipient-evidence/first-outputs/digits-controls-keyed.csv).

Для содержательно другой партии выполнено дополнительное размытие предоставленных 16 изображений: `reshape(8,8) → gaussian_filter(sigma=1.1, mode='constant', cval=0) → flatten(64)`. Новый файл передан CLI, без нового выбора модели. Изменились четыре предсказания; CLI совпал с независимым вызовом загруженной модели. [Вход](recipient-evidence/first-outputs/digits-other-batch-sigma1.1.npy), [выход](recipient-evidence/first-outputs/digits-other-batch-sigma1.1.stdout). Это проверка применимости входа, а не новая оценка accuracy: для этих 16 пиксельных строк не передано отдельного явного соответствия исходным меткам. Сопоставление с первыми 16 строками evaluation по порядку даёт те же предсказания, но одного совпадения прогнозов недостаточно для доказательства связи пикселей и меток.

До полного чтения `truth` оно пересчитано только по `position/confidence` и сохранено в [отдельной фиксации](recipient-evidence/first-outputs/queue-rule-before-full-labels.json). Первые три строки evaluation с метками ранее были видны при ознакомлении с форматом; слепую оценку меток не заявляю. Правило и выбранные позиции после этого не менялись.

Все 37 позиций и их порядок совпали с `decision_before_labels.json`; флаг `review` совпал с принадлежностью очереди. По предоставленным 450 строкам evaluation: accuracy `427/450 = 0.9488888888888889`, ошибок `23`, в очереди `12`, вне очереди `11`, доля просмотра `37/450 = 0.08222222222222222`. Проверены уникальность `position` и `original_index`. Это независимый пересчёт готовой таблицы; заново получить все 450 предсказаний и confidence из переданных пикселей пока нельзя. Заявленную чистую accuracy `0.9844444444444445` по отсутствующим чистым пикселям независимо не пересчитывал. Модель предсказывает отдельную цифру; точность целого телефона не вычислялась. Чужая истина прогнозом не заменялась.

## RCP11-01 — полный вход финальной партии не передан

**Приоритет P2; минимальный остаток передачи.** `evaluation.csv` содержит `position,original_index,truth,prediction,confidence,review`, но единственный переданный пиксельный вход `control_features.npy` имеет только 16 строк. README описывает CLI для готового `request.npy`; рецепта получения полной партии 450 строк из `original_index`, нормализации и исходного/размытого состояния не даёт. Это первое место, где для полного воспроизведения accuracy и очереди из модели понадобились бы дополнительные сведения автора. Загрузка и 16 контролей при этом успешны.

Минимальная правка: передать полные `clean_request.npy` и `blur_request.npy` формы `(450,64)` с явным отображением `position → original_index`, либо документированный исполнимый рецепт восстановления, фиксирующий источник/разбиение, порядок, деление на 16, sigma и режим границы. Проверка закрытия: получатель загружает прежнюю сохранённую модель без `fit`, по ключам сверяет все предсказания и confidence, фиксирует 37 позиций по неизменённому правилу до оценки по truth, затем пересчитывает accuracy и ошибки вне очереди. Переобучение для этого остатка не требуется. Наличие sklearn datasets у проверяющего не превращает недокументированную внешнюю реконструкцию в переданный вход.
