# Мои знания после главы 11

1. Нейрон sigmoid(x@w+b) — логистическая регрессия. Слой(n,p)@(p,h) даёт(n,h), bias имеет h значений. Параметров a*b+b на слой. Без нелинейности W1@W2 схлопывает глубину. Скрытые признаки могут разделить XOR, где логит на исходных признаках даёт .5.
2. Для BCE+sigmoid d2=(p−y)/n. Ошибка скрытого слоя — outer(d2,w2)*(Z1>0). Все градиенты считаю с весами исходного forward, затем обновляю. При W2=[.4,.8],H=[1,2],D=1 после шага .1 получатся [.3,.6], но dH текущего forward равен [.4,.8]. Численная центральная разность проверяет формулу, а не заменяет обучение.
3. Каждый путь графа добавляет вклад в градиент. He sqrt(2/n_in) задаётся отдельно для каждого слоя ReLU; Xavier sqrt(1/n_in) — для симметричных активаций. Clip по общей норме сохраняет направление; по координатам может повернуть его. Порядок: backward→clip→step. Постоянно плохой lr обрезкой не лечу.
4. Pipeline со scaler должен быть внутри CV. alpha — сила L2, не learning_rate. loss_curve_ показывает train; эпоху выбираю по validation. В собственной ошибке epoch-gap я передал 600 финальных меток к 450 внутренним прогнозам. Теперь проверяю соответствие индексов и форм, а не полагаюсь на знакомые имена.
5. Tensor float32 обычно копия numpy, from_numpy делит память. detach().cpu().numpy() возвращает тензор из графа/устройства. Модуль регистрирует слои в атрибутах; вместо обычного list нужен ModuleList. Linear хранит(out,in). zero_grad очищает накопление, backward считает, step обновляет. В моём torch-прогоне grad5=−138.7, повтор без обнуления=−277.4, grad9=−26.3.
6. Для одного изK классов — K логитов и CrossEntropyLoss; для независимых меток — сигмоиды и BCE. Повторный softmax перед CrossEntropyLoss не нужен. Батч 64 на 400 строк даёт 7 шагов в эпоху;100 эпох не означают одинаковое число обновлений при разных размерах батча.
7. Dropout работает в train с делением на 1−rate, в eval выключен. BN в train использует батч, в eval — накопленные статистики. Smoke проверяет формы/nan, стартlnK, зазубривание 16–32 объектов и короткую эпоху. Он не доказывает качество новых данных. В native MSE1.159→2.4e−13 на 32 доставках.
8. state_dict не хранит всю подготовку и архитектуру. Для передачи я сохранил архитектуру, порядок 16 столбцов, scaler, шкалу цели, состояние и 16 контрольных прогнозов в минутах; новая загрузка дала maxdiff0. Нельзя после загрузки заново fit scaler и считать это тем же прогнозом.
9. Digit accuracy не равна точности полного номера. Очередь 37 цифр не означает 37 карточек. Для целой записи нужны ID, позиции, полный эталон и прогноз строкой, факт и результат работы оператора. В blur-transfer32 ошибки,12 поймано,20 осталось вне очереди. Высокая уверенность .981 не защитила от ошибки 6→4.
10. Выбранная защита от сдвига вправо не гарантирует защиту влево: финальная accuracy .529. Для новой партии правило и очередь фиксирую до меток; неудобный итог не даёт права переопределить стратегию задним числом.

Оставшиеся затруднения: не умею по этим данным оценить время проверки реальной карточки; не проверял сегментацию цифр из скана; не выводил аналитически устойчивую многоклассовую потерю из logits. Для последней темы пока опираюсь на CrossEntropyLoss и устойчивый softmax из урока.
