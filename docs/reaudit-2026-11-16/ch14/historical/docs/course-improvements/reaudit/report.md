## Качество подачи учебного материала

Оценка методиста **4,36 из 5**, предыдущая — **4,39**. Ясность объяснений — 4,87, опора на SQL и Excel — 4,80, последовательность и темп — 4,00, условия и обратная связь — 3,87, самостоятельность — 4,27. Из 75 оценок пересмотрены две. В главах 7 и 9 балл за условия снижен с 4 до 3, поскольку буквальное следование формулировке может изменить вычисленный результат. Разница характеризует повторную экспертную оценку той же шкалой. Темп и перенос навыка у людей предстоит измерить. [Методическая ведомость](methodist.md) · [Предыдущая оценка](../progress.md#как-изменилась-подача)

Работы по ролям распределены как в плане курса. Агент-студент работал с `gpt-6.1-sol / medium`, предметный эксперт, независимый рецензент и методист — с `gpt-6-astra / high`. Выборочные решения студента записаны до знакомства с мнениями остальных ролей.

В главе 7 правило отметило 166 из 750 заявок. Условие требует выделить модели те же 166 мест, а подсказка предлагает передать долю 0,221. Из неё получается только 165. На этой партии число пойманных договоров остаётся 64 при обоих лимитах. Разница проявилась в составе очереди. В главе 9 полные значения R² различаются на 6,55 × 10⁻¹⁵, а после преждевременного округления одного числа разность достигает 1,42 × 10⁻⁵. При допуске 10⁻⁹ эти способы дают противоположные ответы. Для обеих карточек следует назвать точное значение для решения и отдельно — формат вывода. [Пояснения и контрольные примеры](methodist.md#что-изменилось-в-оценке)

## Почему прежние прогоны пропустили ошибки

Штатная проверка исполнила 1 319 задач с решениями и заготовками, 933 примера из теории и 202 предсказания результата. Все 2 454 записи прошли. В Jupyter выполнены 1 208 задач с решениями и те же 1 208 со стартовым кодом, проблем 0. ID карточек и тексты `setup/check` совпали в экспорте, опубликованном HTML и каталоге для блокнотов. У всех 161 уроков и контрольных, 15 введений и 15 итоговых тестов проверены локальные пути из основного содержимого страниц. [Подробности охвата](coverage.json)

Для содержательной проверки эксперт заранее задал ожидаемые вердикты для **35 программ в 16 выбранных карточках**. Три из 18 корректных программ получили отказ. Девять из 17 ошибочных получили зачёт. Оба рантайма дали одинаковые результаты по всем 35 случаям. Рецензент подтвердил все 12 расхождений. Семь конкретных случаев впервые внесены в очередь исправлений, пять воспроизводят уже известные причины. Примеры намеренно отобраны по риску. По ним нельзя оценить частоту ошибок среди всех карточек. [Условия и критерии по главам](expert.md) · [Фактические вердикты в Pyodide](expert-pyodide.jsonl) · [Нативные вердикты](expert-native.jsonl)

В контрольной главы 1 `map(parse_line, строки)` действительно применяет требуемую функцию и даёт выручку 254 542 ₽. Проверка искала прямой вызов и отклонила работу. В главе 4 перестановка меток Android и iOS сохраняет набор из четырёх чисел. Проверка отсортировала числа отдельно от ключей и засчитала вывод с перепутанными платформами. В главе 7 полная и сокращённая ROC имеют площадь 0,9132983153, но проверка отклонила полную кривую. Все три авторских решения при этом проходят. Здесь нужны проверки взаимоотношения между строками, точками или действиями программы, а также буквальной инструкции, которую читает ученик. [Исполняемые примеры](expert_probes.py)

У методических тестов обнаружился ещё один независимый источник ложной уверенности. **В 192 из 223 вопросов единственный самый длинный вариант правильный.** Выбор только по длине гарантирует порог 80% в 12 главах, даже если все остальные ответы окажутся неверными. В главе 2 учтены 18 вопросов основного пути. Данные не показывают, применял ли кто-либо эту стратегию при обучении. ## Как проверить следующую редакцию

Сначала повторить сохранённые ошибочные вердикты на исправленном условии. Для пары «перепутанные метки платформ» надо принять перестановку целых строк, отклонить перестановку только подписей и показать, у какой пары расходится значение. Затем дать студенту восстановиться по одному сообщению. Эту тройку можно переиспользовать для связок «кофейня — ставка» и «момент — яркость». Реигру старых программ дополнять свежим решением с другой реализацией. [Инструкции для четырёх ролей](../../course-audit.md#как-обнаруживать-ошибки-до-повторного-прохождения-студентом)

Для оценки читаемости дать двум сопоставимым группам текущую и отредактированную формулировки. До показа решения записать, какое действие участник счёл первым, его первую попытку, один запрос помощи и время без загрузки Python. Для тестов попросить сначала дать короткий ответ без вариантов. Для переноса после перерыва использовать новую дату, другой файл или иной бюджет. Сохранить прежнюю шкалу и обсуждать изменение каждого из пяти баллов по наблюдаемым действиям. [Сценарий пилота и бланк](../methodist-pilot.md)

После интервью повторно сопоставлены приёмы с открытыми материалами. У Berkeley Data 8 есть промежуточная сдача климатического проекта. В нашем курсе так можно разделить чтение условия выпускной работы и передачу артефакта. В Data 100 предлагается оценить модель с учётом последствий её ошибки в конкретной области. В главе 8 подходящий перенос — объяснить, как изменится решение о рассылке при другой доле органических покупок. В редактуре длинных условий применим порядок «цель читателя → первое действие → уточнения». Для первой самостоятельной практики применимо чередование разобранного примера и аналогичной задачи с изменёнными данными.
