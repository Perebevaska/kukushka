# Первые открытые ответы — до итоговых вариантов и исполнения проекта

## Итоговый открытый вопрос
Сохраняю независимый набор исходных фото вне обучения и подбора настроек. По одним ID проверяю исходную и затемнённую версию: одни метки, одна уже обученная модель; отдельно собираю снимки новой камеры в реальном свете. Нормировку/аугментацию выбираю на обучении/валидации, затем один раз оцениваю фиксированный способ на независимых фото. Сравниваю общую точность, ошибки «пусто» и группы света. Затемнение тех же фото — парный стресс-тест, не новые независимые фотографии. Копии теста не должны попасть в обучение.

## 1. События витрины
Храню ключ (день,time,slot), истинный и предсказанный класс, is_empty=(pred==0). Сортирую и восстанавливаю сетку 15 минут для каждого slot; отсутствие снимка прерывает подтверждение. Сигнал один раз при первом достижении k пустых подряд, повторную выдачу разрешаю после занятого состояния. Истинные эпизоды строю отдельно по true==0; у каждого сохраняю начало/конец и первый сигнал. Сигналы вне истинной пустоты — ложные, несколько в одном истинном эпизоде — повторные, отсутствие сигнала — пропуск. Задержка в минутах от первого истинно пустого снимка, не от начала предсказанной серии. По первому дню сравню k1/2/3 по заранее указанным 120₽ ложный,300₽ пропуск,30₽ повтор,1₽/минута; зафиксирую наименьший при равенстве. Второй день не открываю до фиксации. Пока k ещё не выбран: данных первого дня не считал.

## 2. Допекание
Наблюдаемое число пустых кадров умножу на 0.25 часа и сложу по ячейкам: это ячейко-часы, не время закрытия всей витрины и не потерянные продажи. По inventory симулирую один и тот же спрос и начальные запасы для исходного 13/17, переноса 13→11 и копии партии 11 при сохранённых 13/17. В каждом сценарии пополнение только пустых ячеек перед спросом. Сравню интервалы 11–13,13–17 и весь 07–22, чтобы утренняя выгода не скрыла дневной ущерб. Для постоянного решения нужны реальные продажи/неудовлетворённый спрос, время выпечки, остатки и списания, стоимость партии и труда, несколько реальных смен; в учебной симуляции спрос задан и не меняется от наличия товара.

## 3. Перенос на парковку
Сначала выберу правило два свободных кадра подряд: хочется не отправлять водителя на случайный ложный «свободно». Цену для пилота задаю до проверки: ложное сообщение 100 условных₽, минута задержки 1₽, пропуск 300₽. Это мои допущения, не наблюдаемая экономика. Ключ(day,time,place); один сигнал в серии; отсутствующий снимок прерывает её. Малый журнал:09:00 занято/модель свободно,09:15 занято/занято,09:30 свободно/свободно,09:45 нет кадра,10:00 свободно/свободно,10:15 свободно/свободно,10:30 занято/занято. По k2 сигнал 10:15, не 10:00: кадры 09:30 и 10:00 не соседние по времени. От первого наблюдаемого истинно свободного 09:30 задержка 45 минут; точный момент освобождения между снимками неизвестен. Отдельно проверю истинный эпизод с пропуском: неизвестное состояние не выдаю за доказательство непрерывности. На следующем дне применю тот же k2 и те же цены, сохраню ложные/пропуски/повторы/задержки; изменение k по итогам будет следующей версией, а не исправлением первого выбора.
