## Сверка исходных пар с журналом

Найдены 19 пар в `student/<lesson>/`: `attempt-NN → feedback-NN`, `choices-NN → choices-feedback-NN`, `hint-NN → hint-feedback-NN`. В каждой паре совпали число строк и ID. Из них 97 оценочных строк и одно отдельное неоценочное событие подсказки. Мультимножество исходных строк **точно** совпало с [initial-attempts.jsonl](student/initial-attempts.jsonl) по полям `id, code, expect, choice, passed, feedback, visible_output`. Повторные ID учитываются по фактическому содержимому каждой попытки. Типы и пустые значения `visible_output` сохранены: пустая строка и список с пустой строкой не приравнивались.

Три реальных отказа:

- `initial-attempts.jsonl:31`, `02b-vectorize/vectorize`: сообщение требует реальные вызовы `perf_counter`. Первый вывод пустой.
- `initial-attempts.jsonl:33`, тот же ID: сообщение повторилось; вывод содержит `t_loop=0.03979999999999961`, `t_vec=0.00019999999999953388`, `speedup≈199`, `same=True`, `total=19281182`. Поэтому объяснять этот отказ нулевым таймером нельзя. Следующая отправка, строка 34, принята. Внутреннюю причину определяет проверка автотестов, а не эта сверка.
- `initial-attempts.jsonl:55`, `03b-own-model/group-mean`: `AttributeError: 'numpy.ndarray' object has no attribute 'values'`. В строке 57 принят вариант с Series. [Ученик](student/findings.md) прямо связывает исходную замену типа с собственным восстановлением окружения. Это нельзя автоматически называть наблюдавшимся отказом штатной заготовки.

Исходные ожидания и ошибки оставлены как есть, включая ожидание «положительное измеренное float-время» для `best-of` (строка 28). Оно уже самого видимого контракта, допускающего ноль, и не превращено задним числом в верное ожидание.

## Помощь и Cognitive Walkthrough

Есть положительное инструментальное свидетельство одной подсказки: [запрос](student/02b-vectorize/hint-01.jsonl), [ответ](student/02b-vectorize/hint-feedback-01.jsonl). Открыта подсказка 1 для `vectorize` после двух отказов; она объясняет массивную арифметику и `np.where`, не контракт измерения. Успешная отправка прямо декларирует эту помощь в `expect`. Считать: 1 уникальный ID с подтверждённой подсказкой, 93 принятых ID без записанного события подсказки; среди последних `group-mean` исправлен после обратной связи. «93 полностью без помощи» было бы сильнее имеющихся данных. Поля `help` в сводном журнале нет. Неоткрытие авторских решений — декларация ученика; отдельного полного журнала кликов, доказывающего отсутствие всех открытий, нет. Чтение теории отделено от открытия подсказки.

Во всех 97 оценочных строках заполнен `expect`. Практические Q1–Q3 обычно содержат цель, названное объяснение/операцию и проверяемое следствие: выручка в одном числе (строка 1), конкретные минуты (3), форма `(2,2)` (17), ранги 4/4 после удаления зависимого столбца (42), сравнение сырых R² до отчётного округления (75). Часть ожиданий качественная («близко к машинному округлению»), что честно отражает неизвестное до расчёта число. У встроенных predict/quiz есть краткое собственное вычисление/обоснование, но Q2 шаблонно ссылается на вопрос и соответствующую теорию, без точного места. У всех 16 финальных ответов Q3 повторяет выбранный ответ, а Q2 также шаблонный: это сохранённый выбор до проверки, но недостаточное свидетельство конкретного пути обнаружения действия. Наличие Q1–Q3 само по себе не равно полному Cognitive Walkthrough.

В уроках сохранены `before.md`, `answers-before.md`, Q4, `difficulty.md`, `knowledge.md`; после отказов — отдельные `feedback-02-Q4.md` / `feedback-03-Q4.md`. В [README](student/README.md) и [findings](student/findings.md) честно указаны текстовый пакет и отправки через `submit.py` в отдельном профиле Chromium, без ручного прохождения всей страницы. Эта сверка подтверждает согласованность сохранённых пар, а не наблюдение за каждым действием или человеческие сроки и эмоции.
