# Открытые проверки: Q4

Это мои математические и исполняемые самопроверки, а не вердикт тренажёра для открытых ответов.

- Порядок по ключам: четвёртая кодовая ячейка notebook реально выполнила reindex для двух порядков справочника:23и23, без сопоставления16. Следующий шаг понятен: связывать qty/price по ingredient до умножения. Числа23/16 были раскрыты координатором заранее; независимость числового ответа не заявляется.
- Новая строка после fit: та же исполняемая ячейка подтвердила (0,4) и прогнозы1,1,1.6. Следующий шаг понятен: различать явный перенос весов и выбор нового решения при зависимом обучении. Коэффициенты нового fit взяты из самого публичного примера, собственного повторного подбора здесь не было.
- Чек-дубль: реальная сдача dup-receipt принята с unique=False, rank1 и исправленной системой ранга2. Следующий шаг понятен; отсутствие единственности не равно отсутствию решения. Это знакомая математика с уточнённым именем.
- Температура: проверил подстановкой F=1.8C+32 в (b−32w/1.8)+(w/1.8)F; сокращаются сдвиги и остаётся b+wC. Это символическое объяснение, не выдаю его за интерфейсную автоматическую оценку. Следующий шаг: учитывать согласованность физической пары и условие единственности нового fit.

Содержательно новый timed_call принят в трёх практиках: apply-col,vectorize,nearest-shop. Выданы реальные входные функции, получены измеренные времена; нулевого замера в этих трёх фактических сдачах не было. Код обрабатывает такой случай speedup=None. Ускорения относятся к наблюдаемым машинным вызовам, не к человеческому времени обучения.

Уточнение своего температурного объяснения после проверки: для двух независимых fit при зависимых столбцах гарантированно совпадают прогнозы в аффинной оболочке обучающих строк. Согласованная новая температура лежит в ней, если обучение охватило хотя бы две разные температуры и других ограничений нет. При единственной обучающей температуре согласованность шкал сама по себе не гарантирует экстраполяцию. Явный перенос уже выученных весов сохраняет любой согласованный прогноз без этого требования. Первоначальное ожидание open-before не переписано.
