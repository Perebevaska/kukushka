
- 01-gradient: Спуск обновляет оба параметра по старым ошибкам; остановка по малому изменению потери не гарантирует малого градиента. Parsons требует буквальные строки, функционально эквивалентный код не подходит.

- 01b-numeric: Различаю непрерывный корень и дискретную границу доли. Стоимость спуска сравниваю по всем итерациям, учитываю память XTX. Исправил собственную ошибку переноса заготовки grad после NameError.

- 02-gd-many: Масштабирование выравнивает кривизну. В мини-батче знаменатель — его реальный размер; порядок обновляется каждую эпоху. Убывающий шаг уменьшает дрожание. Parsons принимает4пробела, мои однопробельные отступы вызвали отказ транспорта.

- 02b-optimizers: Инерция накапливает скорость; Adam хранит первый и второй моменты с поправкой на старт. L2 не штрафует свободный член, alpha Ridge=lambda*n. Все7ID приняты первым реальным запуском.

- 03-boosting: Остатки пересчитываются на каждом шаге; старт train/test один — среднее train. Дерево переносит поправку на новые строки. MAE-упражнение использует медиану и знаки. Все12ID приняты; Parsons перед первой сдачей поправлен по уже изученному правилу.

- 04-tuning: Выбор остановки на валидации, финальный тест не участвует. staged_predict даёт кривую без повторного fit на каждом числе деревьев. HGB принимает категории и пропуски; заполнение леса нулём — выбранная стратегия. Все12ID приняты.

- 05-project: Разовый план фиксирует информацию на дату выпуска; сценарная погода не будущий факт. Последняя доступная пятница для утреннего1августа —25июля. Календарный ориентир заморожен до выпуска. По feedback исправил rain float и clone готового TrendBoost на deepcopy; все10ID приняты.

- 06-libraries: Раннюю остановку выбираю по отдельному периоду истории. Замеры fit/predict — реальные интервалы готовых функций, сохраняю без округления. В браузере2ID приняты, native-упражнения далее.

- test: Открытый ответ записан до вариантов. Закрепил различие градиента по весам и антиградиента по прогнозам, время/память широких матриц, предел инерции и честную временную валидацию.

## Карточка знаний для следующей главы

- Производная по весу показывает рост потери, поэтому вычитаю learning_rate×градиент. Знак градиента сейчас не равен знаку изменения оптимального веса в будущем.
- Для MSE градиент2/n×X.T@(Xw−y). Масштаб признаков меняет допустимый общий шаг; большой градиент с маленьким изменением потери не доказывает минимум.
- SGD считает производную по батчу и его фактическому размеру. Эпоха — проход всего набора, не одно обновление. Перемешивание не сбрасывает веса. Убывающий шаг уменьшает шум около минимума.
- Momentum на постоянном градиенте даёт предельный шаг eta×|g|/(1−beta). Adam нормирует по сглаженному квадрату градиента с поправкой на нулевой старт. При первом шаге модуль eta×|g|/(|g|+eps), не всегда ровно eta; величину lr всё равно выбираю.
- L2 добавляет2lambda×w, но не к свободному члену. Для Ridge со штрафом к сумме alpha=lambda×n. Уменьшение нормы весов может повысить ошибку обучения.
- Бустинг начинает со среднего train для MSE, обучает каждое дерево на текущем y−F, обновляет train/test тем же деревом с малым шагом. MAE-упражнение начинает с медианы и использует знаки. Последовательные деревья исправляют остатки; лес усредняет независимые деревья.
- Проверяю качество на будущем, выбираю параметры по более раннему будущему — валидации. Не объявляю победителя по финальному тесту. staged_predict экономит повторные fit, но не оправдывает подбор по тесту.
- Нормальное уравнение O(nd²+d³) и памятьd² могут быть дешевле полного k-шагового спуска на узкой таблице и тяжелее на широкой. Бисекция непрерывного корня отличается от поиска минимального целого обещания для ступенчатой доли.
- В разовом плане доступность признака привязана к выпуску, а не к дате целевого события. Будущая касса/погода запрещены в признаках; сценарий строю до выпуска, архивный прогноз подтверждаю датой доступности. Обновлённый план — отдельный эксперимент. Открытый перенос на энергосбыт записан до тестовых вариантов.
- При передаче плана сохраняю origin времени, категории/порядок столбцов, модель, дату выпуска, входы без будущего ответа, версии и относительные пути. Проверяю reload, целый пакет, одиночную строку и CLI. Метрики в тыс.₽ не переводятся автоматически в экономию людей/закупок.
- На моей собственной конфигурации без погоды trend_hgb выбран по valRMSE7.688, finalRMSE8.672 иMAE6.335; все выводы ограничены учебной сетью и этим горизонтом. Проверка88ID/14тестовых вопросов подтверждает выполнение знакомых заданий, не гарантирует усвоение любого нового бизнеса.

- Native освоено на своём исполнении: CatBoost принимает строки черезcat_features, LightGBM —pandascategory, ранняя остановка использует отдельный временнойval. Сохраняю реальные версии/доступность библиотек. Для сравнения параметра держу seed/patience/cap одинаковыми; первый собственный дизайн был смешанным и сохранён отдельно. Меньшийlr не гарантирует меньшийtestRMSE или строго большее число деревьев на любой кривой. Снятие тренда может уменьшить RMSE, но увеличить модуль среднего смещения; проверяю обе метрики. Native5+8выполнены, отдельный проект не перевыбран по их тестовым итогам.
