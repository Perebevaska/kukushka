**До выбора вариантов.** Прогноз выпускают 1 февраля сразу на три месяца. Для апрельского прогноза предлагают фактическую погоду апреля. Какие данные могли бы честно заменить её и что нужно зафиксировать о дате их доступности?

::: quiz 01-gradient
Что показывает знак производной функции потерь по весу?

- [x] Направление роста потери по этому весу
  > Спуск: w ← w − lr · производная.
- [ ] Качество модели относительно базовой
  > Качество показывает сама потеря.
- [ ] Число шагов до завершения обучения
  > Производная этого не знает.
- [ ] Необходимость включения свободного члена
  > Это вопрос устройства модели.
:::

::: quiz 01-gradient
Шаг обучения слишком маленький. Что будет?

- [x] При выполнении условий сходимости спуск замедлится
  > При выполнении условий сходимости меньший шаг обычно требует больше итераций до той же точности.
- [ ] Спуск обязательно начнёт расходиться от минимума
  > Малый шаг сам по себе не означает расходимости; слишком большой шаг может её вызвать.
- [ ] Модель обязательно переобучится из-за малого шага
  > Шаг влияет на скорость, а не прямо на переобучение.
- [ ] Число итераций и итоговая траектория сохранятся
  > Число шагов до цели сильно вырастет.
:::

::: quiz 02-gd-many
Чем стохастический спуск по мини-батчам отличается от обычного?

- [x] Градиент шага считается по небольшой порции строк данных
  > Шаг по мини-батчу обычно дешевле, но градиент шумнее. Это удобно на больших данных; выигрыш до заданной точности зависит от задачи и настроек.
- [ ] Каждый шаг даёт более точный градиент, чем полный набор
  > Наоборот, шумнее.
- [ ] Обновление весов не использует производные функции потерь
  > Использует, только по части данных.
- [ ] Обновление весов не требует задавать скорость обучения
  > Требует.
:::

::: quiz 03-boosting
Чему учится каждое следующее дерево в градиентном бустинге (для MSE)?

- [x] Разнице между ответами и прогнозом текущего ансамбля
  > Каждое дерево исправляет то, что ещё не объяснено.
- [ ] Исходным ответам независимо от текущего ансамбля
  > Это независимое обучение на исходных ответах, а не исправление ошибки текущего ансамбля.
- [ ] Ответам случайной подвыборки без учёта других деревьев
  > Случайная подвыборка сама по себе не задаёт бустинг: важна цель нового дерева — остатки текущего ансамбля.
- [ ] Остаткам ансамбля на отложенной тестовой выборке
  > Тест в обучении не участвует.
:::

::: quiz 03-boosting
Зачем в бустинге маленький шаг (learning rate), а не прибавлять поправку целиком?

- [x] Для более осторожной подгонки ценой числа деревьев
  > Шаг и число деревьев настраивают вместе.
- [ ] Для сокращения общего времени обучения ансамбля
  > Наоборот, нужно больше деревьев.
- [ ] Для автоматического уменьшения глубины каждого дерева
  > Глубина задаётся отдельно.
- [ ] Для возможности сложить прогнозы разных деревьев
  > Прогнозы деревьев можно складывать и при learning_rate = 1. Малый шаг нужен для постепенных поправок, а не для самой возможности сложения.
:::

::: quiz 02b-optimizers
Спуск идёт со штрафом L2: к градиенту прибавляется 2λw, причём 0 < 2ηλ < 1. Как действует именно добавка штрафа на штрафуемый вес?

- [x] Штраф добавляет сдвиг веса в сторону нуля
  > w − η(g + 2λw) = (1 − 2ηλ)w − ηg. Компонента штрафа стягивает вес к нулю; полный шаг зависит также от g. Для MSE при сходимости это решение Ridge с согласованной силой штрафа.
- [ ] Штраф обнуляет каждый вес при любом положительном λ
  > Компонента штрафа умножает вес на 1 − 2ηλ, а не обнуляет его. Градиент данных может действовать в любую сторону; нулевой итоговый вес также возможен.
- [ ] Штраф увеличивает шаг обучения в (1 + 2λ) раз
  > Шаг η не меняется. Меняется сама цель: к ошибке добавлен штраф за размер весов.
- [ ] Штраф уменьшает только свободный член модели
  > Наоборот: свободный член не штрафуют, он отвечает за средний уровень прогноза.
:::

::: quiz 04-tuning
Что такое ранняя остановка бустинга?

- [x] Остановка при прекращении улучшения на валидации
  > Так выбирают число деревьев без перебора.
- [ ] Остановка по заранее заданному времени обучения
  > Время тут ни при чём.
- [ ] Ограничение максимальной глубины каждого дерева
  > Глубина — другой параметр.
- [ ] Ограничение ансамбля первыми десятью деревьями
  > Число определяется по валидации.
:::

::: quiz 04-tuning
Чем удобен HistGradientBoosting по сравнению с обычным GradientBoosting?

- [x] Быстрее на больших данных, поддерживает пропуски и категории
  > Признаки раскладываются по корзинам-гистограммам, поэтому деревья строятся быстро.
- [ ] Не требует настройки и подходит с параметрами по умолчанию
  > Требует, как любой бустинг.
- [ ] Не переобучается независимо от глубины и числа итераций
  > Переобучиться может.
- [ ] Принимает только текстовые признаки без числовых столбцов
  > Он для табличных данных.
:::

::: quiz 05-project
Энергокомпания 1 января выпускает план потребления сразу на полгода. Для 1 марта аналитик берёт фактическую температуру 1 марта. Чем заменить её при честной проверке январского плана?

- [x] Средняя температура марта из истории до выпуска плана
  > Историческое среднее можно вычислить по данным, доступным 1 января. Оно не подменяет январский план фактической погодой будущего марта; его точность нужно оценить отдельно.
- [ ] Фактической температурой марта из тестового периода
  > Фактическая погода марта ещё неизвестна 1 января. Наличие её в более позднем архиве не делает её допустимым входом январского плана.
- [ ] Фактической температурой первого дня будущего марта
  > Даже один фактический день будущего марта ещё неизвестен в момент выпуска плана.
- [ ] Средней температурой недели после январского выпуска
  > Неделя после выпуска — тоже будущее на 1 января, поэтому её фактическая температура создаёт утечку.
:::

::: quiz 01b-numeric
Линейная регрессия предсказывает числовую оценку отзыва по MSE: 200 000 текстов и 30 000 слов-признаков. Почему здесь предпочитают спуск прямому решению нормального уравнения?

- [x] Слишком дорогая матрица XᵀX размером 30 000 × 30 000
  > Для плотного XᵀX нужны 900 млн чисел, около 7.2 ГБ при float64, плюс память для решения системы. Это делает прямое решение дорогим; спуск может работать с разреженной матрицей признаков.
- [ ] Нормальное уравнение даёт неверные веса для любых текстов
  > Нормальное уравнение относится к линейной регрессии с MSE и не запрещено для текстовых признаков. При зависимости столбцов решение может быть неединственным; здесь сравниваем вычислительную цену.
- [ ] Градиентный спуск быстрее формулы при любых размерах X
  > При небольшом числе признаков прямое решение может быть дешевле множества шагов спуска. Универсального выигрыша нет.
- [ ] Само число строк запрещает применять нормальное уравнение
  > Число строк входит в обе оценки линейно. Решает число признаков.
:::

::: quiz 01b-numeric
Делением пополам ищут обещанное время доставки на отрезке от 0 до 300 минут с точностью 0.01. Что будет с числом делений, если взять отрезок от 0 до 600?

- [x] Число делений увеличится только на единицу
  > Число шагов — $\lceil \log_2(\text{длина} / \text{допуск}) \rceil$: 15 для 300 минут и 16 для 600. Поэтому отрезок можно брать с запасом.
- [ ] Понадобится вдвое больше делений отрезка
  > Вдвое длиннее отрезок съедается одним лишним делением, а не удвоением их числа.
- [ ] Поиск не найдёт ответ на столь широком отрезке
  > Найдёт, если на концах отрезка у функции разные знаки. Ширина влияет только на число шагов.
- [ ] Понадобится ровно столько же делений отрезка
  > Изменится, но всего на один шаг.
:::

::: quiz 02b-optimizers
Признаки не масштабированы: градиент по весу суммы заказа в тысячи раз больше, чем по весу расстояния. Какое свойство Adam помогает при таком различии масштабов?

- [x] Масштабирует шаг каждого веса по истории его градиента
  > Обычный спуск шагает пропорционально градиенту: шаг, безопасный для суммы заказа, слишком мал для остальных весов.
- [ ] Масштабирует исходные признаки перед вычислением потери
  > Признаки он не трогает. Он меняет длину шага, а не данные.
- [ ] Использует только инерцию, полностью устраняя эффект масштаба
  > Инерция сама по себе масштаб не лечит: она копит тот же неравный градиент. Помогает деление на размер градиента.
- [ ] Обеспечивает сходимость при любом заданном шаге обучения
  > Не при любом: при слишком большом η он скачет у дна. Шаг Adam тоже подбирают.
:::

::: quiz 02b-optimizers
Спуск с инерцией: v ← β·v + g, w ← w − η·v. Начальная скорость v = 0, шаг η постоянен, градиент g ненулевой и неизменный. Как меняется длина шага при β = 0.9?

- [x] Растёт к десятикратному шагу спуска без инерции
  > Скорость накапливается: каждый толчок добавляется к сохранённой доле прошлой скорости. Поэтому инерция ускоряет спуск по длинным пологим склонам.
- [ ] Остаётся равным шагу обычного спуска на всех итерациях
  > Так было бы при β = 0. При β = 0.9 сохраняется 90 % прошлой скорости.
- [ ] Неограниченно растёт при постоянном ненулевом градиенте
  > Предел есть: при постоянном градиенте скорость стремится к g / (1 − β).
- [ ] Уменьшается до нуля, чтобы избежать перескока минимума
  > Уменьшение шага — другая идея (затухание шага). Инерция на ровном склоне шаг увеличивает.
:::

::: quiz 06-libraries
В CatBoost уже заданы early_stopping_rounds=100 и cat_features. Какие данные передать в eval_set, чтобы выбрать число деревьев для прогноза будущей выручки?

- [x] Отдельный период после fit и до финального теста
  > Валидация имитирует будущее относительно fit. early_stopping_rounds=100 останавливает обучение после 100 итераций без улучшения; тест остаётся для итоговой оценки.
- [ ] Те же строки, на которых модель учится в fit
  > На строках fit измеряется подгонка к обучающим данным, а не качество на следующих периодах. Нужен отдельный период валидации.
- [ ] Финальный тест: по нему выбрать лучшее число деревьев
  > Это утечка: тест начнёт влиять на модель, и его ошибка перестанет быть честной.
- [ ] Все периоды вместе, включая финальный тест
  > Здесь тест участвует в выборе числа деревьев, поэтому его оценка уже не проверяет модель на нетронутых данных.
:::
