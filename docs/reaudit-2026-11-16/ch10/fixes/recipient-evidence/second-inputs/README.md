# Передача двух режимов прогноза

Запускайте команды из корня этой папки. Исходная первая передача заморожена отдельно; здесь её копия с новым интерфейсом. Единица прогноза — тыс. ₽ выручки одной кофейни за день. Ключ — `date,shop_id`, `as_of` в плане обозначает утро выпуска.

Сохраняю прежний собственный выбор: no-weather, trend_hgb с отдельным экспоненциальным трендом и HGB200итераций, глубина3, learning_rate0.05, random_state11,1поток. Новый выпуск не подбирает рецепт заново по финалу. Протокол до первого fit — `protocol-before-fit.json`: 1сентября2025, последние наблюдения31августа, горизонт1сентября–30ноября. Будущая погода исключена; сценарий этому рецепту не нужен. Календарь holiday/promo из `new-request.csv` считаю утверждённым к выпуску; CSV не доказывает дату его утверждения, в эксплуатации нужен сохранённый снимок плана.

**Режим1: загрузка сохранённой модели, без fit.**

```bash
python run.py saved --model model.joblib --metadata metadata.json --request request.csv --output reproduced-plan.csv
```

`model.joblib` и `request.csv` скопированы из первой передачи. `metadata.json` фиксирует её выпуск1июля. `plan.csv` содержит те же июль–декабрьские прогнозы с явным as_of. Сравнивайте результат с plan.csv по дате и кофейне, а не по порядку строк.

**Режим2: новый выпуск, дата задаётся параметром, ячейки менять не нужно.**

```bash
python run.py issue --as-of 2025-09-01 --history data/daily_sales.csv --request new-request.csv --output new-plan.csv --model-out new-issue.joblib --metadata-out new-issue.json --verify-future-invariance
```

Команда выбирает историю строго до --as-of, заново сохраняет категории и fit по фиксированному рецепту, рассчитывает план. Дата, горизонт, последняя доступная история, параметры, версии и реальные длительности сохраняются в `new-issue.json`. Проверка подменяет будущие кассу и погоду, сохраняя календарь, заново выполняет тот же рецепт и требует совпадения прогнозов. Погода не используется даже в истории. Для другой даты передайте согласованный новый календарь; история должна содержать завершённые наблюдения до новой даты.

Сохранённый новый выпуск также можно пересчитать без fit:

```bash
python run.py saved --model new-issue.joblib --metadata new-issue.json --request new-request.csv --output new-reproduced.csv
```

Зависимости: Python3.12,numpy,pandas,scikit-learn1.8.0,joblib. Для блокнота — nbformat,nbclient,ipykernel. Точные версии будут в outputs и metadata. `project.ipynb` выполняет команды и проверяет совпадение ключей/прогнозов из чистого ядра. Ранее скопированные выводы первого дизайна лежат в `first-handoff-copy/`, они не являются новым выполнением. Письмо директору — `director-letter.md` после фактической проверки.

RMSE измеряет типичный масштаб дневного промаха, а не прибыль или экономию. Для пилота нужно сопоставить решения смен/закупок с действующим правилом, стоимостью лишней смены, потерянного обслуживания и списаний. Проверку на новом периоде считаем повтором уже знакомого набора, не новой независимой оценкой качества модели.

`available-history.csv` — фактически доступные 3654 строки до выпуска1сентября. Полный `data/daily_sales.csv` оставлен для ретроспективной проверки подмены будущих фактов. `issue` всегда фильтрует вход истории по --as-of. Для эксплуатационного выпуска без ретроспективного теста можно передать `--history available-history.csv`.

Фактические проверки: saved воспроизвёл1104июльских ключа; новый issue и его повторная загрузка —546ключей. Новый RMSE7.856тыс.₽ против14.419у замороженного недельного ориентира.
