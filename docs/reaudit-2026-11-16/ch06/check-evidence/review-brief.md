# Фиксированный пакет для независимого рецензента

Глава 6, исходный SHA `5c4c2efe1f75243e763b5cd583952ab5d49ccf45`. Здесь нет входов ученика: пакет предназначен эксперту/рецензенту и содержит скрытые решения.

Исходные уроки — `source-original/`, предложенная редакция — `source-revised/`; исходные 98 исполнимых контрактов — `tasks-original.json`, после правок — `tasks-revised.json`. Входные CSV заморожены в `data-baseline/`, отдельные файлы с неизвестной точкой, singleton и 40 рабочими кандидатами лежат рядом. Фиксирован также `harness.py`. Точное соответствие файлов задаёт `manifest-sha256.json`.

Нужно независимо воспроизвести новые T06-01…T06-10 из `../checks.md`, вынести решение по наблюдению и отдельно по предлагаемой правке. Приоритет: C09 (правильный inline-фильтр ошибочно отвергнут), C11 (метки не соответствуют ID), C19/C20 (интервалы калибровки), C34/C50 (законный порядок признаков), C36 (переобучение на финальном test), C45…47 (выбор только по validation), C51…53 (40→4 и ничьи по ID). C39/C41 содержат все значения train/test для реального singleton и неизвестной кофейни, а не только их среднее. C03/C16/C33/C36 включают реальные прогнозы/риски переданных моделей.

Проверка выполнялась CPython 3.12 и установленным Pyodide через Node. Это runtime опубликованного тренажёра; новый GUI-прогон в этой роли не заявляется. Подробные версии — первая строка каждого JSONL.

Из корня репозитория:

```sh
PYTHONPATH=.venv/lib/python3.12/site-packages /private/tmp/ku-audit/nb-env/bin/python docs/reaudit-2026-11-16/ch06/check-evidence/run-native.py revised
node docs/reaudit-2026-11-16/ch06/check-evidence/run-pyodide.mjs revised
```

Для исходной редакции замените `revised` на `original`: манифест содержит все 53 кода. Исторические необработанные результаты первого запуска сохранены раздельно: `*-original.jsonl` (C01–42), `*-original-extra.jsonl` (C43–50), `*-original-fixtures.jsonl` (C51–53); это не 106 разных проб. Для контроля старого `tools/checks/ch06_acceptance.py` используйте фазу `acceptance` (7 программ и 1 проверка границ/дат/схемы).

`expected` — ожидаемый результат по целевому критерию проверки. У C45–47 исходное видимое условие само требовало подбора по test, а у C51–52 исходная проверка была рассчитана на 2400 рабочих строк. Поэтому эти пять наблюдений оценивают изменение процедуры/перенос, а не ошибочный отказ правильному решению неизменённого старого условия. C13 — встроенный перенос на singleton: на исходных шести крупных точках удалять singleton не меняет результата; C40 показывает отказ той же программе при настоящем singleton. Эти оговорки обязательны при подсчёте дефектов.

Не требовать OOF в `shop-rate`: его видимая учебная цель — граница train/test, а собственная метка обучающей строки явно входит в среднее. C49 сохраняет отказ leave-one-out как другому контракту; C39/C41 подтверждают, что singleton получает собственную метку только в явно описанной демонстрации. Самостоятельный рабочий target encoder следует проверять отдельно.

Секундомер проверяется дважды: в первом запуске сохраняются реальные длительности, во втором реально выполняются fit/predict с событийными показаниями perf_counter. Проверка не утверждает, что лес на любой машине обязан быть медленнее дерева. Рецензенту проверить также другой честный способ расстановки t0/t1/t2 и восстановление monkeypatch после успешной/неуспешной сдачи.

Пакет фиксирует baseline данных до изменения рабочего пула на G-30001…G-32400. Тесты C51–53 уже используют отдельные WORK-ID. Полный финальный прогон с новым рабочим пулом — отдельное свидетельство координатора; не приписывать его этому baseline.
