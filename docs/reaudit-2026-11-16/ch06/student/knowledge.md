# Карточка знаний после главы 6

Роль: SQL/Excel уверенно, Python/pandas/EDA и статистика из первых пяти глав. ML изучен по ученическому пакету главы 6.

- Постановка начинается с решения, объекта, момента прогноза, целевого признака, сравнения и цены ошибок. Классификация предсказывает категории, регрессия — числа, кластеризация ищет группы без готового ответа.
- Дерево выбирает вопросы по снижению взвешенного Gini. Класс — большинство листа, вероятность — доля класса среди обучающих строк листа. Глубина и минимум строк листа ограничивают переобучение. Важность не равна причинности; много возможных порогов может завышать важность числового признака.
- Лес использует бутстрэп и случайные признаки. sklearn усредняет вероятности деревьев, а не только классы. После десятков деревьев качество часто выходит на плато, время продолжает расти.
- Категории без порядка кодирую флагами. Новые данные готовлю той же функцией и выравниваю по столбцам обучения. Незнакомые категории получают нулевые известные флаги; их накопление требует проверки сдвига. Коэффициенты флагов читаю через разницы категорий и «при прочих равных»; величины весов разных масштабов напрямую не сравниваю.
- Логистическая регрессия — классификатор: линейная оценка → сигмоида → вероятность. Порог меняет число тревог, охват событий и долю оправданных тревог.
- До выбора откладываю test. Модель и настройки выбираю на validation/CV; статистики подготовки оцениваю только внутри обучающей части каждого фолда. Фолды одинаковы для моделей и правил. После фиксации победителя test использую один раз. Мелкая разница на одном разбиении ненадежна; std фолдов не является готовым доверительным интервалом.
- Для новых клиентов держу все заказы клиента в одной части: GroupKFold/GroupShuffleSplit. Для будущего периода проверяю по времени. В признаках клиента допустимы только прошлые заказы. Удалить guest_id недостаточно: адрес может узнавать клиента.
- База — частый класс и бизнес-правило, для MAE регрессии — постоянная медиана train. MAE — средний абсолютный промах; RMSE сильнее штрафует крупные ошибки; R² сравнивает со средним теста. Взаимодействие «пеший × км» можно явно добавить линейной модели.
- Бюджетный топ сортирую по риску убыванием, ничьи разрешаю по ID. Лифт = доля событий в топе / доля во всей аудитории; охват = события в топе / все события. Сравниваю с правилом при одинаковом бюджете.
- Калибровка сопоставляет средний риск с фактической долей в корзинах, включая 0 и 1; смотрю размеры групп. Высокая accuracy не гарантирует правдивых вероятностей. Время fit/predict измеряю perf_counter на одной машине.
- При признаках на T и цели «нет визитов в [T,T+60)» отрицательная метка созревает в T+60 при полном логе. card_blocked, доступный только вместе с меткой, — утечка. Незрелые метки не считаю отрицательными.
- Исторический топ для оценки и актуальный список для акции строю по разным срезам. После фиксации оценки можно переобучить выбранную конфигурацию на всей созревшей истории для production.
- avg_check при нуле визитов не определен. Ноль — только технический код вместе с флагом отсутствия визитов. Риск ухода не доказывает, что бонус удержит: нужен контролируемый пилот и расчет маржи.

В собственном проекте выбран лес по CV. Исторические метрики относятся к модели на 75% октябрьской истории. Свежая декабрьская выдача относится к той же конфигурации после refit на всей созревшей истории; отдельной проверенной метрики у этой production-модели нет. Блокнот выполнен с чистого ядра, выводы сохранены.

Исходный маршрут: 145 из 146 ID приняты; 09-project/top отклонен из-за неописанных current_risk/current_ids и индекса guest_id. Это разрыв учебного контракта. Пересдам после его явного опубликования. Из упражнений 03/06/07 не переношу привычку выбирать best по тесту: для выбора нужна валидация.
