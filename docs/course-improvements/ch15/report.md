## Качество подачи учебного материала

Публичный CRM-бриф оставляет выпускнику решение о составе очереди и требует обосновать деньги, даты и ограничения. В прежней работе есть проверяемый положительный пример, свежую приёмку необходимо сопоставлять с собственным новым письмом и файлами. ## Пути улучшения подачи

Передать другой команде чистую копию проекта и новый лимит звонков. Попросить её запустить README, объяснить выбор адресатов, срок ценности удержания и как измерить эффект звонка. Сверить контрольные вероятности, город каждого адресата и повторяемость CSV. В [исходной сдаче](../../audit-2026-11-13/ch15/student-project/README.md) есть материал для такого сравнения.

## Исполнение плана

У собственных решений выпускника проверяются даты, ID, город, модель, контрольные вероятности и список звонков. На прошлых срезах добавлены прогнозы вне фолда и калибровка. Отдельно считаются рубли при фиксированной очереди и при переотборе. Подтверждён основной маршрут из главы 8.

В новой папке команда из README воспроизвела исходный файл на 65 офисов. Семь частей старой реальной сдачи прошли с чистого ядра; в ячейке 12 остался Warning. При фиксированных 66 офисах в прошлом квартале сценарии 30/50/70 % дают 58 010 / 260 021 / 462 033 ₽, при переотборе меняется и размер списка (34/66/97). Сервис вернул HTTP 422 на булево значение вместо числа визитов. В MLflow 3.18.0 три запуска завершены, максимальная разница 20 контрольных вероятностей после загрузки champion равна нулю. Docker в среде отсутствует.

## Что осталось

В окружении отсутствует Docker. Образ контейнера не запускали. Нативные API и MLflow и передача выпускного пакета проверены исполнением. Эффект звонков в реальной CRM потребует пилота с контрольной группой.

Повторная диагностика 14 ноября установила источник предупреждения в ячейке 12. В окружении проверки `joblib/loky` не находил macOS-утилиту `sysctl` и использовал число логических ядер. После добавления `/usr/sbin` в PATH штатный `check_notebook.py --project ch15/06-final-project` в чистой копии принял 7 из 7 частей, итог «исправить — 0, посмотреть — 0». Изменения кода выпускной для этого не понадобились. Запуск образа в Docker остаётся отдельной открытой проверкой.
