## День 1: расчёт до ответа

Истинный эпизод пустоты начинается в 09:45 и длится три кадра. Одиночные ложные предсказания пустоты стоят в 09:00 и 10:45. Правило подаёт один сигнал при первом достижении длины серии.

| k | Ложные вызовы | Задержка истинного эпизода | Пропуски | Стоимость при 45 ₽ за ложный вызов | При новой цене 6 ₽ |
|---|---:|---:|---:|---:|---:|
| 1 | 2 | 0 минут | 0 | 2 × 45 = 90 ₽ | 2 × 6 = 12 ₽ |
| 2 | 0 | 15 минут | 0 | 15 ₽ | 15 ₽ |
| 3 | 0 | 30 минут | 0 | 30 ₽ | 30 ₽ |

При обычной цене выбираю k = 2. При новой цене **до просмотра дня 2 фиксирую k = 1**: два ложных вызова стоят 12 ₽, дешевле 15 минут ожидания. Ещё более долгое ожидание k = 3 ничего не выигрывает по ложным вызовам на этом журнале.

Ответ до клика: «Один кадр. Два ложных вызова теперь обходятся дешевле, чем ожидание второго кадра». Ожидаю подтверждение смены правила вслед за ценой.

## День 2: собственный расчёт до сверки

Первый выбор получил «Верно». Только после него показан новый журнал 12:30–13:45. Сохраняю **k = 1**, не подбираю его по новому дню.

По фото: 0 1 1 0 0 0; по модели: 1 1 0 0 1 0. Сигналы k = 1 в **12:30 и 13:30**. Оба ложные: в эти моменты на фото есть выпечка. В 12:45 модель продолжает уже начатую серию, поэтому нового сигнала не выдаёт. Истинный эпизод 12:45–13:00 пропущен. Получается 2 ложных вызова, 1 пропущенный эпизод, обнаруженных истинных эпизодов нет; задержка для них не определена и в стоимость ожидания даёт 0. Цена: **2 × 6 + 1 × 300 = 312 ₽**.

Этот день хуже дня выбора. Ретроспективно переключать k на 2 ради красивого итога нельзя: это была бы новая настройка по проверочному дню. Мой вывод для управляющей — выбранное дешёвое правило не подтвердило надёжность на новом журнале.

Теперь открываю «Сверить свой расчёт после разбора второго дня».

Сверка подтвердила мои времена и 312 ₽. Для k = 2 на новом дне было бы 0 ₽, для k = 3 — 300 ₽; это оставляю сравнением после проверки, а не заменой своего заранее выбранного k. Реальный видимый выбор в quiz — один кадр, он принят.

## task-light: намеренно пустой рисунок

Условие требует 61 пару «время — яркость» в порядке съёмки и подписи реального времени. Для расчётов загружаю доступный showcase_day.npz: средняя по пикселям вырезки, затем средняя 12 ячеек по каждому time. Отношение вечера с 18:00 к более ранним моментам округляю до трёх знаков; наибольший спад — минимум diff. Числа заранее не знаю; первым запуском проверю собственный расчёт.

Намеренная ошибка только в рисунке: создаю пустые оси, без ряда. Ожидаю, что проверка укажет на отсутствие временного ряда, хотя расчёты готовы.

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

data = np.load("showcase_day.npz")
X = data["X"]
times = data["time"]
frame_brightness = X.reshape(len(X), -1).mean(axis=1)
bright = pd.Series(frame_brightness).groupby(times).mean().sort_index()
ratio = round(bright.loc[bright.index >= "18:00"].mean() / bright.loc[bright.index < "18:00"].mean(), 3)
step_time = bright.diff().idxmin()
print(len(bright), ratio, step_time)
fig, ax = plt.subplots()
plt.show()
```

Собственный запуск вывел **61, 0.651, 18:00**. Это 61 момент, вечерняя яркость около 65.1% дневной; наиболее резкое падение в 18:00. Теперь отправляю этот же код с пустыми осями на проверку.

## Первое сообщение и моя попытка восстановления

Вердикт пустым осям: **«Пока не так. Сверьте пару „время — яркость“ в bright. Усредните кадры одной съёмки и сохраните время как индекс.»**

Сообщение отправляет к расчёту bright и не называет пустой рисунок. В моём коде время уже является индексом, а данные сгруппированы по съёмке. Сомневаюсь, что требуется пересчитывать bright. Сначала исправлю только рисунок: выведу все 61 значение по порядку и подпишу время на оси. Расчёты оставляю буквально прежними, чтобы выяснить, в них ли причина.

Полный код второй отправки:

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

data = np.load("showcase_day.npz")
X = data["X"]
times = data["time"]
frame_brightness = X.reshape(len(X), -1).mean(axis=1)
bright = pd.Series(frame_brightness).groupby(times).mean().sort_index()
ratio = round(bright.loc[bright.index >= "18:00"].mean() / bright.loc[bright.index < "18:00"].mean(), 3)
step_time = bright.diff().idxmin()
print(len(bright), ratio, step_time)
fig, ax = plt.subplots(figsize=(10, 4))
x = np.arange(len(bright))
ax.plot(x, bright.to_numpy(), marker=".")
ticks = list(range(0, len(bright), 8))
ax.set_xticks(ticks)
ax.set_xticklabels(bright.index[ticks], rotation=45)
ax.set_xlabel("Время съёмки")
ax.set_ylabel("Средняя яркость")
ax.set_title("Средняя яркость витрины по времени")
fig.tight_layout()
plt.show()
```

Ожидаю зачёт, поскольку теперь рисунок показывает требуемые пары. Подсказку и решение не открывал.

Вторая отправка с реальным рядом тоже получила тот же отказ про bright. Значит, пустой рисунок сам по себе пока не локализован сообщением. Дальше проверю структуру собственной Series и исходных данных, не заглядывая в проверку.
