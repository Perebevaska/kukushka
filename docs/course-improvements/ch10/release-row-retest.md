Как SQL-аналитик, отберу нужную кофейню, date < as_of и тот же weekday, затем ORDER BY date DESC LIMIT 1. Ожидаю дату источника 2025-07-25; сумму пока не знаю и сначала посмотрю доступную историю. Более поздние строки не должны менять уже выданный прогноз.

До проверки запускаю собственный диагностический вывод sales.columns и sales.tail(), чтобы узнать имена полей и единицы в доступной учебной таблице. Это просмотр данных через редактор, не проверка и не подсказка.

## Данные и код до проверки

В учебной таблице поле суммы называется revenue_k. Через собственный запуск посмотрел строку выбранной исторической пятницы: PRM-1, 2025-07-25, 69.6. Поэтому ожидаю пару (2025-07-25, 69.6), то есть **69 600 ₽**. Это календарный ориентир на 8 августа, а не будущий факт и не сумма за неделю.

```python
import pandas as pd

def baseline_at(sales, as_of, target, shop_id):
    as_of = pd.Timestamp(as_of)
    target = pd.Timestamp(target)
    available = sales.loc[
        (sales["shop_id"] == shop_id)
        & (sales["date"] < as_of)
        & (sales["date"].dt.weekday == target.weekday())
    ]
    row = available.sort_values("date", ascending=False).iloc[0]
    return row["date"], row["revenue_k"]

print(baseline_at(sales, "2025-08-01", "2025-08-08", "PRM-1"))
```

Ожидаю зачёт: строгая граница date < as_of не пропустит факты 1 августа и позже. Порядок строк исходной таблицы не важен, поскольку сортирую явно. Сомнения только в неизвестных заранее именах столбцов снял просмотром данных; в границе даты сомнений нет.
