# Пилот с SQL-аналитиками: перенос решения на новые данные

После соответствующей главы участник получает знакомую рабочую задачу с изменённым условием. Ведущий фиксирует, где человек принимает первое самостоятельное решение, в какой момент запрашивает помощь и что именно меняет после неё. Для глав 10, 11 и 14 это сценарий проверки материалов после девятой главы. Результатов занятий с людьми пока нет.

## Как провести занятие

Предложите задания SQL-аналитикам, которые изучают Python и DS и уже прошли соответствующий материал. Проводите четыре короткие пробы по порядку глав, при необходимости в разные дни. Перед началом запишите анонимный код участника, главу, перерыв после обучения и знакомство с этим примером. Копируйте участнику только один лист и первую порцию данных. Вторую порцию выдавайте после того, как сохранён первый ответ. Оставьте доступ к собственному коду, SQL, Python или Excel. Если участник сверился с образцом, отметьте это в журнале.

Начните отсчёт с открытия листа. Время до записи правила и до законченного ответа фиксируйте отдельно от загрузки Python, обучения моделей и технических остановок. После первой попытки можно спросить: «Как вы проверите свой выбор?» Если участник просит помощи, сначала используйте наводящий вопрос из ключа; затем при необходимости покажите один разобранный шаг. Сохраните первоначальную запись, исправление и вид помощи. Участник может закончить пробу на любом этапе.

### Глава 5. Решение по A/B-тесту

**До выдачи результатов.** Команда тестирует изменение срока доставки. Единица назначения — сессия. Внедрение требует значимого снижения доли опозданий и подтверждения, что падение выручки на сессию укладывается в допустимые 20 ₽. Разность денежных показателей вычисляется как B − A. До получения итогов запишите, как вы будете принимать решение по 95%-му интервалу и какое пересечение границы оставит решение открытым.

**После записи правила.** Ведущий выдаст два результата. В обоих тестах назначение прошло проверку, опоздания значимо снизились, дата анализа заранее назначена. Выберите действие в каждом случае и назовите край интервала, определивший решение.

**11.** Готовьте две партии в одной среде, зафиксируйте версии sklearn и SciPy. Ниже код подготовки в Python. Возвращённые изображения, позиции, прогнозы и уверенности передавайте участнику; метки второй партии держите отдельно до фиксации очереди. Позиции нумеруются с нуля внутри каждой партии. Если участник выбрал своё обоснованное правило, пересчитайте результат именно для него.

```python
import numpy as np
from scipy.ndimage import gaussian_filter
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier

digits = load_digits()
ids = np.arange(len(digits.target))

def split(ids, seed):
    return train_test_split(ids, test_size=0.25, random_state=seed,
                            stratify=digits.target[ids])

def batch(train, other):
    model = MLPClassifier(hidden_layer_sizes=(64,), alpha=1e-3, max_iter=500,
                          random_state=0).fit(digits.data[train] / 16, digits.target[train])
    images = gaussian_filter(digits.images[other] / 16, sigma=(0, 0.8, 0.8),
                             mode="constant", cval=0)
    probs = model.predict_proba(images.reshape(-1, 64))
    return images, np.arange(len(other)), probs.argmax(axis=1), probs.max(axis=1), digits.target[other]

development, holdout = split(ids, 42)
fit, validation = split(development, 7)
first = batch(fit, validation)
second = batch(development, holdout)
```

Контроль подготовки в sklearn 1.9.1: из 337 валидационных цифр три ошибки с уверенностью от 0,90, в том числе позиция 55. При отборе 37 из 450 финальных цифр по наименьшей уверенности и затем по меньшей позиции вне очереди остаются 52 ошибки. Для другой версии библиотеки используйте фактические прогнозы этой же партии. Для целых номеров нужны связанные позиции цифр, эталон и прогноз по одному документу. Для каждого участника отдельно отметьте три наблюдения.

- **Темп.** Запишите минуты до первого осмысленного действия и до решения, а также конкретный переход, на котором человек остановился. Для сравнения редакций используйте одинаковую точку старта, сопоставимую задачу и разные группы с одинаковыми предпосылками.
- **Обратная связь.** Если первый ответ неверен, сохраните сообщение или вопрос ведущего и следующее действие. Отметьте «исправил после одного вопроса», «потребовался разобранный шаг» либо «ошибка осталась». У верной первой попытки запишите «помощь не потребовалась».
- **Самостоятельность.** Различайте «верно до помощи», «верно после вопроса», «верно после разбора», «пока не выполнил». Засчитывайте перенос, когда правило записано до раскрытия и его применение подтверждено на новом входе. Открытый заранее ответ, сбой среды или знакомство с тем же набором фиксируйте отдельно.

В сводке указывайте число участников, распределение попыток, диапазон активного времени и характерные места остановки. Пять исходных оценок методиста пересматриваются отдельно по свидетельствам каждого критерия. Этот сценарий сам по себе баллы не изменяет.
