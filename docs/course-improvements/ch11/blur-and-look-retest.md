## look: ожидание и первая отправка

Считаю counts через bincount, balanced по минимуму/максимуму, mean_imgs по каждому классу в исходной шкале 0–16. Намеренная ошибка — у третьей панели среднего класса 2 заголовок 9. Ожидаю отказ с указанием подписи панели при верных числах и картинках.

```python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.datasets import load_digits
digits = load_digits()
y = digits.target
counts = np.bincount(y, minlength=10)
balanced = bool(counts.min() >= 0.9 * counts.max())
mean_imgs = np.array([digits.images[y == label].mean(axis=0) for label in range(10)])
print(counts, balanced, mean_imgs.shape)
fig, axes = plt.subplots(1, 10, figsize=(15, 2))
for label, ax in enumerate(axes):
    ax.imshow(mean_imgs[label], cmap="gray", vmin=0, vmax=16)
    ax.set_title(str(label if label != 2 else 9))
    ax.axis("off")
plt.show()
```

Первый ответ: **«Пока не так. Панель 2 слева: подпишите изображённую цифру 2 в заголовке, сейчас '9'.»** Числа вывода: [178 182 177 183 181 182 181 179 174 180], balanced = True, mean_imgs.shape = (10, 8, 8).

Сообщение точно называет цифру и неверный заголовок, поэтому меняю только ax.set_title на str(label). Подсказки и готовое решение не нужны. Ожидаю зачёт без изменения расчётов. Код второй отправки:

## blur-transfer: план до открытия итоговых меток

Самостоятельная новая проба: размытие sigma = 0.65, нулевой край. Сначала найду в validation ошибочную цифру с уверенностью ≥ 0.90 и действительно рассмотрю её изображение. Для blind заранее выбираю правило **margin**: меньший разрыв двух лучших классов сигнализирует о неоднозначности между вариантами. Это не гарантия найти уверенные ошибки; их возможные пропуски надо измерить после открытия меток. При равном margin беру меньшую позицию. Очередь — ровно 37 цифр, не анкет.

Пока никаких final_labels не запрашиваю. Пробным запуском выведу кандидатов и картинку одного примера; observation запишу после собственного просмотра.

Вторая проверка после единственной правки заголовка: **«Верно!»**. Реально выведено: **32 ошибки всего, 14 в очереди, 18 вне очереди**. Равенство 32 = 14 + 18 сходится. Это только 37 мест для проверки цифр; не утверждаю, что оператор обязательно исправит все 14, и не превращаю 18 оставшихся ошибок цифр в ошибочные телефоны.

Как разделил ошибки: `blind_pred != final_labels` даёт флаг для каждой позиции; `errors[queue].sum()` считает ошибки строго среди заранее выбранных 37, а разность с total_errors — вне очереди. Метки второй партии до записи margin и всех позиций недоступны: первый вызов даже остановился на подписи до возврата меток. После успешного открытия ни правило, ни очередь не менял.

Ограничение о телефонах: evaluation_unit = digit, phone_accuracy = None. Нужны связанные ID целого номера, порядок его цифр, истинный номер и результат реальной проверки/исправлений оператором. Вероятности и ошибки по независимым картинкам не измеряют долю целиком верных номеров.
