# Ученик: глава 11

Вход — видимая постановка, формулы и заготовки. Исходники, эталоны и готовые решения не читались. Цели и ожидания записаны до кода и клика в сыром JSONL.

Своя сеть numpy действительно обучена 300 шагов. Сохранены W1, b1, W2, b2; `own_proba` имеет форму 450×10 в исходном порядке картинок. Суммы вероятностей отличаются от 1 не более чем на 4.44e-16. Accuracy .967 вычислена по argmax собственных выходов. Проверка: «Да, так и есть».

Карточка очереди оператора прошла: MLP ошибается 8 раз, частая пара (8, 1), review_share = .082, errors_caught = .75. При равной очереди из 37 картинок вне очереди MLP остаются 2 ошибки, вне очереди kNN — 4. При равенстве максимальных вероятностей использована исходная позиция картинки. `operator_queue(A,A,B; True,True,False)` вернула `['A']`: каждый ID один раз, в порядке первого отмеченного появления. Вердикт: «Отлично, задача решена».

Новый вопрос архива реально отвечен: для доли полностью верных шестизначных номеров нужны эталонные полные номера и прогнозы для тех же документов. Ответ записан до результата, «Верно». Точность цифры сама по себе не даёт точность полного телефона или инвентарного номера без дополнительных условий.

Следующее действие понятно: нагрузка измеряется по цифрам, а карточки анкет нужно дедуплицировать. `load_digits` не содержит настоящих ID телефонов и не оценивает долю целиком правильных номеров. Проверка искажений на отдельной валидации и окончательном наборе, PyTorch, dropout и BatchNorm лично не повторялись; полного теста не было.
