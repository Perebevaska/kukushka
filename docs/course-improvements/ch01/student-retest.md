Функцию отчёта построил заново по новой карточке; старый финальный ответ не подставлял.

## Начало урока и прохождение

Вверху первого урока я увидел: «Теория 0 из 4 · Обязательные задачи 0 из 8 · ★ по желанию 0 из 1». В практике прямо сказано, что для урока достаточно решить все задачи, кроме звёздочных. Я понимаю требование так: восемь обычных задач нужно решить, девятая — дополнительная. Теория показывается отдельно; одна звезда не заменяет обязательную задачу.

Сначала открыл «Две строки одним print» и написал print("Открыто", "с 8:00 до 22:00", sep="\n"). Первая проверка приняла код, появились две нужные строки. Счётчик изменился на «Обязательные задачи 0 из 8 · ★ по желанию 1 из 1». То есть я получил отдельный результат за дополнительную работу, а основной прогресс остался прежним.

Затем открыл обычную задачу «Первое приветствие»: print("Привет, Зерно!"). Первая проверка приняла. Теперь «Обязательные задачи 1 из 8 · ★ по желанию 1 из 1». Мне осталось семь обязательных задач; урок целиком я не завершал. Различие счётчиков теперь не приходится угадывать.

## Шаг 6: день недели

Прочитал карточку, сохранил DAYS и построил by_day циклом по clean. До проверки нажал «Запустить» и специально напечатал промежуточный словарь:

Затем вывел «среда 5070». Здесь я увидел, что максимум действительно относится к индексу 2, а не к третьему попавшемуся ключу словаря. Первая проверка приняла код. В проекте стало 1 из 8 обязательных задач.

## Шаг 7: сборка текста по частям

Сначала запустил заготовку, ничего не дописывая: получил ровно заголовок «# Отчёт за 2026-09» и «Принято заказов: 37». Это дало работающую отправную точку.

Вернулся к карточкам шагов 3–5 и прочитал названия переменных и порядок топа. В этом чистом профиле я не выдавал их за уже сданные: их проверки не нажимал. Собственные новые расчёты перенёс внутрь build_report, где вход теперь называется orders.

1. Добавил цикл суммы и среднее. Запуск показал четыре строки, новые суммы — 16370 ₽ и 442 ₽.
2. Добавил группировку по городу и сортировку. Следующий запуск показал пятую строку: Казань (5770 ₽).
3. Добавил подсчёт напитков и сортировку по (-количество, название). Шесть строк: Американо (9), Раф (8), Флэт уайт (8).
4. Перенёс свой расчёт шага 6 вместе с DAYS внутрь функции, заменив clean на orders. Семь строк завершились «среда (5070 ₽)».

Только после этих запусков нажал «Проверить»: принято с первой попытки. В проекте стало 2 из 8. Мне помогло конкретное указание добавлять строки через append до return: я видел, что изменилось после каждого небольшого блока, а не пытался сразу написать весь отчёт.

## Шаг 8: от CSV к скачанному файлу

Я прочитал, что здесь clean уже не подготовлен, и прошёл три этапа карточки.

1. Вставил свои прежние импорты, чтение CSV и удаление дублей. Оставил диагностический print и запустил: «37 3 1». Это совпало с ориентиром карточки. Не понадобилось искать, в каком из двух блоков ошибка.
2. Вставил именно новую функцию шага 7 и вызвал build_report(clean). Запуск показал тот же отчёт с семью строками.
3. Собрал список строк журнала, вычислил исходное число как len(clean) + n_bad + n_dupes, записал text и журнал через open(..., "w", encoding="utf-8"). Открыл записанный файл и напечатал его. Получил журнал 41 / 3 / 1.

В консоли остались диагностические print предыдущих этапов, поэтому полный отчёт там виден дважды. Я понимаю причину: сначала print(text), затем печать прочитанного файла. В самом файле отчёт один — проверил после скачивания. Диагностический вывод не попал в report.md.

Первая проверка шага 8 приняла код, появилась ссылка «Скачать report.md», счётчик проекта стал 3 из 8. Нажал ссылку, получил браузерное скачивание с именем report.md, сохранил его отдельно в этом каталоге. Это новый файл из новой программы, а не копия прежнего результата.

Прочитал скачанное содержимое: семь строк отчёта, затем «## Качество данных» и три строки журнала. Кириллица и знак рубля читаются. Руководитель найдёт напитки в строке «Напитки по числу заказов», день в следующей строке, исключённые данные — в журнале. Сходится 41 = 37 + 3 + 1.
