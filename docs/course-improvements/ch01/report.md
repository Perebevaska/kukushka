## Пути улучшения подачи

1. **Показать, на какие данные распространяется вывод.** В проекте ученик подписывает сумму как учтённую по принятым заказам. Из двух строк сумму прочесть нельзя, для записи `1 250` можно уточнить формат у владельца выгрузки. В итоговом тесте этот же вопрос поставлен в другой области: 18 книг подтверждены по десяти читаемым записям библиотеки. У каждого из четырёх вариантов своё объяснение. [Проект](../../../content/ch01/14-project.md) · [Вопрос 15](../../../site/ch01/test.html)
2. **Давать нужную опору в точке затруднения.** У входа появились ссылки на запуск, исправление и чек. У загрузчика пример `fromisoformat(row["date"])` и обратный переход к нему. У функции с ошибкой ученик сначала прогнозирует, что успеет произойти. При проверке обе ссылки загрузчика пройдены в браузере, новая попытка ученика принята без подсказки. [Вход в главу](../../../site/ch01/index.html) · [Загрузчик](../../../site/ch01/13-files.html#task-loader)
3. **Соединять знакомые действия в одну сдачу.** В шаге 7 ученик сверяет сначала заголовок и число заказов, затем выручку и средний чек. После этого переносит три группировки из собственных решений. В шаге 8 он может увидеть результат очистки и текст для руководителя ещё до записи файла. Повтор с другим месяцем выполняет проверка. Следующая методическая проба — дать человеку новую выгрузку после перерыва и отметить, где он впервые вернулся к подсказке. [Шаг 7](../../../site/ch01/14-project.html#task-report) · [Шаг 8](../../../site/ch01/14-project.html#task-file)
