# Технические пары повторного аудита 15 ноября 2026

`reaudit_technical.py` воспроизводит T01–T12 из
`docs/course-improvements/reaudit/review.md`. Фикстура
`fixtures/reaudit_20261115.jsonl` содержит **точные 35 исходных программ**,
сохранённых до изменений. Их нормативные ожидания не переписаны.
`fixtures/reaudit_20261115_tasks.json` — соответствующие 16 карточек из
исторического экспорта с SHA-256
`064d90ff887e7ef449676077629cf3bfae5ffdd91af7433c5f59b756bffc4eda`.

Запуск из корня проекта в среде курса:

```sh
python tools/checks/reaudit_technical.py --baseline --output /tmp/before-native.jsonl
python tools/checks/reaudit_technical.py --output /tmp/after-native.jsonl
python tools/checks/reaudit_technical.py --baseline --emit /tmp/before
python tools/checks/reaudit_technical.py --emit /tmp/after
node docs/course-improvements/reaudit/expert_pyodide.mjs /tmp/before/tasks.json /tmp/before/programs.jsonl > /tmp/before-pyodide.jsonl
node docs/course-improvements/reaudit/expert_pyodide.mjs /tmp/after/tasks.json /tmp/after/programs.jsonl > /tmp/after-pyodide.jsonl
```

`--baseline` сравнивает результат со **старыми наблюдаемыми вердиктами** в
`docs/course-improvements/reaudit/expert-native.jsonl`, включая 12 известных
расхождений с учебным условием. Это воспроизведение дефектов, а не их одобрение.
Нормативное ожидание остаётся в `expected_original`. После исправления
исполняются те же 35 программ, семь явно отмеченных миграций и дополнительные
положительные/отрицательные пары. Исходные отчёты и программы не меняются.

## Два уточнённых контракта

* `shop-rate`: условие теперь явно задаёт среднее train для неизвестной точки
  и сохранение исходного индекса заказа. Старый позитив не обрабатывает
  неизвестную кофейню; его отказ на новом входе ожидаем. В фазе `migrated`
  добавлен только fallback `y_train.mean()`. Сам чекер принимает любой способ
  вычислить это значение: проверяется результат по ключу, не наличие fillna.
* `compare` и `speed-table`: ученик получает **готовые измерители**
  `timed_fit`/`timed_predict`. Они вызывают реальные методы и возвращают
  зафиксированные интервалы в секундах/миллисекундах. Задача ученика — собрать
  отчёт и сделать вывод по этим наблюдениям. Прежний самостоятельный таймер
  perf_counter не регистрирует измерения; его ожидаемый отказ нельзя выдавать
  за дефект прежней программы. В миграциях заменён только способ получения
  интервалов; выдуманные значения в отрицательных вариантах сохранены.
  Собственные функции, делегирующие поставляемому таймеру, тоже принимаются.

Поэтому совпадение исходных нормативных ожиданий после правки — **32/35**:
три прежних положительных программы требуют миграции. Остальные 32 сохраняют
свои нормативные ожидания. Дополнительные пробы отдельно проверяют сдвиг и
случайную подмену времени, единицы, быстрые/медленные зарегистрированные
интервалы и вывод о минутном окне. Синтетические показания таймера вводятся
только в детерминированных пробах; сами fit/predict при этом исполняются.
Никакой универсальной длительности обучения или победителя по скорости нет.

Перестановки строк, полная и сокращённая ROC, разные индексы parsed и разные
способы нарезки батчей остаются положительными случаями. Отрицательные пробы
меняют ключи отдельно от значений, существенную вершину, внутреннюю точку
диагонали, источник долей, входной RNG, допустимые темы и нарушения диапазонов.

Дополнительная независимая проверка batches выявила потерю столбца X и
игнорирование size. Обе ошибки приняты чекером непосредственно перед уточнением
и отклоняются после него. Фикстура `batches_20261115_refinement.json` сохраняет
тот чекер и обе программы отдельно от исторических 35. Для повтора используйте
`--batches-before --output /tmp/batches-before.jsonl` или
`--batches-before --emit /tmp/batches-before` с тем же исполнителем Pyodide.
Текущий набор содержит 69 программ: прежние 67 и эти две ошибки. Правильный
генератор проверяется на полном X из трёх столбцов, произвольных метках y,
размерах 4/3, seed 0/17 и двух последовательных эпохах для каждого сочетания.
